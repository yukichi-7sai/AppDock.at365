# AppDock.at365

リボン・コマンドパレット・リボングループ・ホーム・ログ・通知センター・バナー・デスクトップ通知の8領域を、本体同梱のDefault ShellまたはShell Appletが描画します。「設定 → 表示 → ワークスペースの表示」で領域ごとに提供元を選べます。例えばリボンにApplet A、ホームにApplet Bを指定できます。Default Shellは常時有効です。無効・未導入・未提供・故障の指定はその領域だけDefault Shellへ戻し、割り当てを保持します。Appletを有効に戻すと、故障の抑止がなければ元の指定先へ復帰します。必要時は領域ごとに再試行できます。Shell Appletは通常のコマンド・設定・ページも提供でき、未割り当てでも通常の機能を使えます。起動時に困った場合は`--safe-shell`で保存設定を保ちながらDefault Shellを使用できます。全体ログとApplet詳細ログは同じ割り当てを使います。

設定画面はすべてのShellで共通の本体画面です。旧版の設定Shell指定は保持しますが、設定画面の描画には使用しません。

新規設定のテーマはLight、Applet通知の許可とマウスジェスチャーはONです。保存済みの設定値は引き継ぎます。テーマは「表示」ページの先頭で選べます。

割り当ては変更時に自動保存します。パレットを表示中に割り当てを変えた場合は次回から使い、現在の提供元が停止した場合は同じ要求をDefault Shellで続けます。通知の切り替えでは通知IDや表示期限を引き継ぎます。

旧版の単一Shell指定は、既存8領域への指定として読み込み、次の保存で領域別形式になります。旧版へ戻すと領域別指定を再現できず、Default Shellを使う場合があります。戻す予定がある場合は更新前の`settings.json`を保管し、AppDockを完全終了してからそのコピーを復元してください。

設定の文字・数値・URL・JSONは、Enterまたはフォーカスを外した時に確定して自動保存します。入力中は設定へ反映せず、Escapeでその欄の未確定入力を取り消せます。複数行の欄はShift+Enterで改行し、日本語変換中のEnter・Escapeは変換操作を優先します。追加・編集ダイアログはOKでまとめて保存し、検索は入力に合わせて絞り込みます。入力途中の数値やJSONは画面内で修正し、保存失敗はそのページに表示します。全体保存・破棄と未保存警告はありません。タイトルバーの「通知」でバナーへフォーカスし、Escapeで元の画面へ戻れます。バナーは複数通知に対応します。通知の履歴はPC専用領域へ保存します。リボンの「通知センター」でアクティブな通知と終了履歴を確認し、検索・既読・履歴削除を行えます。開いただけで全件既読にはしません。独自デスクトップ通知はトレイ付近に積み、本体画面を隠していても表示できます。Windowsの通知とは別の画面です。全画面・ロック中などは表示を抑制し、その間も表示時間は進みます。

登録したWebAppletの「開く・戻る・進む・リロード・開始ページへ」と、名前・既定の表示先をApplet/MCPから操作できます。「設定 → 操作の許可」で許可を変更できます。新規環境のApplet側はAI・読み上げ・MCP利用・カスタムコマンド管理・プロセス起動がOFF、その他はON、MCP側は接続と操作許可がOFFです。保存済みの許可・拒否は引き継ぎます。MCPの情報取得は連携ON時に利用でき、Windowsへの生のキー送信は直接公開しません。

自作の常駐ツールを**Applet**としてまとめて使う、Windows x64向けのアプリです。Appletの有効化、設定、ショートカット、トレイ操作をひとつの画面で管理できます。

「設定 → 通知」で、本体と対応Appletが宣言した通知種類を確認できます。種類ごとの通知先、表示時間、読み上げを変更し、変更時に反映します。時間欄を空にすると閉じるまで表示します。通知先はバナー、デスクトップ通知、Windows通知、読み上げを複数選択でき、必須の通知先がない種類は通知センターのみにすることもできます。デスクトップ通知からもセンターを開けます。更新を適用した後の再起動では、完了通知をバナーへ表示します。既定6秒で消え、通知設定で変更できます。同じ結果を次の通常起動で繰り返し表示しません。通知種類を宣言していない旧方式のAppletだけに「旧方式の通知」を表示します。Gmailなど種類を宣言したAppletには、宣言済みの通知種類だけを表示します。通知そのものをOFFにする設定はありません。Windows側の表示時間はOSが管理し、設定した寿命の間は通知センターで閲覧・操作できます。

設定ページは「タイトルと説明 → ツールバー → 設定」の共通構成です。「読み上げ」は接続先、モデルと声、試聴の順に設定できます。「モデル一覧を更新」でサーバーの候補を取得でき、一覧非対応の場合もIDを直接入力できます。Qwen3-TTS形式の一覧ではダウンロード済みモデルを表示します。APIキーはこのPCだけに暗号化保存します。

通知先には「読み上げ」も選べます。画面通知との併用も、読み上げだけの選択も可能です。「通知センターのみ」を選ぶと画面通知・読み上げ・MCP Eventsを外します。通知用の声・速度は「通知の読み上げ」で必要な項目だけ共通設定から変更できます。Codex連携は有効化後に「Codexへ登録」、続いて「このPC内の接続テスト」で確認できます。登録名や保存先などは「登録先と接続の詳細」にまとめています。

画面ロック中・スリープ中は、通知の表示・Appletの着信音・新しい通知の読み上げを保留し、解除後に届けます。表示時間もその間は停止します。自動サインイン後のロック画面でAppDockが起動した場合も対象です。保留は起動中だけで、終了・再起動を越えて持ち越しません。手動の読み上げ・試聴とMCP Eventsの外部配信は通常どおりです。

通知種類ごとの「MCP Events」をONにすると、購読中のdot等へ新しい通知のタイトルと本文を送れます。初期値はOFFです。MCP連携を有効にし、ChatGPTから接続できる経路を用意したうえで、AppDockプラグインを再スキャンし、dotに「この種類の通知を監視して、届いたら○○して」と指示します。ChatGPTとの接続にはSecure MCP Tunnelまたは認証付き公開HTTPS等の準備が必要です。種類をOFFにすると購読を残して送信を止め、送信待ちを破棄します。OFF中もdot側から有効な購読の期限を更新でき、再ON後は有効期限内なら新しい通知から送信を再開します。AppDockが停止中・未購読・OFFの間の通知を後から送る機能はありません。期限切れやMCP無効化・トークン再発行による解除後、旧版でOFFにして購読が削除済みの場合は、ONにしてdotで監視を登録し直してください。メール等はタイトル・本文の内容を送ってよい種類だけ選択してください。[接続条件と配信の仕組み](docs/mcp-events-design.md)に詳しく記載しています。

Appletの設定も本体と同じカード形式です。対応Appletは用途ごとに項目をまとめ、表示方法・起動待ちは共通の枠で設定します。壁紙のモニター一覧やキー送信の一覧は広い入力欄で編集できます。詳細項目は検索からも直接開けます。設定一覧とApplet詳細の「設定」タブは同じ内容を表示します。

「設定 → 一般」の一番上にある「音の再生」で、読み上げ・通知音・試聴をまとめてON/OFFにできます。既定はONです。OFFにすると再生中の音を止め、再生待ちやロック中の通知音保留、OFF中に届く音を破棄します。ONへ戻すと新しい音から再生します。音声生成は続きます。Webサイト自身やWindowsが独自に鳴らす音は対象外です。「音の再生をONにする／OFFにする／切り替える」のコマンドを、リボンやショートカット等にも割り当てられます。

## MCPハブと保存型コマンド

0.60.0から、AppDockをMCPクライアントとして他のサーバーへ接続し、ツールをAppDockのMCPから中継できます。ツールの呼出しを「カスタムコマンド」へ保存すると、パレット・ショートカット・ジェスチャー・トレイからも利用できます。

1. 「設定 → MCP接続先」で名前とこのPCの接続を登録します。stdioは実行ファイルの絶対パスと起動引数、HTTPはStreamable HTTPのURLを指定します。認証はなし/Bearerに対応します。
2. 「このPCで接続を許可する」をONにして保存し、ツールを取得・選択します。引数を入力して実行すると、同じ画面で結果と取消を確認できます。AppDock自身のMCPサーバーをOFFにしたまま使うこともできます。
3. 外部AIへ中継する場合は接続先の「MCPへ公開する」と公開ツール名を設定し、「操作の許可」のMCP列でMCP利用とコマンド実行を許可します。新しいツールを自動で公開しません。
4. 「設定 → カスタムコマンド」で「MCPツールを実行」を選び、接続先・ツール・固定引数を保存します。そのコマンドへ既存のショートカット等を割り当てます。AIに作成させる場合は、カスタムコマンド管理・設定変更・実行と、割り当て先の編集許可も必要です。

接続先の名前とコマンド定義は共有されます。URL・実行パス・認証・公開許可はPCごとに設定し、Bearerと環境変数値は暗号化保存します。固定引数は共有のJSONなので秘密値を記載しないでください。ツール仕様や接続設定を変えた場合は、詳細を再取得して引数を確認・保存します。

AIにMCP接続先の登録も任せる場合は、「操作の許可」のMCP列で「MCP接続先の管理」「設定変更」「コマンド実行」をONにします。「MCP接続先の管理」は初期OFFで、URL・実行ファイル・公開範囲の編集も含みます。未公開ツールの確認には「MCP接続先の利用」も必要です。AIは管理APIで事前検証・登録・ツール確認・公開範囲の設定を順に行えます。保存しただけでは接続しません。[管理APIの契約](docs/mcp-client-design.md#接続先の管理api)を参照してください。

実行の「受付」と「応答を受領」は別です。取消は待機を止めるもので、操作先の効果を元に戻しません。タイムアウトや結果不明の操作は自動再送しません。「10分後の消灯」は、接続先が提供する予約ツールへ600秒等を渡す形で設定できます。

外側のMCP入口は固定なので、導入後の接続先・ツール・定義の増減は一覧の再取得で辿れます。初回の新しい入口はクライアントへの反映が必要です。ChatGPT本体での初回反映と実操作は未確認です。OAuth、MCP Tasks、2026-07-28方式だけの下流、永続予約、複数操作の連結、WindowsTools移行は今回の対象外です。[対応範囲とAPI](docs/mcp-hub-design.md)、[検証記録](VERIFICATION.md)を参照してください。

## カスタムコマンドの種類と説明

「設定 → カスタムコマンド」で、キー送信、コマンド／プロセス起動、MCPツール実行を登録できます。すべてのカスタムコマンドに説明を入力でき、外部へ公開したコマンドの説明はMCPのコマンド一覧にも反映されます。

キー送信は、追加・編集ダイアログの「送信キー」の枠でキーを押して指定します。ショートカット編集と同じ入力枠を使い、Winを含む組合せにも対応します。Tab・Escは「特殊キーから選ぶ」で指定でき、設定をJSONで編集することもできます。「Ctrl+Shift+T」「Enter」「Win+E」などを指定し、OKで保存してからコマンドを実行します。呼出し用のキーと送信キーは別にし、コマンド同士の循環も避けてください。MCP経由のキー送信には「操作の許可」のMCP列でキー送信とコマンド実行の両方を許可します。Applet側の既存入力許可とは独立しています。

プロセス起動は、実行ファイルの絶対パスと引数の文字列配列、コマンドプロンプトの1行コマンド、Windows PowerShellのスクリプトから選べます。作業フォルダーとコンソール表示も指定できます。GUIアプリの表示はコンソールの指定から独立しています。実行結果は起動受付で、終了や出力は待ちません。AppDockを終了しても起動済みアプリは終了しません。外部実行には初期OFFの「コマンド・プロセスの起動」とコマンド実行の許可が必要です。

保存形式をversion 2へ統一します。旧カスタム設定の移行は行いません。未対応版と表示された場合は、カスタムコマンドページのJSON欄で`{"customCommands":{"version":2,"items":[]}}`を明示保存してから、新規登録・割り当てを行ってください。旧定義はこの操作で置き換わります。複数PCで設定を共有している場合は、各PCの本体を対応版へ更新してから作り直してください。固定設定は共有JSONへ保存するため、秘密値を入力しないでください。

WindowsToolsの旧キー送信はWindowsTools 0.2.0で廃止しました。本体0.62.0以降でキー送信のカスタムコマンドを新規登録し、割り当て先を選び直してください。旧WindowsTools設定・ID・割り当ての自動移行は行いません。

## AI文章生成

「設定 → AI」で、ローカルLLMやOpenAI互換のクラウドへの接続を登録できます。接続先と共通プロンプトを本体で管理し、対応AppletとMCPから用途別のモデル・追加プロンプト・入力を渡して文章を生成します。GmailのAI通知連携は今回の本体機能とは別で、まだ対応していません。

1. 一覧の＋から追加ダイアログを開き、種類・名前・ベースURL・既定モデルを設定します。Ollamaは`http://<サーバー>:11434/v1`、LM Studioは`http://<サーバー>:1234/v1`、OpenAIは`https://api.openai.com/v1`です。
2. 認証が必要な場合はBearerを選び、APIキーを入力します。URLやAPIキーでEnterを押すか、モデル欄の取得ボタンを押すと、保存前にモデル一覧を取得できます。
3. OKで接続情報をまとめて保存します。入力中・キャンセル時は設定を変更しません。キーはこのPCだけに暗号化保存され、登録した接続はそのまま有効になります。架空の入力で試験生成もできます。
4. AppletやMCPから使う場合は「操作の許可」のそれぞれの列でAI文章生成を許可します。文章生成には情報取得・コマンド実行の許可も必要です。

一覧の歯車で編集、ゴミ箱で確認して削除できます。＋の隣の並べ替えボタンから表示順を変更できます。接続先を変更した場合、APIキーは再入力してください。モデル指定を省略すると既定モデルを使い、既定もなければエラーになります。接続障害で別サーバーやクラウドへ自動切替しません。推論モデルで本文が空になる場合は、対応するモデルで詳細設定の推論の強さに`none`を指定するか、出力上限を調整してください。生成結果は画面で確認でき、短時間のメモリー保持後に解放します。

AI接続の「サーバーに合わせた詳細設定」で、既定の出力トークン上限（初期8,192、32〜131,072）と待ち時間（初期60秒、1〜600秒）を指定できます。APIで省略した値と文章生成の試験に使い、呼出し側で指定した値を優先します。上限なしは設けず、本文4,096文字等の制限は別に適用します。

AI生成の失敗は、原因を示す結果表示に加えて「エラー通知」とログに残ります。トークン不足は「出力トークンの上限に達しました」と判別できます。「設定 → 通知 → AppDock → エラー通知」で通知先・表示時間・読み上げを選べます。初期状態はバナーとデスクトップ通知、閉じるまで表示、読み上げOFFです。バナーが必須で、「通知センターのみ」にはできません。通知そのものをOFFにする設定はありません。ログも残ります。

設定の反映に再起動が必要な場合や、設定ファイルの読み込み・保存などに失敗した場合は、理由と「再起動」ボタンを通知に表示します。JSONの不正は再起動だけでは直らないため、修正または「バックアップで復元」を使ってください。復元前に壊れた内容をPC内へ退避し、確認中に正常な設定が届けばそちらを優先します。通知を閉じたあとも「設定 → 一般 → 設定ファイル」から状態と復元操作を確認できます。起動時に正常なバックアップもない場合は、復旧画面から正常なJSONを選択できます。復元した設定は同期先のPCにも届きます。

「設定 → 通知」のAppDock欄は「エラー通知」「警告通知」「インフォメーション通知」の順に表示します。エラーと警告は閉じるまで表示し、インフォメーションは既定6秒・バナーのみ・読み上げOFFです。3種類ともバナー必須で、通知全体のOFFはできません。更新確認、Codex連携の接続テストや保存などの結果をインフォメーション通知へまとめ、ステータスバーに重なる結果表示をなくしました。更新中の進捗とキャンセル操作は残ります。保存済みの表示時間は引き継ぎます。通知設定は「通知の受け取り方」「通知の読み上げ」、AppDock・Appletごとのグループの順に並びます。通知種類のカードは最初は閉じており、見出しに現在の通知先・表示時間・読み上げON/OFFを表示します。タイトルを押すと個別設定を開けます。一般設定は「ウィンドウ」「スタートアップ」「Applet・MCPからの操作」「設定ファイル」の順です。

バナー・デスクトップ通知・通知センターは、エラーを赤系、警告を黄系、インフォメーションを緑のポイントで表示します。インフォメーションの背景はライトテーマで白、ダークテーマで暗い色になります。対応Appletの通知にも、指定されたレベルの配色を使います。

## 動作環境・起動

配布された `AppDock.at365.exe` を、書き込み可能な好きなフォルダに置いて起動してください。AppDock自体のインストールは不要です。通常の.NETホストは、利用するPCにインストール済みの **.NET 10 Runtime（Windows x64）** を使用します。Node.jsの別途インストールは不要です。

.NET 10 RuntimeがないPCでは、[Microsoftの.NET 10ダウンロードページ](https://dotnet.microsoft.com/download/dotnet/10.0)から「.NET Runtime」のWindows x64版をインストールしてください。.NET 10 SDKや.NET 10 Desktop Runtimeが入っているPCは、含まれる.NET Runtimeを利用できます。`dotnet --list-runtimes` に `Microsoft.NETCore.App 10.0.x` が表示されることを確認してください。追加の動作環境が必要なAppletは、そのAppletの案内に従ってください。

Electron 44.6.0を使用します。Appletの画面は宣言に応じて本体ページまたは別ウィンドウで表示できます。Gmailは両方に対応します。対応するWebアカウントAppletでは、Applet自身の設定から非表示時に開始ページへ戻す動作をON/OFFできます。Gmail 0.10.0の「非表示になったら受信トレイへ戻す」はAppDock 0.35.2以降で利用できます。

同じアカウントグループに対応するAppletは、一覧・表示名・順番と、同じPC内のログイン状態を共用できます。Gmail 0.12.0はGoogleアカウントグループを使います。アカウントの選択や監視・通知音はAppletごとです。共有枠の削除やWeb画面からのログアウトは、同じグループのほかのAppletにも影響します。

この配布版は未署名です。

## マウスジェスチャー

ショートカットと同じ全コマンド一覧で、未割り当ても表示します。検索・割り当て状態で絞り込み、コマンドの「＋」から追加、割り当てをクリックして編集できます。パネルでは移動・クリック・ホイール・キーボードを選び、条件と有効状態を設定します。

「実行順…」または割り当ての「… → このジェスチャーの実行順…」から、同じジェスチャー内をドラッグ・上下ボタン・Alt＋上下で並べ替えられます。適用時に保存します。削除は確認なしで反映し、追加後も検索と表示位置を保持します。

「設定 → マウスジェスチャー」で、AppDock本体やAppletのコマンドへ割り当てます。右ボタンを押しながら上下左右へ移動して離すか、左/中クリック・ホイール上下・キーを押すと実行します。単一方向の移動を認識し、方向転換や対象変更でキャンセルします。操作せずに離すと普通の右クリックに戻ります。右ボタンを押した時点でCtrl・Alt・Shift・Win（左右どちらも）、左・中・戻る・進むボタンのいずれかが押されている場合は、ジェスチャー待機を始めず通常の操作を通します。途中で先に押していたキーやボタンを離しても、右ボタンを離すまでは待機しません。待機開始後の修飾キーや左・中クリックは従来どおりジェスチャーに使えます。

条件はグローバル、Webブラウザ、指定したexe、AppDock全体、すべてのApplet、提供元のApplet、指定したApplet。「動作設定」の実行方法で、条件に一致した「最初の1つ」または「すべて」を選べます。登録順に選び、同じコマンドは1回です。初期値は従来どおり「すべて」です。キーはCtrl/Alt/Shift付きや英数字、Fキー、対応特殊キーを指定します。WinやOS専用キーは対象外です。

画面の一番上にある折りたたみ「動作設定」に、有効・実行方法・操作感・待機表示・Webブラウザ・除外をまとめています。待機表示は実行方法に合わせた対象コマンドを表示します。表示位置の「表示なし」を選ぶと、操作を維持したまま待機表示を隠せます。不透明度は保持され、表示を戻した際に再利用します。対象ブラウザexeを変更し、Chromium制限をオフにすればFirefoxなども指定できます。操作コマンドへの対応はブラウザによります。本体コマンド「マウスジェスチャーを一時停止／再開」は実行するたびに状態を切り替え、本体再起動で解除します。トレイへの配置やショートカット割り当てができ、トレイでは一時停止中にチェックが付きます。右ドラッグを使うアプリには除外または一時停止を使ってください。

ジェスチャーの初期割り当ては各Appletの宣言から初回だけ取り込みます。0.28.0以降、旧WebBrowserTools内のジェスチャー設定は引き継ぎません。本体のジェスチャー設定がない場合は空の割り当てから設定してください。WebBrowserToolsは本体管理の入力を使う0.3.2以降を利用してください。入力補助プロセスに必要な.NET/WPFは本体EXEへ同梱し、Desktop Runtimeの追加インストールは不要です。他のジェスチャーソフトとの競合や、管理者権限アプリへの送信制限には注意してください。

## 基本の使い方

ホーム・ログ・設定は本文領域全体に表示します。ページ切り替え中の背景も現在のライト／ダークテーマに合わせます。ホームのカードは横幅に応じて列数が変わります。ログは通常、検索欄を残して一覧だけがスクロールし、設定は左の一覧と右の本文をそれぞれスクロールできます。高さが小さい場合は操作欄も含めてスクロールします。

設定のJSONは選択中のページが扱う範囲だけを表示し、妥当な変更を自動保存します。Webアカウント・操作の許可・Codex連携などの操作は各画面で扱い、JSONには含めません。

初回起動でEXEの隣に `settings.json` が作成されます。「設定」からフォームとJSONの両方で編集できます。ウィンドウの×は既定でトレイへ格納します。完全終了はトレイメニューの「終了」です。この動作は設定で変更できます。

AppDock内のテキスト入力では、スペルチェックを無効にしています。

設定とAppletページは変更時に自動保存します。Appletの説明・設定・ショートカット・ログを切り替えても選択中のタブを維持します。並べ替えも操作時に保存します。

入力途中の数値や不正JSONは現在の画面だけに保持します。修正すると保存し、ページを離れると不完全な入力は破棄します。保存失敗や同じ項目の外部変更は画面内に表示し、保存済み値を維持します。

メインウィンドウの位置・サイズ・最大化状態は自動保存し、次回起動時に復元します。最小化中は通常表示の位置・サイズを保持し、「起動時に最小化」の設定も優先します。モニターの取り外しや解像度変更で画面外になる場合は、現在の画面内へ補正します。

- **ホーム**: 実行中・エラーのApplet数、コマンド数、ピン留めしたコマンドとApplet一覧。
- **Applet**: 検索付き一覧から選択。有効・無効、再起動、Appletが提供する画面と操作。横並びの「説明・設定・ショートカット・ログ」タブで、その下の内容を同じページ内で切り替えます。選択中のタブは色で表示し、タブにフォーカスすると左右キー、Home/Endでも切り替えられます。ログは選択したAppletだけを表示し、検索・レベルで絞り込めます。「ショートカット」タブでは、提供元のコマンド順にキーと条件を確認できます。＋で追加、キーと条件をクリックして小さなパネルで編集、その他メニューから確認なしで削除できます。削除は操作時に保存します。左の「並べ替え」をONにすると、つまみのドラッグ・上下ボタン・つまみにフォーカスして上下キーでApplet順を変更できます。操作時に保存して再起動後も保持され、新規Appletは末尾へ追加されます。リボンの配置やキーの実行順は変わりません。
- **設定**: ホスト設定のカテゴリとApplet一覧、横断検索を表示します。個別設定はApplet詳細の設定タブと同じ本文・編集状態を使います。ショートカットは全コマンドを一覧表示し、専用の検索・状態絞り込みも利用できます。選択式設定と動的なモニター一覧に対応します。
- **ログ**: 直近500件、検索、レベルでの絞り込み。Appletが共通APIへ出したエラーは、停止時のクリーンアップ中も表示・保存します。ファイルログは1MBで1世代ローテーション。
- **コマンドパレット**: 既定は `Ctrl+P` / `Ctrl+Shift+P`。`Ctrl+,` で設定を開きます。コマンド名・Applet名・IDで検索し、↑／↓キーで選択、Enterで実行、Escapeで閉じます。☆でピン留め、各行の↑／↓ボタンでピンの順番を変更できます。ピンと順番は操作時に保存します。

Appletページと全体設定は同じ保存済み値を表示します。ショートカットの小さなパネル内の入力は適用時に保存し、キャンセルで閉じられます。全ページをまたぐ下書きや全体保存・破棄はありません。

設定一覧の検索は項目名・説明・キー・所属名から探します。空白区切りはAND検索です。結果を選ぶとページ全体を開き、対象の折りたたみを展開してスクロールし、約2秒強調します。本文は検索語で絞り込みません。検索欄の上下キー・Enterで移動、Escapeで解除できます。停止中のAppletも検索でき、検索のために起動しません。検索語はページ往復・Shell復旧で保持しますが、終了後は残しません。Applet詳細の設定本文内にはローカル検索を置きません。

Applet画面と設定画面の左側の一覧は、同じ背景・余白・選択表示で名前を左揃えに表示します。左パネルの右端をドラッグすると幅を変更でき、両画面で共通の幅を使います。変更した幅は自動保存されて次回起動時も復元します。境界にフォーカスして左右キーでも調整できます。幅は220～480pxで、小さいウィンドウでは表示幅を抑えます。幅はこのPCのLOCALAPPDATA内に保存します。ショートカット設定のコマンド検索と「すべて／登録エラー」の切り替えボタンは同じ行に表示します。表示領域が足りない場合は折り返します。

ページ移動は左の「リボン」に集約しています。「設定 → リボン」で標準ボタンと対応Appletのボタンの表示・非表示を選び、上寄せ・下寄せを指定して、それぞれ行をドラッグするか上下ボタンで並べ替えて保存できます。セパレーターも追加・削除・並べ替えできます。初期状態ではテーマとプロフィールが下寄せです。「リボンを初期状態に戻す」も利用できます。設定ボタンを隠した場合も、トレイの固定「設定…」、`Ctrl+,`や「設定を開く」コマンドから設定へ戻れます。

ページを持つAppletは「設定 → 対象Applet」の「表示方法」で、本体のページまたは別ウィンドウを選べます。リボンボタン・開くコマンド・ショートカットは同じ表示方法に従います。画面を表示中に変更して保存すると、そのまま表示先を切り替えます。ページを離れても、常駐処理はAppletを無効化するまで継続します。すべての独自ウィンドウがページ表示に対応するわけではありません。

ビルトインコマンドの「再起動」（`appdock.restart`）と「終了」（`appdock.quit`）は、AppDock本体を再起動・完全終了します。コマンドパレット、ピン留め、ショートカット、トレイ表示・クリックへの割り当てに対応し、既定のキー割り当てはありません。どちらもAppletを停止してから終了し、再起動は保存済みの設定で起動し直します。単一EXE版は元の配布EXEから再起動します。再起動時は「トレイに最小化して起動」の設定にかかわらず画面を表示し、開いていたページ・設定カテゴリ・選択Appletを復元します。通常の起動ではトレイ開始の設定を使います。

フォームとJSONは変更時に検証して保存します。JSONは選択ページの範囲だけを変更します。不完全なJSONや保存失敗は現在の画面内で修正でき、ほかのページへ移動できます。

対応Appletの設定ページには操作ボタンも表示します。ボタンは押した時点で実行し、成功・失敗をその近くへ表示します。設定変更の保存とは独立した操作です。Appletが停止中の操作は利用できません。

通常の単一EXE版にはAppletを同梱していません。初回起動時のApplet一覧は空で、必要なAppletをEXEの隣の `extensions` に追加して使用します。

「設定 → リボン」でボタンをグループにまとめられます。「持続的」はリボン内へ展開し、開閉状態をこのPCで再起動後も保持します。「一時的」は右側に横1行のパネルを開き、ボタンの選択・外側クリック・Escapeで閉じます。所属先の選択やドラッグでボタンを移動でき、グループを解除すると中のボタンが元のグループ位置へ戻ります。

一時パネルはグループボタンと高さを揃えて表示し、タイトルや閉じるボタンは表示しません。横幅が足りない場合だけスクロールボタンを表示します。開閉してもリボン本体の下のボタンは移動しません。

一覧の編集アイコンから、各ボタンの「ボタン名」と「リボンにアイコンのみを表示する」を変更できます。ボタン名を空欄にすると登録元の名前へ戻ります。登録元のAppletやページの名前自体は変わりません。グループもアイコンだけにでき、グループ名が空欄の場合はアイコンだけを表示します。登録元がなくなった項目には削除アイコンが付き、保存された配置・所属・表示設定を消せます。停止中のAppletの項目は配置を保持します。

登録元がなくなっても、変更したボタン名や保存時に記録した登録名があれば、設定一覧にその名前を表示します。今後リボンの配置・表示を変更して保存する際に、配置済みAppletの登録名も記録します。すでに登録元がなく、名前の記録もない項目だけIDで表示します。

「設定 → リボン」には「動作設定」と「リボン編集」のカードが同じ階層に並びます。先頭の「動作設定」を開くと、「右クリックのコマンド」を選べます。既定は「リボン設定を開く」です。その下の「リボン編集」でコマンドボタンを追加し、名前・固定候補のアイコン・実行するコマンドをダイアログで設定できます。本体・Applet・登録済みカスタムコマンドを選べ、グループ内にも配置できます。未登録・停止中の実行先は設定を保持したまま無効になります。リボンの初期化は編集内容を初期化し、動作設定の右クリック割当を保持します。

グループの編集では「色」から、ボタンの枠の色を選べます。持続的グループを開くと、同じ色の縦線が枠から子の一覧へつながります。「色なし」では枠と縦線を表示しません。色見本・自由な色選択・HEX入力を利用でき、確定すると反映・保存されます。セパレーターの編集アイコンからは名前を変更でき、空欄で自動生成した名前へ戻せます。

対応Appletのボタンには件数または点のバッジが付きます。100件以上は`99+`、グループ内にバッジがある場合はグループにも点を表示します。Gmailでは監視中のアカウントの未読の新着スレッド数を表示します。

## 通知の読み上げ

「設定 → 通知」で、通知種類ごとに「通知を読み上げる」をONにできます。初期値はすべてOFFです。タイトルと本文を1回読み上げ、同じ通知の本文更新・表示先変更・既読化では繰り返しません。画面への通知先をすべて外した場合も読み上げを使えます。「通知センターのみ」を選ぶと読み上げもOFFになります。

通知ページ上部で、声と速度をそれぞれ共通の読み上げ設定から継承するか、通知全体で上書きするかを選べます。接続先・モデル・APIキーと速度の適用方式は共通です。「通知の読み上げを試聴」で保存済みの設定を確認し、「試聴を停止」でその試聴だけを止められます。声・速度の変更は次の通知から適用します。

読み上げには共通TTSの接続先・モデル・有効な声が必要です。本文を設定先のサーバーへ送信します。Applet/MCPの直接TTS利用許可とは独立しているため、通知のONでそれらの許可を変更しません。TTS未設定・接続失敗・キュー満杯でも、通知表示と履歴は継続します。

ロック・サスペンド・通知抑制中は自動読み上げを止め、解除後にまとめて再生しません。発行から60秒以内に再生を開始できなかった音声は取り消します。短時間表示の通知が自然に消えても音声は継続しますが、手動で閉じる・発行元が解決する・読み上げOFF・Applet停止では対象音声を止めます。「設定 → 読み上げ」の全体停止は起動待ちも含めて停止します。

## 読み上げ

「設定 → 読み上げ」でOpenAI互換TTSサーバーのAPIベースURL（例: http://host:8080/v1）、モデル、既定のボイス・速度を設定します。APIキーは任意で、設定済みの場合だけBearer認証を使います。キーはこのPCへ暗号化保存し、接続先を変えたら再設定します。通常設定とキーをまとめて同期することはありません。

「ボイス一覧を更新」で候補を取得できます。一覧非対応のサーバーでは詳細設定の手動一覧、またはボイスIDの直接入力を使用します。「試聴する」で入力したテキストをサーバーへ送って再生し、「すべての読み上げを停止」で止められます。本文・生成音声は保存しません。

読み上げ・通知音・試聴は共通の順番待ちで再生し、重なりません。音声生成中は通知音を再生でき、準備ができた音から順番に鳴ります。通知音のWAV未選択は無音です。

速度は0.25～4倍です。既定ではAppDock側で音程を保って再生速度を変更し、サーバーには等速生成を要求します。サーバーが速度変更に対応している場合は、詳細設定の「速度の適用先」で生成側へ変更できます。現在のQwen3-TTSボイスクローン用サーバーでは、AppDock側の速度変更を使用してください。

Applet/MCPから使う場合は「設定 → 操作の許可」の各列で「TTSサーバーへの送信・読み上げ」をONにします。初期値は両方OFFです。読み上げには公開情報取得・コマンド実行の許可も必要です。受付後は生成・再生を順番に進め、音はAppDockが動いているPCの既定デバイスへ出ます。最大4096文字・10分の音声・16件の待ち件数に対応します。長文の自動分割と音声保存は行いません。

## Codex連携

設定変更は公開コマンドを使います。Applet自身が公開する設定とON/OFF/切り替えに対応し、生成したコマンドはショートカットの候補にも表示します。WebAppletの「開く」も本体の公開コマンドとして利用できます。

各Appletの有効・無効・再起動コマンドを本体が自動生成します。「設定 → 操作の許可」のMCP列で「公開コマンドの実行」と「Appletの有効・無効・再起動」の両方を許可すると、Codexからも使えます。Applet管理の許可は初期状態ではOFFで、設定変更の許可とは独立しています。有効・無効は保存し、再起動では有効状態を変えません。無効なAppletの再起動は拒否します。生成コマンドはショートカット・ジェスチャー・トレイにも割り当てられます。Applet一覧・ログ・更新画面を開くコマンドも利用できます。更新の適用は含みません。

Codexでショートカットの割当・条件・実行順を取得し、追加・変更・削除・同じキー内の並べ替えができます。「設定変更」「コマンド実行」と、初期OFFの「ショートカット編集」の3つを許可してください。新しい割当先は公開済みの引数なしコマンドです。既存の割当は保持し、変更は既存の編集画面にも反映されます。

タスクトレイのメニューとシングル／ダブルクリックの割り当てをCodexから編集できます。「設定変更」「コマンド実行」に加え、初期OFFの「タスクトレイ編集」を許可してください。メニュー項目・区切り線・グループを追加し、移動・並べ替え・グループ名変更・削除ができます。グループ解除では中の項目を残し、末尾の「設定」「終了」は固定です。ダブルクリックは未設定へ戻せます。MCPは22ツールです。接続情報を変更した後はCodexを再読み込みしてください。

リボンの表示・非表示、上下配置、並び順、セパレーターの追加・削除、初期化をCodexから変更できます。「設定変更」「コマンド実行」に加えて、初期OFFの「リボン編集」を許可してください。無効なAppletの配置も編集できますが、有効化はしません。初期化は未導入Appletの保存済み配置も含めて元に戻します。更新後にCodexを再読み込みしてください。

マウスジェスチャーの割当・条件・実行順と、全体のON/OFF・対象アプリ・移動距離などの動作設定もCodexで編集できます。「設定変更」「コマンド実行」に加え、初期OFFの「ジェスチャー編集」を許可してください。ショートカット編集の許可とは別です。公開済みの引数なしコマンドへ割り当て、変更は既存のマウスジェスチャー画面に反映されます。保存と実際の入力の成功は別なので、変更後に使う場面で動作を確認してください。更新後にCodexを再読み込みしてください。

Codexへの登録名は「AppDock」です。複数登録するときは「接続の詳細」で「AppDock_Test」など別の名前を指定できます。登録済みの名前は自動変更しません。「登録を解除」してから「登録・修復」で登録し直してください。

「設定 → MCP・Codex連携」で「連携を有効にする」をONにして、Codexの設定ファイルを確認し「Codexへ登録」（登録済みなら「登録を修復」）を押します。Codexを再読み込みまたは再起動し、新しいチャットで「AppDockの状態を確認して」と依頼してください。Codex CLIの別途インストールは登録に不要です。

本体情報、Applet一覧・詳細、対応設定の説明と値、外部公開コマンドの一覧を取得できます。「設定 → 操作の許可」のMCP列で「公開コマンドの実行」と「公開設定の変更」の両方をONにすると、本体のテーマ・通知・閉じる動作・起動時の最小化と、各Appletが公開した設定を変更できます。GUIで編集中の入力は保持し、変更が競合した場合は再読み込みを案内します。

設定以外の通常操作は、MCP列の「公開コマンドの実行」をONにすると利用できます。AppDockの表示・設定・コマンド検索、稼働中のGmail/WebAppletを開く操作、壁紙スライドショーの次へ・開始/再開・停止に対応します。停止中のAppletを自動で有効化しません。操作結果は受付または処理からの応答を表し、操作先での効果を確認したものではありません。

API呼出しの成功・失敗は「ログ」で提供元を「automation」に絞って確認できます。API名、公開された対象ID、処理時間などを記録し、引数の値や認証情報は残しません。既存のhost.logにも保存します。

自動登録の対象は同じWindows上のCodexです。AppDockの起動中だけ利用でき、サーバー稼働・Codexへの登録・このPC／ネットワークの最終接続日時を別々に表示します。「このPC内の接続テスト」はAppDock内の疎通確認です。日時にはCodex以外のMCPクライアントも含むため、実際のアプリから操作できることは別途確認してください。連携操作はこのPCへ即時反映され、settings.jsonの設定変更とは独立しています。

操作許可は連携がOFFの間も準備できます。ONでも前提となる許可が足りない操作には理由を表示します。情報取得はMCP連携中に許可され、生のキー送信はMCPへ直接公開しません。

初期状態は無効・読み取り専用です。接続情報はPC専用領域へ保存し、登録用トークンはCodexのローカル設定にも保存します。停止は連携スイッチ、登録の削除は「登録を解除」を使います。他のCodex設定は保持します。外部アプリでAppDockの登録を削除した後も、保存済みの管理情報があれば「登録・修復」から再登録できます。接続ポートや認証情報を変更した場合は「登録・修復」を押してCodexを再読み込みしてください。AppDock内からCodexへ会話する機能は含みません。

### LAN・tailnetから使う

「MCP・Codex連携」の「接続範囲」で「このPCのみ」（初期値）と「ネットワークからも接続可能（IPv4）」を切り替えます。ネットワーク接続では、到達可能なすべての接続元に同じ認証トークンとMCPの操作許可を適用します。LAN・tailnet以外のネットワークインターフェースも待受対象です。

1. 連携を有効にし、接続範囲を「ネットワークからも接続可能」にします。
2. 「ネットワークからの接続」に表示される接続先候補を、接続元のMCP対応アプリへ登録します。方式はStreamable HTTP、URLは`http://<AppDockのPCのIPv4>:<ポート>/mcp`です。
3. 「接続トークンをコピー」でOSクリップボードへコピーし、接続元へBearer認証として設定します。Ollamaを使う場合は、Ollamaを呼ぶMCP対応AIアプリや中継プログラムに設定してください。
4. 接続元からツール一覧や本体情報の取得を確認します。IPやネットワークの変更後は「接続の状態を再読み込み」で候補を更新できます。

認証設定の例は画面の「認証の設定例」にも表示します。Bearerトークン用の環境変数名を指定するクライアントでは、名前を`MCP_BEARER_TOKEN`（任意の例）にし、接続元アプリが参照できるその環境変数へ**コピーしたトークンだけ**を保存します。`Bearer `は付けず、追加・変更後は接続元アプリを再起動します。ヘッダーを直接設定する場合は、キーを`Authorization`、値を`Bearer <コピーしたトークン>`にします。`Bearer`の後は半角スペース1つで、山括弧ごと実際のトークンに置き換えます。通常はどちらか一方を使い、環境変数名は接続元アプリの指定と一致させてください。ヘッダー値に変数名を書くだけでは展開されません。

候補はこのPCのIPv4アドレスです。Hyper-Vの`vEthernet (Default Switch)`は仮想マシン向けのNAT側アドレスなので候補から除外します。Tailscaleや外部ネットワーク用の仮想アダプターは残します。候補からの除外は表示だけで、直接URLを指定した接続の許可を変更しません。

ホスト名を使う場合、このPCのホスト名は利用できます。MagicDNSの完全名や別のDNS名は「登録先と接続の詳細 → 追加の接続先ホスト名」へ1行ずつ登録します。入力欄を離れると保存し、URL・ポート・IPアドレスは指定しません。接続元でその名前がAppDockのPCのIPv4へ解決される必要があります。

範囲変更だけなら、同じPCのCodexの接続先・トークン・登録は変わりません。切替中に通信が一時切断されるため、戻らなければ接続元アプリで再接続してください。応答が途切れた操作は実行済みの場合があるため、結果を確認してから再操作してください。起動に失敗すると停止状態になり、原因の解消後に「接続を再試行」で再開できます。ポートを変更した場合はCodex登録の修復と外部アプリのURL更新が必要です。認証情報を再発行した場合は全クライアントのトークンを更新してください。

LAN直結は暗号化されないHTTP通信です。tailnet経由ではTailscaleの通信経路で保護されます。接続できる範囲はネットワークとWindowsファイアウォールの設定にも依存し、AppDockからそれらを自動変更しません。IPv6の直接接続とブラウザーからの別originの直接呼出しには対応していません。同じトークンのクライアントは操作許可とAI・読み上げジョブの管理範囲を共有します。

## オールインワン版

AppDockのGitHub Releaseに添付する`AppDock.at365-all-in-one-<本体の版>.zip`には、単一EXEのAppDock本体と、リリース時に同梱した全Appletが入っています。ZIP全体を新しい書き込み可能なフォルダーへ展開し、`AppDock.at365.exe`を起動してください。AppletはEXEの隣の`extensions`に配置済みなので、使いたいものを一覧から有効にできます。初期状態はすべて無効です。.NET 10 Runtimeなど、本体・各Appletの動作要件は通常版と同じです。

同梱したAppletの版は`bundle.json`で確認できます。このファイルは配布時の一覧で、導入後の個別更新には追従しません。既存環境の更新には、本体・Appletの更新ボタンを利用してください。オールインワンZIPを既存フォルダーへ重ねて展開すると、個別に更新したAppletを古い版へ戻す場合があります。

## ショートカット

「AppDockを表示」をグローバルに割り当てると、ほかのウィンドウの背後・最小化・非表示から前面へ表示できます。キー送信コマンドはデスクトップを選択した状態でも使えます（例: WindowsToolsのWin+Eでエクスプローラーを開く）。

「設定 → ショートカット」には、本体と全Appletのコマンドを未割り当ても含めて一覧表示します。コマンド横の＋で追加、キーと条件をクリックして小さなパネルで編集します。キー・条件・有効状態はパネルで適用すると保存します。上部の「実行順…」または割り当てのその他メニューの「このキーの実行順…」から専用パネルを開き、同じキー内の順番をドラッグ・上下ボタンで変更できます。Applet画面から開いた場合も、他のAppletを含むそのキーの全割り当てを表示します。順序はパネルで適用すると保存します。

「いつ・どこで」はリストから選びます。

| 条件                | 受け付ける場面                                       |
| ------------------- | ---------------------------------------------------- |
| グローバル          | 他アプリ操作中やトレイ格納中も有効                   |
| AppDock全体         | 本体またはAppDockが管理するAppletウィンドウを操作中  |
| すべてのApplet      | いずれかのApplet操作ページがアクティブ               |
| Gmailなどの提供元名 | そのコマンドを登録したAppletの操作ページがアクティブ |
| 指定したApplet      | チェックしたAppletのどれかの操作ページがアクティブ   |

提供元の項目にはApplet名だけを表示します。AppDock本体のコマンドにはこの項目はありません。
新しくキーを割り当てると、Appletのコマンドは提供元のApplet、本体のコマンドはAppDock全体が選ばれます。既存行のキー変更では条件を保持します。
ショートカット一覧・コマンド検索・ホームのピン留めには完全なコマンドID（例: `at365.gmail.nextAccount`）を表示します。コマンド名・提供元名・コマンドIDで検索できます。
一覧は「コマンド」「割り当て」の2列で、同じコマンドの複数のキーと条件をまとめて表示します。上部の検索はコマンド名・ID・提供元・キーで絞り込めます。「すべて／割り当て済み／未割り当て／登録エラー」も選択できます。追加後も検索と表示位置を保ち、自動スクロールしません。

パネルの記録欄ではEnterやDeleteもキーとして入力できます。Tabは次の項目へ移動、Escapeはキャンセルです。Tab/Escapeなどは「特殊キーから選ぶ」でCtrl/Alt/Shiftと組み合わせて指定できます。
グローバルキーは登録に失敗したときだけ理由と「登録を再試行」を表示します。キー入力中もエラー表示を保ち、正常時の「登録済み／未登録」や「同じキーの割り当てあり」は表示しません。同じキーに複数のコマンドを割り当てることはできます。

割り当てを外すときは「…」→「削除」を選ぶと、確認なしで一覧に反映されます。保存前なら「変更を破棄して再読み込み」で戻せます。無効な割り当てや停止中のAppletでも操作できます。選んだ割り当てだけを解除し、同じコマンドの別の割り当ては残ります。Deleteはキー欄でショートカットとして記録できます。

Appletを新しく導入してAppDockを起動すると、そのAppletが指定した既定のキー・条件・有効状態を初回だけ追加します。Applet詳細の「ショートカット」では、一覧から必要な割り当てだけ編集できます。各コマンドに割り当てられたキーと条件を列挙し、未割り当てと無効も表示します。
WebAppletの管理画面では、これから追加するWebAppletの既定の割り当てを編集できます。初期状態はリロード=F5、戻る=Alt+左、進む=Alt+右で、いずれも追加したWebAppletのページで有効です。変更は既存のWebAppletには遡って反映されません。

Gmail、各WebAppletを個別に選択できます。対象は名前を変更しても保持されます。独立したWPF/WinForms等のnative Applet独自ウィンドウはページ条件の対象外です。

同じキーの複数割り当てを許可し、押した瞬間に条件を満たした利用可能なコマンドを実行順に処理します。同じコマンドが重なった場合は1回だけ実行します。途中でページが変わっても実行対象は変わりません。失敗はログに記録して後続へ進みますが、終了・再起動後の処理は実行されません。実行中のコマンドの再入と長押しによるローカルキー連打は抑制します。

Ctrl / Alt / Shift、Pause、F1〜F24などに対応します。本体の文字入力中はCtrl/Altなしのキーを実行しません。AppletのWeb画面では通常の文字入力を保つため、Ctrl/Alt付き・F1〜F24・Pauseだけを受け付けます。IME変換中のローカル入力、キー記録中は実行しません。グローバルキーはOS登録なので他アプリの入力にも作用します。

検索と「登録エラー」は、該当コマンドに付いているすべての割り当てを表示します。未導入・停止中のコマンドや無効な割り当ては保持します。設定変更は操作時に保存し、Appletの一覧にも反映されます。トレイ配置は「タスクトレイ」で設定します。

グローバルは利用可能なコマンドのキーをWindowsへ登録します。同じキーは一度だけ登録し、条件判定後に複数コマンドへ振り分けます。他アプリとの競合は登録エラーとして表示し、再試行できます。キー記録中は一時解除し、停止・変更・終了時に更新/解放します。Watchの既定はグローバルのPauseです。

## プロフィール

「設定 → プロフィール」でユーザー名とアバターを変更できます。PNG / JPEG（5MB以下）を選び保存すると、`data/assets/profile/`に元のファイル名で登録します。同名同内容は再利用し、同名の別画像は登録できません。画像を外しても登録ファイルは残します。設定には相対パスだけを保存し、対応表は作りません。

## Appletの追加

### URLからWebAppletを追加する

本体0.44.0への単独更新ではWebAppletは自動導入されません。旧サイト設定とログイン領域は保持します。対応Appletを併せて配置してください。[移行と保存の詳細](docs/web-applets.md)。

WebAppletは独立したApplet.WebApplet.at365（AppDock 0.44.0以上）です。extensionsへ導入して有効にし、「管理画面を開く」からサイトと初期ショートカットを編集します。登録したサイトはそれぞれの名前でApplet一覧・リボンに表示され、個別の設定やショートカットも編集できます。

Appletページで停止すると、対象Applet（WebAppletやGmailなど）のリボンアイコンを自動で隠します。再開すると元の配置へ戻ります。

WebAppletの管理画面の「サイトを追加」で、好きなWebページの名前とURLを登録できます。登録するとApplet一覧とリボンへ追加され、本体ページまたは別ウィンドウで開けます。ページ遷移は開始ページ固定・同じorigin内・HTTP(S)のページを許可から選び、認証先を追加で許可できます。

WebApplet専用のアカウント枠を選び、サイトのログイン状態を保存します。同じ枠を使うWebApplet間で共有し、Gmailのアカウントとは分離します。Web側が推奨設定JSONを提供していれば名前・アイコン・遷移の初期設定を取り込めます。手動の変更は再取得でも保持します。最大64件、アカウント32枠で、追加/削除に本体再起動は不要です。サイトによってはElectron内でログインできない場合があります。

枠の管理はWebAppletの管理画面、または「設定 → Webアカウント」で行います。追加はその場で反映し、名前は入力欄からフォーカスを外すか、「名前を変更」またはEnterで確定します。確定前にEscapeを押すと保存済みの名前へ戻します。ほかの設定とは独立した即時操作です。「枠を削除」「ログイン情報をクリア」は警告画面で確認してから実行します。使用中の枠は、WebAppletの使用アカウントを変更して保存するまで削除できません。削除は枠と保存データをまとめて消します。使用中などで消せない保存ファイルは削除待ちとして記録し、次回起動時に自動で片づけます。クリアは枠を残してログイン情報とサイトデータを消します。

枠がない状態でWebAppletを追加すると、「個人用」をその場で作成します。WebAppletを削除しても枠は残り、管理ページから削除できます。

### 配布フォルダーからAppletを追加する

1. AppDockを完全終了します。
2. 信頼できるAppletの配布フォルダーを、EXEの隣の `extensions` に置きます。`extensions/<Appletフォルダ>/extension.json` と、そのAppletの実行に必要なファイル一式をそろえてください。
3. AppDockを起動し直し、「Applet」一覧で有効にします。新規Appletは既定で無効です。

追加・削除・更新後はAppDockを起動し直してください。同じIDのAppletが複数ある場合は先に見つかったものが使われ、重複をログに記録します。必要なAppDockバージョンは各Appletの案内を確認してください。非対応のバージョンでは起動できないことがあります。

Appletは利用者と同じ権限でファイルやネットワークへアクセスできるため、信頼できるものだけを追加してください。

| Applet                                                             | 主な機能                                                                                  |
| ------------------------------------------------------------------ | ----------------------------------------------------------------------------------------- |
| [Watch](../Applet.Watch.at365/README.md)                           | 独立した半透明のデスクトップ時計                                                          |
| [Gmail](../Applet.Gmail.at365/README.md)                           | 本体ページ／別ウィンドウのGmail画面、新着一覧・検索、アバター、並べ替え・個別監視・通知音 |
| [WallpaperSlideshow](../Applet.WallpaperSlideshow.at365/README.md) | モニターごとの壁紙スライドショーと履歴                                                    |
| [WindowMover](../Applet.WindowMover.at365/README.md)               | 最前面ウィンドウの移動・サイズ変更・終了                                                  |
| [WindowsTools](../Applet.WindowsTools.at365/README.md)             | 消灯予約・キー送信・無操作時のPCロック                                                    |
| [WebBrowserTools](../Applet.WebBrowserTools.at365/README.md)       | ブラウザー操作コマンド（ジェスチャーは本体設定）                                          |

Appletは設定された表示名で表示します。表示名・元の名前・IDのいずれでも検索できます。

通知対応のAppletが新着を知らせると、AppDockのトレイに橙色の印を表示します。対応Appletで通知を確認・クリアすると解除されます。トレイのクリック動作やメニュー表示は、本体のタスクトレイ設定で選択できます。

Windowsのデスクトップ通知をクリックしたときの起動先は、その通知を出した配置先のAppDockです。起動中は対応Appletの操作を実行し、終了後や古い通知では本体を開きます。修正版への更新前に表示された通知には旧版の起動先が残るため、新しく届いた通知から確認してください。

Web画面対応のAppletは、アカウントごとに独立したブラウザー領域を使用します。同じグループを使うAppletは、同じアカウントの領域を共用します。ログインはWebサービスの画面で利用者自身が行い、PC専用の`%LOCALAPPDATA%/at365/AppDock/profiles/<配置ID>/`内に保存します。Applet更新時もこの領域を保持してください。Gmail画面の×は非表示、Appletの無効化で自身の監視とページを停止します。

## Appletの遅延開始

すべてのAppletに「開始までの秒数」を設定できます。有効化・再起動から指定秒数後にプロセスを起動し、待機中もAppDockの設定は編集できます。0で即時、最大86400秒。無効化・AppDock終了で取り消し、待機中の秒数変更で待ち直します。実行中の変更は次回から適用します。既定の待ち時間はAppletごとに異なり、指定がない場合は即時起動します。開始待ちの詳細画面には予定時刻と「今すぐ開始」が表示されます。

## アップデート

更新適用後のお知らせは「更新適用完了」の通知として表示し、既定6秒で消えます。手動の更新確認結果は「インフォメーション通知」、失敗は「エラー通知」で案内し、表示時間と通知先は「設定 → 通知」で変更できます。結果をステータスバーへ重ねて表示しません。

「設定 → バージョン情報・更新」の色付きボタンから、本体・Appletの一括更新を行います。本体の更新元や起動時チェックは、普段は閉じている「更新の設定」を開いて変更します。Appletの更新元は、同じ画面の「インストール済みのApplet」にある各欄の「更新元の設定」から変更できます。本体・Appletとも「既定に戻す」を利用でき、変更時に自動保存します。Appletの既定値は配布元が指定した更新先で、空欄の保存は更新確認を無効にします。ローカルの絶対パス、UNC、HTTP(S)の更新情報JSONのURL、`github:owner/repo`、GitHubリポジトリ/リリースのURLに対応します。Webの配布フォルダーURLは末尾に `/` を付けます。本体には `update.json` と本体EXE、Appletには発行済みファイル一式または `update.json` と `update.zip` が必要です。ローカルの既存Applet発行フォルダーは `extension.json` を直接読み取れます。GitHubのReleaseには更新情報とビルド済み配布物を添付します。

- **本体と全Appletを更新**: 本体とインストール済みの全Applet（無効なものも含む）の更新をまとめて準備し、確認後に1回の再起動で適用します。本体の新版を一緒に適用する場合は、その版が必要なAppletも更新できます。更新がない対象や、更新元が未設定・取得できない対象は交換せず、各欄に結果を表示します。WebAppletも親Appletを個別に更新し、登録サイトはその設定として保持します。
- **AppDockを更新**: 本体EXEを更新します。画面下部からも利用できます。
- **Appletを一括更新**: 無効なAppletも含めて確認し、適用できる更新をまとめて準備します。未設定・通信エラー・必要な本体バージョン不足は各Appletに表示します。
- **このAppletを更新**: 選んだAppletだけを更新します。Appletの詳細画面にもあります。

更新操作は「まとめて更新」「本体」「インストール済みのApplet」に分けて表示します。「更新」ボタンで候補を確認して準備し、最後の確認でキャンセルできます。本体・Appletの現在版は色付きバッジで表示し、新しい版が確認できたときはその右側に「→ 更新後の版」を並べます。最終確認日時と結果は画面内で確認できます。Appletの一覧と実行環境の詳細は折りたたみを開くと表示します。

更新の確認・取得中は画面下部のステータスバーに進行状況を表示します。ダウンロードでは取得量・全体量・割合、一括更新では何件目かを確認できます。完了量が分からないフォルダー取得では、取得済み容量を表示します。「キャンセル」で準備を中止し、インストール済みファイルを変更せず元の操作へ戻れます。交換直前の確認画面では、その画面のキャンセルを使用します。更新開始を確定した後はファイル交換を中断できません。

準備・ハッシュ検証後に対象と版を表示します。「更新して再起動」を押すと本体と全Appletを終了し、共通ミニプログラムが交換して再起動します。一括更新の再起動は1回です。からの再起動後は、トレイ開始の設定にかかわらず元の画面を表示します。旧版で記録されていない画面状態は復元できません。設定の保存処理中は更新・確認ボタンを使えません。有効・無効、`settings.json`、`data`内の設定・ログイン情報、ほかのAppletは保持します。対象Appletの配布フォルダーは一式交換するため、独自の保存データはその中へ置かずAppDockの保存領域を利用してください。

起動時の本体/各Appletの更新確認、確認までの待ち時間、更新発見時の通知を設定できます。起動時は情報の確認だけでダウンロード・更新は行いません。起動時確認は既定OFF、待ち時間は10秒です。「同じバージョンの再適用」をONにすると同じ版のビルドし直しも適用できます。古い版へは戻しません。単一EXE形式を維持し、ミニプログラムはEXE内から更新時だけ一時フォルダーへ取り出します。

本体更新は元の名前 `AppDock.at365.exe` のportable版で利用します。信頼できる配布元を指定してください。通信に設定・メール・画像・ログは含めません。ハッシュはファイルの整合性確認で、配布元を保証する電子署名ではありません。非公開GitHubの認証、プレリリースは非対応です。交換完了前の失敗は元の配布物へ復元し、結果を画面とログへ表示します。中断記録がある場合は起動時に復旧を試み、全交換の完了が記録済みなら新しい版を保持して後片付けします。強制終了などで復元エラーが出た場合は、一時ファイルとPC専用保存先の`update-transaction.json`を残して確認してください。

## モニター設定と画像履歴

WallpaperSlideshowの複数ソースフォルダー・表示モード・タイル枚数・上下左右の余白をモニターごとのフォームで編集できます。旧JSON設定も読み取り、フォルダー選択・項目追加・並べ替え・削除に対応します。

履歴画像は指定したサイズで表示します。画像プレビューとパネル上部のモニター切替に対応しています。

## トレイの操作

「設定 → タスクトレイ」でクリック・ダブルクリックと右クリックメニューを編集します。「＋ コマンド」は検索して選択、「＋ グループ」は任意の名前で追加、「＋ 区切り線」は項目の間を区切ります。グループは1段で、別のAppletのコマンドも同じグループへ入れられます。

左端のハンドルをドラッグ、または選択した項目の上下ボタンで並べ替えます。ハンドルにフォーカスして上下キーでも移動できます。「配置先」でトップレベル／グループを選べます。グループ解除は中の項目をその位置へ戻します。「メニューから外す」はトレイへの配置だけを解除します。変更時に保存して反映します。

「設定…」「終了」は常に末尾固定です。旧設定は現在のApplet別グループを引き継ぎます。空グループや余分な区切り線は実メニューに表示しません。利用できないコマンドも配置を保持して無効表示します。クリック先が利用できない場合はログに記録してウィンドウを開きます。

同じ場所の単一EXEを更新しても、Windows通知領域のアイコン識別を維持します。必要ならWindows側でアイコンを常に表示する設定（ピン留め）にしてください。以後は同じEXE名・配置先・Windowsの一時フォルダーで使う限り、更新で新しいアイコンとして登録されることを防ぎます。EXEの移動/改名や一時フォルダーの変更は別の配置として扱います。Windows自身による設定のリセットは防げません。

更新はAppDockを完全終了してから行ってください。実行用ファイルは`%TEMP%/AppDock.at365-<識別子>/`へ展開され、EXEの配置フォルダーの同期には含まれません。二重起動では使用中の本体を再展開せず、既存のAppDockを開きます。一時展開ファイルは最後の本体/ランチャーの終了後に削除します。ランチャーだけが強制終了された場合に残った一時ファイルは、次の通常起動・終了で整理します。共有設定・登録素材はEXE隣、ログインなどのPC専用データは`%LOCALAPPDATA%/at365/AppDock/`配下です。詳細は[保存先](#設定とデータの保存先)を参照してください。

JSONでは`trayMenu`にメニュー構成、`host.trayClickCommand`にクリック先を保存します。`trayCommands`は旧形式の移行用で、新しい構成がある場合は派生値です。空にしたメニューへ項目を自動復活させません。

「タスクトレイ」で「トレイクリックのコマンド」と「トレイダブルクリックのコマンド」を別々に設定できます。クリックの既定は「AppDockを開く」です。ダブルクリックの既定は未設定。未設定の場合はシングルクリックを即時実行します。

ダブルクリックに割り当てると、Windowsのマウス設定に応じた判定時間だけシングルクリックを待機させます。判定時間を取得できない場合は、Windowsの既定値500ms（0.5秒）を使用して警告を記録します。ダブルクリックが来れば待機中のシングルを取り消し、ダブル側だけを実行します。保存後すぐ反映し、再起動は不要です。JSONの`host.trayDoubleClickCommand`はコマンドIDまたは`null`（未設定）です。

## ハードウェアアクセラレーション

「一般」の「ハードウェアアクセラレーション」で、AppDockの画面描画にGPUを使用するか切り替えられます。既定はOFF。変更を保存後、トレイの「終了」でAppDockを完全終了し、起動し直すと反映します。ウィンドウを閉じてトレイへ格納するだけでは反映されません。

「一般」の「スタートアップに登録」をONにして保存すると、このWindowsユーザーのサインイン時にAppDockを起動します。「常に管理者として起動」もONにすると管理者権限で起動します。既定はどちらもOFFで、「起動時にトレイに収納」とも組み合わせられます。

管理者設定は管理者グループに所属するWindowsユーザーで使用してください。管理者でのスタートアップ登録・権限変更・解除にはUAC確認が必要です。登録後のサインイン時には毎回のUAC確認を出しません。手動でEXEを開く場合はUAC確認を表示します。キャンセルすると通常権限で動作し、設定画面に結果を表示します。編集中の内容を保存すれば「管理者として再起動」も使えます。管理者設定をOFFにした後は完全終了し、通常の方法で起動し直してください。

登録状態と現在の権限は「現在の起動状態」で確認できます。Windows側の変更後は「状態を確認」を押してください。登録はEXEの配置先とユーザーごとに分かれるため、移動・削除する前に登録をOFFにして保存します。以前の手動登録（スタートアップフォルダー、別名のタスクなど）は自動削除しません。必要なら以前の登録を解除してください。

JSONでは`host.hardwareAcceleration`に`true` / `false`を保存します。項目がない旧設定もOFFで読み込み、保存済みのtrue / falseは保持します。Applet独自の描画設定は変更しません。

## 設定とデータの保存先

正常な設定変更は操作時に保存し、終了・再起動後も保持します。不完全な入力や保存失敗値の再起動後の復元は行いません。

単一EXEの配布方式は維持しています。**共有設定・端末別設定・登録素材はEXEの隣、認証や処理状態はLOCALAPPDATA**へ保存します。

| 保存先                                            | 内容                                                                                                      |
| ------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| EXE隣の`settings.json`                            | 共有するApplet設定・キー・リボン・プロフィール等 |
| EXE隣の`settings-<端末名>.json` | このPCのApplet有効状態・端末専用Applet設定・表示と一般の設定 |
| `data/web-applets/accounts.json`                  | 共有するWebApplet枠の名前・ID                                                                             |
| `data/assets/profile/`                            | 登録したアバター原画像                                                                                    |
| `data/assets/applets/<Applet ID>/sounds/`         | 登録した通知音（Gmailはat365.gmail）                                                                      |
| `%LOCALAPPDATA%/at365/AppDock/profiles/<配置ID>/` | Chromium、全ログイン状態、Gmail専用枠、Window状態、処理データ、秘密情報、ログ、更新記録、設定バックアップ |

Webアカウント枠が空で以前のWebAppletが残っている場合は、設定 → Webアカウントで枠を追加し、WebAppletの設定でその枠を選んで保存できます。ホスト画面の操作エラーはログページにも記録します。

0.57.0以降、Appletの有効・無効はPCごとに保持します。Applet設定のツールバーで「このPCで設定を保持する」をONにすると、設定一式・開始待ち・表示先をこのPC専用にできます。初回は現在の設定をコピーし、OFFで共有設定へ戻します。端末用の設定は残り、再びONにすると再開します。JSON表示と「ファイルを開く」も現在の保存先へ連動します。

本体の「表示」「一般」は常にこのPC専用です。テーマ、Shell選択、音、GPU描画、起動・トレイ収納の動作をPCごとに設定できます。この2ページの同じチェックボックスはチェック済み・操作不可で表示します。初回は従来の保存済み値を引き継ぎます。更新は同期して使う全PCの本体へ適用してください。旧版は端末別JSONを読みません。

端末用ファイルも同期できますが、各PCはOSの端末名に合うファイルだけを使います。同じ同期先では端末名を一意にしてください。端末名を変えて引き継ぐ場合は、AppDockを終了して旧名のJSONを新名へコピーし、内部のmachineNameも変更します。元ファイルは自動削除しません。端末設定の破損・欠落では、共有値で上書きせずPC専用バックアップから復旧します。

配置IDはEXEの配置先から決まります。同じ場所で更新するとPC専用データを引き継ぎ、配置を変えると新しい保存先になります。WebApplet枠とアカウントグループの名簿は同期できますが、ログインは各PCで行います。Gmailの名前・ID・順番はGoogleグループ名簿、選択・枠ごとの監視・通知音割当はPC専用です。既存のPC専用Gmail登録はグループへ一度だけ引き継ぎます。

**旧PC専用データは自動移行・削除しません。** EXE隣の`data`または`.appdock`に旧データが残る場合は共通の「警告通知」で案内します。「詳細を見る」から本体ログを開き、「整理対象」の行で検出したフルパスを確認できます。一般設定に旧データ専用欄はありません。空のフォルダーも対象です。同期前に完全終了し、必要なデータをバックアップしてから表示された対象だけを整理してください。新方式では旧ログインやGmail枠を引き継がず、各PCで登録し直します。data全体や.appdock全体を消すと素材等も失う可能性があるので、丸ごと削除しないでください。通知を閉じたあとも、本体ログは確認できます。同じ状態は起動中に繰り返し通知せず、解消後の再発と次回起動時は再評価します。

ファイル同期で届いたsettings.jsonは起動中に自動反映します。書き込みが落ち着くまで待ち、変更通知に加えて2秒ごとの照合も行います。壊れたJSONや一時的な欠落では最後の正常な設定を使い、編集中の入力を保持して古い内容での上書きを拒否します。ハードウェアアクセラレーションなど起動時だけ使う設定は次の起動で反映します。Windowsの起動登録はこのPCでの明示保存が必要です。

正常な設定を各PCの`settings-backups/`に直近20世代とlast-good.jsonで保存します。破損したまま再起動してもバックアップがあれば動作を続け、共有ファイルを勝手に書き戻しません。「バックアップで復元」は同期先にも届くことを確認してから実行し、破損ファイルをPC内へ退避します。正常な設定が届けば通常動作へ戻ります。バックアップをまだ作れていない場合は読み込みエラーになります。

登録素材のファイル名をIDとして使います。同じ登録元・用途のフォルダー内で同名別内容は拒否し、別フォルダーでは同名を使えます。素材一覧は実ファイルから作り、枠を消しても共有素材を自動削除しません。素材だけ届く変更も表示に反映します。

2台で未同期のまま同時に保存した変更を自動合成する仕組みではありません。同名別素材を2台で同時登録する場合も同期サービスの競合になるため、競合コピーやPC内の設定バックアップから内容を確認してください。同期サービスの設定は利用者が行います。

JSONはUTF-8の標準JSONです。JSONCには対応しません。旧settings.jsonの欠落項目は既定値で補います。`profile.avatar`は登録画像の相対パスまたはnullで、従来のavatar.pngも読み取れます。[設定例](settings.example.json)を参照してください。
