# 本体の起動計測

「設定 → AppDockについて」の最下部にある「起動時間の計測」を開くと、今回の起動の区間時間、処理回数とデータ量を確認できる。このSectionは最初は折りたたんで表示する。「計測データ」を開くと比較用JSONを選択してコピーできる。再計測は本体の再起動で行う。記録はメモリー上だけに保持し、設定項目・保存ファイル・外部送信を追加しない。設定値、コマンド名、画像の名前や内容は計測データへ含めない。

## 時間の起点と範囲

最小のmain bootstrapで、本体モジュールのimportと同期的な設定読み込みより前に計測を開始する。「本体処理開始 → ウィンドウ表示」は本体Windowの最初のshowイベント、「操作準備完了」はstartupReadyの設定まで。「本体初期化の経過時間」は通知・連携サービスなど、initialize内の初期化処理が終了するまでを示す。ウィンドウの表示と画面に実際に描かれた時刻は区別する。

本体処理開始前のOSによるEXEロードやElectronの初期化は、この本体区間に含めない。「計測開始前の参考時間」はNodeのプロセス時計を読んだ値で、OSによるEXEロード開始からの実測値ではない。外部で観測した起動時間と比較するときはこの範囲の違いを考慮する。

区間には本体モジュール、Electron準備待ち、設定読込、Windows起動状態確認、復旧確認、サービス構築、初期設定反映、登録画像の一覧取得、Window作成、本文読込、Applet検出・初期値整合、初期Shell、入力同期・ジェスチャー表示、タッチパッド、本文/Shell準備待ち、通常Applet開始、通知/連携初期化を含む。既存の順序と待機を変えず、前後で時計を読む。入れ子・並行を含むため区間や処理の時間を合計しない。「終了」は呼出しの終了を表し、内部で回復された失敗まで成功と判断するものではない。

設定復旧や起動時非表示など、通らなかった区間・通知は省略または「—」になる。非表示で起動し、初期化完了後に利用者が開いた場合の時間を、起動時表示の時間へ混ぜない。

## 処理の内訳とデータ量

設定ファイルの読取、JSON解析、検証/既定値復元、バックアップ、設定スナップショットの複製、共有/端末設定統合、コマンド一覧/状態/整合、本体/設定ページの表示データ生成について回数・累計・最長を集計する。共有/端末別JSONのサイズは主ファイルを最初に正常読取したbytesで、初期値整合による保存後のサイズへ置き換えない。累計読込量はバックアップ等を含む実際の読取bytesを合計する。

コマンド一覧・画像一覧・検出パッケージの件数も記録する。検出パッケージには本体Default Shellを含み、有効Applet数とは異なる。コマンド数と画像数は既存の処理で得た一覧の件数で、計測だけのために別のスキャンやカタログ再構築は行わない。

初期化完了時に区間とカウンターを固定し、その後に設定ページを開いたり操作しても増やさない。各計測には少量の時計読取と集計の負荷がある。ファイルへ逐次ログを書き込まず、記録数は固定の区間/処理ID数に制限する。

比較では同じEXE・表示設定・画像や関連データ・起動条件を揃え、設定ファイルの大きさだけと、登録件数や内容の違いを分ける。実測値・成果物のhashは[検証記録](../VERIFICATION.md)へ残す。
