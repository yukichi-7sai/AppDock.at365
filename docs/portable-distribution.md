# フォルダー型ポータブル配布

本体はElectronの展開済みフォルダーをそのまま使用する。インストーラーと起動時の自己展開は不要。`win-unpacked/AppDock.at365.exe`を起動し、DLL、`locales/`、`resources/`、`appdock-host.json`も同じ配置に保持する。終了時に本体ファイルを削除しない。ソースの標準発行は`publish.bat`から行い、更新用の`update.zip`と`update.json`を同じ発行先に作る。

ビルダーの作業先は`.artifacts/host-build`とし、発行先の実行用フォルダーをビルダーへ直接渡さない。発行時も管理対象の本体ファイルだけを配置するため、発行先で動作確認して作成された設定・data・extensionsを再発行で削除しない。ZIPは作業先のクリーンな本体から作成し、発行先の利用者データを混ぜない。実行用フォルダーのAppDockを終了してから再発行する。

## 配置と保存領域

配置先のルートにある`AppDock.at365.exe`を維持し、プログラムを別のサブフォルダーへ移動しない。共有設定、端末別設定、`data/`、`extensions/`、配置パスから決まるLOCALAPPDATAのPC専用rootは従来どおり。設定・ログイン情報を新しい場所へコピーする移行は行わない。保存先の詳細は[設定同期](settings-sync.md)を参照する。

初回の単一EXE版からの切り替えは、AppDockを完全に終了し、同じ既存配置先へ発行先の`deploy.bat`で本体一式を配置する。配布ZIPを使う場合も本体一式を同じ配置先へ展開する。旧版の更新プログラムはフォルダー型ZIPに対応していないため、初回は手動で切り替える。新しいフォルダーや`win-unpacked`というサブフォルダーへ設定だけ移すと配置IDが変わるので、既存環境の切り替えでは配置先ルートを維持する。

発行先に既存の配置スクリプトがある場合、再発行でも運用者のファイルとして保持する。単一EXE版の`deploy.bat`/`scripts/deploy.ps1`が残っている場合はEXEだけを配置する旧動作なので、初回切り替えにはフォルダー型対応のスクリプトを用意するか、新しい本体一式を同じ配置先へ展開する。

## 配布物と所有範囲

`appdock-host.json`はビルド時に作成する本体ファイル一覧で、schemaVersion、version、entriesを持つ。entriesは本体が所有するルート直下の名前だけを列挙する。EXE・Electronの固定ファイル、`resources`、`locales`、この一覧自身に限定し、Updaterの許可一覧でも検証する。設定・data・extensionsなどは受け付けない。配布フォルダーに一覧外のファイルやリンクがあれば発行・更新準備を拒否する。

`update.zip`は本体フォルダーの内容だけを格納する。feedはschemaVersion=1、kind=host、id=host、payload.format=zip。SHA256と配布サイズを従来どおり照合する。圧縮ファイルは512MiB、展開済み本体は1GiB、ファイル数は10,000件を上限とする。Appletの既存512MiB上限は変えない。

## 自己更新と配置

新しい本体一覧と既存の一覧から、EXE、その他のルートファイル、resources/localesの交換計画を作る。追加はinstall、交換はupdate、不要になった既存の本体項目はuninstallとして既存のパッケージトランザクションへ渡す。本体とAppletの一括更新も同じjournalで扱い、終了確認・変更前/後のハッシュ・範囲・リンク検証を維持する。設定などが混在する配置ルート全体を交換しない。

自己更新では交換前後の本体をjournalに対応する一時領域へ保持し、commit前の中断は元へ戻す。commit後は新しい版を検証して後片付けする。復旧対象の検証に失敗した場合はjournalを残す。EXEやresources自体が欠けて本体を起動できない中断では、journalに記録された専用TEMPのhelperから`--recover <配置先> <PC専用root>`を実行する。詳細は[更新と復旧](updates.md)を参照する。

手動deployは配布物のhelperだけを使い、管理対象の本体ファイルをコピー・照合する。既存の本体一覧に沿って不要ファイルを整理し、一覧を最後に配置する。旧EXEの別フォルダー退避は行わない。AppDockを終了してから実行し、失敗時は終了コードを確認する。

## 検証

`tests/folder-host.test.cjs`でZIP/feed、手動配置、管理対象の追加・削除、保護対象の拒否、journalの復旧を確認する。既存の更新・Appletパッケージ・Release・全体ZIP回帰も使用する。GUI fixtureのコピーは`scripts/copy-host.cjs`へ集約し、固定配布物の本体一式をコピーする。実配布物で起動・再起動・本体/一括/個別更新・保存領域保持・トレイ識別・二重起動を確認する。起動時の表示とAppletの開始順は[本体ページの起動](host-pages.md#起動と戻り先)を参照し、Appletの並列化は別工程とする。
