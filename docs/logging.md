# ログ

ログの重要度は`debug / info / warn / error`、種類は`normal`（通常）/`audit`（監査）で別々に持つ。起動段階や処理時間などの詳細診断はdebug、通常の起動・終了はinfo、警告や失敗は既存のwarn/errorを使う。監査は重要度ではなく、操作の受付・成否などを追跡するための種類である。

## 記録

共通HostLogが時刻・レベル・種類・提供元・メッセージを1件として保持し、既存host.logへJSON Linesで保存する。種類を持たない従来の記録は通常として扱う。debugと監査も常に記録し、画面の絞り込みで記録を止めない。記録レベルを保存する設定や別の監査ファイルは設けない。

既存のApplet API、MCP/APIとMCP Events、MCPクライアントのジョブ、AI/TTSのジョブ、Applet API許可変更の監査経路をauditへ分類する。監査用の受付・成功・拒否などの重要度と内容は維持する。最終失敗を共通ErrorReporterへ送る既存経路は通常のerrorのまま維持し、分類のために同じエラーを二重記録しない。要求引数、秘密値、生の例外文を追加しない。詳しい記録範囲は[共通操作API](appdock-api.md)、[MCP/API監査](automation.md#api監査ログ)、各機能の文書を参照する。

Appletは[共通ログAPI](extensions.md#sdkで使えるサービス)で記録する。提供元と通常の種類はホストが決定し、Appletの自己申告で監査ログを作成できない。debugは本体0.109.2以降とSDK/Runtime 0.27.1以降で利用できる。メッセージは文字数で切り詰めず全文を記録し、ログ検索の文字数制限も設けない。Appletの標準エラー出力も4000文字で切り詰めない。停止中のログ受付・停止後の拒否、起動後直近500件の画面用保持、ファイル1MBのローテーションと前世代1ファイルの保持は従来どおり。1件が1MBを超える場合も全文を同じ行に保存し、次の書込時に通常のローテーションを行う。

## 外部HTTP APIのエラー応答

本体からのREST API/fetch呼び出しは、[`httpFetch`](../src/main/core/http-client.ts)を共通入口にする。Node fetch、Electron net.fetch、アカウント専用transport、試験用の注入transportも同じ経路で扱う。画像・文章・読み上げ、モデル/声一覧、更新/カタログ、MCPクライアント、接続テスト、アカウント画像の取得が対象。HTTPSを直接使うWebhookと起動時のloopback probeは同じモジュールの`logHttpErrorBody`へ応答を渡す。ローカルファイル/登録アセットの読込やWebページ自身の通信はREST API呼び出しへ含めない。

HTTP失敗時は元の応答を消費せずコピーからJSONを読み、トップレベルの`error`がnull以外なら値全体を`JSON.stringify`して、`HTTP <status>`と`response.error=<JSON>`を通常のerrorログへ記録する。未知フィールド、入れ子、配列を選別・翻訳・マスク・文字数による省略で変えない。応答がJSONでない、`error`がない、本文を取得できない場合はHTTPステータスだけを記録する。正常に処理するリダイレクトを失敗ログにしない。HTTP成功でもエラーJSONを返す形式は、既存のJSON読込後に`logHttpJsonError`または`logHttpErrorBody`へ渡す。画像/音声など成功した大きなバイナリー応答を診断のためだけに複製しない。

この応答由来の`error`全体は利用者の指定に基づく診断ログの例外であり、サーバーが入力や秘密値を`error`へ含めた場合もその値がログに保存される。要求本文、Authorization、Cookie、APIキー設定、接続先URLや他の応答フィールドは診断へ追加しない。監査、通知・通知履歴・読み上げ、公開API/ジョブ結果には生の応答を渡さず、既存の安全なエラーコード/説明を維持する。API失敗の最終報告とは別の応答詳細として記録し、状態照会で詳細を再記録しない。診断障害による結果の変更、自動再送、接続先の切替は行わない。新たな待機期限は追加せず、呼出元の既存取消・待機条件を使う。

新しいHTTP連携を追加する場合もこの入口を使い、独自transportが必要なら応答を共通診断へ渡す。HTTP成功のエラー形式では、既存の受信サイズ検査を通してから共通JSON診断を呼ぶ。`tests/http-client.test.cjs`はこの共通境界と未知のJSON全体の保持、既存連携の実経路を確認する。

## 保存先と端末間の同期

新しいログはEXE隣の`data/logs/<OSの端末名>/host.log`へ保存する。例は`data/logs/KAGUYA/host.log`と`data/logs/LUNA/host.log`。同じdataを同期するPCはそれぞれ異なる端末名を使い、自端末のフォルダーだけへ書き込む。同期サービス自体の設定・起動は行わない。別端末からファイルを読めるのは同期が届いた範囲までで、即時反映や全履歴の保存を保証しない。

フォルダーの作成・ローテーション・追記に失敗した場合、その行を既存のPC専用rootの`logs/host.log`（`%LOCALAPPDATA%/at365/AppDock/profiles/<配置ID>/logs/host.log`）へ退避する。次の行では共有先を再び試し、書ければ共有先へ戻す。共有/退避先のどちらも保存できない場合は画面用メモリーに保持し、ログ障害の例外でAppletを停止させたり、障害をログへ再帰的に書いたりしない。ファイル操作の順序・同期書き込み・ローテーション方式は従来どおりで、OSがファイル操作の応答を返さない状態を打ち切る仕組みは持たない。

以前のローカルログ・旧世代・退避済みログは読み込み/コピー/移動/共有先への再送をしない。新しい行だけを書き込み、書込先での通常のローテーションは継続する。ログ画面には現在起動中の本体が受け取った行だけを表示し、他端末や過去のファイルを自動で読み込まない。保存先の端末名分離とローテーション以外に、設定/認証/Storage/Secretsの保存領域は変えない。

## ログ画面

- 初期表示は「通常」「Info以上」。通常を選んだ場合も監査のwarn/errorを表示し、説明を画面に示す。
- 提供元、通常/監査、レベル、文字検索を組み合わせる。「Debug」で詳細診断、「監査」で操作の記録を確認できる。文字検索は提供元IDとメッセージを対象にする。
- 提供元横の解除は提供元だけを戻す。「絞り込みを解除」は種類とレベルを「すべて」、検索を空に戻す。Applet/Webに固定された埋め込みログでは対象範囲を維持する。
- 新しい行を上に表示し、ミリ秒付き時刻、レベル、種類、提供元と本文を分ける。時刻のツールチップで日付を確認できる。表示件数は直近500件から絞り込んだ件数。
- 操作欄は狭幅で折り返し、表の見出しを残して一覧をスクロールする。保存状態と実際の保存先を表示し、「保存先を開く」は直近の書き込みに成功した共有先/退避先を開く。初回から両方失敗した場合は共有先を開く操作を試し、開けなければ画面にエラーを表示する。退避中は同期されないこと、両方失敗時は画面内だけで保持することを示す。

## 検証

`tests/logging.test.cjs`はdebug・監査の一度だけの保存、引数の非記録、Appletによる種類/提供元の偽装防止、種類とレベルの独立した絞り込み、停止時の受付に加え、2端末の分離、旧ログ非移行、共有先の作成/追記/ローテーション失敗時の退避と復帰、両方失敗時のメモリー保持を確認する。`tests/host-pages.test.cjs`は移動時のフィルター保持を担当する。

`tests/http-client.test.cjs`はHTTP失敗時のJSON全体・長文・未知フィールドの保持、元の応答と取消・非再送、ログ障害時の独立性、HTTP成功のJSON/SSEエラー、連携ごとの共通経路、長文ログの保存・検索を確認する。`scripts/http-error-logs-ui-test.cjs [固定EXE]`はローカル画像APIの400応答、Node Appletのログとstderr、ファイル・実画面の全文保持、4000文字を超える検索、照会による再記録がないことを隔離profileで検査する。

`scripts/host-pages-ui-test.cjs [固定EXE] --logs-only`は既存の隔離起動を使い、Nodeからのdebugと実際のApplet API監査、画面の組み合わせ検索・0件・キーボード解除・明暗と狭幅、非表示中もファイルへ記録されること、他端末/旧ログの保持を確認する。`--logs-fallback`は共有ログへの書込を妨げるfixtureで退避・状態表示・復帰・非移行を確認する。両モードで「保存先を開く」の対象を検査する（OSのExplorer起動だけを隔離プロセス内で置換）。.NET経路はWatchの固定ホストGUIで確認する。実測はVERIFICATIONへ記録する。
