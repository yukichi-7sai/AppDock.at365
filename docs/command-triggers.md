# コマンドトリガー

設定の「コマンドトリガー」は、キー・マウス・タッチパッドのコマンド割り当てを1つの一覧で編集するページ。キー・マウス・タッチパッドの各ページは機能設定だけとし、割り当ての一覧を置かない。各ページの「ジェスチャー共通の設定」は同じブラウザ判定の保存値を参照する。

## 割り当てダイアログ

キー・マウス・タッチパッドの割り当ては、共通の`BindingEditorLayout`に入力操作と条件を並べて編集する。画面幅800px以下では縦に並び、本文だけをスクロールする。有効切り替えと適用・キャンセルはフッターに残す。

- マウスは種類・移動段数をコンパクトなボタンで選び、2段階の方向を横並びにする。種類・段数を切り替えた編集中の選択を保持し、選択中の操作を表示する。
- タッチパッドは3本指、4本指の順に、タップ・上・下・左・右の5ボタンを表示する。保存IDとWindows接続の設定は変更しない。
- 「いつ・どこで」は`CommandConditionEditor`を3方式で共用する。範囲ボタンと、選択範囲に応じたexe名・デスクトップ除外・対象ページの検索とチェック一覧を表示する。対象ページは再編集時にも直接表示し、未導入の保存済み対象も保持する。
- グローバルの「除外するexe」は`when.excludedProcesses`へ保存する。このトリガー全体の除外へ追加する指定で、どちらかに一致するexeでは実行しない。空欄は追加除外なし。exe名はカンマ・改行で区切り、パスを受け付けず、大文字小文字と`.exe`を正規化する。

各機能設定ページの「ジェスチャーを除外するexe」は種類別に独立し、「条件に一致したコマンドの実行方法」の直下へ置く。ダイアログ内は「除外するexe」と表示する。exe名欄の入力例は拡張子を省略し、実際の入力は`.exe`付きでも受け付ける。キーは`keybindingOptions.excludedProcesses`、マウスは`gestures.excludedProcesses`、タッチパッドは`touchpadGestures.excludedProcesses`へ保存し、その種類の全条件に適用する。割り当て側の除外を空にしても、全体の除外は残る。設定値を1つの配列へ合成して保存せず、実行判定で両方を確認する。

登録単位の適用、取消時の破棄、記録中の入力抑止、既存行との競合検査、保存順と実行順は既存の共通基盤を使う。レイアウト専用CSSは3ダイアログに限定し、一般の設定フォームへ適用しない。

## 一覧と編集

全通常コマンドを未割り当ても含めて表示する。保存済みの不明なコマンドもIDで表示し、割り当てを編集・削除できる。列は「コマンド」「ジェスチャー」「いつ・どこで」の3列で、入力と条件を同じ行にそろえる。「いつ・どこで」の文字はクリックまたはEnterで、その割り当ての編集を開く。編集・実行順・削除は条件セルの右端に置き、行のホバーまたは行内フォーカスがあるときだけ表示する。非表示中も領域とキーボード操作を保ち、周囲の位置を動かさない。種類は既存のキー・マウス・タッチパッドのSVGアイコン、入力は文字で表示する。アイコンは1capを基本に16pxを下限とし、種類名をtooltipと操作の読み上げ用ラベルへ残す。

設定インデックスのアイコンは稲妻。コマンドの外部公開状態は共通カタログに従い、非公開コマンドにだけ南京錠を表示する。公開コマンドと公開状態が不明な保存済みコマンドにはマークを付けない。

コマンド列は名前とIDを左に、種類別の追加アイコンボタン3つを右横に縦に並べる。コマンドのまとまりにホバーまたは内部フォーカスがあるときだけ追加アイコンを表示し、領域とTab移動は常に保つ。ボタン自体をホバー・キーボードフォーカスしていないときの枠と背景は透明にする。追加はボタンからその種類の共通編集ダイアログを直接開く。入力と条件を確定したら即時保存し、取消時は同じ追加ボタンへフォーカスを戻す。このまとまりを上寄せし、縦スクロール中はCSS stickyで固定フィルターの下へ一緒に追従させる。自分のセルの下端で止め、次のコマンド領域へはみ出さない。横スクロールではセルと一緒に移動する。

条件の文字は左寄せとし、列幅の配分はコマンド34%・ジェスチャー20%を基本に残りを条件へ割り当てる。コマンド単位の上下余白は8pxを保ち、複数の割り当てがあるときは内部の各行の上下余白を2pxにする。操作ボタンの32px角は保つ。

編集・削除確認・同じ入力の実行順は各割り当て行から操作する。実行順パネルは一覧の検索・提供元・種類の絞り込みにかかわらず、同じ種類・同じ入力の全割り当てを扱う。Applet管理からは提供元、カスタムコマンドの一覧からは対象コマンドに絞ってこのページへ移動でき、この一覧には他のジェスチャー設定へ移動する列を置かない。

文字検索、割り当て有無、キーの登録エラー、提供元、入力で絞り込める。「キー・マウス・タッチ」の種類フィルターはアイコンで、一時フィルターを表示する行の左端に置く。複数選択でき、他の一時フィルターを設定しても解除されない持続フィルターとして扱う。一時フィルターは入力・提供元・コマンドの対象指定を排他的に切り替え、種類の選択は保つ。画面移動をまたぐ保持や設定ファイルへの保存は行わない。種類を指定した場合の割り当て有無は選択中の種類で判定し、全種類を解除した場合は0件とする。「絞り込みを解除」で種類も含めた検索条件を初期値へ戻す。共通一覧のスクロール、フォーカス復帰、保存失敗時の扱い、外部更新との競合検査を使う。

## スクロール

このページのフォームでは、右側の設定本文を縦横共通のスクロール枠にする。ページ見出し・フォーム/JSON切替と操作欄・状態表示・一覧フィルターは表示幅を保ち、横方向だけCSS stickyで固定する。見出しと上部操作は縦に流し、一覧フィルターは従来どおり上端で縦にも固定する。表とコマンド列は本文と一緒に横へ移動する。

本文内のキャンバスと各親要素へ表の最小幅を伝え、固定する要素が親の右端で一緒に流れないようにする。表内のコマンドは同じ本文をスクロール基準とし、CSS stickyでセル内だけ縦に追従する。表の角丸はスクロール枠を作らないclipで保ち、scrollイベントやrAFによるコマンド位置の補正・補間は使わない。フィルターの高さは共通部品のResizeObserverからCSS変数へ反映する。

画面下の共通横スクロールバーは本文と双方向に連動し、矢印/Home/Endの操作も保つ。本文に重複する横バーは表示せず、縦バーは残す。横に収まる幅と空の検索結果では横バーを隠す。ダイアログを閉じたときは本文の縦横位置と元の操作へのフォーカスを復帰する。JSON表示と従来の設定ページは、それぞれの既存スクロール構成を使う。

バーの寸法と配色は、AppDock全体の[共通スクロールバー](appearance.md#共通スクロールバー)を参照する。

## 保存と入力の境界

入力の一時フィルターは、一覧と同じ種類のシンボルと入力内容で表示する。「トリガー: マウスジェスチャー」などの文字の接頭辞は表示せず、種類と入力を含む完全な名前をtooltipと読み上げ、解除操作の名前へ残す。表示用の要素はrenderer内の一時状態にだけ保持し、設定や入力IDへ保存しない。

- ページIDは`command-triggers`、開くコマンドは`appdock.settings.command-triggers.open`。検索・ページ選択・コマンド公開は共通の設定カタログから生成する。
- 設定投影・フォーム・JSON・ページリセットの対象は`keybindings`、`gestures.bindings`、`touchpadGestures.bindings`のみ。既存の設定キー、割り当てID、保存ファイルを継続使用する。
- 表示用の行IDと入力IDには種類を含め、異なる種類に同じ保存済みIDや入力文字列があっても区別する。表示専用の情報は保存しない。
- 表示順は投影のみ。保存済み配列の順序は既存の編集・並べ替え関数で変更し、一覧を表示しただけでは実行順を書き換えない。タッチパッドは3本指→4本指、それぞれタップ→上→下→左→右で表示する。
- タッチパッド接続用キーは通常のキー割り当てとして重複表示しない。有効化・Windowsとの接続・認識・ブラウザ判定などの動作設定と入力処理は既存仕様を使う。

保存・競合処理は[設定基盤](settings-foundation.md)、操作は[共通一覧](settings-list-editing.md)、入力固有の契約は[キー](keybindings.md)・[マウス](gestures.md)・[タッチパッド](touchpad-gestures-design.md)を正本とする。

## 次の段階

今後の対象は、種類別の基本値に加えた入力単位の実行方式と、グローバル条件の割り当て別exe除外。入力単位の実行方式は、たとえばF1に一致する割り当て全体へ適用する。2段階キー入力も将来の別機能として扱う。
