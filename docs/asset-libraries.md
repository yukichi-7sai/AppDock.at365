# 素材ライブラリー

Appletとの登録・参照・生成の分担は[アセットの実装方針](applet-assets.md)を正本とする。Applet向けの将来の生成APIはライブラリー登録までを扱い、生成結果専用の取得APIは作らない。本体で使う生成と保存の内部処理は維持する。

## 範囲と共通基盤

### 外部フォルダ

管理ページでUNCパス上のファイルを削除する場合は、元ファイルを完全削除し、ごみ箱から戻せないことを確認画面に常時表示する。「完全削除」の確定後にだけ実行し、取消では元ファイルとグループ所属を保つ。画像・音・テキストで共通とする。ローカルパスは従来どおりごみ箱へ移し、ごみ箱処理の失敗を完全削除へ自動で切り替えない。確認時の保存先・削除方法を本体に保持し、実行時にも内容世代・保存先・編集権限・使用中参照を確認する。設定保存の失敗・競合では元ファイルを排他的に復元する。ドライブ文字に割り当てたネットワークドライブの自動判定は行わない。

管理ページの「外部フォルダを追加」からローカル絶対パスまたはUNCパス、表示名、アクセスモードを登録する。アクセスモードの初期値は「読み取り専用」で、「編集可能」も選べる。登録後はフォルダの「…」→「外部フォルダの設定」でモードを変更する。ダイアログのOKで登録単位に保存し、取消では変更しない。登録は画像・音・テキストで共用し、各画面では対応形式だけを表示する。登録一覧はPC専用の`settings-<PC名>.json`の`librarySources`へ保存し、共有設定へ絶対パスを含めない。データ素材フォルダと登録済み外部フォルダに重なる場所（同一・祖先・子孫）は追加できない。

従来の「すべてのフォルダー」の表示名は「データフォルダ」とし、その対象範囲と保存先の対応を維持する。外部フォルダは同列の独立ルートとし、ルートは配下全体、「直下」は直下のファイル、子フォルダはその子孫を表示する。フォルダは単一選択で、検索とグループは選択中のルート・フォルダとの積で絞り込む。全ルート横断ノードは設けない。画像・音の選択ダイアログにも同じルートを表示する。

外部素材はどちらのモードでも閲覧、検索、プレビュー・試聴、ファイル・本文のコピー、グループの追加・解除・順序変更ができる。グループ情報は既存のAppDock設定に保存する。読み取り専用では追加・生成保存・本文編集・複製・改名・移動・削除・フォルダ作成を無効にし、直接届いた操作もホスト側で拒否する。編集可能ではこれらの操作を登録先へ適用する。ルートを選択して追加・生成・テキスト作成した場合はその直下へ保存し、データフォルダへ暗黙に切り替えない。アイコンセットの取り込みは従来の内蔵保存先を維持する。設定用に選んだ画像・音の保管コピーは、引き続き内蔵の`assigned-images`・`assigned-sounds`へ保存する。外部フォルダやその兄弟へメタデータ・キャッシュを保存しないが、編集処理では同じファイルシステム上に一時ファイル・復旧用コピーを作る。

モード変更は登録ID・参照・グループ所属を変更しない。実際の書込みはWindows・共有フォルダの権限に従い、AppDockはOSの権限を変更しない。書込み確定前にも現在のモードを確認し、読み取り専用への変更や登録解除後の処理を拒否する。既に変更したファイルの復元と一時ファイルの整理は継続する。外部ルート自体の改名・削除や、切断されたルートの自動再作成は行わない。空の子フォルダだけを削除できる。

ファイルの改名・移動では原本照合と同名上書き拒否を維持し、ルート間の移動にも対応する。異なるデバイスでは移動先の一時コピーを照合してから元ファイルを除去する。失敗時は元の場所を復元し、復元できない場合は復旧ファイルを保持してエラーにする。ハードリンクなど必要なファイルシステム操作が許可されない場合は操作を失敗として扱う。外部フォルダの改名は、同居する画像・音・テキストのグループ参照を一度の設定保存で更新する。設定保存の失敗や競合ではフォルダ名を戻す。

接続不能時はルートに状態を表示し、登録とグループ参照を保持する。通常の監視、既存の補助監視、明示再読込で再接続を検出する。ネットワークの走査完了を他ルートの初期化の条件にしない。登録解除は参照元の登録だけを削除し、元ファイルを削除しない。既存のグループ参照は欠落参照として保持する。再登録には新しい登録IDを割り当てるため、自動的な再関連付けはしない。

通常監視は[共通.NET監視プロセス](file-watch-assistance-design.md#共通net監視プロセス)を使用する。監視エラーと実アクセスの失敗を区別し、監視だけの失敗で読み取り可能なルートを接続不能・編集不可にしない。UNC共有ルートの実パス比較では末尾区切りを正規化し、ルート自身のイベントを親フォルダのイベントとして扱わない。補助確認は既存設定を維持し、エラーを理由に自動でONにしない。

参照の形は従来の`{ file: string }`を維持する。内蔵の相対参照と`@assigned/`は変更せず、外部素材は`@external:<登録ID>/<ルート内相対パス>`で識別する。絶対パスは参照に含めず、同名素材とルートを区別する。外部参照を他ルートの同名素材へ自動追従させない。登録レコードの`access`は`read-only`または`read-write`を受け付け、未知の値を拒否する。既存の読み取り専用登録は変更せずに読み込む。外部ルートとしての寿命・監視・保存範囲と、編集権限を独立して管理する。

登録先と走査・読取対象に既存のリンク境界を適用する。`lstat`のシンボリックリンク判定と実パス照合でリダイレクトされたディレクトリ・ファイルを拒否し、シンボリックリンク・junction配下を走査しない。すべてのWindowsリパース属性を一律に拒否する方式ではない。UNCの接続・権限には実行中のWindowsユーザーを使用する。

### 内蔵フォルダと共通操作

画像・音・テキストの管理ページと、画像・音の選択ダイアログは、実フォルダー、複数所属のグループ、保存順、検索、選択、一括操作、ドラッグ移動、表示状態を共用する。種類ごとの形式検証・プレビュー・試聴はアダプターへ分離する。画像の公開APIと保存形式は維持する。文字入力パレット・外部アプリへの入力・登録テキストごとの実行コマンドは、管理機能と分けて設計する。

原素材は共有`data/assets/images`・`data/assets/sounds`・`data/assets/texts`へ置き、一覧は実ファイルから生成する。分類は`imageLibrary`・`soundLibrary`・`textLibrary`へ種類別に保存する。フォルダーは保存場所、グループは論理分類であり、一つの素材を複数グループへ所属させられる。登録数の固定上限や別のID索引ファイルは設けない。

共通のファイル基盤は安全なパスの検証、通常監視と既存の補助監視、世代付き読取、排他的な登録、同名同内容の再利用、改名・移動の復旧、ごみ箱削除を担当する。外部移動で所属先が消えた場合、同名候補が一つのときだけ追従する。複数候補や未到着時は参照を保持する。設定用コピーは外部移動追従の対象にしない。音の保管コピーを外部から改変した場合は内容hashの不一致を拒否し、再選択で復旧できる。

起動時は3種類の一覧を並行して準備する。各走査では独立したファイルの属性を先読みし、列挙順に一覧へ反映する。ファイルごとのリンク・実パス確認を行い、内容読取・登録・削除では利用時点の検証を行う。複数取込みでは次の小さなファイルを先読みし、選択順に公開・結果報告する。先読みの作業量は登録可能な件数や容量に影響しない。

管理UIは画像ライブラリーと同じ分類欄・ツールバー・カード・コンテキストメニューを使用する。音のカードには形式・再生時間を表示し、明示操作で試聴する。単一クリックは選択、ダブルクリックまたは試聴操作で再生する。音に画像コピーやアイコンセット取り込みは表示しない。コピー・改名・移動・削除・所属操作は選択全件を対象とする。音の初期カード幅は160px、最小40px。幅・折りたたみ・カード寸法は、種類と管理/選択画面ごとにPC内へ保存する。

3種類の管理ページはカード／コンパクトなリストの切替、名前・種類・更新日時・容量の表示ソート、現在のグループからのドラッグ脱退を共用する。表示形式と並び順は種類別のPC内表示状態へ保存し、原素材や共有のグループ順を変更しない。Deleteは矩形選択の直後も削除確認を開く。詳しい操作・保存・拒否条件は[管理ページの配置と操作](image-gallery.md#管理ページの配置と操作)を正本とする。

## 音と選択

WAV・MP3・AAC・M4A・FLAC・OGG・OGA・OPUS・WEBMに対応する。音声ファイルの容量上限は設けず、形式と再生時間を検査する。対応コーデックとファイルから読む方式は[共通音声再生API](audio-playback.md#ファイルからの読み込み)を参照する。試聴も単一audioPlaybackを使い、停止・対象変更・画面終了では、その試聴だけを取り消す。待機と再生中を区別し、音の再生OFFを無視しない。

音選択はフォルダー/グループ/検索で絞り、試聴後に「音を使う」で確定する。取消では親の設定を変更しない。選択した音声はdata/assets/assigned-soundsへ内容hashで保管し、原素材の改名・移動・内容変更・削除によって設定済みの通知音が変わらないようにする。保管コピーは部分的な設定一覧から自動削除しない。

既存のApplet別通知音と絶対パスの再生は保持する。Webアカウントの音選択を共通ダイアログへ接続し、新規選択は本体の保管コピーを指す参照と表示名を保存する。Node Appletの既存audio.playはこの参照を本体側で解決する。汎用の音声ファイル選択も共通ダイアログを使用し、従来の絶対パス/取消の戻り値を保つ。既存設定の一括移行や、実利用設定への自動変更は行わない。

### 音声生成

既存の生成ダイアログは[バックグラウンドジョブ基盤と生成結果の永続保全](background-jobs-design.md)を使う。生成・保存は画面から独立し、閉じる・ページ移動後も続く。生成済みWAVはPC専用ストアへ保全し、開き直し・再起動後に同じ結果へ戻れる。

音ライブラリーの「音を追加」の隣にある「音声を生成…」から共通ダイアログを開く。「音声生成AI」に登録したサーバー、文章、話し方と保存先フォルダーを選び、「生成して保存」を押す。モデル・ボイス・認証は選んだサーバーの設定を使い、既定サーバーや設定値を書き換えない。話し方の上書きはその生成だけに適用し、サーバーの常時付与文は維持する。

「生成して保存」を押すとすぐにカードを追加し、その時点の文章・サーバー・話し方・保存先を確定する。フォームの入力は残し、生成中も次の依頼を受け付ける。実際の生成は既存の共通TTSキューで受付順に進める。生成待ち・生成中・保存中・失敗・中止をカードごとに表示し、生成中と保存中のビジー表示も該当カードだけに出す。待機中のキャンセル、生成中の中止はそのカードにだけ適用する。

生成したWAVは毎回、自動で音ライブラリーへ保存する。現在の実フォルダー（「データフォルダ」では直下）を初期保存先とし、選択中の実グループにも所属させる。ファイル名は読み上げる文章の先頭20文字までと連番から作り、`処理が完了しました。-001.wav`のようにする。文字の区切りは結合文字や絵文字を分断しない単位とし、既存のファイル名長制約に収まる位置までにする。改行や空白を整え、ファイル名に使えない記号を置換し、予約名と空の名前も補正する。同じ名前があれば空いている次の連番を使い、同じ音声でも既存ファイルを上書き・再利用しない。ライブラリーと同じWAV検証を適用する。生成時のサーバー応答制約は[TTS](tts-design.md)に従い、ファイル登録の容量制限とは分ける。

右側の「生成リスト」には、そのダイアログで受け付けた依頼を新しい順に表示する。保存済みのカードから明示的に試聴・停止、名前変更、ごみ箱への削除を行い、別の音の生成中も操作できる。削除は対象名を確認し、ライブラリーの実ファイルにも反映する。外部変更を検出した音は古い内容として操作せず、元のライブラリーで確認する。カードは見出し・情報・操作・生成条件の4段に揃える。見出しと情報はそれぞれ1行で省略表示し、操作欄はボタンの数にかかわらず高さを確保する。待機・生成・保存・完了・中止・失敗と試聴で、折りたたんだカードの高さと各行の上下位置を変えない。情報行には状態・保存先をまとめ、保存済みでは状態文言を省いて保存先フォルダー・形式・再生時間を表示する。試聴状態も同じ情報行へ表示する。「生成したときの条件」を明示的に開くと、ファイル名・保存先・文章・サーバー・話し方を省略せず確認できる。カードの操作は名前のツールチップとアクセシブルなラベルを持つアイコンボタンを使う。生成直後には自動再生しない。広幅ではフォームとリストを罫線で区切り、独立してスクロールできる。狭幅では横罫線を挟んで縦に並べる。フォーム内の項目ごとの罫線は省き、スクロール領域内にフォーカス枠の余白を確保する。「生成して保存」は共通のアクセント色を使う。

生成失敗・中止はそのカードに残し、「再生成」で同じ文章・サーバーID・指定した話し方を新しいジョブとしてキューへ登録する。元のカードは残す。接続設定と認証は再受付時の値を使う。終了したジョブは右上の×で一覧から削除でき、保存済みの音声は残る。未登録・未分類の結果は先に保存または救出し、ジョブ削除時に保存先を照合する。保存に失敗した場合は生成済みの音声データを保持し、「保存を再試行」で同じ音を保存する。グループ保存だけが失敗した場合はWAVを残して所属だけを再試行する。保存の再試行でサーバーへ再生成を要求しない。一つの失敗でほかのカードの処理を止めない。

閉じる操作とページの終了は表示とそのダイアログの試聴だけを終了する。待機・生成・保全・登録は継続し、開き直すと同じ生成リストを表示する。生成結果・履歴に時間による削除期限はない。登録失敗時は保存だけを再試行でき、保全原本を別フォルダーへ救出する操作も用意する。「生成した音声を削除する」は確認後に登録ファイルと保全原本を削除し、ジョブを残す。ジョブの削除は×だけで行い、再起動でも戻さない。本体終了時は進行中・登録待ちのジョブを確認し、メモリーにしかない結果は損失を示して別途確認する。

## テキスト管理

原本はUTF-8の`.txt`。空の本文、日本語、絵文字、複数行を扱い、不正なUTF-8・NULを含むバイナリは拒否する。既存ファイルのBOMとCRLFを保ち、本文が変わっていない保存では原本のbytesを変更しない。人為的な容量上限は設けず、実行環境がBuffer/stringとして扱える範囲で読み込む。

リボンと`appdock.text-library.open`から開く。新規作成・本文編集・複製は共通ダイアログを使い、確定時だけ保存する。本文はEnterとShift+Enterの両方で改行する。IMEの変換確定を優先し、「適用」でファイルへ保存する。複製は元の本文から別ファイルのドラフトを開き、元ファイルを変更しない。同名ファイルへの上書きは拒否する。新規作成と複製は現在のフォルダーへ保存し、選択中の実グループへ追加する。分類保存だけに失敗した場合は作成済みファイルを残し、共通の所属再試行を表示する。

通常はフッターの手前まで本文入力欄を広げる。保存に失敗したときだけ、本文欄の下に理由と「詳細」を表示する。本文の下端が上がり、「キャンセル」と「適用」は同じ位置に残る。

カードには本文冒頭・ファイル名・文字数/行数・グループを表示する。冒頭表示の800 UTF-16コード単位は表示用の抜粋で、保存や検索の上限ではない。選択・ダブルクリック/Enterでの本文表示・コンテキストメニューは共通管理画面へ接続する。本文プレビューは全文をプレーンテキストとして表示する。画像ライブラリー・画像選択のプレビューと横幅をそろえ、右上の「×」・背景クリック・Escapeで閉じる。本文の選択やダイアログ内の余白のクリックでは閉じず、閉じた後は呼び出し元へフォーカスを戻す。「本文を編集」「複製」は1件を対象とし、コピー・改名・移動・削除・所属変更は選択全件を対象とする。Ctrl+Cは本文、Ctrl+Shift+Cはパスをコピーし、本文は一覧の順序で改行区切りに連結する。ファイルとしてのコピーもコンテキストメニューに残す。

検索はファイル名と本文に対する大文字小文字を区別しない部分一致。フォルダー・グループとの積で絞り、グループの保存順を保持する。本文の検索索引はmainのメモリーに共有し、世代が変わったファイルだけ読み直す。検索操作ごとのディスク再読込や本文全体の一覧IPC送信はしない。読み込み中は状態を表示する。

作成・保存時は、公開後に確認した本文と世代をそのファイルの索引へ反映して完了する。他のファイルの索引作成中でも保存した本文を検索できる。外部の差し替え後に古い世代の結果を登録しない。

本文の保存では表示時の世代と保存直前の内容を照合し、同じフォルダーの一時ファイルから原子的に置換する。外部エディターやエクスプローラーによる変更・削除・移動が競合した場合は上書きせず、編集ダイアログの入力を保持して通知する。外部移動時のグループ追従は共通の同名単一候補判定を使い、曖昧な候補や欠落参照を勝手に統合しない。

分類は`textLibrary.groups[].files`、PC内表示状態は`textGallery.library`へ保存する。初期カード幅260px・最小40px、分類欄の幅と折りたたみを画像/音と独立して保持する。

## 外部の入力欄で使うパレット

本体の「設定 → パレット」では「定型文パレット」と「クリップボード履歴パレット」を常時展開する。定型文のカードには候補の管理と履歴保存スイッチ、履歴のカードにはWindows設定へのボタンがあり、各カードの最終行に「呼び出しコマンド」を置く。「定型文パレットを開く」(`appdock.text-palette.open`) と「クリップボード履歴パレットを開く」(`appdock.clipboard-history.open`) は通常のコマンドとしてトリガーに割り当てられる。初期キー割り当てはない。設定内のコマンドリンクは本体のコマンドパレットで対応するコマンドを選択する。

「定型文を管理」で文字ライブラリーの固定グループを開く。このグループの所属順が候補順になる。グループ自体は先頭に固定し、所属の追加・解除・並べ替えと本文の編集はライブラリーの通常操作で行う。既存の同名グループは独立して扱う。確定時に表示時と同じ世代の本文を読む。履歴保存スイッチの初期値はオン。オフでは以後の貼り付けをWindows履歴から除外する。いずれも現在のクリップボードには最後の定型文が残り、定型文からのクラウド同期は除外する。

履歴パレットは開くたびにWindowsから一覧を取得し、文字の冒頭と画像のサムネイルを表示する。開いている間は行の順序を保ち、選択時にWindowsの項目IDを照合して元の項目を現在のクリップボードに戻す。項目が削除済みなら貼り付けずに一覧を取得し直す。履歴が空・無効・アクセス拒否の状態は区別する。「Windowsのクリップボード設定を開く」からシステム設定へ移動できる。AppDockに履歴の複製を保存しない。

両方とも元の入力先のフォーカスを保ち、キャレット位置（取得できない場合はポインター付近）の上下で空きが広い側に開く。それぞれの設定に「開いたときの表示件数」があり、既定8件・1以上の整数で指定する。候補数と画面の空きに応じて実際の行数を減らし、残りの候補へはスクロールで移動できる。設定値はパレットページの共有／PC専用の保存先に従う。登録候補数は制限しない。

定型文の表示名は末尾の拡張子を省き、ツールチップに元の相対ファイル名を表示する。右上の文字ライブラリーアイコンはパレットを閉じて本体の「定型文」グループを開く。設定インデックスの「パレット」は「通知」の直下に絵の具のパレットアイコンで表示する。

各パレットの設定に「開いたときの幅（px）」がある。既定370、最小260の整数で、Windowsの表示倍率を反映する論理ピクセル単位。画面より広い値は表示時だけ作業領域に収め、保存値は変えない。定型文・履歴で独立して保存し、初めて表示する際に反映する。

パレット設定の「共通」に「操作ガイドを表示」があり、既定はオン。オフにすると下部のキー説明を省き、候補の表示件数を保って全体を小さくする。設定は次に開いたときから両パレットに反映し、共有／PC専用の保存先に従う。説明を省いた場合も右下のサイズ変更ハンドルは残る。

右下のハンドルをドラッグすると、元の入力先を保ったまま幅・高さを変えられる。ハンドルは候補とスクロールバーに重ねず、タイトル・管理ボタン・1行の候補を操作できる最小サイズと、表示中の画面の作業領域内で調整する。サイズは開いている間だけパレットの種類ごとに保持し、左右で戻ると復元する。閉じて開き直すと設定した幅と表示件数から初期サイズを計算し直す。ドラッグでは幅・表示件数の設定を変更せず、PageUp／PageDownも設定件数のまま動く。

| キー | 動作 |
| --- | --- |
| ↑／↓ | 1件ずつ選択移動。長押しで繰り返し、先頭・末尾で止まる |
| PageUp／PageDown | 設定件数分の選択移動。端を越える場合は先頭・末尾で止まる。長押し対応 |
| Home／End | 先頭・末尾を選択 |
| 1～9／0 | 一覧全体の1～10件目を1回入力。画面外でも同じ番号。存在しない番号は消費して表示を保つ |
| ←／→ | どちらももう一方のパレットへ1回切り替える。長押しで繰り返さない |
| Enter | 選択項目を1回入力 |
| Esc | 入力せず閉じる |

キー操作で選択した行は見える位置までスクロールする。数字は修飾キーなしの数字列とNumLockが有効なテンキーに対応し、各候補の右端にキーを表示する。入力・切り替えの長押しは再実行せず、押下と解放を元の入力先へ漏らさない。左右の切り替えは同じ入力先を保ち、開いている間だけ種類ごとの候補順・選択位置・スクロール位置を復元する。閉じて開き直すと先頭へ戻り、履歴も再取得する。切り替え中の旧画面操作は拒否する。履歴が無効・空でも左右で定型文へ戻れる。

クリックも1回貼り付ける。Esc、外側のクリック、入力先の変更で閉じる。標準の編集欄は貼り付けメッセージを使い、文字は選択位置と長さの変化を確認する。その他の入力先ではCtrl+Vを一度送る。画像への対応は貼り付け先に従う。

## 確認

テキスト固有の試験はUTF-8/空本文/BOM/改行、作成・編集・複製・取消、同名拒否、外部編集の競合、本文索引、分類の独立性を担当する。GUIは本文検索・安全な全文表示・選択全件のコピー・現フォルダーへの取り込み・グループ付き作成・フォルダードロップ・狭幅/明暗・表示状態の再起動保持を確認する。実Windowsクリップボードと物理IMEは模擬操作から区別する。

共通化した画像の契約、音の登録・形式拒否・改名/移動/削除の競合と復旧、設定用コピーの独立性、音声キューの試聴取消、選択の確定/取消と呼出元の終了を確認する。音固有のGUIは通知音/Webアカウントと実Node Appletの入口、試聴/停止、選択/取消、改名/移動、狭幅、独立した表示状態と再起動を担当する。共通UIの複数選択・ドラッグ移動・明暗は画像ライブラリーの回帰でも検証する。実スピーカーから聞こえる音とfixtureでの再生開始/終了は区別する。検証結果はVERIFICATION.mdを正本とする。
