# 設定画面のUI・レイアウト方針

本体設定・Applet設定・設定ダイアログの新規作成と改修に適用する共通レイアウト指針。保存・入力の契約と現行の共通部品の対応状況は[設定基盤](settings-foundation.md)、一覧編集の操作とダイアログの利用方法は[一覧形式の設定編集UI](settings-list-editing.md)を参照する。

## 基本方針

- **レイアウトに説明させる。** ラベル、配置、グループ分け、余白によって、設定の意味や操作方法が自然に分かる構成にする。
- ラベルやレイアウトで伝わる内容を、説明文で重ねて案内しない。説明を追加する前に、ラベルやレイアウトの改善を検討する。
- 現在の設定値や状態、必要な説明・補足情報は、共通部品の仕組みを使用して表示する。
- 個別の設定画面は、表示する内容と状態を共通部品へ渡す。配置・余白・装飾・表示方法は共通部品が管理する。
- 個別の設定画面に、独自の説明欄・通知欄・状態表示欄を追加しない。

## 説明・補足情報

- 現在の設定値や状態、説明・補足情報は、必要に応じてレイアウト部品の `description`・`hint` へ渡す。
- `description`・`hint` は、次の基準で使い分ける。

| プロパティ | 用途 | 表示方法 |
| --- | --- | --- |
| `description` | 現在の設定値や状態、設定の理解・判断に必要な重要な説明 | 指定された内容を、ヒントの表示設定にかかわらず常時表示する |
| `hint` | 操作のコツなど、非表示でも設定の理解・判断・操作に支障のない補足 | ヒントの表示設定に従って表示する |

- `description` は固定の説明文に限定せず、設定値や状態の変化に応じて内容を更新できるものとする。
- 現在の設定値や状態、重要な説明を、ヒントの非表示によって確認できなくなる場所へ入れない。
- 表示位置・余白・装飾・折り返し・詳細の表示方法は、レイアウト部品が管理する。
- `SettingsHint` は使用しない。必要な説明・補足情報は、レイアウト部品の `description`・`hint` で扱う。
- ヒントアイコンが必要な場合は、レイアウト部品側で `SettingsHintIcon` を配置する。

## 状態・操作結果・エラー・処理中表示

- 現在の設定値や継続的な状態、一時的な操作結果、エラー、処理中表示を区別し、それぞれの用途に合った共通の仕組みで扱う。
- 接続状態など、継続して確認する状態は `description` で表示できるものとする。状態に応じた装飾や表示方法も共通部品が管理する。
- 表示の出現や文言の切り替えによって、周囲の入力欄やボタンの位置が不意にずれないようにする。
- 通知が必要な一時的な操作結果は、通知基盤を使用する。通常の設定変更・保存のたびに完了通知を表示しない。
- 設定項目に結びつく状態や入力エラーは、対象との対応が分かるように、共通部品が定めた位置と方法で表示する。
- 処理中のボタン表示、二重実行の防止、変更された一覧項目の強調表示なども共通部品で扱い、個別画面で独自に実装しない。

### エラー表示

- `SettingsError` は、ページやダイアログの共通レイアウトにあらかじめ組み込まれたエラー表示領域として使用する。
- ページやダイアログ全体に関わるエラーと、特定の設定項目に結びつくエラーを区別する。
- 個々の設定は、共通の仕組みを通して、エラーメッセージと対象を識別できる情報を渡す。共通レイアウトが既存の `SettingsError` への表示と、対象との対応付けを管理する。
- 個々の設定で `SettingsError` や独自のエラー表示欄を配置・追加しない。
- エラー表示の位置・余白・装飾・表示切り替えは、共通レイアウト側で管理する。エラーの表示・非表示によって、周囲の入力欄やボタンの位置が不意にずれないようにする。
- エラーはヒントの表示設定にかかわらず確認できるようにする。
- 長いエラーメッセージも全文を確認できるようにし、詳細の表示方法は共通部品で統一する。

## 画面構成と共通部品

- 設定画面・設定ダイアログは共通部品を使用し、全体で統一されたレイアウトにする。
- カードで囲むことを必須にしない。一覧中心の画面はApplet管理の構成を基準にし、検索・絞り込み・件数・一覧・操作を共通部品で揃える。設定項目のまとまりに応じてカードや行を使い分ける。
- カードを不必要にネストしない。複数のカードをまとめることだけを目的とした外側のカードは作らない。
- カード内で複数の項目を個別に折りたたむ場合は、`SettingsSection variant="row" collapsible`を使用する。項目と同じ文字サイズ・余白・区切り線を使い、右端の開閉アイコンと行全体の操作領域を共通部品で統一する。
- 折りたたみ行のハイライトは共通の淡いアクセント色を使用する。文字・開閉アイコン・区切り線の位置を維持し、背景の左右に余白を確保する。hoverやキーボードフォーカスで周囲の配置を動かさず、明暗テーマと狭い幅でもカード内へ収める。
- 関連する項目は、`SettingsField`の`group`で項目名の左に小さなグループ名を添えられる。groupの有無でタイトルの高さを変えない。グループ名だけのためにセクションを入れ子にせず、各項目の余白・入力列・区切り線は共通部品へ任せる。
- `SettingsField`の横並び表示では、タイトル・ヒントを32pxの入力行の縦中央へそろえる。スイッチも同じ高さの中央へ配置する。説明文や複数行の入力全体に合わせてタイトルを中央寄せせず、先頭の入力行へそろえる。縦積み・読み取り専用のタイトルには入力行用の最小高さを付けない。
- 狭い画面や文字を拡大した状態でも、必要な情報を確認でき、入力欄や操作ボタンへ到達できる構成にする。
- 設定インデックスのキーボードフォーカス枠は各ボタンの内側へ収め、スクロール領域の端でも欠けずに表示する。通常の設定項目と検索結果で同じ表示にする。
- 設定値の選択欄と絞り込みの表示枠は、中身に必要な幅を基本とする。選択欄は選択肢の表示に必要な幅を確保し、画面やダイアログの利用可能な幅を超えないようにする。絞り込みの解除操作も枠内へ収める。
- ヒントやエラーの詳細は、キーボードでも確認できるようにする。開閉やフォーカスの扱いは共通部品で統一する。
- 既存の共通部品で表現できない場合は、共通部品の拡張または追加を検討する。
- その他、共通化が必要なレイアウトは部品化する。
- 全設定ページのフォーム・JSON・Applet設定で、タイトル・説明・上部操作を本文と同じ外側の縦スクロールへ含める。独立した縦スクロール枠を本文へ追加せず、固定する一覧フィルターは共通の`CommandListToolbar`へ任せる。JSON入力欄の編集領域と、テーブルだけの横スクロールは維持する。
- `SettingsSection`直下のボタン列は`SettingsActions`を使い、12pxの間隔・上下12pxの余白・折り返しを共通化する。`SettingsField`内でも同じ部品を使える。表やツリーなど内部構造を持つウィジェットの外枠は`SettingsContent`を使い、機能固有の内部配置はそのウィジェットが管理する。個別画面でセクション直下へレイアウト目的の`div`を追加しない。

画面構成に使用する共通部品：

- `SettingsPage`
- `SettingsModal`
- `SettingsDialog`
- `SettingsSection`
- `SettingsField`
- `SettingsActions`
- `SettingsContent`
- `SettingsListTable`

共通レイアウト内部で使用する部品：

- `SettingsError`
- `SettingsHintIcon`
