# リボンの装飾・コマンドボタン・右クリック動作の拡張設計

状態: 第1・第2段階を実装済み。更新日: 2026-10-19。設計の基準はAppDock 0.64.0、main `459b649`、実装版は第1段階0.65.0、第2段階0.66.0。設計前の最新取得は更新なしで成功し、実装時は同じチャットの未コミット設計文書を保持して継続した。検証と発行物の結果は[検証記録](../VERIFICATION.md)を参照する。

既存の[グループとバッジ](ribbon-groups-badges-design.md)、[リボンAPI](shell-api.md)、[設定基盤](settings-foundation.md)、[一覧編集UI](settings-list-editing.md)を前提とする。[実装計画](ribbon-customization-implementation-plan.md)に従い、装飾と名前編集、コマンド実行の2段階で実装した。登録画像は後続の機能として残す。

## 目的と受け入れ条件

| 対象 | 完成時の動作 |
| --- | --- |
| 動作設定 | リボン設定の最上部に独立した「動作設定」カード。その下に「リボン編集」カードを置く |
| 右クリック | 「動作設定」内の「右クリックのコマンド」で実行先を選ぶ。説明は「リボンを右クリックしたときに実行するコマンドです。」 |
| グループの色 | グループボタンを指定色の枠で囲む。「色なし」を選べる |
| 持続的な展開 | ボタン枠と展開部分の左側の縦線が、同じ色・太さでつながって見える |
| 共通パレット | 色なし・色見本・自由選択・HEX入力・プレビューを共通部品で提供する |
| コマンドボタン | 追加と編集のダイアログで名前・固定候補のアイコン・実行コマンドを設定できる |
| セパレーター | 既存の安定IDを保ったまま、編集ダイアログで名前を変更できる |

## 設計開始時に確認した実装

- [RibbonSettings](../src/renderer/settings/RibbonSettings.tsx)は上下配置、グループ、セパレーター、通常ボタンの別名を編集する。グループの追加と編集には既存の`SettingsDialog`を使っている。
- [保存型](../src/shared/ribbon.ts)のグループに色はない。セパレーターはIDの配列で、[ribbonItems](../src/shared/applet-pages.ts)が一覧の順から「セパレーター 1」のような表示名を生成する。
- [Default Shell](../shells/default/main.tsx)の持続的な子は`.ribbon-children`へ描画され、[style.css](../shells/default/style.css)の`border-left: 2px solid var(--accent-soft)`が縦線になっている。
- [UiPresentation](../src/main/core/ui-presentation.ts)の`ribbon.configure`はリボン設定を開く固定操作。一般コマンドボタンの保存型・追加操作はまだない。
- コマンド候補は本体、カスタムコマンド、Applet管理、Applet提供分をまとめる既存の`uiCommands`にある。選択は本体設定の`CommandPicker`を共用できる。
- 設定の編集・保存は本体renderer、表示はShell、実行先の決定と実行は本体が所有する。この境界を維持する。

## 設定画面の構成

完成時の順序とラベルは次のとおりとする。

```text
リボン
  動作設定                         独立したグループカード
    右クリックのコマンド            コマンド選択
    リボンを右クリックしたときに実行するコマンドです。
  リボン編集                       別のグループカード
    上寄せ
      コマンドボタンを追加 / グループを追加 / セパレーターを追加
      編集一覧
    下寄せ
      同じ追加操作と編集一覧
    リボンを初期状態に戻す
```

`SettingsSection`と`SettingsField`を使い、カード内の見出しを重複させない。動作設定とリボン編集は、外側に共通のカード枠を重ねず、設定本文のトップレベルへ並べる。動作設定は既存のジェスチャー設定に合わせて初期状態を折りたたみとし、検索から対象へ移動するときだけ開く。開閉のための新しい保存設定は作らない。リボン編集の上下一覧は表示する。

ダイアログは既存の追加・編集の一時入力、OKでの登録単位保存、取消、保存失敗時の入力保持、フォーカス復帰を共用する。グループ名の空欄と「アイコンのみ表示」は既存の仕様を維持する。設定を保存しただけでコマンドを実行しない。

グループの追加・編集は、グループ名、アイコン、アイコンのみ表示、展開方法、色とプレビューの順に並べる。色とプレビューは最下部にまとめる。

## グループの色

### 保存値と色なし

- グループ編集に「色」を追加する。初期値は「色なし」。未指定と`null`を色なしとして解釈する。
- 色は不透明な`#RRGGBB`で保存し、大文字へ正規化する。任意のCSS、透明度、テーマ変数は保存値に受け付けない。
- 色なしでは、グループボタンの装飾枠と展開部分の縦線の両方を表示しない。現在のテーマ色の縦線へ戻す意味にはしない。
- 既存グループの色が欠落している場合も色なしとなる。読み込み時の設定書き換えや移行処理は作らない。

### 描画

- 色はグループボタンの外形の枠と、持続的な展開の連結線にだけ使う。ボタン背景やアイコンを一律に指定色へ染めない。
- 枠と線は同じCSS変数から同じ不透明色を使い、太さはどちらも2 CSS pxを基準にする。
- 持続的を開いている間は、枠の左辺と縦線の位置をそろえ、ボタンと子一覧の間の余白も線でつなぐ。左下の角と接続部を調整し、二重線・隙間・太さの違いを作らない。
- 持続的を閉じた状態と一時的グループにはボタン枠を表示する。一時的パネルの外周には今回のグループ色を追加しない。
- 色なしや開閉で幅・余白・クリック領域を変えない。枠の領域をあらかじめ確保するか、内側に描画する。スクロール領域で枠を切らない。
- グループボタンの選択時には別の緑色の短い選択線を重ねず、既存の背景・文字色とアクセシブルな状態で選択を表す。子の通常ボタンの選択マーカーと、キーボードのフォーカス表示は維持する。
- 明暗テーマとズームで接続部を確認する。色の自動変更で入力値と表示色を食い違わせず、色が背景に近い場合もフォーカスと選択状態を別の表示から判別できるようにする。

### 共通の色選択部品

`src/renderer/settings-ui`へ制御型の`SettingsColorPicker`を用意する。値は`string | null`、色なしを許すかは呼び出し側が指定する。

- 「色なし」、名前付きの固定色見本、ブラウザーの色選択、6桁のHEX入力、現在の見本を一つにまとめる。
- 色見本はTabとEnter/Spaceで操作でき、選択状態と色名をアクセシブルにする。色なしもラベルで識別できるようにする。
- HEXの入力途中・IME入力・不正値は画面内に保持し、正しい値を確定するまで親の有効値を置き換えない。ダイアログ内のEnterで登録全体を誤確定しない。
- 不正なHEXや未確定入力が残る間はダイアログのOKを無効にし、理由を入力欄へ示す。直前の有効色だけを黙って保存しない。入力の有効性を親へ通知する契約も部品に含める。
- グループ編集では枠と縦線のプレビューへ反映し、実リボンへの反映・保存はダイアログの確定時に行う。
- パレットの履歴・お気に入り用の保存ファイルや追加ライブラリは導入しない。他の設定で利用できる部品にするが、既存の色設定を今回まとめて変更しない。

## セパレーターの名前

- ID配列`separators`を維持し、任意の`separatorTitles`へID別の名前を保存する。
- 追加は現在と同じ即時追加。各行の編集ボタンから「セパレーターを編集」を開き、名前だけを変更する。
- 名前は前後空白除去後80文字以内、制御文字不可。空欄は名前の解除として保存マップから除去し、現在の自動生成名を使う。
- 変更名は設定一覧と`role="separator"`のアクセシブル名へ使う。リボンに文字付きの新しい見出しは追加しない。
- 移動・名前変更でIDを作り直さない。削除時は所属・配置・非表示と名前を同時に除去する。

## コマンドボタン

### 登録と編集

- 上寄せ／下寄せの追加操作に「コマンドボタンを追加」を加える。追加と編集は同じ`SettingsDialog`を使う。
- 項目は「コマンド」「名前」「アイコン」「アイコンのみ表示」の順に並べる。名前は前後空白除去後1〜80文字、制御文字不可とする。
- コマンド選択には既存の本体設定の選択パレットを使う。本体・Applet・登録済みカスタムコマンドを同じカタログから選ぶ。
- 名前は初回選択時にコマンド名を補えるが、利用者が編集した名前を後の選択やカタログ更新で上書きしない。
- 保存するのは既存文法のコマンドIDだけ。実行引数やプロセス設定をボタンへ複製せず、固定入力が必要な処理は既存のカスタムコマンドとして登録して選ぶ。
- 新規のボタンIDは`button:<stable-id>`とし、名前・アイコン・コマンドの変更で変えない。ボタンIDをコマンドIDとして扱わない。
- 上下配置・非表示・ドラッグ・上下移動・グループ内配置を既存の共通レイアウト操作へ接続する。グループ解除では中のボタンを同じ位置へ戻す。
- ボタンの削除は登録内容と配置を削除する共通確認を使う。実行先コマンドやその設定は削除しない。

### 実行と利用不可

- ボタンはページ選択と別の操作として投影する。単に実行したことを理由に選択中のページを変更しない。
- 選択候補と実行可否は既存のコマンドカタログ・実行経路を使う。IDの接頭辞から所有者や権限を推測しない。
- 実行先が未登録・停止中・無効・実行不可なら、ボタンと設定を保持して無効表示し、理由をツールチップ等へ示す。登録元を自動起動・有効化しない。
- コマンドの再登録・停止・種類変更で表示用revisionも更新する。設定に変更がなくてもShellへ利用可否を通知する。
- 押下時にも現在の登録先と利用可否を再照合し、既存の共通実行サービスへ一度だけ渡す。一時的グループでは既存の受付確定・パネル閉鎖・実行の順序を維持する。
- 既存のrequestIdの重複抑止、実行中の再入防止、取消、共通エラー報告を維持する。失敗や結果不明の操作を自動再送しない。

### 固定アイコンと将来の登録

現在の7種類（folder / mail / clock / image / extensions / settings / bell）をグループとボタンで共用する。`RibbonIconPicker`と固定アイコン一覧を共通化し、保存値は現行と同じ名前文字列とする。ボタンの初期アイコンはextensionsとする。

将来の登録画像は、この選択部品と表示時のアイコン解決を拡張する。今回、素材登録・削除画面、未実装の画像参照型、移行用データは追加しない。後続で登録素材APIと既存のopaqueな`assetId`の表示経路へ接続し、Shellへファイルパスを渡さない。

## 右クリック動作

- `ribbon.rightClickCommand`にコマンドIDを保存する。省略時の既定値は新しい本体コマンド`appdock.ribbon.settings.open`とし、現在と同じリボン設定を開く。
- この本体コマンドを通常のコマンドカタログへ追加し、既存の`NavigationCoordinator`を使って設定のリボンページを開く。設定入力のflushと表示・フォーカスの処理を共用する。
- 選択と保存は即時反映する。空文字や不正IDは保存しない。今回、右クリック自体を無効にする追加選択肢は作らない。
- 保存済みの未知ID・一時的に利用不可のIDは保持する。利用不可時はその操作を実行せず、設定画面で理由を示す。別コマンドへ自動的に置き換えない。
- 設定画面を開く別の入口として、既存のトレイ固定「設定…」とコマンド検索を維持する。従来の「右クリックから必ず設定へ戻れる」という案内は更新する。
- リボン内の通常ボタン・グループ・区切り線・余白の右クリックを同じ本体アクションへ集約し、バブリングで二重実行しない。独立した一時的グループパネルは今回の対象に含めない。
- 右クリックもコマンドボタンと同じ利用可否・権限・実行時再検査を受ける。現在のcontextActionIdの特例を任意コマンドの検査省略に使わない。

## 保存形式と編集操作

既存の`settings.json`の`ribbon`へ任意項目を追加する。新しい保存ファイルと設定移行コードは作らない。

```ts
type RibbonColor = string | null; // 検証後の #RRGGBB、または色なし

interface RibbonCommandButton {
  id: string;                    // button:<stable-id>
  title: string;
  icon: RibbonBuiltinIcon;        // 共通の固定7種類
  commandId: string;
  iconOnly?: boolean;
}

// RibbonGroupへ追加
// color?: RibbonColor;

// RibbonLayoutへ追加
// separatorTitles?: Record<string, string>;
// buttons?: RibbonCommandButton[];
// rightClickCommand?: string;
```

`RibbonBuiltinIcon`は現在の固定候補から作る型名の案。実装時にグループ側の参照も同時に整理する。既存の`itemOverrides`は通常項目の別名と登録名の用途を保ち、セパレーター名や新規ボタンの本体定義を混在させない。

| 検証対象 | 方針 |
| --- | --- |
| 色 | 省略・null・6桁HEXのみ。保存前に正規化 |
| セパレーター名 | マップは最大50件。登録済みセパレーターのIDだけを許す |
| コマンドボタン | 最大100件、一意ID、必須の名前・固定アイコン・既存文法のcommandId |
| 所属と配置 | 未登録のbutton IDを拒否。1項目1所属、グループの入れ子禁止を維持 |
| 全体上限 | 既存のorder / hidden / bottomは各550件、グループの子は500件、ルートと子を合計した通常項目は500件を維持。上限を越す追加は保存前にエラーとする |
| 未知コマンド | IDの文法が正しければ読込と保持を許す。実行可否は登録状況で判定 |

共有の`parseRibbon`、`editRibbon`、`RibbonCommands`の読取投影・Schema・結果、設定ページのフォーム／部分JSONに同じ定義を反映する。

追加する編集操作は次のとおりとする。

- 第1段階: addGroup / updateGroupの任意color、`updateSeparator { id, changes: { title } }`。既存のaddSeparatorは名前省略で動作し、削除で名前を回収する。
- 第2段階: `addButton { id, title, icon, commandId, iconOnly?, placement }`、`updateButton { id, changes }`、`removeButton { id }`、`setRightClickCommand { commandId }`。
- 上記の編集は`appdock.ribbon.update`へ追加する。read→expectedRevision→dryRun／保存の契約と、複数操作の原子的な適用を維持する。GUIも既存のeditRibbon入力経路を使う。
- レイアウト読取の`items.kind`へcommandを追加し、ボタンの登録・表示・利用可否を区別する。`retainedIds`へ保存済みの正常なコマンドボタンを誤分類しない。
- リボン編集内のresetは配置・別名・グループと色・セパレーターと名前・コマンドボタンを初期化する。別カードのrightClickCommandは保持し、その区分を確認文へ示す。

既存の未知フィールド保持、未導入Appletの配置・別名、PC専用の持続的な開閉状態を維持する。同値操作で不要な保存やrevision更新をしない。古い版はグループの未知フィールドや新IDを拒否し得るため、複数PCでは本体を対応版へそろえてから新項目を保存する。旧版が新設定を編集できることや、自動ダウングレードは保証しない。

## Shellと外部操作

- 色はschema 2のグループへ任意`color`として投影する。コマンドボタンは既存の表示用`kind: "button"`とopaqueなactionIdで表す。表示用の新しいkindは作らない。
- contextActionIdの文字列契約は維持し、schema 2の任意の`contextActionEnabled`と`contextDisabledReason`で右クリックの利用可否を伝える。旧Shellがこれらを使わなくても本体側の検査で実行を拒否できるようにする。
- schema 1の構造と既存のグループ平坦化を維持し、色とcontextActionEnabled／contextDisabledReasonは省略する。schema 2の追加表示情報を使わない既存Shellに、新機能の描画まで保証する扱いはしない。
- ShellへコマンドIDや実行引数を渡さず、本体でactionIdから解決する。Shellの`executeCommand`の自己所有範囲を広げない。
- 通常Applet／MCP経由の投影と実行は、現在のcaller・コマンド公開宣言・個別許可を使う。ローカルで実行可能なボタンの追加を、外部へそのコマンドを公開する許可に読み替えない。操作カタログと実行時の判定を一致させる。
- 編集用ribbon.getにはボタン定義を返すが、ボタンのcommandIdとrightClickCommandは外部から実行できるものだけを公開する。実行先を省略した読取用定義を保存型から分け、取得した不完全な定義を丸ごと保存させず、対象のIDとchangesを指定する既存の操作形式で編集する。公開情報の判定に別のID一覧を作らない。
- 色やセパレーター名の追加だけで、Node／.NETのバッジSDKの変更を要求しない。共通のribbon.get／updateの契約試験で両呼出し経路を確認する。

## 保存・競合・復旧

ダイアログ開始時のbeforeと最新の設定を比較し、同じリボンへの外部更新は既存の競合として扱う。古い一覧を再保存して上書きしない。設定同期・PC専用保存の現在の分類を使い、リボンへ新しい保存先切替は追加しない。

色選択・名前入力・コマンド選択・dryRun・キャンセル・読取で対象のコマンドを実行しない。保存失敗時は確定前の実リボンを保ち、ダイアログへ入力と原因を残す。削除・初期化・復帰でも無関係な設定とコマンド定義を維持する。

受け入れ試験と各段階の完了条件は[実装計画](ribbon-customization-implementation-plan.md)を参照する。
