# リボンの配置・装飾・グループ・バッジ

## 設定画面の構成

完成時の順序とラベルは次のとおりとする。

```text
リボン
  ツールバー                       このページを既定値に戻す
  動作設定                         独立したグループカード
    右クリックのコマンド            コマンド選択
    リボンを右クリックしたときに実行するコマンドです。
  リボン編集                       別のグループカード
    上寄せ
      ＋ コマンド / ＋ グループ / ＋ 区切り線
      編集一覧
    下寄せ
      同じ追加操作と編集一覧
```

`SettingsSection`と`SettingsField`を使い、カード内の見出しを重複させない。動作設定とリボン編集は、外側に共通のカード枠を重ねず、設定本文のトップレベルへ並べる。動作設定は既存のジェスチャー設定に合わせて初期状態を折りたたみとし、検索から対象へ移動するときだけ開く。開閉のための新しい保存設定は作らない。リボン編集の上下一覧は表示する。

上寄せ・下寄せの追加操作は各見出しのすぐ横から左寄せで並べる。追加・各行の上下移動は[共通アクセントボタン](appearance.md)を使う。コマンドボタンの追加/編集ダイアログでは、「コマンド」をボタン名・アイコンと同じラベル書式にそろえ、選択ボタンを次の行へ配置する。

編集の項目行はトレイのコンテキストメニュー編集と同様に枠なし・通常40px以上とし、名前と補足を1行にそろえる。グループの子項目は1pxの縦線とインデントで示し、32px角の上下・編集・削除ボタンと配置選択を保持する。長い名前・補足は省略しtooltipで全文を確認できる。狭い画面では操作列を次の行へ移し、項目と操作の対応を保つ。

初期化は共通ツールバーの「このページを既定値に戻す」へ統一し、リボン編集の下部へ専用ボタンを置かない。確認後に配置・装飾・コマンドボタンと右クリック割当を既定値へ戻し、このページのJSONは`{}`になる。確認・保存・競合検査は[ページリセット](settings-foundation.md#ページリセット)に従う。

ダイアログは既存の追加・編集の一時入力、OKでの登録単位保存、取消、保存失敗時の入力保持、フォーカス復帰を共用する。グループ名の空欄は「グループ」の名前で表示する。項目ごとの「アイコンのみ表示」は編集画面に設けず、リボン全体の表示モードへ従う。設定を保存しただけでコマンドを実行しない。

グループの追加・編集は、グループ名、アイコン、展開方法、色の順に並べる。展開方法の補足説明と独立した色のプレビューは表示しない。色選択は最下部にまとめる。

### 保存値と色なし

- グループ編集に「色」を追加する。初期値は「色なし」。未指定と`null`を色なしとして解釈する。
- 色は不透明な`#RRGGBB`で保存し、大文字へ正規化する。任意のCSS、透明度、テーマ変数は保存値に受け付けない。
- 色なしでは、グループボタンの装飾枠と展開部分の縦線の両方を表示しない。現在のテーマ色の縦線へ戻す意味にはしない。
- 既存グループの色が欠落している場合も色なしとなる。

### 描画

- 色はグループボタンの外形の枠と、持続的な展開の連結線にだけ使う。ボタン背景やアイコンを一律に指定色へ染めない。
- 枠と線は同じCSS変数から同じ不透明色を使い、太さはどちらも2 CSS pxを基準にする。
- 持続的を開いている間は、枠の左辺と縦線の位置をそろえ、ボタンと子一覧の間の余白も線でつなぐ。左下の角と接続部を調整し、二重線・隙間・太さの違いを作らない。
- 子一覧と接続部の色線は、子ボタンの選択・hover・focusの背景より前に描画する。線の重ね描画はポインター入力を受け取らず、既存の幅・余白・クリック領域を維持する。
- 持続的を閉じた状態と一時的グループにはボタン枠を表示する。一時的パネルの外周にはグループ色を追加しない。
- 色なしや開閉で幅・余白・クリック領域を変えない。枠の領域をあらかじめ確保するか、内側に描画する。スクロール領域で枠を切らない。
- グループボタンの選択時には別の緑色の短い選択線を重ねず、既存の背景・文字色とアクセシブルな状態で選択を表す。子の通常ボタンの選択マーカーと、キーボードのフォーカス表示は維持する。
- 明暗テーマとズームで接続部を確認する。色の自動変更で入力値と表示色を食い違わせず、色が背景に近い場合もフォーカスと選択状態を別の表示から判別できるようにする。

### 共通の色選択部品

`src/renderer/settings-ui`へ制御型の`SettingsColorPicker`を用意する。値は`string | null`、色なしを許すかは呼び出し側が指定する。

- パステル・くすみ・ベーシックの各8色を用意し、既定はパステルとする。パレット名と切り替えボタン、丸い色見本、その下に「色なし」とブラウザーの色選択・6桁のHEX入力をまとめた1行を配置する。切り替えは表示する候補だけを変え、選択色・入力途中の値・有効性を保持する。パレットの選択は保存せず、部品を開き直すとパステルへ戻す。
- 選択中の色見本は枠とチェックで示す。「自由な色」「HEX」の可視ラベル、説明文、独立したプレビューは表示しない。入力のアクセシブル名は維持し、不正値は入力欄の赤い枠と`aria-invalid`で示す。フォーカス中の外枠も赤にする。
- 色見本はTabとEnter/Spaceで操作でき、選択状態と色名をアクセシブルにする。色なしもラベルで識別できるようにする。
- HEXの入力途中・IME入力・不正値は画面内に保持し、正しい値を確定するまで親の有効値を置き換えない。ダイアログ内のEnterで登録全体を誤確定しない。
- 不正なHEXや未確定入力が残る間はダイアログのOKを無効にし、入力欄をエラー表示にする。直前の有効色だけを黙って保存しない。入力の有効性を親へ通知する契約も部品に含める。
- 実リボンへの反映・保存はダイアログの確定時に行う。パレット変更やダイアログ内の選色だけでは保存しない。
- パレットの履歴・お気に入り用の保存ファイルや追加ライブラリは導入しない。他の設定で利用できる部品にするが、既存の色設定を本機能まとめて変更しない。

## セパレーターの名前

- ID配列`separators`を維持し、任意の`separatorTitles`へID別の名前を保存する。
- 名前を指定していない区切り線はすべて「区切り線」と表示し、連番を付けない。保存済みの独自名は保持する。
- 追加は現在と同じ即時追加。各行の編集ボタンから「セパレーターを編集」を開き、名前だけを変更する。
- 名前は前後空白除去後80文字以内、制御文字不可。空欄は名前の解除として保存マップから除去し、現在の自動生成名を使う。
- 変更名は設定一覧と`role="separator"`のアクセシブル名へ使う。リボンに文字付きの新しい見出しは追加しない。
- 移動・名前変更でIDを作り直さない。削除時は所属・配置・非表示と名前を同時に除去する。

### 登録と編集

- 上寄せ／下寄せの追加操作に「コマンドボタンを追加」を加える。追加と編集は同じ`SettingsDialog`を使う。
- 項目は「コマンド」「名前」「アイコン」の順に並べる。名前は前後空白除去後1〜80文字、制御文字不可とする。
- コマンド選択には既存の本体設定の選択パレットを使う。本体・Applet・登録済みカスタムコマンドを同じカタログから選ぶ。
- 名前は初回選択時にコマンド名を補えるが、利用者が編集した名前を後の選択やカタログ更新で上書きしない。
- 保存するのは既存文法のコマンドIDだけ。実行引数やプロセス設定をボタンへ複製せず、固定入力が必要な処理は既存のカスタムコマンドとして登録して選ぶ。
- 新規のボタンIDは`button:<stable-id>`とし、名前・アイコン・コマンドの変更で変えない。ボタンIDをコマンドIDとして扱わない。
- 上下配置・非表示・ドラッグ・上下移動・グループ内配置を既存の共通レイアウト操作へ接続する。グループ解除では中のボタンを同じ位置へ戻す。
- ボタンの削除は登録内容と配置を削除する共通確認を使う。実行先コマンドやその設定は削除しない。

### 実行と利用不可

- ボタンはページ選択と別の操作として投影する。単に実行したことを理由に選択中のページを変更しない。
- 選択候補と実行可否は既存のコマンドカタログ・実行経路を使う。IDの接頭辞から所有者や権限を推測しない。
- 実行先が未登録・停止中・無効・実行不可なら、ボタンと設定を保持して無効表示し、理由をツールチップ等へ示す。登録元を自動起動・有効化しない。
- コマンドの再登録・停止・種類変更で表示用revisionも更新する。設定に変更がなくてもShellへ利用可否を通知する。
- 押下時にも現在の登録先と利用可否を再照合し、既存の共通実行サービスへ一度だけ渡す。一時的グループでは既存の受付確定・パネル閉鎖・実行の順序を維持する。
- 既存のrequestIdの重複抑止、実行中の再入防止、取消、共通エラー報告を維持する。失敗や結果不明の操作を自動再送しない。

### 固定アイコンと登録画像

固定アイコンはfolder / mail / clock / image / extensions / settings / bell / userをグループとボタンで共用する。`RibbonIconPicker`と固定一覧を共通化し、固定アイコンは従来の名前文字列で保存する。ボタンの初期値はextensions。

登録画像は同じ部品から選び、`image: { file } | null`として保存する。グループ、コマンド、通常ページ、WebAppletは[共通画像ライブラリー](registered-images.md)とopaque assetIdの表示経路へ接続する。Shellへパスを渡さない。

## 右クリック動作

- `ribbon.rightClickCommand`にコマンドIDを保存する。省略時の既定値は新しい本体コマンド`appdock.ribbon.settings.open`とし、現在と同じリボン設定を開く。
- この本体コマンドを通常のコマンドカタログへ追加し、既存の`NavigationCoordinator`を使って設定のリボンページを開く。設定入力のflushと表示・フォーカスの処理を共用する。
- 選択と保存は即時反映する。空文字や不正IDは保存しない。本機能、右クリック自体を無効にする追加選択肢は作らない。
- 保存済みの未知ID・一時的に利用不可のIDは保持する。利用不可時はその操作を実行せず、設定画面で理由を示す。別コマンドへ自動的に置き換えない。
- 設定画面を開く別の入口として、既存のトレイ固定「設定…」とコマンド検索を維持する。従来の「右クリックから必ず設定へ戻れる」という案内は更新する。
- リボン内の通常ボタン・グループ・区切り線・余白の右クリックを同じ本体アクションへ集約し、バブリングで二重実行しない。独立した一時的グループパネルは対象に含めない。
- 右クリックもコマンドボタンと同じ利用可否・権限・実行時再検査を受ける。現在のcontextActionIdの特例を任意コマンドの検査省略に使わない。

## 保存形式と編集操作

既存の`settings.json`の`ribbon`へ任意項目を追加する。

```ts
type RibbonColor = string | null; // 検証後の #RRGGBB、または色なし

interface RibbonCommandButton {
  id: string;                    // button:<stable-id>
  title: string;
  icon: RibbonBuiltinIcon;        // 共通の固定7種類
  commandId: string;
  iconOnly?: boolean;
}

// RibbonGroupへ追加
// color?: RibbonColor;

// RibbonLayoutへ追加
// separatorTitles?: Record<string, string>;
// buttons?: RibbonCommandButton[];
// rightClickCommand?: string;
```

`RibbonBuiltinIcon`は現在の固定候補から作る型名の案。実装時にグループ側の参照も同時に整理する。既存の`itemOverrides`は通常項目の別名と登録名の用途を保ち、セパレーター名や新規ボタンの本体定義を混在させない。

| 検証対象 | 方針 |
| --- | --- |
| 色 | 省略・null・6桁HEXのみ。保存前に正規化 |
| セパレーター名 | マップは最大50件。登録済みセパレーターのIDだけを許す |
| コマンドボタン | 最大100件、一意ID、必須の名前・固定アイコン・既存文法のcommandId |
| 所属と配置 | 未登録のbutton IDを拒否。1項目1所属、グループの入れ子禁止を維持 |
| 全体上限 | 既存のorder / hidden / bottomは各550件、グループの子は500件、ルートと子を合計した通常項目は500件を維持。上限を越す追加は保存前にエラーとする |
| 未知コマンド | IDの文法が正しければ読込と保持を許す。実行可否は登録状況で判定 |

共有の`parseRibbon`、`editRibbon`、`RibbonCommands`の読取投影・Schema・結果、設定ページのフォーム／部分JSONに同じ定義を反映する。

追加する編集操作は次のとおりとする。

- 第1段階: addGroup / updateGroupの任意color、`updateSeparator { id, changes: { title } }`。既存のaddSeparatorは名前省略で動作し、削除で名前を回収する。
- 第2段階: `addButton { id, title, icon, commandId, iconOnly?, placement }`、`updateButton { id, changes }`、`removeButton { id }`、`setRightClickCommand { commandId }`。
- 上記の編集は`appdock.ribbon.update`へ追加する。read→expectedRevision→dryRun／保存の契約と、複数操作の原子的な適用を維持する。GUIも既存のeditRibbon入力経路を使う。
- レイアウト読取の`items.kind`へcommandを追加し、ボタンの登録・表示・利用可否を区別する。`retainedIds`へ保存済みの正常なコマンドボタンを誤分類しない。
- 公開APIの編集操作`reset`は配置・別名・グループと色・セパレーターと名前・コマンドボタンを初期化し、rightClickCommandを保持する。互換性のためこの契約を維持する。GUIのページリセットはrightClickCommandも既定値へ戻すため、この編集操作とは区別する。

既存の未知フィールド保持、未導入Appletの配置・別名、PC専用の持続的な開閉状態を維持する。同値操作で不要な保存やrevision更新をしない。古い版はグループの未知フィールドや新IDを拒否し得るため、複数PCでは本体を対応版へそろえてから新項目を保存する。

## Shellと外部操作

- 色はschema 2のグループへ任意`color`として投影する。コマンドボタンは既存の表示用`kind: "button"`とopaqueなactionIdで表す。表示用の新しいkindは作らない。
- contextActionIdの文字列契約は維持し、schema 2の任意の`contextActionEnabled`と`contextDisabledReason`で右クリックの利用可否を伝える。旧Shellがこれらを使わなくても本体側の検査で実行を拒否できるようにする。
- schema 1の構造と既存のグループ平坦化を維持し、色とcontextActionEnabled／contextDisabledReasonは省略する。schema 2の追加表示情報を使わない既存Shellに、新機能の描画まで保証する扱いはしない。
- ShellへコマンドIDや実行引数を渡さず、本体でactionIdから解決する。Shellの`executeCommand`の自己所有範囲を広げない。
- 通常Applet／MCP経由の投影と実行は、現在のcaller・コマンド公開宣言・個別許可を使う。ローカルで実行可能なボタンの追加を、外部へそのコマンドを公開する許可に読み替えない。操作カタログと実行時の判定を一致させる。
- 編集用ribbon.getにはボタン定義を返すが、ボタンのcommandIdとrightClickCommandは外部から実行できるものだけを公開する。実行先を省略した読取用定義を保存型から分け、取得した不完全な定義を丸ごと保存させず、対象のIDとchangesを指定する既存の操作形式で編集する。公開情報の判定に別のID一覧を作らない。
- 色やセパレーター名の追加だけで、Node／.NETのバッジSDKの変更を要求しない。共通のribbon.get／updateの契約試験で両呼出し経路を確認する。

## 保存・競合・復旧

ダイアログ開始時のbeforeと最新の設定を比較し、同じリボンへの外部更新は既存の競合として扱う。古い一覧を再保存して上書きしない。設定同期・PC専用保存の現在の分類を使い、リボンへ新しい保存先切替は追加しない。

色選択・名前入力・コマンド選択・dryRun・キャンセル・読取で対象のコマンドを実行しない。保存失敗時は確定前の実リボンを保ち、ダイアログへ入力と原因を残す。削除・初期化・復帰でも無関係な設定とコマンド定義を維持する。

受け入れ試験と各段階の完了条件は[実装計画](ribbon-customization-design.md)を参照する。

## 採用する仕様

| 対象 | 仕様 |
| --- | --- |
| グループ | 1階層。ボタンと区切り線を収容し、グループの入れ子は作らない |
| 所属 | 各ボタンはトップレベルまたは1グループに所属する。同じボタンを複製しない |
| グループの編集 | 名前、組み込みアイコン、アイコンのみ表示、展開方式、上寄せ／下寄せ、表示、子の順序を設定できる |
| 持続的 | グループボタンの直後に子を縦に表示する。開閉をこのPCで保存し、再起動後も復元する |
| 一時的 | グループボタンの右側に横1行のパネルを開く。同時表示は1つ。幅不足時は横スクロールする |
| 子のバッジ | 数値、点、非表示。登録元が更新と解除を管理する |
| グループのバッジ | 表示対象の子にバッジが1つでもあれば点を表示する。件数の合計は初版に含めない |
| Gmail | 監視対象の全アカウントについて、既存の未読の新着スレッド数を合計して表示する |

初版では多段グループ、同じボタンの複数配置、任意コマンドのリボン登録、自由なバッジ文字列／色、グループへの数値合計指定を追加しない。既存のボタン登録対象を使い、本体にGmail固有の件数取得処理を置かない。

### グループに共通する動作

グループボタンは名前、アイコン、開閉の印を持つ。展開中もボタンを残し、同じボタンから閉じられるようにする。子は既存のページ表示、別ウィンドウ表示、テーマ切り替え等の実行経路を使う。

名前は空欄を許可する。空欄または「リボンにアイコンのみを表示する」がONならラベルを描画しない。名前が空欄の場合もツールチップ・アクセシブル名・設定一覧には「グループ」を使い、IDは変えない。

現在のページが子に対応する場合は、親にも選択中の印を表示する。選択ページの変更やバッジ更新によって自動展開しない。開閉だけでは現在のページやAppletの稼働状態を変更しない。

- 子の上寄せ／下寄せは親から継承する。親ごと移動する場合も子の順序を保つ。
- 非表示の子と無効Appletの子は実リボンから除外する。保存された所属、順序、非表示設定は保持する。
- 有効Appletの起動待ち・エラー・再試行時の項目と操作可否は、現在のリボンの規則を保つ。
- 表示対象のボタンが0件のグループは実リボンに表示しない。設定一覧には残し、子の復帰時には保存した開閉状態を使う。
- 区切り線だけのグループは空と扱う。先頭、末尾、連続する区切り線は描画時に整理し、登録は消さない。
- グループ解除では子を親があったトップレベルの位置へ順番に戻す。ボタンやApplet自体は削除しない。

### 持続的な展開

閉じた状態では親ボタンだけを表示し、開くと直後に子ボタンを並べる。薄いガイド線等で子の範囲を示し、アイコンの有効領域を過度に狭めない。子を操作しても開いた状態を維持する。複数グループを同時に開ける。

新規グループと、このPCで初めて取得したグループの初期状態は閉じる。開閉は明示した真偽値を本体へ渡し、同じ要求の再受付で反転しない。保存成功後のモデルを確定状態とし、保存中は対象の開閉操作を重複受付しない。保存失敗時は直前の開閉状態を保ち、既存の共通エラー報告へ接続する。

表示する子が増えても、本体の横幅を変えない。上部・下部の既存リボンスクロール領域を利用する。展開しただけでページ本文やリボン全体を自動スクロールしない。キーボードで移動した対象を見える範囲へ入れる処理は行う。

### 一時的な展開

パネルはグループボタンの右側に表示し、子ボタンの縦中央を元のグループボタンの縦中央に揃える。画面端ではクライアント領域内に補正し、右側の利用可能幅で最大幅を制限する。見出しと閉じるボタンは描画せず、子は折り返さず1行とする。横幅が不足する場合だけ左右スクロールボタンを表示し、横スクロールとキーボード移動でも到達できるようにする。子の名前・アイコンのみ表示・バッジは既存ボタンと同じ意味で表示する。一時型を開いてもリボン内に子のコンテナや余白を挿入せず、他のボタンの位置を保つ。

追加Shellの配置等で右側にボタン1個分の幅も確保できない場合は、横位置をクライアント領域内へ補正し、少なくとも1個とスクロール操作へ到達できる幅を確保する。通常の左側リボンでは右方向の配置を維持する。

表示中のページのWebContentsやログインsessionは保持する。パネルの開閉によって本文の再読み込みや表示先の変更を行わない。

| 閉じる契機 | 処理 |
| --- | --- |
| 実行可能な子ボタンの選択 | 実行要求を1回だけ受け付け、パネルを閉じて共通操作を実行する |
| 無効な子ボタンのクリック | 実行せず、パネルを維持する |
| 親ボタンを含むパネル外のクリック | パネルを閉じる。そのクリックを下のページへ再送しない |
| Escape | 閉じて、元の親ボタンへフォーカスを戻す。IME変換中は閉じない |
| 所有Windowのフォーカス喪失、非表示、最小化、終了 | 閉じる。別アプリからフォーカスを奪わない |
| route変更、パレット等の別オーバーレイ表示 | 現在のパネルを閉じる |
| グループの削除、非表示、方式／所属変更、リボン提供元の変更 | 現在のパネルを閉じる |
| Windowのリサイズ、zoom／DPI変更、元リボンのスクロール | 位置のずれを避けるため閉じる。再度押した時点で位置を計算する |

パネル外クリックは閉じる操作として消費するため、別グループを開く場合は閉じた後にそのグループを押す。クリックの透過・再送や擬似クリックを導入しない。

バッジや利用可否の更新は開いているパネルへ反映する。子の停止・削除で表示対象が0件になったら閉じる。実行失敗時は共通エラー通知を使い、パネルの自動再表示や操作の再送を行わない。

### キーボードと読み上げ

親ボタンに`aria-expanded`を付け、一時型には適切な`aria-haspopup`を付ける。持続型の子は通常のリボンのTab順に入り、折りたたみ後はTab対象から外す。

一時パネルは名前付きのダイアログ内に横方向のツールバーを置く。開いたら最初の実行可能な子、全て無効ならダイアログ本体へフォーカスする。左右キーとHome／Endで子を移動し、Tab／Shift+Tabはパネル内で循環する。Escapeで戻れるようにする。

閉じた後のフォーカス復帰は、同じrouteとリボンsessionが有効で、所有Windowにフォーカスがある場合だけ行う。子の選択でページへ移った場合は移動先の通常のフォーカス処理に従う。

### 共有するリボン設定

`settings.json`の`ribbon`に配置・グループ・ボタンの表示設定を保存する。ルートの設定schemaVersionは現行の1を維持する。以下はリボン部分の例で、製品の既定値ではない。

```json
{
  "ribbon": {
    "order": ["image-library", "group:messages", "settings", "logs", "notifications", "theme"],
    "hidden": [],
    "bottom": ["theme"],
    "separators": [],
    "groups": [
      {
        "id": "group:messages",
        "title": "メッセージ",
        "icon": "folder",
        "expansion": "persistent",
        "children": ["page:at365.gmail:gmail"]
      }
    ]
  }
}
```

保存・表示の正規化は、本体と設定UI、MCPが共用する純粋な解決処理に集約する。

| フィールド | 意味 |
| --- | --- |
| `order` | トップレベルの明示した順序。全グループを1回ずつ含み、グループの子は含めない |
| `groups[].children` | グループ内の順序の正本。既存のボタンIDまたは区切り線IDを保持する |
| `hidden` | トップレベル、グループ、子それぞれの非表示指定。親の非表示は子の実効表示に適用する |
| `bottom` | トップレベルの下寄せ指定。グループの子は含めず、親から配置を継承する |
| `separators` | トップレベルとグループ内の区切り線の登録一覧 |
| `groups` | グループの定義。配列自体の順序を表示順に使わない。任意の`iconOnly`はboolean、省略時false |
| `itemOverrides` | 通常ボタンIDをキーにした`{title?, iconOnly?, lastKnownTitle?}`。最大500件。未導入IDも保持し、グループと区切り線は対象外 |

`order`にも`children`にもない新規の登録ボタンは、従来と同じカタログ順でトップレベルの末尾へ補う。所属先を推測して自動でグループへ入れない。未導入ページのIDは保存対象として保持し、設定画面で未導入と表示する。

グループへ移す操作は、元の親／`order`からの除去、新しい`children`への挿入、`bottom`の除去を1回の設定保存で行う。トップレベルへ戻す操作とグループ解除は、子を`order`へ挿入し、親の配置を`bottom`へ反映する。非表示指定は前節の規則に従う。

### 保存値の検証

- グループIDは`group:<stable-id>`とし、UIではUUIDを生成する。名前変更でIDを変えず、削除したIDを再利用しない。ID末尾は既存separatorと同じ英小文字・数字・ハイフン、先頭英小文字または数字、80文字以下とする。
- 名前は前後空白を除いた0～80文字で制御文字を拒否する。通常ボタンの別名は空なら`title`を除去し、表示指定もない空のoverrideは除去する。アイコンは公開された組み込みアイコン名の限定リストから選ぶ。任意のURLやファイルパスを保存しない。
- 方式は`persistent`または`temporary`。グループは最大50件、区切り線は既存と同じ最大50件とする。
- `order`と全`children`を通した明示配置IDは重複不可。グループの子にグループIDを含めない。未知のページIDは既存の形式検証を満たす場合だけ保持し、未知のgroup／separator参照は拒否する。
- 既存の各ID配列の上限500へグループ50件分を加えて550とする。`children`は1グループ500件以下とし、明示配置全体の葉は500件以下とする。上限超過は保存前にエラーとし、切り捨てない。
- `hidden`は有効な既存ボタンID、定義済み区切り線／グループIDのみ。`bottom`は有効なトップレベルIDのみ。各配列内の重複も拒否する。
読み込みだけでファイルを書き換えず、次の通常保存で反映する。
- 不正な構造は既存の設定検証・バックアップ・外部読込障害処理へ接続する。部分的なグループだけを勝手に捨てない。

### PC専用の開閉状態

保存先は既存の配置別local root内の`ribbon-state.json`とする。共有する`settings.json`や`data/`へ開閉状態を書かない。

```json
{
  "schemaVersion": 1,
  "expanded": {
    "group:messages": true
  }
}
```

保存時の`expanded`のキーは現在定義されているグループID、値はbooleanとする。読込時に残っている削除済みIDは無視する。未記録はfalse。持続型から一時型へ切り替えた場合も持続型の最後の値を保持し、持続型へ戻したときに復元する。一時パネルの表示中状態をここへ書かない。

本体の`RibbonStateStore`が既存`atomicWrite`を利用して直列に保存する。同値は書き込まず、保存成功時だけ状態revisionを進める。グループ定義を変更しても残存IDの開閉は保持する。同期で届いた設定も、現在のPCの開閉を他PCの値で上書きしない。

削除済みグループの値は無視し、次のローカル状態保存時に除去する。共有設定保存とこの整理を一体のトランザクションにせず、整理失敗で成功済みの設定変更を巻き戻さない。欠落時は全閉、破損時は共通エラーへ記録して全閉で起動する。読み込み失敗だけで元ファイルを上書きしない。

### メモリー上だけの状態

一時パネルのsession、アンカー、スクロール位置、フォーカス対象と、登録元のバッジ値は保存・同期しない。バッジは新しいruntime起動時に登録元から再発行する。Shellの再起動だけでは本体が保持するバッジや持続型の状態を失わない。

## 本体とShellの責務

| 部分 | 責務 |
| --- | --- |
| 共通リボン解決処理 | 構造検証、配置と所属、非表示、未導入ID保持、表示対象の解決 |
| `RibbonStateStore` | このPCの持続型の開閉、原子的保存、状態revision |
| `RibbonBadgeService` | 登録元・runtime世代・対象別のバッジ、解除、変更通知 |
| `UiPresentation` | グループと子の表示モデル、選択状態、親の点、現在有効な操作ID |
| `RibbonGroupSession` | 一時パネルの内容、選択受付、取消、実行要求の重複防止 |
| `OverlayHost` | View、重なり順、アンカー変換、ready、フォーカス、寿命、Shell復旧 |
| Default Shellと追加Shell | 公開snapshotの描画、キー操作、ローカル座標の計測、横スクロール |

本体からShellのReact実装をimportしない。Shellから保存ファイルやホスト内部実装へ直接アクセスしない。バッジの変化でページやリボンViewを再作成せず、既存の集約された変更通知へ載せる。

### リボンの描画契約

`RibbonView`にschemaVersion 2を追加し、既存のbutton／separatorにgroupを加える。グループは`expansion`、`expanded`、`selected`、`badge`、`actionId`と、表示対象の子の個数を持つ。持続型で開いている場合だけ`children`に子の描画モデルを載せる。一時型の子のモデルはパネルのsnapshotへ載せる。

ボタンは後述の`badge`と、ラベルを省く`iconOnly`を持てる。本体が実効表示名と`iconOnly`、数値の表示文字列、説明、親の点を決定する。rendererはメール件数の集計や登録元の推測を行わない。バッジ値・開閉・実効表示・選択・利用可否が変われば表示revisionを進め、設定revisionとは分ける。

グループの操作も`ui.actions.invoke`の本体発行actionIdを使う。持続型は「現在と反対の値へ設定する」操作として発行し、同じrequestIdを再受付して反転しない。非表示・空・削除済み・失効sessionの操作は拒否する。バッジ更新だけで実行中の操作の受付記録を破棄しない。

一時型を開く要求には、選択中のローカルShellだけが親ボタンの矩形を付加できるようbridgeを拡張する。座標はそのShellのCSS座標で、mainが現在のView位置とzoomからクライアント領域のDIPへ変換する。有限値、正の寸法、表示領域との交差、対象グループ、sessionを検証する。OS座標や任意Windowは受け付けない。

アンカー計測直後のスクロール／レイアウト変更はShellから本体へ通知してパネルを閉じる。接続元の照合を共通bridgeで行い、別Shellのパネルを任意に閉じる操作口にしない。所有Windowのblurを監視し、リボンからパネルへのWebContents間のフォーカス移動は取消にしない。

### 一時パネルのShell領域

公開領域`overlay.ribbon-group`を追加する。Default Shellは対応するHTMLを提供し、追加Shellもこの領域だけを提供できる。割り当ては既存`host.shellProviders`へ追加する。未指定はDefault Shellとし、リボン提供元から暗黙に推測しない。

`OverlayModel`をkindで分岐し、既存のcommand-palette契約を維持したまま、ribbon-group用のschemaVersion 1を追加する。内容はグループ名、クライアント領域内のアンカーと表示制約、子の描画モデル、閉じる操作、session／revisionとする。ローカルパス、Applet設定全文、Gmailの本文やアカウント名は含めない。

既存`OverlayHost`の単一モーダル枠を再利用する。背景は暗くせず透明とするが、パネル外クリックと入力を一時的に受け止めるため`modal: true`とする。既存の共通キー／ジェスチャー停止を引き継ぎ、パネル自身の操作を有効にする。リボンのCSSをView外にはみ出させる方式は使わない。

Hostのcommand-palette固定の領域参照、送信元検証、provider解決、ready、故障記録をControllerの領域へ一般化する。内容判断はControllerへ残す。パレットとリボンパネルが同じ枠を奪い合うときは、既存の新しい要求による取消を使う。

子を選ぶときは、現在のsession・子・利用可否・requestIdを照合して実行内容を確定し、その受付を記録してから閉じる。閉じた後に消えた子のactionIdをもう一度`UiPresentation.invoke`へ投げ直さない。受付済みの内容を共通dispatcherへ渡し、実行直前にも登録元・世代・現在のコマンド利用可否を照合する。

表示中の提供元は固定し、故障時は同じ要求をDefault Shellへ引き継ぐ。source側のリボンsessionやアンカーが失効していれば取消する。実行受付済みの操作を復旧で再実行しない。Viewの破棄と購読回収は既存Hostに集約する。

### 既存Shellと外部取得の互換性

manifestの`shell.ribbonSchemaVersion`を追加し、対応値を1／2、省略を1とする。新しいリボンは2を宣言した提供元へ接続する。旧提供元は設定指定を保持したまま、ribbon領域だけDefault Shellへ復帰させ、理由を表示する。他の提供領域には影響させない。最低ホスト版も実装版に合わせる。

外部の`ui.ribbon.get`には任意の`schemaVersion`を追加し、省略時は従来の1を返す。1への射影では、グループの操作ボタンを通常のbuttonとして返し、開いている持続型の子を直後へ平坦化する。バッジ等の新フィールドは付けない。2は構造化した新モデルを返す。どちらも同じ機能サービスと操作受付を使う。

一時パネルの開始は、アンカーを検証できる選択中のローカルShellに限定する。通常Applet／MCP向けモデルでは一時グループの開く操作を無効とし、理由を返す。外部からページを開く場合は従来の公開コマンドを利用できる。持続型の開閉は既存のUI操作権限で扱い、共有設定編集の権限を要求しない。

新領域を共通カタログへ追加しても、旧指定を自動で新領域へ割り当てない。

### 入力と所有者

新しい`ribbon-badges` capabilityを宣言したAppletに、Nodeの`context.ribbon.setBadge(target, badge)`と.NETの対応メソッドを公開する。RPCは`host.ribbon.setBadge`に統一する。型の案は次のとおり。

```ts
type RibbonBadgeTarget =
  | { pageId: string }
  | { collectionKey: string; itemId: string };

type RibbonBadge =
  | { kind: 'count'; count: number; label?: string }
  | { kind: 'dot'; label?: string }
  | null;
```

静的ページと実行中に登録した動的ページは`pageId`、設定由来のページは`collectionKey/itemId`で指定する。本体が実際のページ登録情報・CollectionBindingと呼出し元を照合し、リボンIDへ解決する。呼出し元IDを引数で受け付けず、ID文字列の接頭辞から所有者を推測しない。

登録済みの自身のページだけを対象とし、未知ページ、他Appletのページ、本体ボタン、利用者のグループを拒否する。collectionの仮想Applet IDも所有者の判定に流用しない。UIから非表示にしたページへは値を保持できるが、実際の表示とグループ集約には含めない。

起動処理中は、現在のruntime世代と宣言済み／登録済み対象を確認したうえで受け付ける。停止処理開始後は既存の規則どおり拒否する。未対応のcapability、余計な入力フィールド、不正な値を検証し、失敗時は既存値を変えない。

自己所有の表示状態更新として扱い、`appdock-api` capabilityやMCPの包括的な設定変更許可は要求しない。通常Applet／MCPから任意の登録元のバッジを書き換えるAPIは提供しない。本体ボタンは同じサービスのホスト内部の登録元として利用可能にするが、通知センター等の新しいバッジ連携は対象外とする。

### 値と表示

`count`は0以上の安全な整数に限定する。0とnullは非表示に正規化し、1～99は数値、100以上は`99+`と表示する。内部の値は丸めず保持する。dotは件数を持たない印とする。

`label`は任意の説明用のプレーンテキストで、前後空白を除いた1～120文字、制御文字なしとする。件名、本文、アカウント名、認証情報を渡さない用途に限定する。説明はボタン名と実数または印の状態に添え、ツールチップと支援技術の読み上げへ反映する。省略時は本体の共通説明を使う。

バッジはアイコンの右上に重ね、ヒット領域をボタンと共用する。バッジ独立のクリック操作は作らない。ボタン名と選択マーカーを隠さず、テーマに応じた色とコントラストを使う。色だけで数値と印を区別しない。

値は登録元runtime世代と対象の組でメモリーに保持する。同値更新はrevisionと通知を増やさない。戻り値は`changed`を含む受付結果とし、Shellの描画完了を保証する意味にはしない。

停止、無効化、異常終了、アンインストール、対象ページの削除／登録解除時に本体が解除する。古いruntimeから遅れて届いた更新は採用しない。ページを再登録した場合は同じIDでも新しい値の発行を必要とする。Shellの切り替え、ボタンの移動、グループの開閉だけでは解除しない。

グループの点は、現時点で表示対象となる子ボタンの非空バッジから本体が導出する。折りたたみ状態は集約対象を減らさず、非表示・無効・未導入の子は除外する。開いている間も同じ点を維持し、グループ内の注目状態を一貫して示す。

## 外部からの配置編集

`ribbon.get`と`appdock.ribbon.update`を拡張し、GUIと同じ構造検証・編集処理へ接続する。既存のexpectedRevision、dryRun、設定変更・コマンド実行・リボン編集の独立した許可を維持する。バッジ更新とPC専用の開閉では共有設定revisionを進めない。

`ribbon.get`はlayoutにgroups/itemOverridesを含め、itemsへ実効表示名、親ID、実効配置、設定上の表示、実効表示を加える。未導入IDの所属と順序も取得できるようにする。グループが閉じているかは配置編集の表示／非表示と混同せず、描画APIで取得する。

| 操作 | 追加する意味 |
| --- | --- |
| `addGroup` | ID、名前、アイコン、方式、配置、任意のiconOnlyを指定して空グループを末尾へ追加する |
| `updateGroup` | 名前、アイコン、方式、iconOnlyを変更する。表示と配置は既存updateへ接続する |
| `updateItem` | 通常ボタンのリボン内の別名とiconOnlyを変更する。保持中の未導入項目も対象 |
| `removeMissing` | 現在カタログにない保持項目の配置・非表示・所属・表示設定を除去する |
| `moveItem` | 子またはトップレベル項目を移す。宛先のparentIdとbeforeIdを指定し、トップレベル／末尾はそれぞれnull。トップレベル宛てだけplacementも必須とする |
| `ungroup` | 子を同位置へ戻してグループだけ解除する |
| `reorderChildren` | 指定グループの全childrenを重複なしで渡す。未導入IDも含む |
| 既存`reorder` | 選んだ配置の全トップレベル項目を渡す。非表示・無効とグループを含み、子は含めない |
| 既存`update` | 子の表示は変更可。子のplacement変更は所属先と競合するため拒否し、moveItemへ案内する |
| 既存`removeSeparator` | 所属先と全参照から対象だけを除く |
| 既存`reset` | groups/itemOverridesを含む共有リボン設定を初期化する |

既存reorderで未導入のトップレベルIDを除外する契約は維持し、保持IDを破棄しない。reorderChildrenは新規契約として未導入IDを含む正確な全順序を要求する。旧クライアントの古い一覧による編集はrevisionまたは集合照合で拒否し、子を意図せずトップレベルへ戻さない。

全operationsを仮状態へ順番に適用して検証し、最後に1回だけ原子的に保存する。dryRunはローカル開閉状態、バッジ、パネル、Appletの起動に影響させない。

## リボンの表示モード

リボンの上端には装飾用のアプリロゴを置かず、上下の専用余白を設けない。先頭の項目は上端の通常余白6pxから表示し、アイコンのみ/名前付きの両モードで同じ配置にする。

既定では下寄せの「表示モードの切り替え」項目で「アイコンのみ」（compact、56px）と「アイコン＋名前」（expanded、200px）を選ぶ。展開時は名前をアイコンの右に1行で表示し、長い名前は省略してtooltipとアクセシブル名で全文を保つ。グループの持続的な子はインデントせず、色の縦線で示す。線は疑似要素で描画し、親・子・通常項目のアイコンの横位置を変えない。グループ親の開閉マークも絶対配置とし、モード切替やグループの開閉でアイコンをずらさない。項目ごとの旧iconOnly指定は保存・API互換のため読み取るが、実際の描画は全体モードから導出する。名前・画像・配置・実行コマンドはモード切替で変更しない。

表示モードは既存のPC専用ribbon-state.jsonへdisplayModeとして、グループのexpandedと一緒に原子的に保存する。旧ファイルと未指定はcompact。保存に失敗したら公開中のモードと幅を変えない。共有設定のrevision/即時入力を変更しない。safe-shell中はcompact固定で切替を無効にする。本体はHostSnapshotのモードからCSSの幅を予約し、ShellとAppletページの既存ResizeObserver/viewport経路で再配置する。Viewの作り直しは行わない。

切替項目も通常のリボン編集対象（ID: ribbon-display-mode）とする。名前、画像、上寄せ/下寄せ、順序、グループへの移動、表示/非表示を既存のitemOverrides/order/hidden/groupsで保存する。名前未指定はモードに応じた操作名、指定時はその名前を両モードで使う。外部向けとschema 1には切替actionIdを渡さない。ローカルのグループpopup内に実際に配置された切替項目は、そのグループの候補検査を経て選択できる。

Applet本文がホストrendererを覆う状態でも、モード変更時のuseLayoutEffectでリボン/本文のviewportを直接更新する。ResizeObserver通知のみには依存せず、既存のNative Viewを移動/リサイズし、ページや入力・認証状態を再生成しない。

Default Shellのアイコン位置は両モードで左側へ固定する。ラベルはDOMに保持し、実際のnativeリボン領域の幅に対するmedia queryで表示を切り替える。モードモデルが幅変更より先に届いても、折りたたみ前の広い領域の中央へアイコンを寄せたり、ラベルだけを先に消したりしない。一時グループpopupは従来どおり項目モデルのiconOnlyを使う。
