# コマンドスタック

コマンドスタックは、コマンドの実行順、各行の有効状態と「いつ・どこで」、一致した行を「最初の1つ」または「すべて」実行する設定をまとめる単位。

## 作成と編集

- 名前を付けて再利用するスタックは、カスタムコマンドの種類「コマンドスタック」で作る。パレット・トレイ・各入力へ通常のコマンドとして割り当てられる。
- トリガーは、入力方式と正規化した入力IDの組に専用スタックを1つ持つ。この専用スタックは通常のコマンド一覧や外部コマンドカタログへ公開しない。名前付きスタックをその中へ追加できる。
- キー・マウス・タッチパッドの設定ページは、動作設定の下にトリガー単位の一覧を表示する。コマンドトリガー画面の「キージェスチャー」「マウスジェスチャー」「タッチパッドジェスチャー」タブからも同じ記録を編集する。カスタムコマンド画面はタブを持たず、作成したコマンドだけを表示する。
- コマンドトリガー画面の「コマンド一覧」タブは、コマンドから割り当てを探す逆引き表示。既存行の条件・歯車は同じ専用スタックを開き、その行を選択する。新規割り当ての簡易ダイアログも同じスタックへ行を追加する。

編集画面は左に実行順、右に選択した行の条件を表示する。コマンド検索から追加し、行の削除、ハンドルのドラッグ／↑↓キーで並べ替える。条件の入力途中はダイアログ内に保持し、不正な行が残っていると保存できない。チェックボックスに囲み枠を付けない。

トリガーの追加は「トリガーを選ぶ」「コマンドを組む」の2段階とする。マウスとタッチパッドは割り当て追加ダイアログと共通の`GestureInputPicker`を使い、種類・方向・段階・指の本数をマークで選ぶ。キーは共通の記録部品を使う。未入力・既存トリガーとの重複があると次へ進めない。「トリガーを選び直す」で戻っても、コマンドと入力途中の条件を保持する。最後の「追加」だけで保存し、途中のキャンセルでは保存しない。

既存トリガーのダイアログ名は「トリガーの編集」。トリガーを表示専用にし、実行方法とコマンドスタックだけを編集する。入力方式やトリガーIDは保存時にも元の値を使う。別の入力を作る場合は追加から行う。この制約は編集UIに適用し、既存の保存形式やAPIの更新契約は変更しない。

専用ダイアログは高さを最大900px、画面上下の余白を合計32pxとして画面内に収める。追加の選択段階は選択欄全体を1つのスクロール領域とし、コマンド編集段階では上部のトリガー表示・実行方法、コマンド一覧、条件を罫線で区切る。一覧と条件を個別にスクロールし、本文全体にはスクロールバーを出さず、フッターの操作を固定する。狭い画面では一覧と条件を上下に配置する。

カスタムコマンドの名前付きスタックも、同じ一覧・条件の罫線とスクロール構成を使う。共通項目と実行内容を横に並べ、狭い画面では切り替える。さらに狭く一覧と条件が上下になる場合は、実行内容全体を1つのスクロール領域にし、一覧や条件を小さな枠へ閉じ込めない。切り替え中もスタックの選択行や入力途中の条件を保持する。詳細設定・JSON編集の展開時にも本文全体をスクロールさせず、フッターを表示し続ける。

専用スタック一覧はマークや選択欄と同じカタログ順にする。マウスは移動・複合移動・クリック・ホイール・キー、タッチパッドは3本指・4本指の各選択肢順。キーは英字A〜Z・数字0〜9・操作キー・移動キー・ファンクションキーの順で、同じキーでは修飾なし、Ctrl・Alt・Shift・Winの選択順による組み合わせを続ける。この表示順は保存順やスタック内のコマンド実行順を変更しない。

専用スタックの実行方法は入力方式の設定を継承するか、first/allを指定する。専用スタックの保存は最低1行を要求する。空の名前付きスタックは実行するコマンドがない状態として保存できる。対象スタックが外部で変更された場合は古い編集を拒否する。削除確認はスタック全体と、逆引き画面の1行削除を区別する。

## 保存と既存API

名前付きスタックは`customCommands.version: 2`の定義として保存する。種類IDは`appdock.commands.stack`、configVersionは1。configは`{ executionMode: "all" | "first", entries: [...] }`で、各行は`id`・`command`・`enabled`・`when`を持つ。

共有settings.jsonの入力割り当ての正本は次のブロック。kindは`shortcuts`・`gestures`・`touchpad-gestures`、executionModeは`inherit`・`first`・`all`。キーの行だけに`blockOriginalInput`を持たせる。

```json
{
  "triggerStacks": {
    "version": 1,
    "items": [{
      "kind": "gestures",
      "input": "move-up",
      "executionMode": "inherit",
      "entries": [{
        "id": "row-1",
        "command": "appdock.settings.open",
        "enabled": true,
        "when": { "scope": "global", "appletIds": [], "processes": [] }
      }]
    }]
  }
}
```

保存時に`keybindings`、旧`shortcuts`／`globalShortcutCommands`、gesture/touchpadのbindings、入力別inputExecutionModesはこのブロックへ集約する。実行時と既存公開API・設定ページJSONには、同じ記録から従来の行配列と入力別モード辞書を投影する。コピーした別のスタック集合は保持しない。入力方式全体のexecutionMode・除外・Windows接続は従来の設定に残す。既定値と一致するブロックは共通の省略規則に従う。

旧形式の読み取りは既存パーサーで受け付けるが、互換性保持のための移行処理や旧形式への二重保存は追加しない。通常の保存で新形式になる。旧版へ戻すと新形式の割り当てを扱えない。現在使用中の設定ファイルを実装・検証のために削除しない。

設定ページのリセットは、そのページに表示するスタックも対象とする。カスタムコマンド画面のJSONとリセットは名前付き定義だけ、各入力ページは自身の方式、コマンドトリガー画面は選択タブにかかわらず3方式の専用スタックを扱う。APIの編集権限、expectedRevision、dryRun、原子的保存を維持する。

## 実行の契約

共通`planCommandBatch`が呼び出し開始時のcontextで条件を評価し、名前付きスタックを展開してから`CommandDispatcher`へ渡す。後続コマンドで前面アプリやページが変わっても条件を選び直さない。同じコマンドIDでも選択された各行を保存順で実行する。実行候補がない入れ子は選択対象から除外する。

firstで選んだコマンドが失敗になっても次の候補へ繰り下げない。allは個別の失敗を記録して次へ進む。取消、アプリ終了、スタックの無効化／削除、マウス入力対象の変更では後続を停止する。独立した入力は同じコマンドやスタックでも受け付け、それぞれの計画内だけ順次実行する。

順番に待つのは各コマンドハンドラーの応答まで。プロセス起動や非同期MCP処理の受付を、外部処理そのものの完了とは扱わない。時間指定の待機ステップ、自動再試行、待ち行列は今回追加しない。

外部から名前付きスタックを実行する場合は、そのスタックと選ばれた入れ子も公開・実行許可が必要。各末端コマンドは元のorigin／callerと個別の公開・権限・SELF_CALL検査を通す。同じ呼び出し経路内で同じコマンドや実行中Appletへ戻る循環を拒否する。独立した要求に共通のBUSY制限は設けない。ローカルUIでは既存のローカル実行権限を使う。

名前付きスタックは最大256行、入れ子8段、展開上限2000件。専用スタックは最大2000行、展開上限は同じ。既存のカスタム定義のJSONサイズ制限も適用する。自己参照・循環・上限超過は保存前に拒否し、実行時にも展開を制限する。

nativeの事前判定は末端へ到達する条件経路（経路内AND／経路間OR）を受け取る。元キーのブロックとマウス待機表示に入れ子の条件も反映し、native候補の行IDとmainの計画を照合する。キーのブロックは一致した全行から合成し、first/allやbusyで変更しない。タッチパッド専用キーの入力契約は従来どおり。
