# 共通画像ライブラリーと宣言型リボン

AppDock 0.69.0以降の現行契約。登録原画像、分類グループ、Applet設定、リボン表示は本体の共通基盤で扱う。プロフィール固有の保存処理や描画分岐は持たない。採用時の判断と境界は[分離設計](registered-images.md)を参照する。

管理画面は独立した「画像ライブラリー」ページ。左のグループ一覧、カードサイズ変更、複数登録と一括所属を備える。画像選択・壁紙履歴にも同じカードと拡大表示を使用する。表示部品の利用方法は[共通ギャラリー](image-gallery.md)、全体の設計は[ページ化の設計](image-gallery.md)を参照する。

## 保存と参照

原画像は注入された共有assets rootの`images/<元ファイル名>`、標準配置ではEXE隣の`data/assets/images/`に保存する。参照は`RegisteredImageRef = { file: string }`、未選択は`null`。パス、URL、他の属性は受け付けない。Windows禁止文字、予約名、末尾空白・点、180文字超、拡張子がPNG/JPEG/WebP以外の名前を拒否する。rootとファイルの転送も拒否する。

PNG/JPEG/WebPの静止画像、5MiB以下、各辺8192px以下かつ16Miピクセル以下。拡張子・実形式・decode・寸法を検証する。原画像の解像度、縦横比、透過、bytesを保ち、アイコン化した画像で置き換えない。APNGとアニメーションWebPは受け付けない。

大文字小文字を無視して同名照合し、同名同内容は再利用、同名別内容は拒否する。登録は一時ファイルへ書込み・flush後、排他的なlinkで完成したファイルだけを公開する。既存原画像を上書きせず、自動の連番や移動は行わない。登録ファイル数に固定上限は設けない。専用インデックスJSONやID対応表は作らない。

起動時の一覧取得とwatch/2秒pollは、ファイル名・サイズ・更新情報・転送の有無だけを調べ、原画像のbytesを読んだりdecodeしたりしない。存在する安全なファイルは読込候補としてavailableになり、未decodeの寸法は0、サムネイルは空または直近正常の表示になる。実形式・静止画・寸法の検証は初回利用時に行い、不正な画像はその時点でerror/利用不可になる。新規登録・importは従来どおり公開前に検証する。

画像の表示要求に応じて、64px長辺の一覧サムネイルと96pxの円形表示画像をメモリーへ生成する。円形表示だけ中央で切り出す。リボンのモデル生成は読込を開始せず、ShellがopaqueなassetIdの表示データを取得した時点で非同期に読み込む。閉じたグループや非表示の項目はモデルに含まれてもdecodeしない。完了まで通常アイコンを使い、完了後に差し替える。ファイル名・パスや読込関数をShellへ渡さない。

同じファイル版への同時要求はまとめ、読込/検証は直列に行う。小型画像はファイル版ごとにキャッシュし、変更したファイルも次の表示要求まで再decodeしない。generationは内容hashと区別したopaqueなファイル版で、変更/再到着時に更新する。読込前後の更新情報と現在の版を検査し、差し替え・削除・終了に遅れて完了した結果を採用しない。原画像の内容hashは利用時に計算し、ギャラリーの縮小画像キャッシュと削除確認の照合に使用する。

管理ページ・画像選択・拡大プレビュー・設定欄の画像表示は、それぞれの表示寿命に結び付ける。ギャラリーの縮小画像は要求した画面が開いている間だけ共有し、最後の利用画面を閉じたら本体のキャッシュから外す。プレビューだけを閉じても背後のギャラリーが使う画像は残す。管理ページの遷移、選択の確定・取消、rendererの再読込・終了でも回収する。閉じた画面だけが要求した待機中の読込/decodeは開始せず、進行中の処理は完了しても応答やキャッシュを復活させない。他の生存画面やリボンの同時要求は取り消さない。

一時表示の読込は寸法・内容hashなどのメタデータだけを残し、64px/96pxの小型画像を登録一覧へ常駐させない。新規登録も原画像の検証とメタデータの公開までとし、画素は利用時に取得する。リボンなど継続利用から要求された小型画像と欠落時の直近表示は従来どおり維持する。原画像・共有設定・PC専用コピーは解放対象にしない。参照の解放と実際のメモリー回収は別であり、Chromium/OSの使用量が閉じた直後に同じ量だけ減ることは保証しない。

未到着・一時削除・部分ファイルでは参照と直近正常の表示を保ち、正常なファイルが届けば再取得する。初回から画像がなければ通常アイコンを使う。decode失敗をpollごとに繰り返さず、ファイル更新または管理ページの再読込で次の要求を受け付ける。寸法/表示の更新は既存の変更通知を使う。MCPの候補取得・分類操作はキャッシュ済みファイル名一覧だけを使い、画像の読込・decode・取込みを開始しない。

PNG/JPEGはNativeImage、WindowsのNativeImageが扱わないWebPは専用の非表示offscreen rendererでdecodeする。sandbox・contextIsolationを有効にし、Node/preload/ホストbridgeを渡さず、CSPでdata画像だけを許可する。元bytesを読み込み、小さい表示用PNGだけを返す。処理は直列、15秒の上限、1秒のidle後に回収し、本体終了後の待機処理は新しいrendererを作らない。原画像は変換しない。起動前の補助Window終了で本体を終了しない。

NASの設定場所切替・分散書込み・ネットワーク切断への完全な回復処理は[共有場所の設計](shared-settings-location-design.md)の別工程。ローカルファイル試験を実NASの検証として扱わない。

## グループ

共有`settings.json`へ次の分類だけを保存する。画像は複数グループへ所属できる。

```json
{
  "imageLibrary": {
    "groups": [
      { "id": "photos", "name": "写真", "images": [{ "file": "flower.png" }] },
      { "id": "buttons", "name": "ボタン", "images": [{ "file": "flower.png" }] }
    ]
  }
}
```

グループ数・各グループの参照数・全体の所属数に固定上限は設けない。IDは英小文字・数字・ハイフン、先頭英数字で80文字以下。名前は空白除去後1～80文字、制御文字と大文字小文字を無視した重複を拒否する。同一グループ内の画像重複も拒否する。「すべて」「未分類」は保存しない仮想一覧。

名前変更、所属編集、並べ替え、グループ削除は原画像の名前・場所・使用先の参照を変更しない。グループは分類であり、アクセス許可やリボンの親子関係ではない。未使用画像の自動整理は行わない。

MCPは[共通設定APIのグループ/所属対象](settings-api.md#画像グループと所属)から同じ分類を編集する。グループの名簿とグループごとの所属一覧を探索し、現在の登録画像候補を使って追加・解除・並べ替えを行う。管理画面と同じ変更計画・既存の検証/保存を使い、MCPの読取りやdryRunで原画像を走査・decode・変更しない。原画像の取込みや削除はこの分類操作へ含めない。

管理カードの下端は「グループ」「削除」。画像のクリックでプレビューを開く。「削除」は確認後に原画像をごみ箱へ移し、全グループの所属から外す。保存済みのリボン・Applet設定（無効・未導入を含む）や、導入済みAppletの既定の画像設定から使用している画像は削除できない。使用先の設定を解除してから操作する。読取不能・未到着の画像は削除対象にしない。

削除対象は本体が保持するダイアログ要求に結び付け、実行時に原画像の内容hash、保存先、使用中の参照を検査する。OSのごみ箱操作に失敗しても完全削除へ切り替えない。移動後に設定競合や所属の保存失敗が起きた場合は、保持した原画像を排他的に復元する。別の画像を上書きせず、復元も失敗した場合は保存先とごみ箱の確認を案内する。ファイルと設定は単一の原子的トランザクションではなく、処理中のプロセス強制終了・電源断・分散書込みまで保証するものではない。

編集は直前値を検査する。所属編集は対象画像の所属集合だけを比較し、別画像への同時変更を保持する。継続する所属の位置は保ち、新たな所属だけ末尾に追加する。同じ画像の所属競合、変更済みグループの編集・削除、古い並び順は拒否し、勝手に再送しない。

## 共通設定と選択画面

公開されたregistered-image設定と一覧の画像列は、[MCPの共通設定API](settings-api.md#登録画像の参照)から登録済み参照の選択・解除に対応する。候補は画像サービスのキャッシュを使い、取得やdryRunによる取込み・画像ファイル変更は行わない。未選択のnullと既定値の継承を区別し、画像を参照する行の削除には先に明示的な解除を必要とする。

画像選択ダイアログは共通ギャラリーの単一選択モードを使う。「画像サイズ」は管理ページと別にPC内へ記憶し、検索・グループ変更では一覧の先頭へ戻す。「拡大」を閉じても選択は保たれ、「画像を使う」で親の値を確定する。取消では親の画像参照を変えない。保存とプレビューのAPI境界は[共通ギャラリー](image-gallery.md)を参照する。

リボンの「画像ライブラリー」、またはコマンド`appdock.image-library.open`から管理ページへ移動する。設定画面の同名カテゴリと案内ページは設けない。保存データの`imageLibrary.groups`は引き続き保持する。左のグループを選び、ファイル名検索、原画像プレビュー、所属編集、グループ追加・名前変更・削除・並べ替えを行う。狭い画面ではグループを上部の選択欄へ畳む。新規の標準リボン配置は先頭。保存済みの順序・非表示は既存の規則を保つ。

一覧は64件ずつ追加表示する。「すべて選択」は検索・グループの該当全件を含み、未描画分も選択する。複数画像をグループへ追加、現在のグループから解除できる。`membership-batch`は各画像の直前所属集合を検査し、全件の形式と所属を検証してから一度だけ保存する。競合では一部だけを変更しない。

画像一覧・グループ欄・フィルター欄の背景クリックで選択を解除し、背景をドラッグして矩形選択できる。Ctrlを押すと既存選択へ追加する。入力やボタンの操作で選択を解除しない。カードを左の通常グループへドロップすると所属を追加する。選択済みカードからは未描画分を含む全選択画像、未選択カードからはその1枚を対象にする。ドラッグ開始時の対象と所属を本体sessionの一度限りのtokenで保持し、ドロップ時に競合を検査する。ほかの所属・原画像は保持し、登録済みの所属を重複追加しない。「すべて」「未分類」はドロップ先にしない。画面内の結果表示に新たに追加した件数を示す。狭幅やキーボード操作では既存の「グループに追加」を引き続き使える。

通常グループは保存済みの`images`配列順に表示し、カードの左右に示す挿入位置へドロップして並べ替える。複数枚は表示順を保ったまままとめて移動する。検索中は表示された画像の前後へ挿入し、検索で隠れた画像同士の順序は保つ。開始後に対象グループが変更された場合は上書きせず拒否する。グループの操作メニューの「画像を並べ替え」では全画像を共通ダイアログで編集でき、↑↓キーにも対応する。「すべて」「未分類」はファイル名順で固定する。各グループの順序は独立し、原画像やほかのグループに影響しない。

所属追加・並べ替えの成功メッセージは、選択の変更/解除、表示グループや検索の変更で消す。これらの保存中に表示対象を変えた場合も、遅れて届いた成功結果を再表示しない。エラーや再試行の案内は別に保持する。

「画像を追加」は複数ファイルに対応し、追加・同内容の再利用・失敗を区別する。登録開始時のグループへ所属を一括追加し、登録後に成功画像を選択して表示する。所属保存だけが失敗した場合は登録原画像を残し、明示的な再試行を用意する。登録は独立した保存操作であり、その後の画像選択や親編集をキャンセルしても登録原画像は残る。

「画像サイズ」は120〜360 CSS px、20px刻み、初期260px。操作中は即時反映し、操作確定時だけPC専用rootの`image-gallery-state.json`へ保存する。グループ・検索・選択・閲覧位置を保持する。共有設定や原画像は変更しない。壊れたファイルや未知の版を上書きせず、当該起動中は保存を止める。外部変更との競合も上書きしない。通常起動の既定ページを変更せず、`--restore-view`で画像ライブラリーも復元する。

管理ギャラリーは必要な画像だけ512/1024/2048px長辺で縮小生成する。実幅とdevicePixelRatioで段階を選び、元画像を拡大しない。内容hashと段階で要求をまとめ、直列decodeと概算64MiBのメモリーキャッシュを使う。Shellにはsession内のopaqueな画像ID・assetIdと表示用ファイル名を渡すが、原画像パスや参照による任意取得は許可しない。従来の小型アイコン用64px/96pxと、既存の画像選択ダイアログの表示は維持する。

Appletは`type: "registered-image"`の設定を宣言する。通常フィールドとobject-listのフィールドで使える。`default`は`null`または有効な参照。object-listの`list.imageKey`は同じ定義内のregistered-imageフィールドを指す。従来の`list.iconKey`とWebAppletのinline iconは保持する。

```json
{ "key": "avatar", "title": "アバター画像", "type": "registered-image", "default": null }
```

文字列には任意の`minLength`と`maxLength`も指定できる。最小長を指定した場合は空白だけの値を拒否する。共通フォームのblur/Enter確定、Escape取消、ダイアログOKによる登録単位の保存を使う。

本体内の選択は共通SettingsDialogを使い、親ダイアログの一時入力だけを変更する。重なったモーダルがある間はショートカット記録の抑止を維持する。ローカルAppletページからの選択は本体へ委譲し、表示中Viewをcapture・hide、独立Windowを操作不可にして本体の選択画面を表示する。完了・取消・提供元停止で同じViewとフォーカスを復元し、WebContents/sessionを再生成しない。本体のダイアログは本文だけを薄くぼかし、Shellの表示・操作を維持する。

### 画像入力部品とアイコンの選択

画像フィールドは共通`RegisteredImageInput`を使う。固定サイズのプレビュー自体を画像選択ボタンとし、画像を外すアイコンだけを隣に置く。別の選択ボタンやファイル名は表示しない。プレビューはクリック・Enter・Spaceで共通選択画面を開き、設定済みなら変更、未選択ならプレースホルダーから選択する。操作名のツールチップとアクセシブル名、キーボードのフォーカス表示を保つ。未選択時は解除を無効にする。解除は利用先の参照だけを外し、ライブラリーの原画像を削除しない。

共通`RegisteredImagePicker`は画像の登録・検索・選択・確定を担当する。「画像を外す」は入力欄に集約し、選択ダイアログには置かない。未選択の「画像を使う」は無効。取消では呼出元の値を変えず、選択開始ボタンへフォーカスを戻す。一覧のファイル名・検索・寸法は画像の識別用に保持する。公開APIのnullableな戻り値型は互換性のため保持する。

選択中のファイル名と画像サイズのスライダーは上部の同じ行に置く。長いファイル名は省略表示し、ツールチップで全文を確認できる。グループと検索はラベルのすぐ隣に入力欄を置き、狭幅では項目ごとに縦へ並べる。検索エリアの下は全幅の罫線で区切り、サムネイル周囲はダイアログと同じ背景色にする。「ライブラリーに登録」はフッター左側、取消と確定は右側に置き、一覧をスクロールしても操作できる。登録中は共通ボタンの処理中表示を使い、重複実行を防ぐ。

画像一覧は「すべて」で多数の画像を表示するときと同じ高さを常に確保する。グループや検索で絞り込んだ結果が少数・0件でもダイアログのサイズとフッター位置を変えない。高さは画面の46%と520 CSS pxの小さい方を基準とし、画面の高さが変わったときは追従する。「さらに表示」も一覧のスクロール領域内に置き、ボタンの有無で外枠を伸縮させない。

リボングループとコマンドボタンは`RibbonIconPicker`で「画像」「既定のアイコン」をこの順に切り替える。画像モードだけが共通画像入力を表示し、既定モードだけが固定アイコンの一覧を表示する。選択中の既定アイコンは枠とチェックで示す。新規追加は画像モード、既存編集は画像参照の有無から開始モードを決める。編集中の切り替えでは両側の選択を保持し、親ダイアログの適用で確定する。既定モードの適用は`image: null`、画像モードは選択した参照を保存する。画像未選択・解除後の適用は従来どおり固定アイコンへ戻る。親編集の取消は設定を変更しない。モードや非選択側の画像を保存する追加設定は作らない。

新しい画像選択欄でもこの共通入力・選択画面を利用する。既定アイコンの切り替えはリボンの責務とし、一般の画像フィールドにリボン固有の選択肢を持ち込まない。

## Applet API

`minimumHostVersion: "0.69.0"`と`registered-images` capabilityを宣言する。原画像の列挙と選択は信頼されたローカルUIだけが利用でき、リモートサイトへbridgeを渡さない。

| 呼出元   | 操作                                                                  | 契約                                                                                      |
| -------- | --------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| Node     | `context.registeredImages.import({ filename?, base64 })`              | 元bytesを登録して参照を返す。512KiB以下。名前省略時は内容hash名                           |
| Node     | `context.registeredImages.copyToCache(image, variant?)`               | `original`（既定）または`thumbnail`を自己のPC専用imageDirectoryへコピーし、絶対パスを返す |
| .NET     | `context.RegisteredImages.ImportAsync(bytes, filename?, token)`       | Nodeと同じ。SDK 0.27.0                                                                    |
| .NET     | `context.RegisteredImages.CopyToCacheAsync(image, thumbnail?, token)` | `RegisteredImageRef`を使い、既定は原画像                                                  |
| local UI | `appletPage.call('registeredImages.snapshot')`                        | メタデータ・参照・グループ。サムネイル本体は別取得                                        |
| local UI | `appletPage.call('registeredImages.preview', { image })`              | 縮小プレビューを返す                                                                      |
| local UI | `appletPage.call('registeredImages.pick', { current })`               | `{cancelled:true}`または`{cancelled:false,image:ref                                       | null}`。現在の選択UIは参照を返し、nullable型は互換用に保持。解除は呼出元の画像入力で行う |
| local UI | `appletPage.call('registeredImages.import', { filename?, base64 })`   | プログラム登録と同じ上限                                                                  |

`copyToCache`は自己manifestのregistered-image設定、またはobject-list内の同型フィールドが現在参照している画像だけを受け付ける。登録しただけでは読取対象にならず、まず自己設定へ保存する。生成コピーはruntime世代別とし、停止・異常終了・世代変更で回収する。共有原画像は回収しない。古い処理の完了で新世代のコピーを消さない。ページで表示するときは既存の`pages.registerImages`へコピーを渡し、その画像IDの寿命も守る。

登録データはbase64で送り、Node/.NET共通の1MiB JSON-RPC行上限内に収める。ネイティブファイル選択による本体の登録だけが5MiB上限を使う。大きい原画像は利用者が共通選択画面から登録する。APIに任意のホストファイルパスは渡さない。

## 宣言型リボン

`ribbon-items`と`settings` capabilitiesを宣言し、最大16件の`ribbonItems`を定義できる。HTMLや空ページは不要。

```json
{
  "id": "main",
  "title": "プロフィール",
  "action": "settings",
  "icon": "user",
  "imageSetting": "avatar",
  "imageShape": "circle",
  "iconOnly": true,
  "defaultPlacement": "bottom"
}
```

IDはApplet内で安定させる。リボンIDは`applet:<Applet ID>:<id>`。actionは自己設定を開く`settings`だけ。画像設定は自己のregistered-imageフィールドに限定する。画像形状はsquare/circle、配置はtop/bottom。省略時はsquare/top、iconOnlyはfalse。実際の検証は`ribbon-items.ts`を正本とする。

宣言の初期値より保存した親グループと配置・表示設定を優先する。宣言のbottomを利用者がtopへ変えた場合は明示overrideを保存する。無効Appletは実リボンから外し、設定と配置は保持する。設定への入口はruntimeの開始失敗時にも使用できる。名前・tooltip・アクセシブル名は宣言値と利用者のリボン表示名から作り、プロフィールのユーザー名・頭文字を投影しない。

グループ・コマンドボタンの`image`、通常／動的ページの`image`、`ribbon.itemOverrides[id].image`も同じ参照を使う。画像が使えない場合は宣言・設定した固定アイコン、WebAppletでは旧inline iconへ戻る。通常項目の固定アイコンを明示した場合の登録元画像との優先順位は[リボンのアイコン](ribbon-customization-design.md#固定アイコンと登録画像)に従う。外部リボン編集のadd/updateButton、add/updateGroup、updateItemも参照またはnullを受け付ける。

## プロフィール

独立repo [Applet.Profile.at365](../../Applet.Profile.at365/docs/usage.md)の`at365.profile`が名前・アバターの自己設定と宣言型リボンを提供する。本体はこのIDや設定キーを固定参照しない。初期リボンは下寄せ・画像のみ・固定名「プロフィール」。未選択時はuserアイコン。

新規ホスト設定にはtop-levelの`profile`を作らない。旧`profile`は解釈しない値として保存時に保持し、旧`profile`リボンIDも設定内に保持する。新Appletを導入して名前と画像を選び直す。WebAppletの既存`icon`も保持し、`image`を選んだ場合に優先する。

## 検証と追加時の規則

`tests/registered-images.test.cjs`は参照・保存・同名衝突・グループ競合・欠落回復・設定・汎用リボンを検査する。`scripts/image-library-ui-test.cjs [固定EXE]`は独立Profile/WebApplet、Node/.NET API、選択画面、原画像hash、表示、再起動を隔離profileで確認する。先に`tests/fixtures/dotnet/AppDock.RegisteredImages`をRelease publishする。必要な出力場所と実測は[VERIFICATION](../VERIFICATION.md)を参照する。

`scripts/ribbon-customization-ui-test.cjs [固定EXE] --icons-only`は共通画像入力とリボンのモード切替、親・子ダイアログの取消、フォーカス復帰、キーボード、解除と適用、明暗テーマ・画面幅、原画像保持・実再起動後の選択状態を確認する。
