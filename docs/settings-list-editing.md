# 一覧形式の設定編集UI

画面構成、`description`/`hint`の役割、状態・エラーの表示と共通部品の責務は[共通レイアウト指針](settings-ui-guidelines.md)を正本とする。ヒント表示設定の共有と現行APIは[設定基盤](settings-foundation.md#ヒントと一時表示)を参照する。

複数の登録項目を管理する設定画面は、AI接続一覧の「一覧＋追加／編集ダイアログ」を基本形とする。利用者が一覧で内容を見渡し、一つの登録に必要な項目をまとめて確定できる構成へ揃える。本体設定と、独自の設定画面を持つAppletで新規作成・改修する際の共通指針とする。

保存の基本契約は[設定基盤](settings-foundation.md)、AI固有の仕様は[AI文章生成](ai.md)を正本とする。この指針だけを理由に既存画面や公開APIを一括変更しない。

## 適用する場面

| 設定の性質                                               | 基本形                                               |
| -------------------------------------------------------- | ---------------------------------------------------- |
| 名前・接続先・認証など、複数の項目で一つの登録が成立する | 一覧＋追加／編集ダイアログ。OKで登録単位に保存       |
| 独立したON/OFF、共通プロンプト、既定値など               | 通常の項目行。既存の即時保存                         |
| 履歴や実行結果など、閲覧が目的                           | 閲覧用の一覧。編集操作は必要なものだけ               |
| ショートカット、ジェスチャーなど固有の操作契約がある     | 共通の見た目とダイアログ基盤を利用し、固有仕様を保持 |

ページ全体の保存／破棄、共有ドラフト、未保存通知は設けない。登録を編集中の一時入力だけを、そのダイアログ内に保持する。単純な設定まで一律にダイアログへ移さない。

## 一覧と操作の配置

ヘッダーは32pxの操作領域と上下6pxの余白を共通にし、ボタンのある表もない表もコンパクトな高さへ揃える。複数行の見出しは内容に合わせて伸ばす。ヘッダーの追加ボタンは32px角の枠なし・アクセント色とし、hoverは淡い背景、キーボードfocusは共通のoutlineで示す。本文の追加ボタンの表示には適用しない。

テーブルの描画は`SettingsTable`を共通の土台とし、背景・ヘッダー・セルの余白・罫線・末尾行を一元管理する。通知、Webアカウント、Applet管理、AI、MCPクライアント、カスタムコマンドとAppletの宣言型一覧は`SettingsListLayout`/`SettingsListTable`を通して利用する。ショートカットとマウス・タッチパッドジェスチャーは`CommandBindingList`内、操作の許可は専用フォーム内で同じ土台を使う。複数割り当てのrowSpan・操作行、許可の狭幅表示、保存・競合検査は各機能に残す。

Applet管理も宣言型一覧と同じ`SettingsListLayout`で枠・テーブル・フィルターの追従・横スクロールを構成する。名前列の追加は共通`SettingsListAddButton`、ヘッダーと操作列は共通クラスを使い、操作列内は左揃えにする。バージョン・稼働状態・更新・再起動・削除・設定への移動は既存の専用セルに保持する。固有の列幅と内容の表示だけをApplet管理側で定義し、表全体の余白や操作配置は共通部品へ任せる。

- 既存の設定ページ・セクションの中に一覧を置く。上位ページのタイトルや説明を一覧内へ重ねて表示しない。
- 追加操作は一覧ヘッダーの名前・サーバー名の横に「＋」を置く。AI・カスタムコマンド・MCPクライアントは共通の`SettingsListAddButton`を使い、名前と同じ行の`settings-list-heading`へ配置する。`SettingsListTable`では`addInTitle`で選択する。件数は共通`CommandListSummary`で一覧上部の右端へ配置する。Appletの宣言型一覧（WebAppletの登録サイト・初期ショートカット、WallpaperSlideshowのモニターごとの画像設定など）でも同じ部品を使い、上部の追加・順番変更ボタンは左側へ揃える。スクロール追従の有無で配置を変えず、狭幅では共通の折り返しで操作と件数を保つ。ヘッダー内の順番変更は画面別の規定に従う。既存の他の一覧は、この指針だけを理由に一括変更しない。
- 行の主情報は名前と用途の判別に必要な値に絞る。補足は一段下へ控えめに表示する。詳細設定の全項目や秘密値を一覧へ並べない。
- 編集は歯車、削除はゴミ箱を基本にする。通常は右端を操作列とし、別画面への移動を持つ一覧では操作の右隣を「移動」列とする。Appletの宣言型一覧では`SettingsListTable actionsAlign="start"`を使い、操作列の位置を保ちながらヘッダーとセル内のボタンを左揃えにする。アイコンだけでも対象と動作が分かるアクセシブルな名前を付ける。例：「接続名を編集」。
- 一覧の操作・移動ボタンは共通の`settings-list-icon`を使う。32px角、7pxの角丸を保ち、通常は背景と枠線を透明にして`--text`のアイコンだけを表示する。hover/キーボードのfocus-visible時に共通の枠線と`--panel`の背景（ライトモードでは白背景）を表示する。割り当てがある場合は`accent-action`のアイコン色で示し、通常時の背景と枠線は透明のままにする。そのhover/focus-visible時は共通のアクセント背景・枠線・前景色を同時に切り替える。枠線の幅は透明時も確保し、状態変化でサイズや配置を変えない。リボン・トレイ・割り当て・カスタムコマンド・AI・MCPの一覧で個別に寸法や通常色を上書きしない。移動・編集・削除という操作の種類だけではアクセント色にしない。追加の＋や更新確認など用途の異なるボタンは、既存の共通部品の寸法を保つ。
- 一覧アイコンのhover/focusには明るさのfilterを重ねず、共通の枠色・背景・前景色をそのまま表示する。ライトモードの淡い枠が明るさ補正で白く消えることを防ぐ。
- 行ごとの有効切り替えに前提がある一覧では、`SettingsListTable.canToggle`で対象のスイッチだけを非活性にする。未設定のMCP接続先のように切り替えられない行でも、編集・削除を一覧全体のbusyへ巻き込まない。接続確認と警告の扱いは[共通MCPクライアント](mcp-client-design.md#保存と設定ui)を参照する。
- 空の一覧にも追加ボタンと簡潔な案内を表示する。並べ替える項目が足りない場合などは、該当する操作だけを無効にする。
- ショートカット／ジェスチャーと同じ表の余白、罫線、行背景、操作ボタンの寸法を使う。AI一覧を具体例にし、列幅だけを対象に合わせる。
- 操作列の寄せ方は共通SettingsListLayoutの`actionsAlign`で指定する。既定は右寄せ、Webアカウント・Applet管理・AI・MCPクライアントは`start`としてヘッダーと行内の操作を左寄せに揃える。
- 行の識別には安定したIDを使う。名前や表示順の変更で別の登録として作り直さない。

名前だけを直接編集するWebアカウント一覧は、既存のblur/Enter確定・Escape取消を保つ。共通の`SettingsListLayout`へツールバーと表の内容を渡し、`SettingsListTable`と同じ枠・罫線・余白・横スクロールを使う。複合登録の追加・編集ダイアログを単純な名前変更へ強制しない。折り返しが必要な使用先等は共通の`settings-list-wrap`セルで表示する。

ショートカット・マウスジェスチャー・タッチパッドジェスチャー・カスタムコマンドの右端には「移動」列を置き、共通のキーボード・マウス・タッチパッド・コマンド画面のアイコンを並べる。移動先はコマンドIDの完全一致で絞り込み、解除ボタンで全体へ戻す。通常のインデックス選択でも解除する。登録済みのカスタムコマンド以外はカスタムコマンドへの移動ボタンを非表示とし、空の登録を自動作成しない。対象と移動要求はrenderer内の一時状態とし、設定や実行条件へ保存しない。

Applet・コマンド・キー・ジェスチャーの一時フィルターは、対象名と×をひとまとまりにして集計行へ置き、件数を同じ行の右端へ揃える。検索がある画面では検索欄の下の行とする。ショートカット・マウス/タッチパッドジェスチャー・カスタムコマンドのフィルターには順序変更ボタンを置かず、割り当て単位の実行順は各行の操作から変更する。`CommandListSummary`を共用し、32pxの一時フィルターと上下paddingを含めて通常時から48px以上の集計行を確保し、表示/解除で高さを変えない。長い対象名は一行の省略表示と全文tooltipにし、解除操作を枠内へ保つ。共通の`--accent-soft`背景・アクセント枠・`--accent`文字を使い、×のhover/focus-visibleでは`--accent-hover`と`--accent-text`を組にする。Appletとコマンドの対象表示を重ねず、コマンド対象を解除した後は残っている提供元条件を表示する。カスタムコマンドは`SettingsListTable.toolbarFilter`へ対象を渡し、`commandListScroll`時の件数行を共通の固定ツールバーへ含める。検索・一時フィルターの解除範囲は変更しない。

移動列には現在の設定ページを除く最大3画面のアイコンを表示する。ショートカット・ジェスチャー・カスタムコマンドの移動アイコン、カスタムコマンドの操作アイコンはセル内で左寄せにする。ショートカット/ジェスチャーの移動列は、最大3つのボタン幅・間隔・セル左右のpaddingを合算して確保する。狭幅やボタンが少ない行でも、セル左右の余白を保ち、ボタンを表の枠へ接触させない。

ショートカット/ジェスチャー一覧は「コマンド・割り当て・操作・移動」の順に表示する。割り当てごとに表の行を作り、コマンドと移動先のセルは同じコマンドの行全体で共有する。「操作」列には鉛筆の編集・既存の実行順・ゴミ箱の削除をこの順に直接並べ、その他メニューは設けない。キーや条件が折り返しても対応する操作との行を揃える。操作列は3つの32px角ボタン・間隔・セル左右のpaddingを確保し、狭い画面では一覧内を横スクロールさせる。Applet詳細の共通一覧にも操作列を使うが、移動先がなければ移動列を省く。コマンドトリガーの統合一覧では、条件の右に歯車と削除を並べ、同じトリガー編集を開く鉛筆は省く。歯車の複数コマンド表示・フォーカス復帰は共通一覧の動作を保つ。

コマンドセルは、提供元マーク・名前・説明アイコン・非公開マークを横に並べ、その下にコマンドIDを置く基本2行とする。外部非公開コマンドだけに南京錠を表示し、公開コマンドと公開状態が不明な保存済みコマンドには付けない。説明のないコマンドには説明アイコンを付けず、利用不可などの状態は常時表示を保つ。長い提供元はマーク内で省略し、全文をtooltipで確認できる。`at365.*`の提供元名は表示上の先頭`Applet.`・末尾`.at365`をマーク内で省き、名前・ID・検索対象は変更しない。長いコマンド名と複数割り当てに必要な高さは残し、行の上下余白は8pxとする。[コマンドトリガー](command-triggers.md)の統合一覧では、コマンド名・IDの右横に追加ボタンを縦に並べ、コマンド内の割り当て間だけ余白を詰める。

提供元のマークは、所有元の安定IDがある場合にその提供元へ一時的に絞るボタンとする。AppDockは所有元null、未知コマンドの所有元undefinedは絞り込みボタンにしない。選択すると検索文字・登録状態・入力/コマンド対象の一時フィルターを解除して提供元を適用し、共通の解除可能な提供元フィルターを表示する。入力マークでの絞り込みは提供元を置き換える。解除後は元のマーク、消えている場合は検索欄へフォーカスを戻す。ページを離れたときに破棄し、設定や表示名の保存を行わない。

説明アイコンは共通`SettingsDescriptionIcon`を使い、マウスのhover・クリック・キーボードのfocusで説明を表示する。Escapeや外側操作で閉じ、長文・改行とスクロール枠外での表示を共通popoverに任せる。任意の設定ヒントとは別の情報なので「ヒントを表示」がOFFでも残す。

割り当てと操作のセルは上下8pxの余白にし、32px角のボタンを保ちながら複数の割り当てをコンパクトに並べる。同じコマンド内の割り当て間には区切り線を設けず、コマンド間の罫線は残す。コマンド/移動先の共有セルと左右の余白は保持し、長い条件が折り返す場合は内容に応じて行の高さを広げる。キー/ジェスチャーのマークは通常、明暗テーマとも本文と同じ`--text`の文字色を使う。入力で絞り込めるマークのうち、異なるコマンドIDが2つ以上登録された入力だけを`--accent`で示す。

行の実行順ボタンは、同じ入力に異なるコマンドIDが2つ以上登録されていればアクセント色にする。検索・提供元・対象の絞り込み前の全保存済み割り当てを参照し、同じコマンドの条件違いだけでは色を変えない。キーの同一性は実行順ダイアログと同じ正規化、ジェスチャーは保存済みのジェスチャーIDで判定する。無効・利用できないコマンド・ジェスチャー機能OFFでも登録として数える。ツールチップと読み上げでも複数のコマンドがあることを示し、追加・変更・削除・外部更新後に再計算する。

本体設定のショートカット／マウスジェスチャー／タッチパッドジェスチャー／カスタムコマンドは、外側のカードと「割り当て」「登録済みコマンド」の見出しを設けず、フィルターと一覧をページ直下に並べる。行数に応じて一覧を自然な高さへ伸ばし、ページタイトル・説明・フォーム/JSON等の上部操作欄も含めた外側の表示枠に縦スクロールを集約する。横スクロールはテーブルだけに適用し、表示枠の下端に置く共通の横バーと双方向に連動させる。横方向に収まる場合は横バーを隠し、必要な場合は12pxの標準スクロールバーと共通の中立色を使う。検索・件数・対象解除は横スクロールさせず、フィルターのまとまりは表示枠の上端へ到達したら一覧の範囲内で固定する。背景はページの背景色に揃え、固定中に後ろの文字が透けて重ならないようにする。カスタムコマンドへ新しい検索・絞り込み機能は追加しない。

`SettingsPageLayout`が全設定ページのフォーム/JSONとApplet設定のヘッダー・本文を同じ`.settings-body.settings-page-scroll`へ収め、`CommandListScrollProvider`と`CommandListScrollbar`で横バーの配置・寿命を管理する。対象のテーブルは`useCommandListScroll`で登録する。外側のまとまりは枠と見出しを持たない`CommandListSection`を使い、検索アンカー・アクセシブルな名前・必要な状態説明を保つ。`CommandBindingList`は共通の登録を使い、カスタムコマンドは`SettingsListTable.commandListScroll`を明示して利用する。フィルターを追加する際はテーブルの横スクロール枠の外で`CommandListToolbar`へまとめ、背景・重なり順・スクロール余白を共通部品へ任せる。リサイズ、検索結果、行の増減、ページ／JSON表示の切り替えに追従し、ダイアログの終了時は外側の縦位置・表の横位置・元の操作へのフォーカスを保つ。

[コマンドトリガー](command-triggers.md)のフォームだけは、`CommandListScrollProvider.pageScroll`で本文を縦横共通のスクロール枠として登録する。共通キャンバスの中で見出し・操作・状態・フィルターを表示幅の横stickyにし、コマンドはセル内の縦stickyにする。共通の下端バーは本文へ接続し、JSONと他の一覧では従来のテーブルを登録する。

Applet管理のフォームも上部ヘッダーを含めた外側の縦スクロールを使い、検索・件数を同じ`CommandListToolbar`で固定する。固定フィルターパネルに下端罫線は付けない。導入可否や検出の説明は固定領域の外へ置く。Applet一覧の横スクロールも共通の下端バーへ接続する。全設定ページのタイトルと上部操作も本文と一緒にスクロールする。

Applet管理・AI・MCPクライアントの順番変更ボタンは、一覧の名前列ヘッダーで追加ボタンの直後へ配置する。件数・フィルター領域へ同じ操作を重ねない。名前とヘッダー操作は折り返さず、セル内へ収める。AI一覧の列幅は内容に応じて配分する。宣言型の`SettingsListTable`では`addInTitle`と`orderInTitle`を指定するとこの配置を使い、未指定の一覧は既存の操作位置を保つ。`onOrder`を省略した一覧には順番変更ボタンを表示しない。Webアカウントの使用中・削除・クリアに関する説明はページ最上部の説明文へまとめ、一覧の上へ重ねて表示しない。

ショートカット/ジェスチャーの割り当てが1件以上ある移動先は共通の`accent-action`で示し、ツールチップと読み上げでも割り当ての存在を伝える。本体が現在の保存値から重複を除いたコマンドIDだけを補助モデルへ投影し、ほかのページのキー・ジェスチャー・条件を渡さない。ID完全一致で判定し、無効な割り当てやジェスチャー機能OFFでも「登録がある」と扱う。追加・削除・外部編集後は最新モデルで更新する。操作の利用可否や外部公開の有無を表す色にはしない。

この3項目のインデックスにも同じ共通アイコンを右寄せで表示する。カスタムコマンドはGoogle Material DesignのKeyboard Command Keyを共通SVGで描画し、文字フォントに依存させない。公式の図形を保ち、色は`currentColor`を参照する。出典と同梱ライセンスは[Material Design icons](../assets/material-design-icons-LICENSE.txt)を参照する。公開コマンドはタイトル横に共通の地球アイコンを付ける。本体の外部公開コマンドカタログから解決し、IDや保存済みのONだけで公開可否を推測しない。アイコンは公開の有無を示し、実行権限・現在の利用可否とは分ける。

追加・編集の完了後は、一覧の検索・選択・スクロール位置を保つ。追加行への自動スクロールや自動フォーカス移動を行わず、元の操作ボタンへフォーカスを戻す。削除等で元のボタンが消えた場合は、追加ボタン等の安定した操作へ戻す。

設定インデックスのApplet管理には共通の`extensions`、通知には共通の`bell`アイコンを右寄せで表示する。リボングループの既定アイコンと同じ`shared/ui-icons`を参照し、選択状態・色・寸法・余白を既存のインデックスアイコンへ揃える。

## 入力マークによる絞り込み

本体設定のショートカットキー/マウスジェスチャー一覧では、割り当てマークをクリック、Enter、Spaceで操作すると、その入力が登録されたコマンドだけを表示する。キーは実行順と同じ正規化後の完全一致、ジェスチャーは保存済みIDの完全一致とし、`F1`に`F10`を含めない。選択したコマンドの他の割り当ても表示して別の入力へ切り替えられるようにする。

選択時はApplet/コマンドの対象、文字検索、状態フィルターを解除し、別Appletを含む同じ入力の割り当てを探せるようにする。上部には共通の対象ラベルを使って「キー: F1」「ジェスチャー: ↑ 上」と解除ボタンを表示する。その後の文字検索・状態選択は入力フィルターと組み合わせる。ラベルの×は入力条件だけ、「絞り込みを解除」は入力・文字・状態の条件を解除する。元のApplet/コマンドの対象には戻さない。外部の入口から新しい対象が指定されたら、入力条件を解除してその対象を表示する。

複数コマンドのマークの色は実行順ボタンと同じ、絞り込み前の全保存済み割り当てから判定する。同一コマンドの条件違いだけでは色を変えない。色に加えてツールチップと読み上げで複数登録を伝え、選択中は`aria-pressed`で示す。無効・利用不能な登録も含め、編集・削除・外部更新へ追従する。該当コマンドがなくなっても解除操作を残す。解除時は操作元のマークへ、マークが削除されていれば検索欄へフォーカスを戻す。

入力フィルターは画面内だけの状態とし、設定保存・コマンド実行・Appletの有効化を行わない。共有の`useBindingCommandFilter`、`CommandBindingToolbar`、`CommandBindingList`を使い、入力方式別の正規化だけを各画面から渡す。

## 追加と編集は同じダイアログ

追加と編集で同じフォーム部品を使い、タイトル・初期値・確定時の操作を切り替える。主要な入力を最初から表示し、利用頻度の低い詳細設定は折りたたむ。種類によって必要な項目や初期値が変わる場合も、利用者が入力した値を不用意に消さない。

共通の`SettingsDialog`を使い、タイトルと閉じる操作、スクロールする本文、キャンセルとOKのフッターを揃える。入力エラーや詳細設定の展開で、押そうとしているOKや取得ボタンが大きく動かない配置にする。狭い画面でもフッターへ到達できる高さに制限する。

### エラーで位置を変えないダイアログ

エラー領域の配置、対象との対応付け、入力やフッターの位置の安定、全文を確認する方法は[共通レイアウト指針のエラー表示](settings-ui-guidelines.md#エラー表示)に従う。現行APIと共通部品側の対応対象は[設定基盤](settings-foundation.md#共通レイアウト指針との対応)を参照する。入力の`aria-invalid`と境界色を使い、境界の太さや周囲の余白は変えない。

通常の`onApply`失敗は共通部品が表示し、入力を保持する。準備・検証だけを中止できる処理は、その間だけ`cancelWhilePending`を有効にしてよい。呼出元は閉鎖時の取消と、遅い応答を適用しない検査を所有する。保存・配置交換へ移った後は閉鎖を禁止し、既存のトランザクションを使う。

### 一時入力と保存

1. 開く時点の対象を複製し、変更前の値と一時入力を分けて保持する。追加では一覧へ空の登録を先に保存しない。
2. 入力・補正・候補取得は一時入力だけを変更する。`settings.json`や関連する秘密値ファイルへは書き込まない。
3. OKで登録全体を検証し、保存側へ一つの操作として渡す。保存側でも入力と競合を検証する。
4. 保存成功時だけ閉じ、最新の保存値から一覧を更新する。保存中は二重送信と閉鎖を防ぐ。
5. 入力不正・通信失敗・保存失敗では、入力と原因の説明をダイアログ内に残す。キャンセル・Escape・画面破棄では一時入力を破棄する。

保存側は対象の変更前の値やrevisionを照合し、最新の設定へ対象の変更だけを合成する。古い一覧全体で上書きしない。同じ対象が外部から更新・削除されていたら競合として扱い、勝手に上書き・再作成しない。設定と関連ファイルを同時に更新する場合は、既存のトランザクションと失敗時の復旧を使う。

### 入力確定と接続確認

- URLには`SettingsUrlInput`を使い、入力途中の`:`や`/`を保持する。補正と検証はEnterまたはblurで行う。ダイアログ内の確定は一時入力の更新であり、保存ではない。
- 接続確認や候補取得は明示操作にする。AIの例ではURL／APIキーのEnterとモデル横の取得ボタンで候補を取得し、blurでは補正だけを行う。
- Enterの意味を項目ごとに定め、取得用のEnterでダイアログ全体を保存しない。文字欄に未確定の変更があればEscapeでその欄を戻してダイアログを保ち、変更がないEscapeでダイアログを取り消す。複数行はEnterで確定・Shift+Enterで改行し、IME変換中のEnterやEscapeを確定・閉鎖と誤認しない。
- 未保存値での接続確認は、取得結果だけを表示する。自動保存・自動生成・失敗後の自動再試行を混ぜない。候補一覧が使えない場合も、対象の仕様が許すなら手入力を残す。
- 通信中の状態とエラーを対象の近くへ表示する。入力変更後・閉鎖後の古い結果を採用せず、取消は要求ID等で対象を限定する。

## 通知種類の編集

通知設定は「通知名／通知先／表示時間／読み上げ／MCP Events／編集」の一つのテーブルを使う。通知名の提供元マークと説明ヒントで種類を識別し、必須の通知先・固定の表示時間・停止中や前提不足の状態はヒントに隠さない。鉛筆で共通ダイアログを開き、OKで通知種類単位に保存する。既定値の継承と明示値を区別し、変更のないOKで既定値を固定しない。保存側では提供元と種類ID、元の上書き値、通知仕様を確認し、他の通知や共通読み上げ設定を保持する。通知種類自体の追加／削除や有効／無効の列は設けず、利用できない種類に残った設定の削除操作は従来どおり保持する。

## 削除と並べ替え

登録内容をまとめて失う削除では確認ダイアログを基本とし、対象名と実際の影響を示す。確定ボタンは「削除」など結果が明確な文言にする。キャンセルでは変更せず、失敗時は確認画面にエラーを残す。関連データや既定項目への影響は、保存側の一つの操作として処理する。

Webアカウント設定の枠削除とログイン情報のクリアも共通`SettingsDialog`で確認する。確定時は確認した枠のID・名前・提供元をホストで再照合し、削除では現在のページ参照も再確認する。対象の変更や処理失敗はダイアログ内へ表示して再確認できるようにする。クリアでは名簿を残し、削除では対象枠だけを外す。設定画面での確認後にネイティブ確認を重ねない。Applet APIなど、確認済みの枠を渡さない従来の呼出しではネイティブ確認を継続する。

ショートカット／マウス・タッチパッドジェスチャーの割り当て削除は、共通`SettingsDialog`で対象名・入力・条件を示して確認する。取消では保存せず、削除確定時に対象の安定IDと内容・編集可否を再確認してから即時保存する。確認中に対象が変更・削除された場合はエラーを表示し、最新の対象を確認し直す。コマンド本体や他の割り当ては削除しない。カスタムコマンド本体の削除も既存の確認を経て保存し、その割り当ては保持する。

並べ替えは専用ダイアログへ対象の一覧を表示し、行（文字・番号・ハンドル）のドラッグまたはハンドルへフォーカス中の↑↓キーで移動する。上下ボタンは設けず、移動後も同じ項目のハンドルへのフォーカスと表示位置を保ち、移動結果が分かる案内を付ける。修飾キー併用・IME変換中はキーで並べ替えない。保存中のドラッグは拒否する。移動中はローカルの順序だけを変更し、OKで確定、キャンセルで破棄する。Applet管理・AI・MCPクライアントなどの表示順ダイアログで共通の操作とする。

「トリガーの設定」も同じ操作で実行順を変更し、実行方法と順序をまとめて適用する。詳細は[トリガーの設定](command-triggers.md#トリガーの設定)を参照する。

表示順・実行順の行は共通の枠なしレイアウトにし、通常40px以上の高さと32px角のハンドルを確保する。名前と判別に必要な補足を横に並べ、コマンドIDは表示しない。長い名前・補足は1行で省略し、tooltipで全文を確認できるようにする。無効・利用不可の状態は常時表示する。狭い画面では名前と補足を縦に配置する。保存ID・競合検査・ドラッグ・キーボード操作は表示方法から独立させる。

表示順・実行順・優先度のどれを変えるかを明記する。AI接続は表示順だけで、生成の優先度にはしない。保存時は元のID列と変更後のID列を検証し、追加・削除・別の並べ替えとの競合を検出する。順序だけを最新の登録内容へ適用し、並べ替え中に更新された別の項目を古い値へ戻さない。

## ダイアログを追加する

開くボタンの所在と、ダイアログを描画する場所を分けて決める。リボンやタイトルバーが入口でも、本体の設定を編集するダイアログは本体rendererに表示する。ダイアログ自体の描画をShellへ提供させる場合は、[共通オーバーレイ](shell-overlays.md)の表示モデル・操作・寿命の契約を使う。

### 共通部品の選び方

| 用途                                    | 使用する部品・経路                            | 呼出側が用意するもの                                             |
| --------------------------------------- | --------------------------------------------- | ---------------------------------------------------------------- |
| 通常の追加・編集・削除確認              | `SettingsDialog`                              | タイトル、一時入力、検証、保存処理、閉じる処理                   |
| キー記録など独自の本文・フッターが必要  | `SettingsModal`                               | 見出しと`labelledBy`、本文・ボタン、初期フォーカス、処理中の制御 |
| 設定以外の本体内プレビュー等            | 本体documentの`<dialog>`を`showModal()`で開く | ラベル、初期フォーカス、Escape・取消・復帰、必要な入力停止       |
| パレットのように描画をShellへ差し替える | `OverlayController`と`OverlayHost`            | 内容別モデル・操作・取消。新しい種類は公開契約と描画側も追加     |

`SettingsDialog`と`SettingsModal`は[SettingsControlsProvider](../src/renderer/settings-ui/api.tsx)の配下で使用する。本体のルートと設定ページは既に接続している。別のSurfaceや試験へ持ち出す場合は、そのSurfaceで許可された`SettingsControlsApi`を注入する。ShellのHTMLへ本体用部品や`window.dock`を持ち込まない。

### SettingsDialogの使用例

以下は`src/renderer/settings/`に置く部品の例。親は開く間だけmountし、`onClose`でunmountする。別の登録へ切り替えるときは対象IDで`key`を分け、一時入力を取り違えないようにする。

```tsx
import { useState } from 'react';
import { SettingsDialog } from '../settings-ui/SettingsModal';
import { SettingsInput } from '../settings-ui/SettingsInput';
import { SettingsField } from '../settings-ui/SettingsSections';

export function ItemNameDialog({
  original,
  onSave,
  onClose,
}: {
  original: string;
  onSave(name: string): Promise<unknown>;
  onClose(): void;
}) {
  const [name, setName] = useState(original);
  return (
    <SettingsDialog
      title="名前を編集"
      valid={name.trim().length > 0}
      onApply={() => onSave(name.trim())}
      onClose={onClose}
    >
      <SettingsField title="名前">
        <SettingsInput
          aria-label="名前"
          data-initial-focus
          value={name}
          onChange={(event) => setName(event.currentTarget.value)}
        />
      </SettingsField>
    </SettingsDialog>
  );
}
```

`onSave`は機能側の既存の検証・競合検査・保存操作に接続する。上の`name`はローカルの一時入力であり、入力ごとの永続保存は行わない。保存失敗はrejectまたはthrowで返す。`SettingsDialog`がエラーを表示して入力を保持し、成功時だけ`onClose`を呼ぶため、呼出側で先に閉じない。`valid`は画面の確定可否であり、保存側の再検証も必要になる。

設定ページの発行済みアクションを`invoke`して失敗した場合は、その呼出元のダイアログや操作欄がエラー表示を所有する。共通の`SettingsPageSession`は呼出元へ失敗を返し、裏のページのエラーや「設定を再読み込み」へ重複表示しない。ページ遷移・JSON/フォーム編集・不正なアクションIDなど、ページ操作自体の失敗は従来どおりページに表示する。

`SettingsDialog`はnative dialogの開始、見出し、本文とフッター、保存中の二重送信・閉鎖防止を扱う。`applyLabel`で「追加」「削除」等を指定できる。`children`に`(ready, setError) => ...`を渡すと入力受付の準備状態とエラー表示口を利用できる。この`ready`はショートカット等の入力停止の準備であり、背景のぼかしには待機を設けない。

入力停止・再開は、既存の入力確定キューを待ったうえで専用の一時操作を送る。現在の設定ページ・session・発行済みの`setShortcutRecording`アクションIDを本体で照合し、利用可能なページの入力制御だけを実行する。設定モデル全体の再取得・再構築・rendererへの返却は行わない。ショートカットとジェスチャーの停止・復帰処理は共通の入力管理を使う。専用操作に対応しない接続では従来のアクション経路を使う。

設定ページからのコマンド選択も同じ一時操作の照合へ接続する。開始・取消・結果の返却だけでは設定ページの表示モデルを作り直さない。親ダイアログの一時入力と、選択後の登録単位での保存・競合検査は呼出側に残す。入力確定キューを待ち、選択待ちではそのキューを占有しない。

`resetAction={{ label, onClick }}`を渡すと、左下に共通の復元ボタンを配置できる。受付準備前と保存中は共通部品で無効にする。onClickは対象機能のダイアログ内の一時入力だけを更新し、適用時の既存保存へ接続する。復元対象を明示したラベルを使い、他の項目や保存データを直接変更しない。

`SettingsModal`を直接使う場合は、見出しIDを`labelledBy`へ渡し、見出し・操作は`header`/`footer`スロットへ渡す。本文のスクロール領域と常設エラー領域は共通部品が配置する。エラーは`error`と`errorTarget`、処理中は`busy`へ渡す。`SettingsDialog`も同じエラーの受け渡し口を持ち、項目固有のエラーは`SettingsField.error`で関連付ける。初期フォーカスは`data-initial-focus`または`initialFocus`で指定し、`onReady`で入力受付を制御し、準備失敗は`onError`へ接続する。非同期処理中は`closeDisabled`と`SettingsButton.pending`・処理側の重複防止を揃える。同じ本体documentの開く前の要素へフォーカスを戻し、その要素が削除された場合は`data-dialog-focus-fallback`を付けた安定した操作へ戻す。

### 描画順と背景の管理

`SettingsModal`はページ本文の矩形内にダイアログ本体と`::backdrop`を収める。本体では`.shell > main`の位置・寸法を使用し、リサイズとzoom変更へ追従する。ローカルAppletなど独立したdocumentではそのviewportを使う。個別ダイアログの高さ上限には`--dialog-max-height`を指定し、本文範囲を超えるmax-heightで共通制約を上書きしない。

背景色は透明で、表示設定の「ダイアログ・パレットの背景」に従う。既定値は「透明」で、「ブラー」を選ぶと本文だけに2pxのぼかしをかける。画像プレビューも同じ設定を使う。リボン・タイトルバー・ステータスバーは撮影・画像化・非表示・再生成をせず、そのまま操作できる。`HostModalLayer`は本体ダイアログの有無を管理するだけで、Shell Viewの描画順や操作可否を変更しない。本体preloadは`dialog:modal`を監視する。画像の取得・転送・decode、準備完了待ち、準備中の透明化は行わない。

`closeOnBackdrop`は既定で無効。OK・キャンセルなどの確定操作がある編集・確認・並べ替えダイアログは、背景クリックで閉じず、一時入力を保持する。閉じる操作だけのプレビューでは明示的に有効にし、本文の背景で押して背景で離したクリックだけで閉じる。ボタンの表示文言やDOM構成から自動判定しない。ダイアログ内の余白、内側から背景へのドラッグでは閉じない。`closeDisabled`中は背景クリックとEscapeで閉じない。入力の一時状態・保存失敗・二重確定防止・IMEのEscape・閉鎖時のフォーカス復帰は共通部品を使う。リボン等で本体の表示先が変わった場合は、元の本体ダイアログを閉じる。ダイアログからのコマンド選択では、パレットの開始・終了だけで親を閉じず、一時入力と選択結果を保持する。取消を保存として扱わない。

コマンドパレットは共通`OverlayHost`で本文の矩形だけに表示する。背景色は透明とし、同じ表示設定に従う。薄いぼかしを選んだときは、別WebContentsのApplet本文にも一時的なCSSを適用し、閉鎖・移動・再読込時に除去する。下のページのWebContents、session、入力状態を保持し、ページへのスクリプト注入や撮影を行わない。画像選択をローカルAppletの別Windowから本体へ委譲する既存処理は、別Windowの入力管理とともに独立した契約を維持する。

### Shellからダイアログを開く

リボン・タイトルバー・ステータスバーは本体と別のWebContentsViewである。開くボタンがこれらのShellにあっても、本体内ダイアログは次の経路へ揃える。

1. Shellが公開モデルの操作IDを`invoke`で本体へ渡す。本体で接続元・提供元・session・ready・現在の利用可否を検査する。二重要求は既存のrequestId契約で扱う。
2. 本体の内容Controllerまたは機能側の所有者が、表示対象・一時入力・完了・取消を管理する。現在のrouteと表示中のnative Viewを確認し、本体の設定Surfaceへ移るか、他の背景Viewも含む表示経路を用意して、本体rendererへ表示を依頼する。Shell Hostへ設定保存などの内容判断を追加しない。
3. 本体のWebContentsへフォーカスを渡し、共通ダイアログをmountする。DOM要素への`focus()`と、別WebContents間のフォーカス移動を分けて扱う。
4. ダイアログと背景は本文範囲内へ収め、呼出元を含むShell Viewの表示・操作を維持する。Shellを撮影・非表示・再生成しない。
5. 閉じたら、元のroute・Windowのフォーカス・呼出元の提供元／sessionと表示可否を確認して戻す。同じShellの元のボタンが残っていればそこへ戻す。提供元の交代・停止やroute変更があれば、現在有効な本体側の操作へ戻し、古いViewへフォーカスしない。

`SettingsModal`が覚える復帰先は本体document内の要素であり、Shell内のボタンは自動では記憶しない。Shellを入口にする新しい操作では、機能側の要求に戻り先の識別を持ち、閉じた後に有効なShellへフォーカスを渡して描画側で元のボタンへ戻す接続を追加する。既存の`focusHost(before/after)`と`onFocus(first/last)`はTab境界用なので、それだけで任意のボタンへの復帰が完成したとは扱わない。

現在、リボンは[Shell API](shell-api.md)の操作カタログ、両バーは[バーの公開契約](shell-bars.md)に定義された操作だけを受け付ける。任意の編集ダイアログを開く汎用APIはまだない。新しい入口では表示モデル・操作契約・本体側の表示要求と終了通知を追加する。`executeCommand`も自Appletの利用可能な自己コマンドに限定され、本体の任意ダイアログを開く迂回路にはしない。パレットは既存の専用オーバーレイ経路を使用する。

ShellのHTML内で`showModal()`しても、そのViewの小さな描画範囲に限定され、本体preloadの監視対象にはならない。本体全体を覆うためにShellのViewを独自に拡張したり、Shell自身のDOMから本体のDOMを操作したりせず、表示の所有者を上記の本体内ダイアログか共通オーバーレイに定める。

### Appletの宣言型一覧

Appletでは[Applet設定の公開契約](extensions.md#共通の設定ページ)を確認する。`object-list`に`list`を宣言すると、本体が共通の一覧・追加/編集・削除確認・並べ替えダイアログを自動生成する。既存の`list`未指定の表示は維持する。WebAppletの管理ページも同じ`SettingsListTable`を利用する。

## Shellで並べ替えを再利用する

`src/renderer/settings-ui/SettingsOrderDialog.tsx`は、Applet管理・AIサーバー・MCPクライアント・画像ライブラリー・宣言型オブジェクトリストで共有する並べ替え部品。`items`にダイアログ内で一意かつ不変の`id`、表示用`title`、任意の`description`を渡し、`title`と`listLabel`で対象を示す。選択肢は保存値ではなく一覧と同じ表示名へ変換して渡す。

`onApply(orderedIds, originalIds)`が成功したときだけ閉じる。保存・入力検証・競合判定は呼び出し側が所有する。オブジェクトリストは開始時のスナップショット内のindexを一時IDに使い、既存の一覧全体の競合判定を保持する。移動途中にpropsを更新しても編集中の順序を置換しない。取消・Escapeで破棄し、保存中のボタン・ドラッグ移動を抑止する。

別Shellでは既存の`configureSettingsControls`へ公開APIのadapterを設定し、共通`controls.css`とテーマ変数を読み込んで使う。本体rendererの内部実装や`settings.css`への依存はない。行、ハンドル、番号、補足、↑↓キーの操作、移動案内、狭幅の配置を共通化する。`SettingsOrderDialog`と`BindingOrderDialog`は共通の`OrderDialogFrame`を使う。幅760px（画面幅から32pxを除いた幅が上限）、通常24px／720px以下で18pxの内側余白、同じテーマ色・見出し・操作欄を適用する。本文では一覧だけを縮めてスクロールさせ、見出し・補足・操作欄を保持する。同一Surface内の表示寿命は`SettingsModal`が担う。

`OrderDialogFrame`は見た目だけを共有するテンプレート。タイトル・任意の補助見出し・本文・フッター文言・エラー・処理中状態・適用可否を受け取り、保存や順序の意味を判断しない。ショートカット／ジェスチャー側は対象選択、条件説明、複数グループの一時編集、変更件数、既存の同期的な適用・競合検出を維持する。表示順側は非同期保存、二重送信防止、保存中の入力停止、失敗時の順序保持を維持する。

## Appletの一覧宣言

`minimumHostVersion: "0.45.0"`以上が必要。例:

```json
{
  "key": "items",
  "title": "登録一覧",
  "type": "object-list",
  "default": [],
  "itemTitle": "項目",
  "list": {
    "columns": ["name"],
    "titleKey": "name",
    "descriptionKey": "url",
    "enabledKey": "enabled",
    "idKey": "id",
    "confirmDelete": true
  },
  "fields": [
    { "key": "id", "title": "ID", "type": "string" },
    { "key": "name", "title": "名前", "type": "string", "default": "新しい項目" },
    {
      "key": "url",
      "title": "URL",
      "type": "string",
      "format": "url",
      "default": "https://example.com/"
    },
    { "key": "enabled", "title": "有効", "type": "boolean", "default": true }
  ]
}
```

`columns`は既存フィールドから1～4列、`titleKey`は主情報、`descriptionKey`はその下の補足。selectの値はラベルで表示する。`enabledKey`はbooleanフィールドのトグル。`idKey`は編集欄に出さず、新規登録時だけUUIDを生成する。`iconKey`は行画像のdata PNG/JPEG/WebP文字列を参照する。`confirmDelete`省略時は宣言型一覧の既存の即時削除を維持する。本体の入力割り当て一覧はこの指定から独立し、常に削除確認を行う。

AppDock 0.46.0以降の`showIndex: true`は、先頭へ`itemTitle`を見出しとした1始まりの番号列を追加する。編集・削除・並べ替えの対象名も`itemTitle`と番号で表示する。モニターのように配列位置が割り当て先を表す設定に使い、番号を永続IDとして保存しない。`string-list`の`format: directory`は共通のフォルダー追加・選択・削除入力を使う。旧JSON文字列の一覧と`aliases`・`numericOptions`を読み、編集した登録だけをOKで正規化して保存する。

フィールドの`propertyPath`は最大3階層の保存パス（例:`["when", "scope"]`）。prototype系キーは禁止。未知の保存項目は保持する。selectの`optionSource: "web-profiles"`は同じAppletの共通プロフィール名簿だけを選択肢に使い、capabilityを必要とする。空の名簿では本体のWebアカウント設定で枠を追加してから選択する。

本体の保存操作は表示中Appletの宣言済み一覧だけを受け付け、開いた時点の一覧と現在値を照合する。変更があればダイアログへ競合を返す。正常時は最新設定へその一覧だけを合成し、共通SettingsCommandsで検証・保存する。任意のApplet向けSettingsPage操作は公開しない。

## 実装時の確認項目

- 適用場面、一覧に出す情報、登録単位、順序の意味、削除の影響が明確である。
- 追加／編集が同じフォームを使い、入力中・候補取得・キャンセルで設定ファイルを変更しない。OKは一度だけ保存する。
- 失敗時に入力が残り、外部の追加・編集・削除・並べ替えを上書きしない。
- URLの連続入力、IME、Enter／blur、Tab移動、Escape、フォーカス復帰を確認する。連続追加で一覧が勝手にスクロールしない。
- 明暗テーマ、狭い幅、長い名前、空の一覧、上限、詳細の展開、処理中・エラー表示でも操作できる。
- 本文範囲への収まり、リサイズ、背景クリック、バー操作、連続開閉での残留要素・CSSの除去を確認する。保存中の取消抑止、IME、フォーカス復帰は保持する。
- Shellを入口に追加した場合は、実際のShellボタンから開き、初期フォーカス・Tab／Escape・同じボタンへの復帰を確認する。入口の停止・交代・route変更後は現在有効な戻り先を確認する。本体内ボタンから開く試験だけで代用しない。
- 開けるrouteごとに背景のnative Viewを確認する。Web／Applet本文・通知の独立Viewを残す設計なら、そのViewを含む表示順・暗化・入力停止を確認し、リボンと両バーだけの成功を全画面へ広げない。
- 設定検索のアンカーを、閉じたダイアログ内だけでなく常設の一覧・項目に置く。検索対象や画面モデルへ秘密値を載せない。
- 実装の影響に応じて保存境界・競合の回帰と隔離したUI確認を行う。実サービスの成功とfixtureの成功は分けて記録する。

既存の確認例は[AI設定UI試験](../scripts/ai-ui-test.cjs)、[URL入力試験](../scripts/settings-url-ui-test.cjs)、[設定操作の回帰](../tests/ai-settings.test.cjs)を参照する。製品の変更・発行がある場合の検証範囲は[開発手順](development-workflow.md)に従う。

背景と入力の確認例は[モーダルGUI試験](../scripts/host-modal-ui-test.cjs)、Shell間の実フォーカス・ドラッグ領域の確認例は[バーGUI試験](../scripts/shell-bars-ui-test.cjs)を参照する。両試験は現在のダイアログ・パレット・既存操作の検証例であり、将来追加するShell起点の編集ダイアログの接続を実装・検証済みとするものではない。WebContentsViewを含む見た目はWindows合成画像と実入力で確認する。

## 共通画像を含む編集

object-listのregistered-imageフィールドは共通RegisteredImageInputを使い、list.imageKeyで一覧プレビューを宣言する。画像選択は親ダイアログの一時入力へ返し、親のOKで参照を保存する。画像登録だけは独立保存し、親の取消で消さない。入れ子のSettingsModalは最後のモーダルを閉じるまで入力抑止を解除しない。ローカルAppletの独自HTMLはホストのregisteredImages.pickを使い、Viewの背景・フォーカスを自己実装しない。[共通画像](registered-images.md)を参照。

## ダイアログ内の推奨値取得

minimumHostVersion 0.86.5以上で、`list.draftAction`に`id`・`title`・入力元の文字列フィールド`inputKey`・反映を許すフィールド名配列`fields`・前回取得値を保持する`historyKey`を宣言できる。同じidを`pageActions`へ宣言し、parametersはinputKeyのstringパラメーター1つとする。独立したローカルページは不要。対象Appletと一覧はホストの現在の設定ページから束縛し、停止中や取得中に交代したruntimeの結果は拒否する。

ホストは既存`page.action` RPCを使い、pageIdを`settings:<設定キー>`として渡す。応答はfieldsにあるキーの推奨値、任意のmessage、任意のPNG/JPEG `imageBytes`（最大256,000 bytes）からなるオブジェクト。未宣言の値は反映せず、識別子・有効状態・画像参照はfieldsに指定できない。historyKeyは宣言済みフィールドと重複させない。

取得結果はダイアログの一時入力だけに適用する。既定値と前回取得値は更新できるが、手入力・未確定の入力・選択済み画像は保持する。URL等の入力元が取得中に変わった場合、取消・画面変更の場合は古い応答を使わない。画像はlist.imageKeyがある場合だけプレビューし、親のOKで共通登録画像へimportする。取得だけでは設定や画像ライブラリーを保存しない。メッセージ・失敗・処理中は共通ダイアログの表示と操作抑止を使う。
