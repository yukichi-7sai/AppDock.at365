# 共通画像ギャラリー

`ui/image-gallery/`はフレームワークに依存しないDOM部品。壁紙履歴を基準にした16:10の画像枠、角丸カード、揃った操作列、サイズスライダーと拡大表示の内容を提供する。本体の画像ライブラリーページ、画像選択ダイアログ、WallpaperSlideshowの壁紙履歴が使用する。

## 部品の接続

`mountImageGallery(container, options)`へスクロール要素と`image/select/activate/action`コールバックを渡し、`setModel(model)`で更新する。型は`src/shared/image-gallery.ts`が正本。キーは画像を識別する安定した`id`、`assetId`は内容世代を表す。取得内容が変わったときは新しいassetIdを発行する。

- `fit: contain | cover`で全体表示と切り抜きを切り替える。
- `selection: none | single | multiple`で履歴・選択・管理を表す。操作の意味、確定、保存、権限は呼出元が所有する。
- タイトルは2行、ラベルは2個と残数表示。`textContent`で描画し、HTMLを受け取らない。
- `image(assetId, edge)`は検証済みdata画像、blob、または既存の`appdock://page-images/` URLを返す。任意のfile/http URLを使わない。
- `anchor()/restore(anchor)`で画像IDと相対オフセットを扱う。キー付き更新はフォーカスと画像を保ち、削除された先頭画像は近傍の残存画像へ引き継ぐ。
- `dispose()`でobserver、イベント、画像参照を回収する。取得中の古い応答を失効させる。

`mountGallerySizeControl`はドラッグ中の`change`と操作確定時の`commit`を分ける。サイズは120〜360 CSS px、20px刻み、初期260px。180px未満ではカード内の余白も縮める。呼出元はchangeでレイアウトだけ更新し、commit時に保存する。操作中と保存応答待ちの値を古いモデルで戻さない。検索・グループ変更などでの選択解除は用途側の判断とする。

管理ページは任意の`interactions`を渡し、共通部品のポインター操作を有効にする。操作rootは左右のパネルを含み、入力やボタンを除く背景のクリックで選択を解除する。背景から6px以上ドラッグすると矩形選択し、Ctrl/Metaで既存選択へ追加する。選択枠に交差するカードを対象にし、一覧端では自動スクロール・追加表示する。Escape・pointercancel・Windowのフォーカス喪失・画面切替で取り消す。カードからのドラッグは呼出元が発行する操作tokenに結び付け、幅180pxの画像カードと対象件数、有効なドロップ先を示す。複数枚ではカードを重ね、通常グループ内では挿入位置の線を表示する。表示物はポインターを透過する。グループ一覧端も自動スクロールする。ドラッグ後のクリックでプレビューや選択解除を起こさない。チェックボックスは36px角のlabelで周辺も選択操作にする。画像とカード枠のhover装飾は行わず、選択枠・キーボードフォーカスは保持する。

管理ページの右側はフィルターと画像を同じスクロール要素へ置き、フィルターパネルをstickyで上端に隙間なく保持する。画像一覧の重なりを分離し、チェックボックスと選択枠がパネルの手前へ出ないようにする。左のグループ欄は独立してスクロールする。`interactions.viewport()`はsticky下の画像可視範囲を返し、範囲選択・自動スクロール・閲覧位置の保存/復元で共用する。検索のフォーカス枠はアイコンを含む外枠の内側へ表示する。

グループの操作メニューはネイティブpopoverのトップレイヤーへ配置し、一覧の高さやスクロール位置を変えない。画面内へ収め、外側クリック・Escape・フォーカス離脱・スクロール・画面サイズ/表示グループ変更で閉じる。Escapeでは呼出ボタンへ戻し、メニュー内は↑↓/Home/EndとTabで操作できる。

CSSは`gallery.css`を読み込む。`.ad-gallery`配下と専用クラスへ限定し、利用側の`button`等の広い規則で上書きしない。テーマは`--surface/--border/--text/--muted/--soft/--shadow`を利用側で指定し、アクセントは[ホストの共通配色](appearance.md)を参照する。固定の高さを外側へ押し付けず、呼出元のスクロール領域をobserverへ渡す。

選択枠はカードの上に重ねた疑似要素で2 CSS pxを描く。画像や市松背景に枠を隠させず、選択時も寸法を変えない。枠はポインター操作を透過する。

`mountGalleryPreview(container, { image })`は拡大画像、読み込み状態、補足情報、所属ラベルを描く。`setModel`のassetIdとstateで取得を切り替え、古い応答と破棄後の応答を無視する。許可URLの検査はカードと共通。モーダル・フォーカス・原画像へのアクセス権は呼出元が所有する。本体はSettingsModal、壁紙履歴は既存native dialogへ配置する。Reactでは`settings-ui/ImageGallery.tsx`の薄いadapterを使う。

画像は可視領域と前後300pxで最大3要求を行い、元の正常画像を保持して次のdecode完了後に差し替える。画面外ではsrcと取得中の応答を失効させ、遅い応答で画像を再保持しない。再び表示範囲へ戻ったときに再取得する。512/1024/2048pxの選択は実カード幅とdevicePixelRatioによる。部品内で原画像の読み込み、保存、外部サービス呼出しを行わない。

本体側の画像キャッシュの寿命も呼出元の画面へ結び付ける。管理ページのControllerは破棄時、画像選択・プレビュー・設定欄のReact adapterはunmount時に自己の画像sessionを解放する。最後の利用元がなくなった縮小画像、待機要求、遅れて完了した応答の扱いは[登録画像の寿命](registered-images.md#保存と参照)を正本とする。このsessionは信頼された本体renderer内部だけで使い、Applet/MCP APIへ公開しない。

## ビルドと配布

`dev.bat pnpm run build:image-gallery`は`out/ui/image-gallery/`にES module、CSS、manifestを作る。通常のbuildにも含む。manifestは`apiVersion: 1`、本体版、出力ファイルと入力ソースのSHA256を持つ。

Appletへ適用するときはこの出力一式をvendorへ梱包し、版とhashを記録する。開発repoの相対参照や本体内部importに依存させない。更新時はbundle全体を差し替え、呼出元のadapterと独立配置での起動を確認する。共通部品の更新だけで未変更Appletを一括発行しない。

WallpaperSlideshowはビルド時に`sync-gallery.ps1`で本体の専用ビルドを実行し、apiVersion・本体版・元ソース・出力hashを照合して`web/vendor/image-gallery/`へ同期する。発行時も同梱ファイルと元のhashを照合する。実行時は同梱ES moduleだけを読み、本体の開発フォルダーを参照しない。

## 本体管理ページの境界

ルートimage-libraryは本体rendererのImageLibraryPageで描画する。本体専用のwindow.dock.pagesとsrc/shared/image-library-page.tsの型を使い、画像カードは共通ギャラリーを利用する。原画像サービス・保存・グループ競合は本体mainが管理し、ページ再生成で旧画像IDは失効する。

プレビュー・グループ編集は本体の`ImageLibraryDialogHost`から共通SettingsDialog/SettingsModal/SettingsOrderDialogを開く。本文は本体と同じdocumentなので、共通native dialogの背景・入力抑止を使う。別Viewのリボン・タイトルバー・ステータスバーはHostModalLayerでcapture・hideする。モーダル中は本文の選択・グループ編集・サイズ変更などを拒否する。Controllerが明示した画像取得と、遅れて届くWindow内のスクロール位置記録だけは許可する。送信元・frame・sessionの検証は共通で維持し、画像取得ではassetId、位置記録では画像IDと有限なoffsetの範囲を検証する。位置記録は共有設定やPC専用ファイルへ保存しない。閉じると同じ本文DOMとフォーカスを維持し、所有元の終了・遷移では待機を取り消す。

管理ページのカード操作は「グループ」「削除」、画像クリックはプレビュー。削除は本体の確認要求に結び付け、使用中の参照を保護する。[削除の保存境界](registered-images.md)を参照する。管理・選択画面のプレビューは`closeOnBackdrop`を有効にし、背景を押して背景で離したクリックで閉じる。画像内のクリックや内側からのドラッグでは閉じず、所属編集・グループ追加などは背景クリックで取り消さない。

表示サイズは`data/settings-<端末名>.json`の`uiState.gallery`へ保存する。`schemaVersion: 1`、`library.cardWidth`と`picker.cardWidth`を独立して保持し、旧`image-gallery-state.json`は読み込まない。選択・検索・スクロールはWindow内だけに保持する。状態は変更時にだけ追加し、破損・未知版を上書きせず、保存前の同じ状態への外部変更も検出する。修復後は再起動して読み直す。UI状態の保存で設定再適用やバックアップ世代を増やさない。

ダイアログを要求した時点から終了応答まで、Shellの本文を`inert`にし、連続クリックやグループ切り替えによる重複要求を防ぐ。背景のcapture/decodeが失敗してもHostModalLayerは本文Viewを隠し、ダイアログを手前で操作できるようにする。成功時も本体documentの描画フレームを待たず、decodeとDOM配置後に本文Viewを隠す。覆われた本体の描画待ちで透明なダイアログを残さない。接続拒否には原因を識別する理由コードを付けるが、操作の許可条件は変えない。

画像選択は単一選択・全体表示とし、「画像を使う」で親の値を確定する。拡大表示の取消は選択を保ち、選択ダイアログの取消は親の画像を変えない。サイズは親の画像編集とは独立して確定時に保存する。信頼された本体rendererの`galleryImage`は現在の参照・内容世代を取得前後に照合し、同じ縮小画像サービスを使う。Applet/Webへこの内部APIを公開しない。

## 検証

`tests/image-gallery.test.cjs`でサイズ保存、競合、一括所属、選択、ページ寿命、部分登録、最大カタログを確認する。`scripts/image-gallery-ui-test.cjs [固定EXE]`は独立した隔離profileでページ・3モードのbundle・明暗・サイズ・再起動を確認する。既存APIと選択ダイアログの互換性は`image-library-ui-test.cjs [固定EXE]`で確認する。これらは物理IME、複数モニターのDPI移動、実NAS、実壁紙操作の証明にはしない。

`scripts/image-gallery-capacity-ui-test.cjs [固定EXE]`は512枚のPNG、64グループ、4096所属を隔離profileに作り、全件選択・追加表示・検索・キーボードでのサイズ変更・原画像/共有設定の保持を確認する。スクロール各地点の画像src数、表示寸法からのRGBA相当量、data URL文字列量、プロセスメモリーを記録する。RGBA相当量は実測したOSメモリーやdecode中の最大使用量とは区別する。共通bundleへの制御した遅延応答で、画面外への移動・再表示・破棄も検証する。

`scripts/image-library-session-ui-test.cjs [固定EXE]`はモーダル表示後に届くスクロール通知を再現し、位置記録でエラーを表示しないこと、背景の編集と不正な画像IDを拒否すること、画像取得とページ再表示を確認する。capture/decode失敗時のダイアログ表示とView復元、準備が遅い場合の連続クリック、終了後のグループ切り替えも確認する。自動化のfocus emulationを無効にした通常表示と、本体preloadの描画フレームを止めた状態でも表示・取消・復帰を確認する。

## サムネイルと表示の安定性

本体の現行64pxサムネイルと96px円形画像は、小型アイコン用として契約を維持する。ギャラリー用には別の縮小画像を必要時に生成する。512／1024／2048pxの長辺を初期候補とし、実カード幅とdevicePixelRatioから最小の十分な段階を選ぶ。原画像より拡大して生成しない。

- 一覧snapshotに全件の大きなbase64画像を含めない。メタデータと画像取得を分け、表示中と近傍のカードから要求する。
- 生成は非同期・同時数を制限し、同一画像・内容世代・サイズ段階の要求をまとめる。WebPは既存のsandbox化したdecoderの制約を維持する。
- 大きな縮小画像はPC内メモリーの上限付きキャッシュとする。初期の生成画像予算は64MiBを基準に計測し、実画像のdecodeメモリーも含めて確認する。新しい画像インデックスや派生画像の永続フォルダーは作らない。
- ピクセル密度の変化やスライダー操作では段階が変わったときだけ再取得し、解像度の高い正常画像を低い画像へ取り替えない。
- 新しい画像をdecodeできるまで現在の正常画像を残す。読み込みでカード高さ、スクロール位置、操作列を変えない。
- 更新・削除検知で内容世代を変え、古い取得結果で新しい画像を上書きしない。復旧時は元の安定キーで置換する。
- Shellへ配信するURL／不透明IDは許可された生存Viewへ限定する。本体の既存asset配信の送信元検査を再利用または拡張し、リモートWebへ公開しない。
- WallpaperSlideshowは既存のページ画像登録と解放をそのままアダプターへ接続する。共通部品の都合で1MiBのRPC上限を緩めたり、画像bytesをpageActions結果へ埋めたりしない。

## 空状態・失敗・アクセシビリティ

| 状態               | 表示と操作                                                                 |
| ------------------ | -------------------------------------------------------------------------- |
| 登録0件            | 「画像がありません」と「画像を追加」                                       |
| 空の通常グループ   | 「このグループには画像がありません」。追加と既存画像の所属変更への案内     |
| 検索0件            | 「該当する画像はありません」と検索解除。グループ自体を消さない             |
| データ取得失敗     | 直近の正常一覧を保持し、状態領域に再取得を表示。失敗を空一覧として扱わない |
| 保存競合           | 入力・選択を保持して再取得を促す。自動上書き・自動再送しない               |
| 画像単体の読取失敗 | カード内に状態を表示。他の正常画像やグループ操作は使える                   |

すべての操作をキーボードで実行可能にする。チェック、スライダー、検索、各ボタンはnative要素を用い、クリック可能な画像にも操作名を付ける。ホバーだけで操作を発見させない。

ダイアログの初期フォーカス・囲い込み・復帰、入力中のIME、Escapeの対象を維持する。画像カードに複合した独自の矢印キー操作を新設せず、検索の文字選択・スライダーの矢印・既存ショートカットを奪わない。

保存・登録の最終失敗は[共通エラー報告](error-reporting.md)、処理中や選択件数はaria-liveと画面内の状態領域へ接続する。共有ヒントの表示設定とエラー／状態表示を混同しない。成功のたびのバナーや読み上げは追加しない。
