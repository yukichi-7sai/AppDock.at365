# 本体の画像ギャラリー

`src/renderer/image-gallery/`は本体専用のDOM部品。16:10の画像枠、角丸カード、揃った操作列、サイズスライダーと拡大表示の内容を提供する。本体の画像・音・テキストのライブラリーと画像選択ダイアログが使用する。mainとrendererで共有する表示モデル・サイズ検証は`src/shared/image-gallery.ts`に置く。

## 部品の接続

`mountImageGallery(container, options)`へスクロール要素と`image/select/activate/action`コールバックを渡し、`setModel(model)`で更新する。型は`src/shared/image-gallery.ts`が正本。キーは画像を識別する安定した`id`、`assetId`は内容世代を表す。取得内容が変わったときは新しいassetIdを発行する。

- `fit: contain | cover`で全体表示と切り抜きを切り替える。
- `selection: none | single | multiple`で履歴・選択・管理を表す。操作の意味、確定、保存、権限は呼出元が所有する。
- `size`・`clickSelect`・`context`は任意。未指定の履歴/選択画面は従来の寸法・クリック動作を維持する。本体の管理ページと画像選択は小型表示・クリック選択・ダブルクリック拡大を使い、管理ページはさらにコンテキストメニューを有効にする。
- タイトルは2行、ラベルは既定で2個と残数表示。任意の`expandLabels`で所属を全件表示できる。`textContent`で描画し、HTMLを受け取らない。
- `image(assetId, edge)`は検証済みdata画像、blob、または既存の`appdock://page-images/` URLを返す。任意のfile/http URLを使わない。
- `anchor()/restore(anchor)`で画像IDと相対オフセットを扱う。キー付き更新はフォーカスと画像を保ち、削除された先頭画像は近傍の残存画像へ引き継ぐ。
- `dispose()`でobserver、イベント、画像参照を回収する。取得中の古い応答を失効させる。

`GalleryInteractions.targets()`の対象には任意の`description(count)`、`hover()`、`canDrop`を指定でき、表示とホバー展開を所有画面へ委ねる。`canDrop: false`はホバー展開だけの入口で、実際のドロップは受け付けない。未指定の呼出元は従来の表示とドロップ操作を維持する。

`mountGallerySizeControl`はドラッグ中の`change`と操作確定時の`commit`を分ける。既定のサイズは120〜360 CSS px、20px刻み、初期260px。本体の管理ページと画像選択は`libraryGallerySize`を渡し、40〜360px・4px刻みを使う。180px未満ではカード内の余白も縮める。呼出元はchangeでレイアウトだけ更新し、commit時に保存する。操作中と保存応答待ちの値を古いモデルで戻さない。検索・グループ変更などでの選択解除は用途側の判断とする。

管理ページは任意の`interactions`を渡し、共通部品のポインター操作を有効にする。操作rootは左右のパネルを含み、入力やボタンを除く背景のクリックで選択を解除する。背景から6px以上ドラッグすると矩形選択し、Ctrl/Metaで既存選択へ追加する。選択枠に交差するカードを対象にし、一覧端では自動スクロール・追加表示する。Escape・pointercancel・Windowのフォーカス喪失・画面切替で取り消す。カードからのドラッグは呼出元が発行する操作tokenに結び付け、幅180pxの画像カードと対象件数、有効なドロップ先を示す。複数枚ではカードを重ね、通常グループ内では挿入位置の線を表示する。表示物はポインターを透過する。グループ一覧端も自動スクロールする。ドラッグ後のクリックでプレビューや選択解除を起こさない。チェックボックスは36px角のlabelで周辺も選択操作にする。画像とカード枠のhover装飾は行わず、選択枠・キーボードフォーカスは保持する。

管理ページの右側はフィルターと画像を同じスクロール要素へ置き、フィルターパネルをstickyで上端に隙間なく保持する。画像一覧の重なりを分離し、チェックボックスと選択枠がパネルの手前へ出ないようにする。左のグループ欄は独立してスクロールする。`interactions.viewport()`はsticky下の画像可視範囲を返し、範囲選択・自動スクロール・閲覧位置の保存/復元で共用する。検索のフォーカス枠はアイコンを含む外枠の内側へ表示する。

グループの操作メニューはネイティブpopoverのトップレイヤーへ配置し、一覧の高さやスクロール位置を変えない。画面内へ収め、外側クリック・Escape・フォーカス離脱・スクロール・画面サイズ/表示グループ変更で閉じる。Escapeでは呼出ボタンへ戻し、メニュー内は↑↓/Home/EndとTabで操作できる。

CSSは`gallery.css`を読み込む。`.ad-gallery`配下と専用クラスへ限定し、利用側の`button`等の広い規則で上書きしない。テーマは`--surface/--border/--text/--muted/--soft/--shadow`を利用側で指定し、アクセントは[ホストの共通配色](appearance.md)を参照する。固定の高さを外側へ押し付けず、呼出元のスクロール領域をobserverへ渡す。

選択枠はカードの上に重ねた疑似要素で2 CSS pxを描く。画像や市松背景に枠を隠させず、選択時も寸法を変えない。枠はポインター操作を透過する。

`mountGalleryPreview(container, { image })`は拡大画像、読み込み状態、補足情報、所属ラベルを描く。`setModel`のassetIdとstateで取得を切り替え、古い応答と破棄後の応答を無視する。許可URLの検査はカードと共通。モーダル・フォーカス・原画像へのアクセス権は呼出元が所有する。SettingsModalへ配置する。Reactでは`settings-ui/ImageGallery.tsx`の薄いadapterを使う。

画像は可視領域と前後300pxで最大3要求を行い、元の正常画像を保持して次のdecode完了後に差し替える。画面外ではsrcと取得中の応答を失効させ、遅い応答で画像を再保持しない。再び表示範囲へ戻ったときに再取得する。管理ページと画像選択は64/512/1024/2048px、ほかの呼出元は512/1024/2048pxから、実カード幅とdevicePixelRatioに応じて選ぶ。部品内で原画像の読み込み、保存、外部サービス呼出しを行わない。

本体側の画像キャッシュの寿命も呼出元の画面へ結び付ける。管理ページのControllerは破棄時、画像選択・プレビュー・設定欄のReact adapterはunmount時に自己の画像sessionを解放する。最後の利用元がなくなった縮小画像、待機要求、遅れて完了した応答の扱いは[登録画像の寿命](registered-images.md#保存と参照)を正本とする。このsessionは信頼された本体renderer内部だけで使い、Applet/MCP APIへ公開しない。

## ビルドと配布

通常のrendererビルドへ含め、Applet向けの独立bundle・manifestは生成・配布しない。既存checkoutに残る旧`out/ui/image-gallery/`も本体の配布物へ含めない。

WallpaperSlideshowの履歴表示は同Appletの`web/history-gallery.js`とCSSが所有する。本体の表示部品をimport・コピーせず、ビルド時の同期もしない。本体のギャラリー変更だけでAppletの追随修正・再発行は不要。ページ表示・Storage・元画像参照などの公開APIの互換性は別途維持する。

部品単体のGUI検査は`scripts/gallery-component-helper.cjs`で現在のrendererソースを各試験profile内にbundle化する。このfixtureは試験専用で、発行物のページを検査する部分と区別する。

## 本体管理ページの境界

ルートimage-libraryは本体rendererのImageLibraryPageで描画する。本体専用のwindow.dock.pagesとsrc/shared/image-library-page.tsの型を使い、画像カードは共通ギャラリーを利用する。原画像サービス・保存・グループ競合は本体mainが管理し、ページ再生成で旧画像IDは失効する。

プレビュー・グループ編集は本体の`ImageLibraryDialogHost`から共通SettingsDialog/SettingsModal/SettingsOrderDialogを開く。本文は本体と同じdocumentなので、共通native dialogの背景・入力抑止を使う。別Viewのリボン・タイトルバー・ステータスバーはHostModalLayerでcapture・hideする。モーダル中は本文の選択・グループ編集・サイズ変更などを拒否する。Controllerが明示した画像取得と、遅れて届くWindow内のスクロール位置記録だけは許可する。送信元・frame・sessionの検証は共通で維持し、画像取得ではassetId、位置記録では画像IDと有限なoffsetの範囲を検証する。位置記録は共有設定やPC専用ファイルへ保存しない。閉じると同じ本文DOMとフォーカスを維持し、所有元の終了・遷移では待機を取り消す。

管理ページのカード下には操作ボタンを置かず、所属グループの表示を広げる。グループ名は全件を折り返し表示し、多い場合は所属欄の中でスクロールする。操作は上部ツールバーとコンテキストメニューへ集約する。画像クリックは選択、Ctrlで選択反転、Shiftで範囲選択、ダブルクリック/Enterでプレビュー。選択中カードの操作は表示範囲外を含む選択全件へ適用する。未選択カードを操作すると、その1枚へ選択を切り替える。単一選択のメニューには「所属グループを編集」を設け、複数時は追加/解除の対象を選ぶ。グループから外す操作は別に設け、他の所属を保持する。削除は本体の確認要求に結び付け、使用中の参照を保護する。[削除の保存境界](registered-images.md)を参照する。管理・選択画面のプレビューは`closeOnBackdrop`を有効にし、背景を押して背景で離したクリックで閉じる。画像内のクリックや内側からのドラッグでは閉じず、所属編集・グループ追加などは背景クリックで取り消さない。複数選択のプレビューでは前後の画像へ移れる。

### 管理ページの配置と操作

左側は実フォルダーのツリーとグループ、右側は現在地・検索・サイズ・選択操作と一覧。「画像ライブラリー直下」は各直下フォルダーと同じ段に置き、実際の子フォルダーだけを字下げする。フォルダーの「…」で作成・改名・空フォルダー削除を行い、現在地の「フォルダーを開く」でエクスプローラーを開く。すべてのフォルダー表示では画像rootを開き、初回でrootがなければ安全な保存先を作成する。消失した子フォルダーは再作成しない。ヘッダーは共通ボタンを使い、「画像を追加」を主操作、「アイコンセットを取り込む」を副操作にする。

左側の境界はドラッグと左右キーで幅を変更できる（160〜480px、初期220px、画面内では40%まで）。狭幅ではボタンから同じナビゲーションを開き、広幅に戻ると保存幅を使う。グループ名の最初の`:`より前を表示上のまとまりにし、`Lucide:`などを折りたためる。グループID・名前・所属・保存順は変えず、折りたたみ中も選択中のグループを右側の解除可能な表示で確認できる。

管理ページは「カード」「リスト」を切り替えられる。カードのサイズは40〜360 CSS px、4px刻み。最小時の画像は約24px。120px未満ではファイル名・所属を隠し、ツールチップ、フォーカス/ポインター位置のファイル名欄、上部の選択操作から確認・操作する。リストは小さなプレビュー、名前、画像の形式・容量／音の再生時間／文字の文字数・行数、所属を横長の行へまとめる。文字は本文冒頭も1行で表示し、所属は先頭と残数にまとめて全件をツールチップで確認できる。行本文のクリックも選択になり、ダブルクリック・Enterの意味はカードと共通。表示切替は選択・カード幅・元の素材を保持する。画像選択ダイアログのカード表示とサイズ範囲は維持する。

検索の隣に表示切替と並び順を置く。「名前」「種類」「更新日時」「容量」は昇順／降順で表示を並べ替え、同値は自然な名前順、未取得の日時・容量は末尾とする。更新日時は走査済みのファイル属性で、並べ替えのために本文や画像を読み込まない。通常グループの「手動順」は保存した所属順、それ以外の「標準順」は従来の相対パス順を表示する。並べ替えは絞り込み結果全体へ適用してから追加表示し、選択を保持する。共有設定・グループ順・定型文パレットの順を変更せず、ドラッグによる順序変更は手動順の通常グループだけで行える。リストの挿入位置は行の上下で示す。

画像・テキスト・音の管理ツールバーは、上段左に「すべて選択」「選択を解除」を隣接させ、上段右に絞り込み結果の総数と選択件数を表示する。全件選択は未描画分も含む絞り込み結果を対象とする。選択解除は未選択でも表示し、無効化する。グループの絞り込み表示、索引更新中、試聴状態も操作ボタン列から分離する。

下段は、素材固有の操作、グループへの追加・解除、移動・その他、削除の順に余白で区切る。各ボタンは共通の線画アイコンと文字を併記し、狭幅では操作のまとまりごとに折り返す。画像は選択画像のプレビュー、テキストは本文の表示・編集・コピー、音は試聴・停止を直接表示する。未選択・複数選択で利用できない操作は位置を保って無効化する。音の停止は選択件数と独立し、試聴中・待機中に使用できる。削除は最後に配置し、実行前に確認する。

右クリック、Shift+F10/コンテキストメニューキー、上部の「その他」は同じ対象・メニューを使い、プレビュー、ファイル名変更、ファイル/パス/画像コピー、エクスプローラー表示、グループ追加/解除、移動、削除へ接続する。Ctrl+Aで絞り込み結果をすべて選択、Ctrl+Cでファイル、Ctrl+Shift+Cでパスをコピーし、F2で改名、Deleteで削除確認を開く。矩形選択の確定時に管理ページへフォーカスを戻し、カードをクリックし直さずDeleteを使える。チェックボックスからのDeleteも同じ削除確認へ接続する。文字入力欄・IME・メニュー内の操作を優先し、長押しで確認を繰り返さない。

画像を実フォルダーへドロップするとファイルを移動し、通常グループへのドロップでは所属を追加する。選択中画像のドラッグは未描画分も含む選択全件、未選択画像のドラッグはその1件を対象にする。移動先と枚数を表示し、600msのホバーで閉じたフォルダー/狭幅ナビゲーションを開く。Esc・移動先以外へのドロップは取り消す。画像はドラッグ開始時の内容世代と要求tokenに結び付け、移動前に全件と移動先を検査する。同名を上書きせず、所属と設定用保管画像を維持する。移動後も現在のフォルダー・絞り込み・閲覧位置を保つ。

成功メッセージは画像エリアの中央上に重ね、4秒後に消す。同じ操作の繰り返しでも再表示し、一覧やツールバーの配置・スクロール位置を変えない。処理中とエラーも同じ重ね表示を使い、エラーは再取得/再試行できる状態で保持する。成功表示はポインター操作を遮らない。

通常グループ内で素材をドラッグすると、一覧の下端に「N件を『グループ名』から外す」を重ねて表示する。この領域へのドロップとツールバーの「このグループから外す」は共通の所属解除へ接続する。対象はドラッグ開始時の選択全件で、未描画分も含む。原ファイルと他グループの所属を保持し、元グループ・所属・内容世代の変更や操作tokenの再使用を拒否する。Escape・領域外へのドロップは取消。「すべて」「未分類」は脱退先にしない。すべて／未分類のツールバーとコンテキストメニューからは従来のグループ選択による解除も使える。

一覧末尾の約300px手前で64件ずつ自動追加する。小型表示で画面を満たしていなければ続けて追加し、選択と閲覧位置を保つ。重複取得を防ぎ、失敗時は自動再試行を止めて再試行ボタンを出す。ページ外側の余白を抑え、フィルター・一覧・末尾の余白を右側スクロール内へ置く。左側は独立スクロールとする。

表示状態は`data/settings-<端末名>.json`の`uiState.gallery`へ保存する（音は`soundGallery`、文字は`textGallery`）。`schemaVersion: 1`、`library.cardWidth`と`picker.cardWidth`を独立して保持し、`library.layout`と`picker.layout`へそれぞれ独立した`sidebarWidth`・`collapsedGroups`・`collapsedFolders`を保存する。管理ページの任意の`library.view`は`mode: cards|list`、`sort: manual|name|type|modified|size`、`direction: ascending|descending`を種類別に保持する。省略時はカード・標準／手動順・昇順。以前のサイズだけの状態もそのまま読み、layout省略時は既定の幅220px・全展開を使う。旧`image-gallery-state.json`は読み込まない。選択・検索・スクロールはWindow内だけに保持する。状態は変更時にだけ追加し、破損・未知版を上書きせず、保存前の同じ状態への外部変更も検出する。修復後は再起動して読み直す。UI状態の保存で設定再適用やバックアップ世代を増やさない。

ダイアログを要求した時点から終了応答まで、Shellの本文を`inert`にし、連続クリックやグループ切り替えによる重複要求を防ぐ。背景のcapture/decodeが失敗してもHostModalLayerは本文Viewを隠し、ダイアログを手前で操作できるようにする。成功時も本体documentの描画フレームを待たず、decodeとDOM配置後に本文Viewを隠す。覆われた本体の描画待ちで透明なダイアログを残さない。接続拒否には原因を識別する理由コードを付けるが、操作の許可条件は変えない。

本体rendererの`image-browser/`はフォルダーツリー、グループのプリフィックス折りたたみ、幅変更、狭幅の分類popover、パンくず、検索欄と見た目を管理ページ・画像選択で共用する。`src/shared/image-browser.ts`はフォルダー・グループ・検索の積集合と保存したグループ内順序を共用する。管理操作は管理ページ側のslotとコールバックで追加し、選択画面には移動・削除・所属編集を渡さない。

画像選択は単一選択・全体表示とし、1クリックで選択、ダブルクリックまたは画像にフォーカスしたEnterで拡大し、「画像を使う」で親の値を確定する。分類・検索で選択画像が隠れても選択を保ち、フッターにプレビューとファイル名を表示する。検索のEscapeは検索解除、狭幅の分類popover内のEscapeはpopoverだけを閉じて起点へ戻す。拡大表示の取消は選択を保ち、選択ダイアログの取消は親の画像を変えない。サイズ・左幅・折りたたみは親の画像編集とは独立して操作確定時に保存する。画像一覧は末尾300px手前で64件ずつ追加し、初期表示や縮小時に画面が埋まらなければ続けて追加する。登録後は分類と検索を解除して登録画像を選択し、その画像を含む件数まで表示して位置を合わせる。信頼された本体rendererの`galleryImage`は現在の参照・内容世代を取得前後に照合し、同じ縮小画像サービスを使う。Applet/Webへこの内部APIを公開しない。

## サムネイルと表示の安定性

本体の現行64pxサムネイルと96px円形画像は、小型アイコン用として契約を維持する。ギャラリー用には別の縮小画像を必要時に生成する。管理ページでは64px、通常サイズでは512／1024／2048pxから、実カード幅とdevicePixelRatioに足りる段階を選ぶ。ラスター原画像は通常サイズで拡大せず、既存の64pxアイコンとSVGは指定した描画サイズを使う。

- 一覧snapshotに全件の大きなbase64画像を含めない。メタデータと画像取得を分け、表示中と近傍のカードから要求する。
- 生成は非同期・同時数を制限し、同一画像・内容世代・サイズ段階の要求をまとめる。WebPは既存のsandbox化したdecoderの制約を維持する。
- 大きな縮小画像はPC内メモリーの上限付きキャッシュとする。初期の生成画像予算は64MiBを基準に計測し、実画像のdecodeメモリーも含めて確認する。新しい画像インデックスや派生画像の永続フォルダーは作らない。
- ピクセル密度の変化やスライダー操作では段階が変わったときだけ再取得し、解像度の高い正常画像を低い画像へ取り替えない。
- 新しい画像をdecodeできるまで現在の正常画像を残す。読み込みでカード高さ、スクロール位置、操作列を変えない。
- 更新・削除検知で内容世代を変え、古い取得結果で新しい画像を上書きしない。復旧時は元の安定キーで置換する。
- Shellへ配信するURL／不透明IDは許可された生存Viewへ限定する。本体の既存asset配信の送信元検査を再利用または拡張し、リモートWebへ公開しない。
- Appletの画像表示・元画像参照の寿命と権限は[メモリStorage](memory-storage.md)を参照する。本体のギャラリーをAppletへ提供する契約には含めない。

## 空状態・失敗・アクセシビリティ

| 状態               | 表示と操作                                                                 |
| ------------------ | -------------------------------------------------------------------------- |
| 登録0件            | 「画像がありません」と「画像を追加」                                       |
| 空の通常グループ   | 「画像がありません」。画像の追加とフィルター解除から選び直せる             |
| 検索0件            | 「該当する画像はありません」と検索解除。グループ自体を消さない             |
| データ取得失敗     | 直近の正常一覧を保持し、状態領域に再取得を表示。失敗を空一覧として扱わない |
| 保存競合           | 入力・選択を保持して再取得を促す。自動上書き・自動再送しない               |
| 画像単体の読取失敗 | カード内に状態を表示。他の正常画像やグループ操作は使える                   |

すべての操作をキーボードで実行可能にする。チェック、スライダー、検索、各ボタンはnative要素を用い、クリック可能な画像にも操作名を付ける。ホバーだけで操作を発見させない。

ダイアログの初期フォーカス・囲い込み・復帰、入力中のIME、Escapeの対象を維持する。画像カードに複合した独自の矢印キー操作を新設せず、検索の文字選択・スライダーの矢印・既存ショートカットを奪わない。

保存・登録の最終失敗は[共通エラー報告](error-reporting.md)、処理中や選択件数はaria-liveと画面内の状態領域へ接続する。共有ヒントの表示設定とエラー／状態表示を混同しない。成功のたびに独立した通知Windowや音声通知を追加しない。画面内の操作結果は上部の状態領域へ表示する。

音ライブラリーでも本体専用アダプターから同じカードと分類UIを使う。`GalleryOptions.errorText`とサイズ操作の`label`は任意で、未指定時の画像用表示を維持する。音の再生・ファイル保存は共通ギャラリーへ追加せず、[素材ライブラリー](asset-libraries.md)側が担当する。

テキスト管理ページは`GalleryItem.textPreview`に短い本文抜粋、`assetId`に空文字を渡す。カードは抜粋を`textContent`で表示し、画像取得を要求しない。全文の取得・編集と本文検索は管理ページの責務で、`textPreview`を省略した表示先は従来どおり画像を描画する。
