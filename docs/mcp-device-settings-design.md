# MCP接続・ツールコマンドの端末別保存と認証復旧

本書は端末別MCP設定・コマンド・秘密の保存境界と復旧の正本。通信・ジョブは[共通MCPクライアント](mcp-client-design.md)、通常のカスタム種類は[カスタムコマンド](custom-commands-design.md)、共通保存とAPIは[設定同期](settings-sync.md)・[設定API](settings-api.md)を参照する。検証結果は[検証記録](../VERIFICATION.md)に分離する。

## 目的と確定した方針

MCP接続定義と保存したMCPツールコマンドを、EXE隣の`data/settings-<端末名>.json`にまとめる。PC交換時にこのファイルを戻せば、接続先とコマンドのID・参照関係を保持し、認証情報の再入力と接続・ツールの確認で利用を再開できるようにする。

- 保存先は自端末の設定ファイルに固定する。共有設定への切り替え、共有値からの継承は設けない。
- APIキーとして使うBearer tokenと、stdioに明示する環境変数の名前・値は、配置別のLocalAppDataで暗号化して管理する。
- MCPクライアント設定内に「MCPツールコマンド」の管理を置く。カスタムコマンドの種類「MCPツールを実行」は廃止する。
- 作成したコマンドを、本体の共通コマンド一覧・パレット・入力割り当て・リボン・トレイ・コマンドスタック・公開コマンドAPIへ接続する。
- 旧設定値の引き継ぎ・変換・ID対応表は作らない。本設計の新形式を将来のPC交換で復旧することと、旧形式からの移行を区別する。
- ここでいう再認証は、現在対応しているBearerと環境変数の再登録・接続確認を指す。OAuth、ブラウザログイン、refresh tokenの自動更新は追加しない。
- バックアップ先やファイル同期サービスの設定、別端末名へのインポート、設定の自動マージは対象外とする。

## 保存先の分担

| 対象 | 保存先・所有者 |
| --- | --- |
| 接続先ID・名前・説明・順序・非秘密接続設定 | 端末別 `mcpClient.servers` |
| MCPツールコマンド | 同じ端末別 `mcpClient.commands` |
| Bearer・環境変数の名前と値 | LocalAppDataの `mcp-client-secrets.json` |
| 操作許可 | 既存のApplet/MCP別PC専用設定 |
| 接続・ツール一覧・ジョブ | `McpClientService`の一時状態 |

秘密を含む通信のidentityとtoolRevisionは接続世代を検出し、永続化するtoolBindingは接続先・ツール定義を検出する。再暗号化やキー再入力だけでは保存した承認内容を失効させない。

## 保存形式と識別子

### 端末別設定

端末別設定のルートへ、独立した`version:1`の`mcpClient`ブロックを追加する。端末ファイルの`schemaVersion:1`と`machineName`、他の設定・`uiState`は維持する。省略時は空の接続一覧・コマンド一覧とする。

以下は新形式の構造例であり、現行版へ入力できる設定例ではない。`connection`は既存の`McpConnection`の項目を使う。

```json
{
  "mcpClient": {
    "version": 1,
    "servers": [
      {
        "id": "b4e4e8f2-238c-43aa-8632-814048608893",
        "name": "ローカル操作サーバー",
        "description": "この端末の操作用",
        "connection": {
          "enabled": false,
          "transport": "http",
          "command": "",
          "args": [],
          "cwd": "",
          "url": "http://127.0.0.1:9000/mcp",
          "authentication": "bearer",
          "published": false,
          "publishedTools": []
        },
        "requiresEnvironment": false
      }
    ],
    "commands": [
      {
        "id": "bc65cb83-7608-4a54-9430-d8385bd1549e",
        "title": "状態を確認",
        "description": "登録先の状態を取得する",
        "category": "端末操作",
        "enabled": false,
        "automation": false,
        "serverId": "b4e4e8f2-238c-43aa-8632-814048608893",
        "toolName": "get_status",
        "arguments": {},
        "timeoutMs": 60000,
        "toolBinding": null
      }
    ]
  }
}
```

- server/commandの`id`は小文字UUID。名前・引数・接続内容・認証の変更で再発行しない。順序は各配列の順序とする。
- 新規サーバーは無効・非公開、明示環境変数なしを既定とする。新規コマンドも無効・非公開を既定とする。参照先は登録済みserverIdから選び、新規作成で未知IDを受け付けない。削除済み参照を持つ既存コマンドは保持する。
- コマンドIDは`appdock.mcp.tool.<UUID>`として生成し、ファイルには重複して保存しない。提供元は本体の登録情報で決め、接頭辞だけから権限を与えない。
- `requiresEnvironment`は、stdioで明示的な環境変数一式が必要かを示す非秘密のboolean。既定false。環境変数の登録・解除と同時にローカルUIから更新する。値だけでなく名前も端末別JSONには載せず、APIに編集させない。
- `toolBinding`は未確認ならnull、確認済みなら`{version:1, endpointFingerprint, definitionFingerprint}`。2つのfingerprintは本体が計算するSHA256であり、利用者や外部APIが任意の承認値として設定する項目にはしない。
- 未確認コマンドは無効・非公開・`toolBinding:null`で保存できる。この未確認保存を除き、新規・実行内容変更・有効化・公開追加時には、確認済みの最新ツールと引数の照合が必要。実行内容を変えた未確認保存へ古いbindingを持ち越さない。名前・説明・カテゴリ・順序の変更、無効化・非公開化・削除は、接続不能でも行える。
- 名前・説明・カテゴリ・UUID・引数形式・timeoutの検証は既存の共通実装を使う。timeoutは1〜600秒、既定60秒。登録件数や保存全体に新しい固定上限を設けない。MCP通信時のサイズ制約は維持する。
- 認証情報をコマンドの引数・起動引数へ埋め込む専用機能は作らない。これらは平文の通常設定であることを編集欄の説明で示す。自由入力された秘密らしい文字列を完全に識別・除去できるとは扱わない。

### 暗号化した認証情報

PC専用rootは従来どおり`%LOCALAPPDATA%/at365/AppDock/profiles/<配置ID>/`。新しい`mcp-client-secrets.json`は`version:1`とserverId別の`entries`を持ち、値はsafeStorageで暗号化した文字列とする。復号後の内容は接続先とのbinding、Bearer token、環境変数の名前・値に限る。通常の接続設定やコマンドを複製しない。

- 秘密はWindowsユーザー・PC・配置に属し、端末別設定を戻しただけでは復元されない。別環境の暗号文が読めない場合は再入力へ案内する。
- 接続先とのbindingにはtransport・URLまたはEXE/args/cwd・認証方式を含める。接続内容の変更後に古い秘密を別の接続先へ送らない。変更と同時に必要な秘密を明示入力するか、未設定状態で保存する。
- 設定UIへ既存の秘密値を返さない。置換を選ばなければ既存値を保持し、置換を選んで空文字または空の環境変数を保存すると解除する。読めない値の修復も明示的な置換で行う。
- stdio環境変数は一式で置換・解除する。復旧時には読めない既存値への部分mergeを行わず、利用者がサーバーの設定から一式を再入力する。新PCで必要な変数名を復元する機能は今回含めない。本体は名前・値の形式を検査するが、任意のサーバーが必要とする全変数の充足は保証せず、接続確認で結果を示す。
- `authentication:bearer`で秘密がない状態を、保存可能な「認証情報が必要」として扱う。従来の「キーがないと設定保存自体を拒否する」条件を、実行前拒否へ分離する。
- 認証なしの接続はBearerを利用せず、方式を変更してOKを押すと不要なBearerを削除する。環境変数の解除と`requiresEnvironment:false`は同じ保存で行う。

## 設定ストア・競合・破損

`DeviceSettingsStore`の既存の設定合成・保存分離へ`mcpClient`を追加する。実行時のSettingsへ投影しても、共有設定への書戻しを禁止する。共有JSONに同名のブロックを置いても適用しない。別端末名のファイルを探索・適用せず、空の自端末設定から共有値を取り込まない。

接続・コマンドの通常編集は端末ファイルだけを保存する。秘密も変えるローカル操作は、端末ファイルと暗号化ファイルを既存の原子的保存・journal・revision検査へ接続する。平文の秘密をjournalやバックアップへ書かない。名前・説明・順序だけの編集で秘密を復号・再暗号化せず、暗号化ファイルのbytesを保つ。

- 保存前に端末設定と秘密の双方の変更を検査する。変更なし・dryRunはファイルとrevisionを進めない。片側の失敗では確定前へ戻し、起動時journal回収でも中途半端な組合せを採用しない。
- ファイル監視・設定適用・バックアップ・診断の表示先を共通ストアへ接続する。独自ポーリングを追加しない。`uiState`だけの変更とMCP定義変更を区別し、必要な更新だけを設定ページ・コマンド一覧・接続へ伝える。
- 端末設定の不正JSON・未知版・不正な新ブロックは、既存の設定受信拒否と直近正常値の保持・復旧に従う。問題のある原本を空設定で上書きしない。
- 秘密の欠落はファイル破損と区別する。1件の復号不能・不正entryは、そのサーバーを認証要修復として表示し、他の接続の編集を妨げない。対象外の不正entryはそのまま保持する。
- 秘密ファイル全体の不正JSON・未知版では秘密の書込みを止める。非秘密設定の閲覧・通常編集は可能だが、秘密の保持を保証できない接続変更・削除は拒否する。既知の秘密を送る通信も止め、認証を使わない独立した接続まで止めない。
- 全体破損時にはローカルUIに「認証情報を初期化」を提示する。対象範囲を確認し、共通復旧経路で原本の暗号文をPC専用領域へ退避できた場合だけ新しい空の秘密ファイルへ置き換える。退避失敗・確認中の外部変更では保存しない。接続・コマンド定義とIDは保持し、該当する認証を再入力できるようにする。
- ページリセットはMCPの接続一覧・コマンド一覧・対応する秘密を一括して対象とし、範囲を確認する。通常の接続削除は参照コマンドを残す。カスタムコマンドのリセットでMCP定義や秘密を消さない。

PC交換では、外部に残した`data`のバックアップまたは同期コピーが必要。LocalAppDataだけにある共通設定バックアップを、PC故障後にも必ず利用できるとは扱わない。2台を同じ端末名で同時に使う場合は同じファイルを編集するため、自動的な端末分離・競合マージは保証しない。

## 認証・ツール確認と復旧

### 状態と操作

保存済みの`enabled`と、現在実行できるかを分ける。復旧時にキーがない、EXEがない、認証が拒否されたという理由で、保存済みの定義や公開指定を消さない。必要な条件がそろわない限り実行を拒否する。

| 状態 | 主な表示と操作 | 実行 |
| --- | --- | --- |
| Bearer欠落・復号不能 | 「認証情報が必要」／「認証情報を再設定」 | 拒否 |
| 明示環境変数が必要で未登録 | 「環境変数の再設定が必要」／接続編集 | 拒否。必要な環境を省いたstdio起動をしない |
| HTTP認証拒否 | 「認証を確認してください」／「認証情報を再設定」「接続確認」 | 認証拒否を保持し、確認まで利用不可 |
| EXE・作業フォルダー等が利用不能 | 「接続設定の確認が必要」／接続編集 | 拒否 |
| 無効 | 「無効」／有効切替・編集 | 拒否 |
| 有効・秘密あり・未接続 | 「未接続」／「接続確認」 | 既存の遅延接続と実行直前照合 |
| ツール削除・未対応・定義変更 | コマンドに理由と「ツール内容を確認」 | 確認・修正まで拒否 |

通常のOFF→ON操作では、既存の接続・一覧取得を試み、失敗時はそのON操作をOFFへ戻す。復元されたONや、認証の再設定・名前編集に、このON操作の失敗処理を流用しない。遅い通信結果で新しい設定を上書きしない。

OFFの接続には確認のための暗黙の一時有効化を行わず、有効化の操作へ案内する。認証・接続確認のために公開設定やAppDock全体の操作許可を変更しない。

「認証情報を再設定」は既存serverIdの編集ダイアログを認証欄に合わせて開く。新しい接続行やコマンドを作らない。OKで暗号化保存し、キャンセル・保存失敗・競合では既存値を保つ。入力中の秘密はダイアログ内だけに保持する。通信は保存と別の「接続確認」から行い、保存成功を認証成功と表示しない。

再設定・接続確認はinitializeとツール一覧取得までとし、ツールの実行はしない。成功時に該当接続の認証エラーと関連コマンドの状態を更新する。認証変更で既存接続・進行中要求は現在の寿命管理に従って失効・取消し、結果不明の操作を自動再送しない。

### 保存する承認内容と実行時の識別情報

識別情報の目的を次のように分ける。

| 識別情報 | 対象・用途 |
| --- | --- |
| `endpointFingerprint` | transport、正規化したURLまたはEXE/args/cwd、認証方式。接続先変更の検出。名前・順序・有効/公開設定・秘密は含めない |
| `definitionFingerprint` | 接続先から取得したツール定義全体。名前、説明、入力/出力Schema、注釈等の変更検出。秘密・取得時刻は含めない |
| 実行時の接続identityと`toolRevision` | 秘密・接続設定を識別する現行の値を維持する。接続世代の検査と組み合わせ、現在の通信と外部APIの最新照合・取消・キャッシュ失効を管理する |

fingerprintは本体所有の共通関数でJSON objectのキー順を正規化して算出し、配列順・値は保持する。定義が変わったのに同じものと扱うための正規化はしない。正規化方式は`toolBinding.version`と一緒に管理し、未対応版は再確認を必要とする。

新規登録と実行内容変更時は、無効・非公開の未確認保存を除き、取得済みの最新カタログ・接続先・引数を確認して2つのfingerprintを保存する。変更されたbindingを設定操作の引数として送るだけでは承認にならない。確認時のrevision・接続identity・ツール定義が保存時まで一致することを検査する。端末ファイルの読込みでは保存済みbindingを受け付け、実行前に実際の接続・ツールと照合する。ローカル設定ファイル自体への書込み権限を暗号署名で保護する設計ではない。

実行時は元callerの文脈で最新ツールを取得し、保存済みbindingと引数を照合してから、その取得結果の現在の`toolRevision`を共通`McpClientService.start`へ渡す。通信準備中に接続・認証・公開許可・定義が変われば既存の検査で拒否する。検証後の値を別要求へ使い回さない。

- 新PCで同じ接続内容・同じツールを確認できれば、秘密の再入力・再暗号化だけでコマンドを作り直したり全件再保存したりする必要はない。
- 接続先やツール定義が異なる場合は「ツール内容を確認」を表示し、現行の説明・Schema・引数を確認して「現在の内容を採用」で保存する。閲覧・再接続だけで採用しない。
- 既知の変更時は理由付き利用不可とする。再起動後にカタログがない場合は実行時照合を行う。ツールが削除されていても名前・引数・IDを保持し、同名の別サーバーへ結び直さない。
- APIで公開する既存の`toolRevision`を安定fingerprintへ置き換えない。外部からの直接ツール実行も従来どおり最新`toolRevision`を要求する。

### 新PCでの復旧手順

1. バックアップした`data/settings-<端末名>.json`と必要な共有設定を戻し、同じ端末名で起動する。ファイルの端末名検査は既存のまま使う。
2. MCPクライアントの接続一覧に、復元した名前・ID・設定と認証の不足状態を表示する。復元したMCPツールコマンドのIDと割り当て参照を保持する。
3. 「認証情報を再設定」でBearer・環境変数を入力する。EXEパスやURLが異なる場合は同じ接続行を編集する。
4. 「接続確認」で最新ツールを取得する。変化のないコマンドは利用可能になり、接続内容・ツール定義が変わったコマンドだけ明示確認する。
5. 保存済みの公開指定とは別に、このPCのApplet/MCP操作許可を確認する。復旧のために全体の許可を自動でONにしない。

## 設定画面

MCPクライアントの同じ設定ページに、フォーム内の「接続先」「MCPツールコマンド」「ツール確認」の3タブを置く。接続一覧とコマンド一覧の検索・順序・選択は混ぜない。タブ選択は一時UI状態とし、新しい保存設定を増やさない。現在の接続試験・ツール試験・ジョブ表示/取消は「ツール確認」へ集約し、ジョブを永続化しない。

- 保存場所は「端末別」で固定表示し、秘密はPC専用領域で保護する旨を説明する。旧共有名簿だけのJSON編集は廃止し、このページはフォームに統一する。非秘密設定の機械的な編集は共通設定APIで提供する。
- 接続一覧は名前・接続方式・現在の状態・操作を基本とする。復旧が必要な行に理由と再設定/編集への入口を表示し、認証の不足で編集・削除を非活性にしない。全体破損時だけ上記の復旧制約を適用する。
- 接続ダイアログは既存の共通一覧＋`SettingsDialog`を使い、登録名・読み取り専用ID・接続方式・接続先・認証をまとめる。接続確認の結果と保存結果を分ける。公開設定と起動の詳細も同じダイアログ内で編集する。
- コマンド一覧は名前・接続先/ツール・有効状態・操作・割り当てへの移動を基本とする。カテゴリ、説明、公開状態、利用不可理由を既存共通部品で表示する。新たな種類選択は不要。
- コマンドダイアログは名前・説明・カテゴリ・有効・MCP公開と、接続先・ツール・引数を編集する。timeout・Schemaは詳細欄に置く。既存の`McpCommandFields`のツール探索・ページ取得・引数入力・仕様確認を分離して再利用し、同じフォームを複製しない。
- サーバー削除は参照コマンドの件数を示して確認する。コマンドは残し、接続先未登録として編集可能にする。サーバー名の一致で再接続しない。
- 「ツール確認」から「コマンドとして追加」を開ける。選択中のserverId・ツール・引数を初期値として渡すだけとし、追加のOKまで保存しない。試験実行自体はコマンドを登録しない。
- 一覧・削除確認・並べ替え・フォーカス復帰・Enter/Escape・IME・明暗/狭幅は[共通一覧編集](settings-list-editing.md)と[UI指針](settings-ui-guidelines.md)に従う。エラーは操作したダイアログ内に出し、入力を保持する。
- 認証・接続・ツール状態はSettingsPageModelのauxiliaryとrevision更新で反映する。rendererのタイマーや状態の独自キャッシュを追加しない。名称・説明・検索・アクセシブル名・移動リンクの翻訳を揃える。

## コマンド基盤とAPI

### 所有サービスと共通実行

`McpClientSettings`を新ブロックと秘密の所有サービスへ変更し、接続の管理APIと設定ページの保存を同じ経路へ接続する。MCPツールコマンドのCRUD・表示投影・binding検証は、本体の`McpToolCommandService`として分離する。`CustomCommandService`へ端末別定義を混ぜたり、見えないカスタム種類として残したりしない。

実行は既存のCommandDispatcher・共通入力計画から`McpClientService`へ接続する。スタックのfirst/all/count、条件、再入防止、取消、元caller/直接callerの保持を別実装にしない。保存サービスごとの一覧を合成する箇所と実行先の照合を共通化し、以下の全入口を同じ登録済みIDへ揃える。

- パレット、共通コマンド選択、コマンドトリガーの逆引き、ショートカット、マウス/タッチパッド、スタック。
- リボン、トレイ、説明文のコマンドリンク、公開`commands.list/execute`。
- 未登録コマンドの表示、利用可否、コマンド編集への移動、設定検索、一覧キャッシュの更新。

`customDefinitionId`をMCPツールコマンドの識別へ流用しない。編集先のメタデータを明示し、MCPクライアントの該当コマンドへ移動する。共有のトリガー/スタックに端末固有IDが保存されて他PCへ届いた場合は、未登録・利用不可として保持する。入力の実行対象やブロック判定からは既存の利用不可規則で除外し、割り当て自体を自動削除しない。

MCP公開はコマンドの`automation`、接続の`published/publishedTools`、現在のMCP/Applet操作許可と元callerの条件をすべて満たす場合に限る。ローカル入力の権限へ格上げしない。ハンドラーの戻り値は既存と同じジョブ受付を表し、外部効果の完了を意味しない。監査へ引数・秘密・結果本文を出さず、失敗通知と取消は共通経路を使う。

### 接続設定の既存API

`mcp.servers.getSettings/updateSettings/inspectTools`と共通設定対象`service.mcp.servers`を維持する。非秘密の接続項目・ID・基本操作は維持し、保存先を端末別へ変更する。復旧で秘密が欠けた行も読み取り・名前編集できる。共通APIとローカルUIの可否は同じ所有サービスから投影する。

秘密の取得・設定・消去、環境変数の名前・値、認証ファイルの初期化は外部へ公開しない。秘密付きの行、またはBearer/環境変数を必要とする復旧待ちの行の接続先変更・削除は、外部APIから拒否する。秘密が欠けたことだけで従来の保護が外れないようにする。ローカル編集では接続先と秘密のbindingを同時に更新できる。

管理保存はread + write、探索は既存のread + execute + useMcpを使う。管理保存・dryRunでは接続・stdio起動・ツール実行をしない。許可の変更は従来のローカル設定に限定する。`requiresEnvironment`は外部から編集できず、秘密の有無と一緒に本体が管理する。

### MCPツールコマンドの管理API

共通設定の固定6入口にlist対象`service.mcp.toolCommands`を追加する。登録・部分編集・削除・並べ替えを提供し、専用の外側MCPツールは増やさない。外部でtargetIdを合成させず、対象一覧とSchemaから探索する契約を維持する。

- 通常項目はtitle/description/category/enabled/automation/serverId/toolName/arguments/timeoutMs。IDは読取り専用で追加時に本体が発行する。本体所有の対象とし、MCPからの設定読書きは既存のread/writeを使う。Appletから本体所有のコマンドを管理する権限は追加せず、公開済みコマンドの実行は既存の共通APIと許可に従う。
- bindingのfingerprintを外部のset項目として公開しない。無効・非公開の未確認保存を除き、実行内容の新規登録・変更・有効化・公開追加には、管理用ツール探索で得た`toolRevision`を検証用の仮想フィールドとして必須にする。これは端末JSONに保存せず、本体が現在のカタログと照合してbindingを生成する。
- 概要には非秘密の利用可否・確認が必要な理由を返す。既存値の詳細取得では、最新の取得済みカタログと保存bindingが一致する場合だけ仮想`toolRevision`を返し、未取得・変更ありなら未設定とする。読取りや候補取得で勝手に接続しない。
- 名前等だけの編集と無効化・非公開化・削除はツール取得を要求しない。実行内容変更時に古い`toolRevision`、接続identity、設定revisionを検出したら再取得を求め、保存済み引数を変更しない。
- 複数行の検証と保存を原子的に行う。`expectedRevision`、`schemaRevision`、dryRun、無変更の扱いと`completion:settingsSaved/effectVerified:false`は共通設定APIに従う。保存はツールを実行しない。
- APIキー等の復旧はローカルUIで行い、外部には安全な不足状態と対処を示す。認証を自動解除したり別サーバーへ切り替えたりしない。

旧`customCommands.types/list/get/update`はMCPの種類・新コマンドを扱わない。他の本体/Applet提供種類・カスタムコマンドAPIは維持する。旧種類を指定した追加は拒否する。

## 旧設定を引き継がない境界

- 共有/端末JSONの旧`mcpServers`、旧`customCommands`内の本体種類`appdock.mcp.call`、旧PCファイル`mcp-client.json`を新形式へ取り込まない。新しい接続・コマンドは空から開始する。
- 旧PCファイルは読込・復号・コピー・自動削除しない。新しい秘密ファイル名により、旧キーだけが新設定へ結び付くことを防ぐ。
- 旧設定項目は実行時投影から除外し、そのファイルを通常保存するときに対象の旧項目だけを除去する。他のカスタムコマンド・Applet設定・割り当て・UI状態は保持する。設定ファイル全体の削除や全端末のファイル走査はしない。
- 旧コマンドIDを参照する割り当ては自動で変換・削除せず、未登録として編集・削除可能にする。新規登録したコマンドは新しいIDを使う。
- 旧ブロックの未知版・不正JSONを正常な新設定に変換して上書きする処理は作らない。既知の旧形式の対象項目除外と、共通の破損・未知版保護を別に検証する。

## 実装の担当

- `mcp-device-settings`・`DeviceSettingsStore`: 自端末の投影・保存分離・journal回復。
- `McpClientSettings`: 接続設定、暗号化秘密、再入力・初期化、設定APIの保護判定。
- `McpToolCommandService`: 独立したコマンドCRUD、安定ID、承認と現在の通信の照合、共通dispatch。
- MCP設定フォームと固定の設定API対象: 同じ所有サービスで編集し、秘密の操作はローカルに限定する。
