# リボン拡張の実装計画

状態: 第1段階0.65.0／第2段階0.66.0の実装済み。更新日: 2026-10-19。設計の基準はAppDock 0.64.0、main `459b649`。[拡張設計](ribbon-customization-design.md)を正本とする。実測結果と未確認範囲は[検証記録](../VERIFICATION.md)へ分離する。

## 推奨する分割

実装は2段階とする。第1段階は見た目・名前・共通の色選択、第2段階はコマンドを実行する入口をまとめる。先に小さな変更で保存・ダイアログ・Shell投影を確かめ、同じコマンド解決を必要とするボタンと右クリックを一緒に仕上げる。

| 段階 | 範囲 | 完了時に動作確認できるもの |
| --- | --- | --- |
| 1. 装飾と名前 | 共通パレット、グループ枠と連結線、色なし、セパレーター名 | 色の確定と取消、開閉、名前の保存、再起動後の復元 |
| 2. コマンド実行 | 任意コマンドボタン、共通アイコン選択、動作設定カード、右クリックの割当 | 本体・Applet・カスタムコマンドの実行、停止時の無効化、両方の展開方式 |

各段階は本体と同梱Default Shellを一緒に実装・検証・通常publishする単位とする。段階内部の作業項目ごとに版を増やさない。今回は0.64.0から、第1段階0.65.0、第2段階0.66.0で進めた。後続の修正・検証再試行だけでは同じ版を重ねて増やさない。

色だけをCSS修正として先に出すことや、コマンドボタンと右クリックに別々のコマンド一覧・実行サービスを作ることは避ける。各段階を利用者が動作確認できる状態まで完成させる。

## 着手前の準備

1. 現在のbranch・追跡先・作業ツリーを確認し、クリーンな場合は[開始前の最新取得](development-workflow.md#設計実装の開始前)を行う。既存変更を退避・破棄しない。
2. この設計と、設定・Shell・リボン編集の現在の仕様に差がないか確認する。保存上限と既存の公開契約を再確認する。
3. 検証資料を`.artifacts/ribbon-customization-<日付>-<段階>/`へ保存する。入力hash、実行コマンド、成功ログ、配布物hash、未確認項目を最初から記録する。

## 第1段階: 装飾と名前

### 1A. 保存と編集操作

- `RibbonGroup.color`、`RibbonLayout.separatorTitles`、色・名前の共有検証を追加する。
- `parseRibbon`と`editRibbon`でグループ追加／変更、セパレーター名変更、削除・初期化を対応する。
- `RibbonCommands`のlayoutOf、公開Schema、items、dryRun／保存へ同じ項目を接続する。既存の未知フィールドと未導入項目を保持する。
- 色なし・欠落の解釈、IDを変えない名前変更、同値保存、複数操作の原子的保存、保存失敗を先に確認する。

### 1B. 共通パレットと編集ダイアログ

- settings-uiの`SettingsColorPicker`でパステル既定・くすみ・ベーシックの候補切り替え、自由選択・HEX・色なしを同じ値へ接続する。不要な可視ラベルと説明は省き、アクセシブル名を保つ。不正値は入力欄の赤い枠と`aria-invalid`で示す。
- グループダイアログの最下部へ色選択を置き、独立した枠／線の見本は表示しない。実リボンへの反映は確定後とする。
- セパレーター行に編集ボタンを加え、名前だけのダイアログを既存の`SettingsDialog`で開く。
- 文字入力・IME・不正値・取消・外部更新との競合・保存失敗・フォーカス復帰を確認する。

### 1C. Shell描画

- schema 2のグループへ任意の色を投影する。schema 1への色の混入と、不要なschema版変更を避ける。
- Default Shellのボタン枠と`.ribbon-children`の縦線を同じ2pxの色へ接続する。左辺・余白・角の接続をそろえる。
- 色なしでは両方を非表示にし、通常ボタンの選択マーカーとフォーカス表示を保つ。
- 持続的の開閉、一時的グループの枠、上下配置、スクロール、明暗、ズームで表示を確認する。

完了条件はC01〜C05、S01〜S03、P01〜P03、F01。第2段階の未使用設定やボタン用の半完成UIを先に保存形式へ追加しない。

## 第2段階: コマンドボタンと右クリック

### 2A. コマンド解決と保存

- `RibbonCommandButton`、button ID、`rightClickCommand`、追加・変更・削除・割当操作を共有型と編集サービスへ追加する。
- 本体コマンド`appdock.ribbon.settings.open`を通常のカタログと実行経路へ登録する。現在の固定右クリックと同じ画面を開くことを確認する。
- 本体・カスタム・Applet管理・Applet提供コマンドの既存カタログから、現在の利用可否と所有者を解決する処理をコマンドボタンと右クリックで共用する。
- 表示投影から保存へ渡る定義と、callerに応じて機密項目を省略する外部投影を分ける。外部の一部省略された読取結果を保存型として再解析しない。
- 新規ボタンは現在のカタログから選択し、保存済みの未知コマンドは保持する。停止・再登録・許可変更で表示を再投影する。

### 2B. 設定画面

- 固定アイコン一覧と`RibbonIconPicker`をグループ／ボタンで共用する。画像登録機能は後続とする。
- 上下の追加ツールバーと、コマンドボタンの追加／編集／削除ダイアログを対応する。既存のグループ内移動・非表示・順序操作を使う。
- 「動作設定」を最上部の独立カードとして追加する。初期折りたたみ、「右クリックのコマンド」と指定説明を実装する。
- 下に「リボン編集」カードを同じ階層で配置し、外側に共通のカード枠を重ねない。第1段階の色／名前編集と既存の上下一覧をこのカード内へまとめる。
- リボンの設定カタログ・検索アンカー・フォーム／JSON・入力セッション投影に新項目を接続する。検索では左側の既存導線を使う。
- 初期化操作は編集側だけに適用し、右クリック割当を維持する。削除・解除・初期化の確認文と、設定へ戻る方法の案内を更新する。

### 2C. 表示と実行

- 保存用のコマンド項目を、表示用の通常buttonとactionIdへ投影する。Rootと持続的／一時的グループの子で同じ実行を使う。
- コマンドボタンは実行後にページ選択状態を勝手に変更しない。未登録・停止・無効では無効ボタンと理由を表示する。
- contextActionIdの契約を保ち、contextActionEnabled／contextDisabledReasonを追加する。現在のcontextActionIdの例外経路も任意コマンドの実行可否を再照合する。
- ローカルShellはinvokeを使い、任意のexecuteCommandを許可しない。Applet／MCPは元のcallerと公開宣言、実行・追加許可を維持する。
- 右クリックはリボン内で1回だけ受け付ける。一時パネル内の右クリックの現行挙動を巻き込まない。
- 同一requestIdの再送と実行中の再入、実行受付後の一時パネル閉鎖、提供元停止、Shell故障・復帰を確認する。

完了条件はB01〜B06、R01〜R04、P01〜P04、F01。第1段階の成功結果は対象入力・条件・hashを照合して再利用し、後続変更の影響があるものだけ再実行する。

| ID | 確認する内容 |

| C02 | 指定色と2pxの太さが枠・接続部・縦線で一致。開閉・色変更で配置が動かない |

| S01 | 名前変更後もID・順序・グループ所属・表示状態を維持し、再起動後に名前が復元する |
| S02 | 空欄で自動生成名へ戻り、80文字・制御文字・未登録IDを適切に検証する |
| S03 | セパレーター削除／初期化でその名前だけを除去し、連続区切り線の既存の省略動作を維持する |
| B01 | 本体・Applet・カスタム各コマンドで、ボタンの追加・編集・保存・再起動後の実行ができる |
| B02 | 上下配置・グループ内配置・並べ替え・非表示・グループ解除・ボタン削除が他の項目を壊さない |
| B03 | 未登録・停止・無効・実行不可の理由を表示し、自動起動せず、再登録で利用可否が更新される |
| B04 | 同一requestIdで1回、実行中の重複／取消／失敗／対象停止は既存の契約どおり。読取・保存・dryRun・取消の実行回数は0 |

| R02 | 省略時と既定コマンド選択時にリボン設定を開き、別コマンドへの変更が即時反映・保存される |
| R03 | 通常ボタン・グループ・セパレーター・余白からの右クリックを各1回処理。未登録先は保持して実行せず、別の設定導線を利用できる |
| R04 | リボン初期化でコマンドボタン・色・名前・配置を初期化し、別カードの右クリック割当を維持する |
| P01 | フォーム／部分JSON／外部編集が同じ検証を使い、revision・競合・保存失敗・同値操作・未知フィールド保持が一致する |
| P02 | ダイアログの取消・保存失敗・検索／画面切替・フォーカス復帰を確認し、実利用設定へ書き込まない |
| P03 | schema 1の既存投影とschema 2の任意追加項目、追加情報を使わないShell、Default Shellへの復旧を確認する |
| P04 | Applet／MCPの公開・非公開コマンドと各許可で表示・読取・実行が一致。ボタン経由／右クリック経由で非公開コマンドを実行できない |
| F01 | レビューと必要な修正後の固定EXEで重要経路が成功し、本体・Default Shell・feedの版／hashと保存復元を確認する |

既存の`ribbon-groups`、`ribbon-commands`、`ui-presentation`、`settings-page`、`settings-page-host`、`settings-sync`、`shell-boundaries`、`shell-region`の関連単体試験を影響から選ぶ。GUIは既存の`ribbon-groups-ui-test.cjs`と`ribbon-layout-ui-test.cjs`を拡張し、必要なコマンド用fixtureを使う。共通入力基盤やShellに追加変更がなければ、無関係な全機能試験を毎回繰り返さない。

見た目はDOMのstyle値だけで完了にせず、固定EXEの実描画で枠と線の接続を確認する。コマンドの受付と実効果を分け、試験用カウンター／専用入力先・試験用プロセス・隔離MCPを使う。実利用先の照明、メール、壁紙などを回帰確認のために操作しない。物理入力・複数DPI・他PCの実確認と、隔離fixtureの成功を区別して記録する。

## 各段階の完了と引き渡し

[共通手順](development-workflow.md#実装)に従い、必要な型検査・本体／Default Shellビルド・関連試験、発行前レビュー1回、必要な修正と再検証を行う。設定追加を含むため、その段階の対象モジュールを1回だけマイナー更新し、本体の`publish.bat`で通常発行する。最終固定EXEの隔離起動・保存復元・対象機能、版・サイズ・SHA256を確認する。

レビューの対象と結果、修正、使い回した試験と根拠、未実行・未確認、発行物をVERIFICATIONへ残す。依存・lockfile・実利用設定を保持する。コミット・プッシュ・公開Release・実利用先deployはそれぞれの明示依頼に従う。画像の登録はこの2段階の完了後の別機能として扱う。
