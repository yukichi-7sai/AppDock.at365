# 設定JSONの既定値省略とページリセット

状態: AppDock 0.72.0で実装（2026-10-20）。[設定基盤](settings-foundation.md)、[端末別設定](device-settings-design.md)、[設定同期](settings-sync.md)の保存・競合・復旧契約を維持する。実測・発行物は[検証記録](../VERIFICATION.md)を参照する。

## 決定

- 設定JSONは既定値との差分を表す。項目の省略は「現在の版・現在のApplet宣言の既定値を使う」を意味する。将来の版で既定値が変われば、省略した項目は新しい値に従う。
- フォームには実際に適用する値を表示し、JSONモードには既定値と異なる値だけを表示する。全項目が既定値なら、そのページのJSONは`{}`となる。
- フォーム・JSON・設定コマンド等の共通保存経路で既定値を省く。既定値の補完は読み込み・実行時だけ行い、補完した値をそのままファイルへ戻さない。
- ページのリセットと、PC用設定を削除して共有へ戻す操作を分ける。前者は既定値、後者は現在の共有値を使う。

## 既定値と比較単位

本体は既存の設定スキーマ、Appletは宣言済みsetting.default、startupDelaySeconds、pagesのdisplayを正本とする。既定値を別の固定表へ重複させない。宣言が取得できないAppletの設定・未宣言キーには既定値を推測せず、保存済みの値を保持する。

objectは既知の既定値と再帰比較し、差分がなくなった親objectも省く。配列は順序を含む一つの値として比較し、要素単位の差分や番号キーへ変換しない。空配列、false、0、空文字、nullは、それぞれの既定値と一致する場合だけ省く。未知キーは省かない。危険なprototypeキー、型、深さ、サイズの既存検証は維持する。

動的ページのリセットは、そのページに宣言された編集対象フィールドだけを扱う。親の登録一覧、項目ID、他の子ページ、保存先を維持する。子ページで既定値が省略されたフィールドは、親のobject-list内の同名フィールドの既定値を継承する。配列内の登録情報は通常の配列として保持し、既定値との差分表示と必要な登録構造を区別する。画像ライブラリーのリセットでも原画像ファイル・session・Secrets等を削除しない。

動的ページの登録行については、宣言されたフィールドの既定値も保存時に省く。登録IDと配列の順序を保ったまま、読込時に親・子の宣言から行の既定値を補い、ページ一覧のドメイン検証へ渡す。これにより子ページのリセット後も将来の既定値へ追従できる。通常の配列の要素削除や部分マージを意味しない。

## ファイルと互換性

- 共有ファイルのschemaVersion、端末ファイルのschemaVersionとmachineName、保存モード、有効状態、初期設定適用済み記録、保存済み識別情報は設定値の省略とは別に保持する。
- 共有・端末ファイルは省略形と従来の全項目形式を読める。設定ページの`{}`と、ファイル全体の管理用構造を区別する。実行時は検証済みの補完値を利用する。
- 起動・閲覧だけを理由とする既存ファイルの書き換えや移行処理を追加しない。実際に保存する対象ファイルだけを省略形で保存する。
- 認証、操作許可、アカウント名簿、ログ、session、画像本体等の別保存領域を汎用リセットへ含めない。JSON編集のないページにはボタンを出さない。
- 端末専用Appletは設定一式を共有から独立させる。端末JSONからキーを消した場合も共有値を復活させず、Appletの既定値を使う。
- バックアップと複数ファイルトランザクションも実際の省略形bytesを扱う。journalのafterと実際に書くbytesを一致させ、途中失敗・外部変更・再起動時の復旧規則を維持する。

## JSON編集

JSONを`{}`に置き換えると、そのページの編集対象だけが既定値に戻る。部分的にキーを削除した場合は削除した項目だけが既定値となる。空のテキストや不正なJSONは従来どおり入力エラーとする。

フォーム用の補完済み投影とJSON用の差分投影を分ける。JSON操作のbeforeも差分投影で検査し、既定値を省く表示によって競合検査が緩くならないようにする。ページ外キーは引き続き拒否する。フォーム側では別項目の変更を保持する。

## ページリセット

JSONを持つページのツールバーに「このページを既定値に戻す」を配置し、フォーム・JSONの両モードで表示する。確認にはページ名、対象保存先、共有の場合は他PCにも反映されることを表示する。

リボン設定もこの共通操作へ統一する。配置と動作設定の右クリック割当をまとめて既定値へ戻し、リボン編集の下部には初期化専用ボタンを置かない。公開APIの配置編集`reset`が右クリック割当を保持する契約は維持する。

確認開始時の対象ページ、保存先signature、revision、ページ値を保持し、確定時に再確認する。対象・保存先・値が外部で変わった場合は上書きせず、確認し直せるエラーにする。未確定入力は通常のblurで先に確定し、不正入力が残る場合は修正または再読み込みを案内する。キャンセルでは変更しない。

確定後は既存の検証・prepareSettings・WindowsLaunch・保存経路を通して1回だけ保存し、成功時だけ閉じる。保存先モード、Appletの起動状態、対象外ページ、認証等を維持する。起動設定は既存のOS登録トランザクションを利用する。JSON表示は`{}`となり、再起動後も既定値のキーを再生成しない。

## PC専用から共有への切り替え

ONからOFFへの操作は共通SettingsDialogで選択してから確定する。

| 選択肢 | 保存と適用 |
| --- | --- |
| このPCの設定を共有設定に反映する | 対象Appletのsettings・startupDelaySeconds・pagesを共有側で置き換え、PC用configurationを削除してOFFにする。他PCにも反映されることを表示 |
| このPCの設定を削除して共有設定に戻す | 共有側を変更せずPC用configurationを削除してOFFにし、最新の共有値を適用 |
| このPCの設定を残して共有設定に戻す | 従来互換の操作。configurationを保持してOFFにする。既定の選択肢 |

反映は対象Appletの設定一式を置き換える。消したローカルキーを共有側の旧値で補わない。enabled、updateSource、リボン、ショートカット、他Appletをコピーしない。子ページのPC専用有効状態は共有へ漏らさない。

反映・configuration削除・モード変更は既存の2ファイルトランザクションへまとめる。保存失敗時は設定とモードを復元する。共有が読めない・不正な場合はOFFを成立させない。確認後の外部変更をrevisionで拒否する。成功通知のための再試行は行わない。

OFF後に再ONした場合、保持済みconfigurationがあれば再開し、削除済みなら現在の共有設定をコピーする。本体の常時PC専用ページや子ページには独立した保存先切り替えを追加しない。

## 実装箇所と検証

共通の既定値比較と補完、SettingsStoreのserialize codec、DeviceSettingsStoreのserialize/journal、ページ投影とJSON適用、SettingsInputSession、settingsPage操作、共通SettingsPageLayout/SettingsDialogを変更する。

検証は本体・Appletの省略/再読込、既定値へ戻したキーの実ファイル非生成、false/0/空配列、未知キー保持、全JSONページの`{}`、対象外ページ保持、子ページの識別保持、PC専用の共有値非復活、OFFの3経路、古いrevision/保存先拒否、保存失敗とjournal復旧、固定EXEで両モードのリセットと保存先切り替えを含める。実際の別PC同期・UAC承認・実アカウント削除は隔離試験から成功を推定しない。

保存JSONの必須項目省略は旧版の読込契約に影響するため、本体をマイナー更新する。同期して使う本体は同じ対応版へ揃える。変更しないAppletの版更新・再発行は行わない。
