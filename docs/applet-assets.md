# Appletとライブラリーアセットの実装方針

画像・音声など、ライブラリーへ保存して繰り返し使うアセットは本体が登録・管理し、Appletは共通の参照を使う。この文書を、新しいアセット機能と外部APIを設計するときの共通方針とする。現在使えるAPIの契約は[Applet API](extensions.md)、[登録画像](registered-images.md)、[素材ライブラリー](asset-libraries.md)を参照する。

## 登録と選択

Appletから利用者に画像・音声を登録または選択してもらう場合は、本体のライブラリー機能と共通UIを呼び出す。Appletごとに取り込み、検証、分類、保存、選択のUIや保存領域を作り直さない。Profileの画像設定のように、宣言型設定から本体の共通選択機能を利用する。

原素材と設定用保管コピーの寿命を区別し、既存の登録・検証・保存・取消処理へ接続する。利用者が選択を取り消した場合は、Appletの設定を確定しない。Appletから任意のbytesを登録する入口を、共通UIの代わりに追加しない。

## 参照とURL

Appletがライブラリーのアセットを使うための新しい取得機能は、種類ごとの共通参照から利用時のURLを得る形にまとめる。生成元にかかわらず同じライブラリーの取得経路を使い、生成結果専用の画像取得APIやURL取得APIを作らない。画像・音声本体を通常の操作メッセージへBase64で載せることや、そのためだけの分割取得APIを標準にしない。

設定にはライブラリーの参照を保存し、一時URLや生成ジョブIDを永続参照として保存しない。既存の参照形式・設定用保管コピーを使い、URLの導入だけを理由に新しいID体系や一括移行を追加しない。

URLを実装する際は、利用先のAppletプロセスまたはローカルページから実際に取得できる経路、許可、所有者、公開対象、失効時点を定義する。本体renderer専用の`appdock://` URLを、そのまま外部プロセスで使えるURLと扱わない。任意パスや無関係な素材を公開せず、保存場所の切替・ファイル変更・削除・画面終了後の扱いも検証する。配信時の分割読込は転送処理の実装であり、アセット全体の容量上限とは分ける。

## 生成して登録するAPI

アセット生成を追加するときは、「サーバーとプロンプトを指定して、生成画像をライブラリーに登録する」操作をUIとともに設計し、AppletとMCPの両方から利用できる共通APIにする。音声などにも同じ登録までの方針を適用する。生成だけを依頼して一時的な画像・音声やそのURLをAppletへ返す操作は公開しない。登録完了後はライブラリーの共通参照を返し、実体の利用は共通のURL取得へ接続する。

非同期の受付と登録完了を区別する。受付時のジョブIDは処理の追跡用、完了結果の参照は登録済みアセット用とする。生成だけの完了を登録完了と扱わない。接続一覧・ジョブ状態取得・取消は付随するAPIとして維持し、後続実装で登録までの状態と取消、MCPの公開先・許可・所有者判定へ接続する。具体的な生成登録の操作名、引数、戻り値、保持期間、重複要求の扱いはAPIとUIの実装時に定義する。画像生成の許可には、現在の「操作の許可」の画像生成AI（`useImageAi`）を使い、MCP側の対応も同時に整える。

本体内部では生成と登録を独立して再試行できるようにする。登録失敗を理由に再生成せず、保持中の生成結果で登録を再試行する。ファイル登録後に分類の保存だけが失敗した場合も、登録済みアセットを保持して残りの処理を再試行する。生成ジョブ、登録処理、登録済みアセットの寿命と取消を混同しない。音ライブラリーの保存再試行を既存の参考実装とする。

## 内部機能と公開APIの境界

Appletへの公開を終了しても、本体で使う生成・取消・結果保持・検証・登録などの内部機能は削除しない。本体の設定試験やライブラリーのUIは、引き続き内部サービスを利用できる。内部プレビューの取得方式をAppletの公開契約へ流用しない。

その場での読み上げを依頼する`tts.speak`や本体の共通音声再生は、保存用アセットの取得とは目的が異なるため維持する。読み上げを自動的なライブラリー登録へ変更しない。Applet自身が作るページ画像やStorageの既存契約も、この方針だけを理由に変更しない。

## 現在の提供範囲と後続実装

| 対象 | 現在の状態 |
| --- | --- |
| 本体のライブラリー登録・選択 | 既存の共通UI・宣言型設定を利用する |
| 登録画像参照・`copyToCache`・ページ画像・`audio.play` | 既存契約を維持する。共通URLへの置換はまだ行っていない |
| 本体の画像生成AI設定・試験 | 生成・表示・取消などの内部機能を維持する。試験結果は一時保持で、ライブラリーへ登録しない |
| Appletの画像生成接続一覧 | `ai.image.connections.list`をread + useImageAi許可で提供する。認証情報やプロンプトは返さない |
| Appletのジョブ状態取得・取消 | `ai.image.jobs.get`（read）と`ai.image.jobs.cancel`（read + execute）を維持する。呼び出し元のジョブだけを扱う。本体の試験ジョブにはアクセスできない |
| Appletの生成単体・生成結果取得 | `ai.image.generate`と`ai.image.results.read`を公開しない。Node/.NETとも汎用Callから実行できない。本体内部の256KiB分割取得は維持する |
| 画像生成AIの操作許可 | `useImageAi`の項目・保存値を維持する。現在の接続一覧と後続の生成・登録APIに使用する。MCP列は引き続き未対応 |
| 共通アセットURL取得 | 後続実装。全アセットをAppletから取得できるAPIが既にあるとは扱わない |
| 画像を生成して登録するAPIとUI | Applet/MCP共通APIとして後続実装する。今回の公開終了と同時には追加しない。付随APIのMCP公開も後続実装とする |

Applet通信の1MiB制限は別の検討対象とし、この整備では変更しない。公開APIの整理、実体の配信方法、通信路の制限はそれぞれ独立して扱う。
