# ドキュメント方針

AppDockと各AppletのREADMEは、インストール方法とビルド方法だけを簡潔に載せる入口です。機能・操作・設定・既定値などの説明は開発文書へ集約します。今後作成するAppletにも同じ構成を適用します。

| 文書 | 読者と内容 |
| --- | --- |
| `README.md` | インストール方法、ビルド方法。詳しい文書への短いリンクを含める |
| `DEVELOPMENT.md` | 開発文書の入口。機能・操作・設定の案内、開発環境、依存ソース、ビルド、テスト、発行、開発者用の配置、実装の補足への参照 |
| `docs/usage.md` | アプリの機能、動作環境、必要なホスト版、操作方法、設定、既定値、更新操作、保存先、互換性、制約、困ったときの対処 |
| その他の `docs/` 内の開発文書 | SDK・API・内部構造などの機能別の正本。共通仕様を重複させずリンクする |
| `VERIFICATION.md` | 実行した検証、その条件と結果、成果物の版・ハッシュ、未確認事項。手順そのものは開発文書を参照する |

## 切り分けの判断

- READMEの見出しは「インストール方法」「ビルド方法」の2つにします。アプリ名のタイトル以外に、概要・機能一覧・設定・既定値などの章を追加しません。
- 本体のインストール方法は、Releasesから`AppDock.at365.exe`をダウンロードして任意の書き込み可能な場所へ置くことと、Applet同梱のオールインワンZIPを展開して起動できることだけを簡潔に記載します。アセット名は配布スクリプトと揃えます。
- Appletのインストール方法は、配布物一式を本体の`extensions`へ置き、有効にするまでを短く記載します。
- READMEのビルド方法には、必要な開発環境、既存のビルド・発行コマンドと出力先、開発ガイドへのリンクを記載します。テスト・開発者用配置・公開の詳細手順はDEVELOPMENTへ置きます。
- 機能・操作・設定・既定値・JSON例・コマンドID・保存先・互換性・制約は`docs/usage.md`へまとめ、DEVELOPMENTの冒頭からリンクします。機能別の詳細が既存文書にある場合は、その文書を正本として参照します。
- Runtimeと最低ホスト版は`docs/usage.md`、開発に必要なSDKの詳細はDEVELOPMENTへ記載します。最低ホスト版はmanifestと照合します。
- 検証の実行結果と未確認事項はVERIFICATIONへ記録します。現行の説明へ実装完了報告を積み重ねません。

## 新規リポジトリの最小構成

```text
README.md
DEVELOPMENT.md
VERIFICATION.md       検証を実施した時点で記録
docs/usage.md         機能・操作・設定・既定値など
docs/                 その他の機能別文書
```

READMEの順序は「インストール方法 → ビルド方法」です。DEVELOPMENTは機能・操作・設定の文書への入口を先頭に置き、「必要な環境 → ビルド → テスト → 発行・配置 → 実装・詳細文書」を基本にします。未確認の機能や存在しない配布先をテンプレートから書き足さないでください。

## 現行仕様と履歴

現行仕様は現在のコードを起点に機能別へ整理します。必要な最低ホスト版、API・SDK・保存形式の版、現在の既定値と障害復旧の手順は残します。過去版からのデータ移行、完了済みの実装計画、不要な変更履歴は現行文書へ残しません。未実装の設計は状態を明示して現行契約から分けます。実測条件と結果は現行版のVERIFICATIONへ記載し、生ログとGit履歴を保持します。

## 記述と統合

会話上の人物名・呼称や発言の引用を成果物へ載せません。要件は主語に依存しない仕様として記述します。同じ契約は機能別の正本へ集約し、操作案内と各Appletからリンクします。検証記録は現行版の条件・結果・未確認事項へ絞り、保存する生ログやGit履歴とは分けます。

## 更新時の確認

1. 既存の変更を保持し、移動した手順・注意事項の欠落や重複がないか確認する。
2. 文書の場所が変わる場合は、相対リンクと他の文書からの参照を更新する。
3. READMEの設定例やコードブロックを読む既存テストがないか確認し、移動先の開発文書を読むように追従する。例の内容と検証を維持する。
4. ローカルリンク、Markdownの構造、`git diff --check`を確認する。設定例を変更した場合は関連する既存テストも実行する。
5. 文書のみの整理を、ビルド・実機動作・配置の検証済みと扱わない。実施した確認だけを報告する。

AppDockの開発文書全体への入口は[DEVELOPMENT.md](../DEVELOPMENT.md)です。
