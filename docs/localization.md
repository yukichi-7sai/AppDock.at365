# 本体の表示言語と翻訳

## 対応範囲

本体の固定文言はi18nextで管理する。本体の設定ページの本文・選択肢・ヒント・検索カタログ・アクセシブル名と、共通の一覧・編集・並べ替え・確認ダイアログを対応範囲とする。設定値の共有検証、設定ページ操作、設定健全性・Windows起動・Shell提供元・タッチパッド接続、AI/MCP接続設定の保存診断もJSONへ集約する。標準配布の基本言語は日本語（`ja`）。追加の言語は外部辞書を使う。

本体の共通サービスが返す結果・検証・診断と標準ダイアログも対象。AI/MCP/TTS、音声再生、更新・Applet管理、設定の保存・復旧、Webアカウント、画像、通知、Shell・入力・コマンドの本体所有メッセージは`services.*`へ集約する。標準ダイアログのタイトル・本文・説明・ボタン・画像フィルター名を翻訳し、ボタン順序、既定／キャンセルID、確定後の操作を維持する。OS標準のファイル選択画面そのものの言語はWindows側が決める。

本体renderer、リボン・タイトルバー・ステータスバー・サイドバー、通知センターと通知バナー、ログ、画像ライブラリーと共通ギャラリー／ダイアログも対象。本体コマンド、更新コマンド、MCPカスタムコマンドの固定ラベルと共有検証エラーも辞書から解決する。Reactの言語コンテキストと共通ギャラリーのモデル更新を使い、言語切替で一覧の選択、検索、通知の展開、ダイアログの入力を初期化しない。

本体所有の.NET入力補助・タッチパッド接続・更新処理の日本語診断も`native.*`へ集約する。入力補助は固定キーと変数を本体へ返し、本体が受信時の表示言語で解決する。例外の種類、エラーコード、操作結果の識別値を維持し、受け取った文章の文字列置換は行わない。API Schemaの説明・AIへの固定指示文、開発用の英語診断、Applet SDK自身の文言は表示翻訳と分けて扱う。利用者が編集するアクセント色カタログの名前も表示辞書とは分け、製品名・プロトコル名・単位・識別子はそのまま使う。

Applet設定に使う本体提供の共通操作（追加・編集・削除など）も対象。Applet自身の辞書・manifestの表示文言・実行時UIは[Appletの翻訳基盤](applet-localization.md)で独立して管理する。本体のhost辞書へApplet固有の文言を追加しない。

カスタムコマンド名、リボングループ名、ラベルの上書き、接続名、ファイルパス、URL、入力値、Applet提供の名前・本文を翻訳キーとして扱わない。固定文言と同じ文字列や、`language.ja`のようなキーに見える名前でも、入力された文字列を表示する。OS・外部処理のエラー詳細もそのまま差し込み、本体が説明する文章だけを翻訳する。

アップデーターには、引き継ぎ時点の言語で解決した進行画面の`services.updaterWindow.*`と、診断・結果用の`native.*`テンプレートを既存ジョブへ渡す。本体終了後や辞書ファイルの交換中も同じ文言を使い、パスなどの変数は補助プロセス内で一度だけ差し込む。本体から呼ぶ展開・検証・復旧では標準入力で同じテンプレートを渡す。保存済みの処理結果や履歴は再翻訳しない。単体CLIは配布元の`translations/host.json`を使い、辞書も引き継ぎもない開発用単独EXEでは固定キーを診断に残す。

内部の`hostTextKey`と`values`は本体所有の.NET通信だけで解決する。Applet RPCやユーザー本文は対象にしない。.NETの`NativeMessages`は共有実装を各補助プロセスへリンクし、別の日本語辞書や.NETランタイムを同梱しない。基本辞書・部分翻訳・変数検査は本体と共通で、入力設定の同期には言語変更も含め、登録エラーの表示を更新する。

## 言語設定と保存

- 「表示」→「共通」の「表示言語」で、起動時に見つかった言語を選ぶ。既定は日本語。言語名は自言語表記で表示し、選択した言語は即時反映する。
- `host.language`の既定値は`ja`。表示ページで選んだ共有／端末専用の保存先を使う。端末専用モードでは共有設定の言語を適用しない。
- 未指定は `ja`。別のPCで選んだ言語のファイルがない場合は基本の表示に戻り、保存済みコードを保持し、選択欄に「翻訳ファイルなし」を表示する。ファイルを戻して再起動すると同じ選択が復元される。空文字、不正な言語タグ、新たに未導入言語を指定する設定ページJSONは入力エラーとする。
- フォーム、表示ページの部分JSON、検索、ページリセット、公開設定定義を共通基盤へ接続する。言語専用の保存APIや移行ファイルは作らない。
- ページモデルの`content.language`は、選択中ページの投影とは別に現在の言語を運ぶ。一般やApplet設定を開いても言語コンテキストを失わない。

## リソースと実行経路

正本は`resources/translations/host.json`。キーはフラットな意味名（例:`general.files.healthy`）とし、画面名・機能・用途で整理する。文章そのものや連番をキーにしない。i18nextのnamespaceは`host`、`keySeparator: false`でドットをキーの一部として扱う。

基本辞書はキーの辞書順昇順（`Object.keys(dictionary).sort()`と同じ比較）で維持する。製品で使わないキーやテストだけのキーは残さず、過去の文言が表示されないことを確認する試験は、その文言を試験側に保持する。削除前には直接参照に加え、型・分岐から組み立てるキー、音／文字ライブラリーの変換、Updaterへ引き継ぐキーも照合する。

リポジトリの `resources/translations/` に基本辞書と追加言語JSONを置く。ビルド時の型参照だけにソースの日本語JSONを使用し、実行時の辞書をASARへ埋め込まない。配布フォルダー・更新ZIP・スターターでは、すべての同梱JSONをEXE隣の `translations/` に配置する。

発行・更新では同名の同梱ファイルを丸ごと上書きし、既存キーとのマージはしない。編集は次の発行・更新まで有効。同梱されていない追加言語ファイルは削除しない。起動時の版判定・辞書更新と `.appdock-version` の生成は行わず、Node workerもホストと同じ辞書を読み取る。更新中断時は更新トランザクションが上書き前のファイルへ復元する。配置と手動置き換えは[配布仕様](portable-distribution.md)を参照する。

同じフォルダーの `host_en.json`、`host_pt-BR.json` などを起動時に読み込む。各ファイルは基本辞書と同じキーに翻訳文字列を割り当てたUTF-8のJSONオブジェクト。選択言語にキーがない場合、空白だけの値、文字列以外の値、変数名の不一致は項目単位で基本辞書の値を使う。基本辞書は配置先の `host.json` を正本とする。壊れた追加ファイルは一覧から外し、他言語は使用できる。変更は次の起動で読み直す。

例えば `translations/host_en.json` に次を保存して再起動すると、表示言語からEnglishを選べる。記載した2項目が英語になり、残りは基本辞書で表示する。

```json
{
  "language.label": "Display language",
  "pages.appearance.title": "Appearance"
}
```

Reactは `HostTranslationProvider` と `useHostTranslation()` を使い、編集中の画面やダイアログを保持する。mainと配布した本体UI・本体rendererが同じ辞書と言語設定を使い、設定カタログやコマンドなどの固定文言も選択に合わせて再計算する。既に履歴に保存された文章は保持する。Nodeの内部ランナーは本体の辞書ディレクトリを読み取り専用で使い、言語変更を内部通知で受け取る。

`HostTextKey`は日本語JSONから導出し、存在しないキーを型検査で検出する。列挙IDからのキー生成も型で制限する。文字列の型キャストで任意入力をキーに変換しない。i18nextインスタンス間ではリソースの変更を共有しない。

```tsx
const { t } = useHostTranslation();
return <span>{t('appearance.shell.active', { name: provider.displayName })}</span>;
```

文章全体を一つのキーにし、変数は`{{name}}`など名前付きプレースホルダーで渡す。語順に依存する断片の連結を避ける。変数名を変える場合は全呼出しを同時に修正する。翻訳値と変数は通常のReactテキスト／属性、またはnativeダイアログの文字列に渡す。`escapeValue: false`はReact側のエスケープを前提とし、`dangerouslySetInnerHTML`やHTML連結には使わない。`skipOnVariables: true`により、入力された`{{...}}`や`$t(...)`を再解釈しない。

文章の途中に強調やコード表示を入れる場合は`HostMessage`へReact nodeを渡す。翻訳時には内部の置換マーカーだけを渡し、翻訳後にReact nodeを差し込む。翻訳JSONやユーザー入力をHTMLとして解析しない。文章を組み立てるための助詞・動詞の断片を増やさない。入力方式などの分岐には表示文字列を比較せず、`inputKind`のような安定した識別値を使う。

共通サービスでは本体が所有する説明・確認文を`hostText`で作り、外部のメッセージ、名前、パスは名前付き変数として渡す。`Error.message`の文章照合による変換や、戻り値の再翻訳は行わない。エラーコード、公開APIのmethod、設定revision、処理結果のstatusは安定した識別値を保つ。通知の安全な要約には従来どおり件数だけを使い、詳細用の名前・パス・外部エラーを混ぜない。履歴へ保存済みの文章は書き換えない。

Webアカウントの仮名`temporaryAccountName`は保存する初期値と旧データの仮名判定を兼ねるため、表示辞書から切り離して維持する。このように保存・判定に使う既存値を翻訳へ置き換えない。将来別言語の初期名を導入する場合も、保存済みの名前や判定を文言編集に連動させない。

## 文言変更と試験

キーとプレースホルダーを維持すれば、JSONの値だけを編集できる。保存項目名、コマンドID、ページID、IPCの操作名、JSONの列挙値は翻訳しない。意味が変わる文言変更は、単なる表記修正として扱わない。

操作の試験はページID、設定アンカー、安定したtest ID、保存状態を中心にする。表示文言・アクセシブル名を保証する試験では期待する日本語を明示してよい。その場合は文言変更時に期待値を更新する。すべての期待値を翻訳関数から生成して、誤った翻訳でも通る試験にしない。翻訳抽出を契機に既存の文言検査を無条件で削除しない。

`tests/localization.test.cjs`は、外部辞書の読み込み・初期化、変数の無変換、言語値の検証、設定の投影・リセット・端末保存、renderer全体と移行済み共有部品への日本語直書き再混入を検査する。`scripts/settings-hints-ui-test.cjs --localization-only`は隔離した画面で先頭配置・日本語だけの選択肢・入力保存・JSON検証・検索・ヒント・本体の設定ページの明暗と狭幅・カスタム名・強調を含む確認文の無変換を確認する。発行EXEの引数も指定できる。これらは外部AI/MCP/TTSサービスの疎通やWindows設定変更の実機証明ではない。

`scripts/host-localization-ui-test.cjs [発行EXE]`は、隔離profileの部分翻訳でバー・リボン・通知バナー・コマンド・MCPコマンド定義・ログ・画像一覧・共通ダイアログの即時切替と日本語へのフォールバック、任意の名前／本文の保持、検索・選択・編集中の入力の保持、実プロセス再起動後の選択言語を確認する。共通ギャラリーのドラッグ・サイズ変更・拡大などの操作回帰は既存の`image-gallery-ui-test.cjs`を使用する。

共通サービスの試験では、翻訳キーの変数名と呼出し側の一致、外部文字列の保持、更新結果の詳細と安全な通知要約も確認する。`scripts/settings-hints-ui-test.cjs --service-localization-only`は隔離プロセスでAIのHTTPエラーを実画面まで通し、Electronに渡すアカウント削除・クリアと画像選択の引数を記録する。ダイアログ応答はfixtureで与え、キャンセル時のデータ保持と承認時の対象限定を検査する。このfixtureはWindowsネイティブ画面のレイアウト・物理操作の検証には使わない。

`tests/native-localization.test.cjs`は補助プロセスの翻訳境界・コードの保持・外部文字列の無変換・実Updaterの拒否を検査する。`tests/folder-host.test.cjs`は更新で辞書が交換されても引き継ぎ済みの結果文言が保たれること、`tests/TouchpadTests`は例外の種類と.NET RPCの互換性・模擬設定の拒否と復旧を確認する。`scripts/native-localization-ui-test.cjs [発行EXE]`は同じ実InputHostを使った言語切替とUpdaterへの引き渡しを検査し、OS入力やフック登録・タッチパッド設定変更は行わない。実更新の進行画面と中断復旧は既存の`updater-window-test.cjs`・`update-recovery-test.cjs`が担当する。

## 今後の進め方

1. 本体のページ／機能単位で固定文言の所有元を確認し、本文、選択肢、アクセシブル名、ヒント、検索語、エラーをまとめて移行する。未移行範囲をこの文書で更新する。
2. データから来た名前を辞書へ登録せず、既定ラベルとユーザーの上書きを区別する。既存の保存値を翻訳済みラベルへ変換しない。
3. 個別画面の未移行文言を翻訳キーへ移すときは、保存済みの値・操作IDと表示文言を区別する。
4. 辞書を追加したら部分翻訳、変数付き文言、複数画面の反映、再起動後の表示を検証する。追加言語の回帰は `scripts/settings-hints-ui-test.cjs --translation-packs-only` で実行する。
5. Appletの翻訳移行は[Appletの翻訳基盤](applet-localization.md)へ接続する。翻訳宣言は任意とし、既存Appletへ一律に要求しない。言語一覧は本体の辞書からだけ作る。

表示言語と地域形式は別の設定概念とする。数値・日付の表示は将来`Intl.NumberFormat`/`Intl.DateTimeFormat`へ集約し、言語・地域・タイムゾーンの方針を決めてから導入する。今回は日時・小数点・保存値を変更しない。今後「特定の瞬間」を保存する場合はUTCのISO 8601等を使う設計が可能だが、毎日の時刻や日付だけの値までUTCへ一律変換しない。
