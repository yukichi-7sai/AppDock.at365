# バックグラウンドジョブ基盤と生成結果の永続保全

## 実装状態と範囲

本書はバックグラウンド生成の実装契約。共通ジョブ基盤、生成原本の保全ストア、画面を閉じた後の継続、再起動後の結果復旧を実装する。画像の15分の結果解放と30分のジョブ破棄は廃止し、原本・履歴の保持に時間制限を設けない。実施した検証と実測範囲は[VERIFICATION](../VERIFICATION.md)に記録する。

初期対象は画像ライブラリーと音ライブラリーの既存生成ダイアログ。基本構成を維持し、本体内部の共通基盤へ接続する。画像生成サービスで共有している結果保持処理の変更は、設定画面の画像生成試験とApplet・MCPの画像生成登録にも適用する。共通ジョブ一覧の新設、画像ライブラリーのタブ化、全非同期処理の移行、一般Applet向けの汎用ジョブAPIは後続とする。

生成済み結果の再起動後の復旧は初期対象に含める。送信中・生成中の外部要求を再起動後に継続したり、自動で再生成したりする機能は含めない。一般の読み上げ・通知音・試聴をすべて永続録音する変更でもない。

## 必須要件

- ダイアログを閉じる、ページを移動する、rendererを再接続する操作で、受付済みの生成・保存を取り消さない。本体が生存する間は継続する。
- 生成画像と生成WAVは、時間経過・画面破棄・通常終了・ジョブ一覧の整理を理由に失わせない。保全できた結果を再起動後に確認・救出できる。
- 生成結果の保全とライブラリーへの登録を区別する。登録・分類に失敗しても、原データから保存だけを再試行する。
- 明示的な中止は処理を止める操作とし、既に受信・保全した生成物の削除を兼ねない。生成物の破棄・登録素材の削除は対象を示して別操作で確認する。
- 根拠のない保持期限、ジョブ件数・保存容量の固定上限、時刻だけを条件にした自動削除を設けない。必要な制限の判断と利用者への報告は[容量と時間制限の方針](settings-capacity.md#時間制限と生成結果の保持)に従う。
- 保存先障害等で永続化できていない結果を、保存済み・復旧可能と表示しない。

## 責務と寿命

| 部分 | 責務 | 寿命 |
| --- | --- | --- |
| `BackgroundJobs` | 機能別サービスを束ね、状態一覧・変更購読・操作・終了影響を提供する | AppDock本体 |
| 機能別ジョブサービス | 入力確定、実行、工程・詳細状態、中止、保存再試行、結果参照を所有する | ジョブ単位。本体に保持する |
| `GenerationStore` | 原データ・復旧記録の永続化、原子的更新、起動時照合、確認済みの明示削除 | 配置別のPC専用データ |
| `ImageAiService` / `TtsService` | 既存の認証、接続、プロバイダー通信、待機列、取消を担当する | 既存の本体サービス |
| ダイアログ接続 | 入力、表示、状態購読、試聴・プレビュー、操作依頼 | 開いている画面 |

本体mainの起動処理でサービスを生成する。Windowやページの生成処理でジョブサービスを作り直さない。画面切断時に解除するのは購読・表示用画像・試聴等だけとし、ジョブの所有者にページ要求IDやダイアログ接続IDを使わない。

実行順序は既存の画像生成スケジューラーとTTS共通キューが決める。共通基盤に第二の生成待機列や全機能共通の同時実行数制限を追加しない。下位TTSジョブと「音声生成から登録まで」の上位ジョブを共通一覧で二重計上しない。

状態の正本は機能別ジョブサービスと、その確定を記録する永続レコード。共通基盤は正本から共通表示を投影する。画面・共通一覧が独立して完了や取消を確定しない。

## ジョブの単位と共通契約

生成要求1回を1ジョブとする。複数画像は同じジョブの複数結果として扱い、各結果の保存・分類状態を保持する。音声生成はWAVの受信・検証だけで完了せず、ファイル保存と要求された分類までを完了条件とする。後からの試聴は完了条件に含めない。

共通スナップショットは以下を持つ。rendererへ送る情報と内部の復旧記録は別の型にする。

| 項目 | 契約 |
| --- | --- |
| `jobId`, `revision` | 本体発行の安定IDと単調増加する表示世代。再接続しても同じ仕事を特定する |
| `kind`, `owner`, `origin` | 機能、権限上の所有者、開始元。所有者と画面の寿命を分離する |
| `state`, `phase` | 共通状態と機能固有の工程。表示文言ではなく安定した値を使う |
| `createdAt`, `updatedAt` | 状態の説明・順序用の時刻。削除期限に流用しない |
| `progress` | 実測できる数量・単位のみ。割合が不明なら工程と経過時間を表示する |
| `actions` | 現在可能な中止・保存再試行・詳細表示等。実行時も状態と許可を再確認する |
| `shutdownImpact` | 中断する処理、保全済みの登録待ち結果、メモリーにしかない結果を区別する |
| `resultSummary`, `error` | 保存・要対処件数、安全なエラーコードと対処。生データや秘密値を含めない |

機能登録は本体コードの明示的な一覧から行う。機能別に状態取得、変更購読、中止、再試行、詳細表示を提供する。rendererから任意コード・任意パス・任意サービス名を実行させない。購読と初回スナップショット取得の間の更新をrevisionで照合し、古い画面からの操作を接続ID・要求IDで拒否する。

受付操作は要求IDで重複を防ぎ、受付済みジョブIDを返す。受付と生成・保全・登録の完了を分ける。保存再試行と中止はジョブ内で競合を調停し、二重保存しない。端末・所有者の寿命を越えた無条件な冪等性は保証しない。

## 状態と操作

| 共通状態 | 意味 |
| --- | --- |
| `queued` | 実行開始待ち |
| `running` | 準備、生成、結果保全、登録、分類を実行中。具体的な処理はphaseで表す |
| `canceling` | 中止要求を受け付け、実処理の終了と受信済み結果の保全を確認中 |
| `attention` | 保存・分類・保全の失敗、再起動による中断など、対処を必要とする |
| `completed` | 必要な登録と分類がすべて完了した |
| `failed` | 生成等が失敗して終了した。残っている結果の有無は別途保持する |
| `canceled` | 処理の中止が完了した。保全済み結果は保持する |

通常はqueuedからrunningを経てcompletedになる。保存失敗はattentionとし、「保存を再試行」で同じジョブの保存工程を実行する。試行番号・操作IDを更新し、以前の試行から遅れて届くイベントで状態を戻さない。

生成自体の再実行は明示操作で新しいジョブを作り、元ジョブとの関連だけを残す。自動再生成・自動再送は行わない。下位サービスの取消受付だけで回収完了とせず、書き込み等の終了を確認する。取消と保存が競合して確定したファイルも記録・保持する。

ジョブ状態と成果物状態は分ける。途中まで保存できたfailed/canceledジョブでも結果へアクセスできるようにする。音声のファイル保存済み・グループ未登録もattentionへ投影し、保存済みという文言だけで隠さない。

## 生成結果の永続保全

### 保存場所と内容

登録済み素材の正本は従来の共有`data/assets/images`・`data/assets/sounds`。登録前の結果と復旧記録は、[配置別のPC専用root](settings-sync.md#保存先)内に新設する`background-jobs/<jobId>/`へ置く。OS一時フォルダー、ビルドの`.artifacts`、時間で掃除するキャッシュへ置かない。共有設定・端末設定JSONにバイナリやジョブ履歴を混ぜない。

構成は、版付きの`manifest.json`、結果ID単位の画像/WAV原本（`<resultId>.bin`）、確定途中の`.partial`ファイル。manifestには種別、復旧状態、元の保存先、結果ID、MIME、長さ、ハッシュ、登録先ref、分類状態、登録操作の照合情報を保存する。生成条件等の必要な詳細もPC内だけに置き、APIキー・認証ヘッダー・認証leaseの秘密値・サーバー応答全文は保存しない。

IDからストア内部のパスを構成し、manifestの任意パスを信頼しない。パス逸脱・reparse point等による保全root外の読書きや削除を防ぐ。復旧記録と生データをMCP応答・通知・一般ログへ含めない。既存の配置IDを使い、配置先変更に伴う自動移動は追加しない。

### 受信から登録まで

1. 外部生成の受付前に保全rootと初期manifestを書けることを確認する。失敗したら新規の外部生成を開始せず、既存の保全データを残して原因を示す。
2. 要求本文・サーバー設定・保存先・グループをジョブへ確定する。参照画像はジョブ用に内容を確保するか世代を照合し、ページで改名・削除された別内容を黙って使用しない。
3. 完全受信した各生成物の原データを速やかに保全領域へ書く。現在のアダプターは完全な応答を受信・復号し、各結果を保全してから登録へ進む。通信途中の部分応答や未完了JSONを生成成功とは扱わない。原データをサムネイルや再生成結果で置き換えない。受信中のストリームを直接永続化する最適化は後続とする。
4. 完全受信した結果の形式・サイズ・ハッシュを検証し、flushと原子的置換、manifest更新を行う。検証に失敗した完全な受信物は要対処として隔離保持し、ライブラリーへ登録・プレビューしない。未完了ファイルを正常な結果と表示しない。
5. 原データの永続化が確認できてからメモリーを解放し、既存のライブラリー検証・登録処理へ渡す。保存先が消えた、アクセスできない、分類先が変わった場合も保全原本を保持する。
6. ファイル登録、必要な分類、manifest確定後にcompletedにする。ライブラリー側の原本が確実に存在することを照合した後だけ、重複した保全コピーを回収できる。

保全コピーの回収は「別の原本へ安全に引き渡し済み」という事実に基づく。時間・容量・ジョブ状態名だけを条件にしない。登録済み素材を利用者が後から削除・変更した場合はその操作を尊重し、残存コピーから勝手に再作成しない。

取消・許可撤回と応答が競合した場合も、完全受信した生成物を終端状態の判定だけで捨てない。保全処理は完了させ、ライブラリー登録の継続可否は最新の許可で判定する。以後の外部通信・登録を止めることと、得られた原本の保護を分ける。

### 保存失敗と復旧

ライブラリー登録失敗では生成済み原本を無期限で保全する。元の保存先を修復した後に未登録分だけ保存を再試行する。別の保存先を使う場合は「ファイルへ救出」で選択したフォルダーへ原本を保存し、ライブラリーの既存追加操作を利用できる。グループのみ未完了なら同じrefへ分類だけを再試行する。

ファイル確定後・manifest更新前の異常終了でも二重登録しないよう、書き込み前に結果IDと保存予定先を記録する。復旧時は操作記録、対象ファイルの同一性・ハッシュを照合し、所有が不明な既存ファイルへ上書き・自動採用しない。曖昧なら要対処で止め、原本を残す。既存の一意名生成・原子的ファイル保存と、結果IDごとの登録記録を接続する必要がある。

起動時はストアを検証し、生成済み・登録待ちの結果と部分保存済みrefを再接続する。生成サーバーへの要求、課金を伴う再生成、未確認の外部操作は自動再開しない。送信済みで結果未受信のジョブは中断・結果不明として示す。保全済み結果は既存の生成ダイアログから確認し、保存だけを明示再試行できるようにする。

破損manifest、未知の形式版、記録に結び付かない結果ファイルは削除せず隔離し、復旧導線を示す。メタデータだけを一覧へ読み、画像・WAV本体は必要時に読む。固定件数上限で古い成果物を追い出さない。

保全ストア自体への書き込みも失敗した場合は、残っているメモリー上の結果を時間で解放せず「永続保存できていない」と表示する。別保存先への救出・再試行を提供し、解消まで新しい生成の受付を抑止する。ディスク障害やOS強制終了まで完全な保全を保証できるとは扱わず、通常終了時の扱いを分ける。

### 削除と保持期限

- 未登録・未分類・隔離中の生成結果は経過時間で削除しない。15分の結果解放を廃止する。
- ジョブ記録の30分の自動削除によって、保全結果へ到達できなくなる構成も廃止する。完了履歴は明示的に整理でき、未解決結果の復旧記録は通常の履歴整理から除外する。
- 原本を失う「生成結果を破棄」は、件数と対象を示した明示確認を必須とする。cancel、閉じる、ページ移動、所有者の停止・権限撤回、アプリ終了に兼用しない。
- 既に時間切れで失われたデータは復旧できない。実装後に新しい保全経路で受信・保存した結果を保証対象とする。

今回の基盤に新しい固定時間制限は設けない。既存の画像・TTSの待機/HTTP期限は成果物の保持期限と区別し、接続時のレビューで値・必要性・打ち切り時の影響を確認する。根拠が確認できない既定値を、そのまま共通基盤の制限として採用しない。必要な制限を追加・変更する場合は、根拠と影響を利用者へ報告する。

## 既存ダイアログへの接続

画像・音声とも、閉じる操作は表示を終了するだけに変更する。既存の中止・再試行・改名・削除・プレビューを維持し、再度開くと同じ種類のジョブと保全結果を表示する。異なるフォルダーから開いても、受付済みジョブの保存先・グループを書き換えない。

入力中のフォームは生成済み結果と別に扱う。初期実装では起動中のフォーム状態を機能別に保持し、ページ移動で消さない。接続や参照画像を外部で変更・削除された場合は再検証し、古い内容で送信しない。新しいフォルダー・選択画像の引き継ぎは新規入力へだけ適用し、復帰した入力を黙って上書きしない。

音声の試聴は閉じる・ページ移動で止め、生成と保存は続ける。別の読み上げや他の画面の再生は止めず、既存の共通audioPlaybackを使う。画像の表示用サムネイルを解放しても保全原本を削除しない。

ページのdispose、rendererの読込・異常終了、Windowのclosedから生成取消を外し、表示接続だけを解除する。既存のbusy/modal制御はダイアログ表示中に限定し、閉じた後の背景ジョブを理由にライブラリー全体を操作不能にしない。古い接続からの編集要求を拒否する検証は維持する。

## 終了・再起動と通知

終了、通常再起動、更新による再起動は共通の終了確認へ接続する。quittingの確定、relaunchの予約、サービスの破棄より前に確認する。トレイへ隠す・最小化は終了に含めない。

進行中の画像・音声件数、保全済みの登録待ち件数、永続化できていない件数を分けて示す。既定操作は「AppDockに戻る」。中止して終了する場合も保全済み結果と復旧記録を残す。メモリーにしかない結果がある場合は救出保存へ誘導し、破棄して終了する操作は実際の損失を示して別途明示確認する。

終了承認時点で新規受付を止め、実処理の中止・保存の確定・復旧記録のflushを待つ。確認中にジョブが完了した場合は最新状態で判定する。固定秒数を過ぎたという理由だけで結果を破棄・強制終了しない。OSによる強制終了は通常終了と区別し、次回起動時に確定済みの記録を照合する。

失敗通知は機能側の確定点から既存の[ErrorReporter](error-reporting.md)へ一度だけ接続する。共通一覧の再描画・状態照会から重複発行しない。通知を閉じても要対処状態は解消しない。取消はエラー通知にしない。必要な警告の寿命は[WarningReporter](warning-notifications-design.md)へ接続する。

ステータスバーには共通基盤の集計と詳細への遷移を後から接続できるようにする。初期の詳細への入口は既存の生成ダイアログ。新しいタブや全機能横断のジョブ画面を前提にしない。

## 画像・音声・公開APIへの影響

| 対象 | 必要な変更 |
| --- | --- |
| 画像ライブラリー | `ImageGeneration`の表示セッションとジョブ一覧を分離。既存ImageAiServiceの結果・保存を保全ストアへ接続 |
| 音ライブラリー | `SoundGeneration`のItem、AbortController、保存、groupPending、結果bytesを画面外のサービスへ移す。既存TTSの生成専用経路を使う |
| 画像生成試験 | ライブラリーへ自動登録しない動作を維持しつつ、結果を保全ストアへ保存。試験画面を閉じても削除せず、画像生成ダイアログから確認・登録・明示破棄できる入口を接続する |
| Applet・MCPの画像生成 | 共有の結果破棄タイマーを除去。保持と取得権限を分離し、権限撤回・所有者の終了でデータを破棄しない。本体の利用者向け復旧操作に限って救出できるようにする |

既存の操作名、引数、通常の状態値、登録済みrefの形式は維持する。共通基盤用jobIdと下位サービスIDを内部で対応付け、公開APIのIDを表示接続IDに置き換えない。永続結果の存在を理由に、古いApplet実行世代・失効したMCP leaseへ取得・操作権限を復活させない。再起動後の別所有者から過去ジョブを自動取得できるAPIは追加しない。

未保存結果には時間による`resultExpiresAt`を設定せず、時間経過による`resultExpired`/`IMAGE_AI_RESULT_EXPIRED`を発生させない方針とする。省略可能な既存フィールドやエラーコードを削除するかは互換性レビューで判断し、コードを削除しなくても正常な保持中データに期限切れを返さない。cancel後の保全結果は本体の復旧経路で扱い、既存の終端状態から公開APIが勝手に再実行しない。

画像・音声のバイナリ、Base64、生成結果専用URLを返す公開APIは追加しない。refは不変なアセットIDではなく、改名・移動で変わる既存参照である。[アセットの共通方針](applet-assets.md)を維持する。

## 実装順序と受け入れ条件

1. 共通状態・所有者・操作・終了影響と、保全ストアの原子的保存・復旧・安全な削除を実装する。
2. 画像生成の結果保持を保全ストアへ接続し、15分/30分の破棄経路、cancel/discard/forgetOwner/closeによる原本消失を置き換える。表示の寿命を分離する。
3. 音声の生成・保存をダイアログ外へ移し、同じ共通基盤と保全ストアへ接続する。
4. ダイアログ再接続、保存先修正・再試行、復旧結果への到達、終了確認を接続する。
5. 関連回帰・固定EXE検証を行い、現行仕様書の未実装注記を実装内容に合わせて更新する。

結果保全を将来の課題へ残したまま、期限を延ばす、無期限にメモリーだけへ置く、閉じる確認だけを削る変更で完了にしない。新しい保存ファイルと公開APIの保持・取消の振る舞いを含むため、実装時は[版更新の判断](development-workflow.md#版更新の判断)に従ってマイナー更新を扱う。文書整備だけでは製品の版更新・publishを行わない。

検証ではローカルfixtureと隔離profileを使い、次を確認する。既存試験の担当範囲は[画像生成AI](image-ai.md#検証)、[TTS](tts-design.md)、[共通テストランタイム](test-runtime.md)を参照する。

- 画像・音声それぞれの待機中・生成中・保存中に閉じる、ページ移動、renderer再接続を行い、同じジョブが一度だけ登録される。
- フォルダー・グループ・参照画像を途中で変更しても、別内容・別保存先へ黙って切り替わらない。
- 保存失敗、分類だけの失敗、複数画像の部分成功で、保存済み分を重複作成せず再試行する。
- 時計を15分・30分より先へ進めても結果を失わない。固定時間の実待機に依存する試験を追加しない。
- 通常終了・再起動・異常終了後に保全原本を照合して復旧する。原本確定とmanifest、登録ファイルと登録記録の各境界で中断するfixtureを用意する。
- ディスク満杯・書込拒否・破損記録・孤立ファイル・未知の形式版でも、未保全を成功扱いせず、唯一の原本を削除しない。
- 中止と保存完了の競合、保存再試行の連打、古い画面操作、失効所有者、設定・許可変更、既存APIの重複要求を検証する。
- 閉じると試聴だけが止まり、別の読み上げ・生成・保存へ影響しない。TTS受信完了を登録完了と誤認しない。
- 履歴整理・保全コピーの回収・明示破棄を区別し、登録素材の削除後に自動復元しない。
- 終了確認を取り消せば全サービスが動作を続ける。保全済み/未保全の表示が実データと一致し、終了承認前に再起動を予約しない。

## 実装の参照と初期範囲

- `src/main/core/background-jobs.ts`: 状態投影・変更購読・操作・終了前の受付停止と処理回収。機能別の待機列を置換しない。
- `src/main/core/generation-store.ts`: SHA256付き原本、flush、原子的manifest、読込時の照合、安全なパス確認。破損・未知・孤立記録は削除せず、生成ダイアログのエラーと「保全データの場所を開く」で調査できる。修復後は再起動して再検査する。
- `src/main/core/image-generation.ts` / `sound-generation.ts`: 本体寿命のジョブと短い表示接続を分離。入力下書きは本体起動中に保持する。
- `src/main/core/image-ai-service.ts` / `tts-service.ts`: 完全受信した結果の保全と、権限・中止の判定を分離する。取消後も下位処理が終了するまでは回収を待つ。
- `src/main/core/image-registration.ts` / `registered-assets.ts`: 書込前の登録intentに、確定予定ref・SHA256・実ファイルのidentityを保存する。復旧時に照合できない対象を自動で再作成しない。
- `src/main/index.ts` / `portable-updates.ts`: 終了・再起動・更新の実行前に確認する。確認の取消前にサービスを終了しない。
- `src/main/core/generation-rescue.ts`: 選択されたフォルダーへ同期・flushした別コピーを保存する。保全原本や既存の同名ファイルを上書き・削除しない。

初期実装は保全コピーを自動回収しない。「生成原本と履歴を削除」で確認したジョブだけを削除し、登録済みライブラリー素材は保持する。ステータスバーへの表示と全体ジョブ画面・タブ化は後続で、初期の確認・復旧の入口は従来の生成ダイアログである。

Windowsの一時共有ロックによるEPERM/EACCES/EBUSYを実測したため、原子的置換は設定保存と同じ`atomic-replace.ts`を使う。既にflushした同一ファイルの置換だけを25・50・75ms待って再試行し、各回に他の書込を照合する。合計150msの待機後も失敗する場合はmainを止め続けずエラーを返し、原本・部分ファイルを残す。これは保存操作の一時ロック対策であり、生成結果・履歴・復旧の期限ではない。

実装・検証結果は[VERIFICATION](../VERIFICATION.md)へ記録する。
