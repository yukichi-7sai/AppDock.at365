# コマンドリンク・説明文タグと本体固定パレットの設計

状態: AppDock 0.105.1の実装仕様。設計worktreeの内容をmainへ取り込み、共通リンク・タグと本体固定パレットを実装した。検証結果は[VERIFICATION](../VERIFICATION.md)を参照する。

設定の説明から関連コマンドを確認できるようにする。再生アイコンと現在のコマンド名からなる共通リンクを設け、クリックすると実行用コマンドパレットを対象コマンドの選択状態で開く。説明文には `[command:コマンドID]` を埋め込めるようにする。パレットの描画は本体の固定UIへ移し、Shellの差し替え対象から外す。

保存・入力は[設定基盤](settings-foundation.md)、画面構成は[共通UI指針](settings-ui-guidelines.md)、パレットの描画・寿命・復旧は[共通オーバーレイ](shell-overlays.md)を正本とする。

## 1. 対象と境界

今回の設計対象は本体の共通部品、説明文の専用構文、参照名の表示・検索への投影、パレットの本体固定UIへの移設と初期選択である。WindowsToolsの設定を最初の適用例にする。現在の検索・選択・ピン留め・実行処理を引き継ぎ、パレットの別実装や新しいShell領域を作らない。

初期実装で対話可能なタグを扱う場所は次のとおりとする。

| 説明の提供元 | 描画する場所 | 扱い |
| --- | --- | --- |
| manifest直下の `description` | 設定上部の `AppletInformationPanel` | コマンドリンクを描画する |
| `settingSections[].description` | `AppletSettingsForm` のセクション説明 | コマンドリンクを描画する |
| `settings[].description` | 各設定項目の説明 | コマンドリンクを描画する |
| `settingActions[].description` | 設定アクションの説明 | 実行ボタンとは別のコマンドリンクを描画する |
| 宣言型一覧の設定フィールドの `description` | 共通一覧編集・編集ダイアログの説明 | 同じ部品を使う |
| 本体が管理する説明文 | 明示的に共通部品を使用した箇所 | 同じ構文と部品を使う |

検索結果、管理一覧、アクセシブルな説明など、内部に操作要素を置けない表示は同じ構文からプレーンテキストへ投影する。コマンドパレットの実行ボタン内にあるコマンド説明も、初期実装ではプレーンテキストとする。ボタンの中にリンクボタンを入れない。

タイトル、キャッチコピー、設定値、利用者が入力する本文、ログ、通知本文、リモートHTML、ヒントのツールチップに対して一律にはタグを解釈しない。`SettingsField` の任意の `ReactNode` を走査・書き換えず、対応する説明の提供箇所が `CommandText` を明示的に使う。

対応ホストは0.105.0以降。旧ホストではタグを文字列のまま表示する。WindowsToolsのタグは先行して0.2.10へ組み込み済みで、本体側でリンクへ解決する。

## 2. 表示と操作

### アイコン

- コマンドのメタファーは輪郭の再生アイコンとする。既存の共通 `Icon` にある再生図形を共用し、文字の `▷` に依存しない。
- 意味を示す既存の `command` アイコンIDを保持し、その図形を再生アイコンとそろえる。保存済みのリボンアイコン指定やmanifestのアイコンIDを書き換えない。
- `play` は従来の実行・再生用途を維持する。`bolt` はコマンドトリガー、`keyboard-command-key` は実際のCommandキーの表現として保持する。キーボード表記のCommandキーまで置換しない。
- リンクは小さなアイコンと現在のコマンド名を横に並べ、共通アクセント色・フォーカス表示を使う。通常の説明文の行高と折り返しへ収める。長い名前や狭幅でも説明文全体を横にはみ出させない。

### 操作契約

1. リンクのクリック、Enter、Spaceで既存パレットを実行モードで開く。リンクを開いた時点ではコマンドを実行しない。
2. 対象コマンドを選択し、結果リスト内の見える位置へスクロールする。フィルターにはコマンドIDを初期入力し、その文字列を全選択する。直接入力で検索語を置き換えられ、空にすれば通常の全候補・ピン順へ戻る。通常のパレット起動は空検索を維持する。
3. パレット内のEnter・実行ボタンで既存の実行経路を使う。検索、上下移動、ピン留め、取消も通常のパレットと共用する。
4. Escape・背景クリックで閉じる。元の設定ページとリンクが残っている場合は、そのリンクへフォーカスを戻す。スクロール位置と入力欄の未確定・失敗値を保持する。

画面遷移ではなく内部操作なので、共通部品は `type="button"` のボタンをリンク風に描画する。フォーム送信、URL遷移、新しいブラウザータブ、OSプロトコル登録は行わない。アイコンは `aria-hidden` とし、操作名とhover/focus時の案内は「{コマンド名}をコマンドパレットで表示」とする。本体の固定文言は既存の翻訳基盤に追加する。

リンクのイベントは親の折りたたみ・行選択・設定アクションへ伝播させない。特に `SettingsSection` の `summary` に置く説明は、リンクのクリック・Enter・Spaceで開閉しないことを確認する。行ボタンに含まれる説明はプレーンテキスト投影を使う。

開く前のblur/Enter確定と保存は既存の入力・送信キューで完了を待つ。保存失敗や入力エラーがあるときに値を破棄してパレットへ進まない。IME変換中のEnterをリンクやパレットの実行として扱わない。

## 3. 専用タグの構文

```text
[command:at365.windows-tools.display-off]
```

```json
{
  "key": "displayOffSeconds",
  "description": "[command:at365.windows-tools.display-off] を実行してから、ディスプレイを消灯するまでの時間です。"
}
```

タグを再生アイコンと現在の「ディスプレイの消灯を予約」という名前に置き換える。コマンド名は説明文へ重複記入しない。コマンド名の変更・表示言語・Applet更新を現在のカタログから反映する。

| 入力 | 解釈 |
| --- | --- |
| `[command:<id>]` | `command` は小文字の固定識別子。IDは既存の `validCommandId` に完全一致する値 |
| 同じ文中の複数タグ | それぞれ独立したリンク。表示順と重複を保持する |
| 改行を含む説明 | 既存の改行・空白の表示規則を保持し、タグだけを置き換える |
| `\[command:<id>]` | 正しいタグの直前のバックスラッシュ1文字を消費し、タグを文字として表示する |
| 空ID、タグ内の空白、不正ID、閉じ忘れ、未知のタグ | 原文を文字として表示する。説明全体やAppletの読込を失敗させない |

IDの大文字小文字を変換せず、空白除去や名前による曖昧検索、接頭辞補完はしない。IDの長さと禁止名の規則は既存の `validCommandId` を共用する。追加のタグ件数上限は設けず、元の説明文の長さ・型の制約を維持する。

エスケープのJSON表記は次のようになる。

```json
{
  "description": "タグ自体の記述例: \\[command:at365.windows-tools.display-off]"
}
```

走査は左から行い、直前の `\` は有効なタグのエスケープにだけ使う。ほかのバックスラッシュを消費しない。例えば実際の文字列でバックスラッシュが2つ続いた後に有効タグがある場合、1つ目を文字として残し、2つ目でタグをエスケープする。

ラベル上書き、引数、キー送信、入れ子タグ、式評価、HTML・汎用Markdownの解釈は追加しない。取得したコマンド名も再度タグ解析しない。HTML風の入力は通常のReactテキストとして描画する。

## 4. 共通部品とデータ

共通実装は次の責務を持つ。

| 要素 | 責務 |
| --- | --- |
| `src/shared/command-text.ts` | `parseCommandText(text)` でテキストとコマンド参照へ分割する。React・IPCへ依存しない |
| `commandTextPlain(text, references)` | 同じ分割結果から、コマンド名へ置き換えたプレーンテキストを作る |
| `src/renderer/settings-ui/CommandLink.tsx` | `commandId` を受け、現在の参照情報で表示・パレット要求・結果・フォーカスを管理する |
| `src/renderer/settings-ui/CommandText.tsx` | テキストと参照を順に描画する。対話可能な説明では `CommandLink` を使う |
| 共通の参照Context | IDで引ける参照情報と、その画面で許可されたパレット要求を渡す。設定ページ・ダイアログで共用する |

参照情報は `{ id, title, available, disabledReason? }` の表示用投影とし、配列を項目ごとに総当たりせず共通のMapを使う。スタック本体、コマンドの引数、設定値、ローカルパスや認証情報を渡さない。表示カタログの既存キャッシュ・変更通知を共用し、説明文の描画ごとに全コマンドを生成しない。

`CommandLink` の標準表示名は現在のカタログから取得する。独自のラベル上書き用propsや、直接実行用のpropsは設けない。Contextがない描画では取得できる名前またはIDのテキスト表示へ戻し、クリック可能な外観だけを残さない。

### 設定ページの投影

`SettingsPageAuxiliary` に任意の `commandReferences` を追加する。ページで表示する対応説明文に登場する有効IDだけを収集し、現在のカタログから最小限の情報を返す。タグがないページへ全コマンド一覧を増配しない。既存の `auxiliary.commands` を必要とするトリガー・トレイ等は、その共有カタログを参照元として利用できる。

ページ以外の本体描画でも、同じ参照Contextを上位から注入する。各Appletの独自HTMLへ `window.dock` や新しい任意実行APIを公開しない。

### 利用可否と参照切れ

| 状態 | リンクの表示・操作 |
| --- | --- |
| 現在のカタログにある利用可能コマンド | 現在名を表示し、対象選択でパレットを開く |
| カタログにある停止中・権限不足等のコマンド | リンクを開ける。パレットで対象を選択し、現在の利用不可理由と既存の実行可否を表示する |
| 未導入・削除済み・非表示など、パレットの候補にないID | 「不明なコマンド（ID）」の非操作表示とする。別コマンドを選択したパレットを開かない |
| 表示後、クリックまでに削除・非表示へ変化した | ホスト側の再照合で開く処理を止め、その場へ参照先を確認する案内を表示する |

リンクの表示やパレットを開く操作では、Appletの有効化・起動・権限変更を行わない。実行した場合の判定は既存のコマンド実行契約に従う。未導入のコマンド名を知るためのネットワーク照会や、名前の推測は追加しない。

## 5. 本体固定パレットと設定画面の接続

### 本体が所有する描画

描画は `src/renderer/command-palette/CommandPalette.tsx`、状態と実行は `CommandPaletteSession`、表示面は `OverlayHost` が所有する。要求から表示までを本体だけで管理する。

- `CommandPaletteSession` の実行/選択モード、ピン保存・利用可否・実行中の制御を維持する。検索文字列と選択位置は描画側の一時状態として引き継ぐ。設定の `CommandPicker` も同じ本体パレットを使う。
- 本体の専用rendererエントリーへ描画を移設する。移設先は `src/renderer/command-palette/` とし、現在のDefault Shellから描画・スタイルを移して共通配色・アイコン・翻訳を使う。Default Shellへパレットの複製を残さない。
- 表示面は本体所有の専用 `WebContentsView` とする。Applet本文が別のWebContentsである構成でも、現在の本文矩形・前後関係と入力を確保できるようにする。本体 `main.tsx` の上へReactを載せるだけの変更にはしない。
- `OverlayHost` の単一モーダル枠・本文矩形・取消・フォーカス復帰は共用する。Surfaceを「本体パレット」と「Shell由来の一時リボングループ」の判別可能な型に分け、パレットではproviderの解決・登録・起動・設定取得を呼ばない。
- 本体側のパレット用preloadと固定URLを用意する。APIは `connect / ready / act / onChanged / onSuspended` に限定し、ready時のsession/model ID、送信元WebContents・main frame・正規URLを確認する。任意コマンドの直接実行、Applet設定取得、汎用IPCは公開しない。
- `act` は選択・実行・ピン操作・取消を `CommandPaletteSession` へ渡す。実行は既存dispatcherへ接続する。パレットを開く時点の既存TriggerContextを共用し、設定の所有Appletから対象ウィンドウを推測しない。
- 初回は遅延生成し、非表示で1件を再利用する。新しい要求では古い検索・選択・sessionを破棄してから新モデルを表示する。ホスト終了・再読込・renderer障害でViewを回収する。Shellの停止・変更・再試行によって本体パレットを破棄しない。

本体パレットにShellの初期選択対応通知や提供元フォールバックは不要となる。readyは本体の描画完了の確認だけに使う。読込失敗・renderer終了・ready期限切れは同じ要求を最大1回、本体Viewの再生成で復旧する。再生成にも失敗した場合は要求を取消し、共通エラー通知とログで案内する。実行開始済みコマンドは復旧のために再実行しない。

新要求による旧要求の取消、所有Windowの非表示・最小化・再読込・終了、本文のroute変更、背景とぼかし、ズーム、検索/IME/Tab、ページのWebContents・session・入力の保持を既存どおりに保つ。一時リボングループは引き続きリボンの提供元を使う。

### 初期選択の追加

[共有型](../src/shared/overlays.ts)の `CommandPaletteRequest` と `CommandPaletteModel.content` に任意の `initialCommandId?: string` を追加する。

```typescript
openCommandPalette({
  requestId: crypto.randomUUID(),
  mode: 'execute',
  initialCommandId: commandId,
});
```

既存の `commandIds` は選択モードの候補制限のままとし、実行モードの初期選択へ流用しない。`initialCommandId` の省略時は現在と同じ通常表示とする。

ホストはID形式と現在のパレット候補への存在を検証する。初期対象が非表示・参照切れの場合は要求を拒否し、一覧先頭へフォールバックしない。利用不可の既知コマンドは候補として表示できる。要求の検証では、表示側から渡された名前・availabilityを信用しない。

本体のパレット描画はモデルIDごとの初回だけ初期対象を選択し、スクロールを合わせてからreadyを通知する。以後のsnapshot更新で検索文字列や選択を初期対象へ戻さない。選択は行番号だけではなくIDで追跡し、ピン順・カタログ順の変化で別コマンドへ移らない。

初期対象が表示中に消え、まだ別の候補を明示選択していない場合は選択を解除して案内を表示する。Enterで代わりの行を実行しない。手動検索・上下移動後は通常の選択規則を使う。実行直前には既存 `CommandPaletteSession.act` が利用可否を再検証する。

### 現在の接続との差分

現行では、[設定ページの要求処理](../src/main/core/settings-page.ts)はパレットの `mode:select` だけを許可する。[本体のページアクション登録](../src/main/index.ts)も、トリガー・トレイ等のページに限って選択用のopen/cancelを発行している。共通部品だけの追加ではAppletの説明から実行用パレットを開けない。

そのため、次の接続を同時に実装する。

- 対応する説明文を持つ本体・Applet設定ページへ、既存のopen/cancelアクションハンドルを発行する。
- `SettingsPageSession.palette` と本体アクションは、従来の選択要求に加え、`mode:execute` かつ有効な `initialCommandId` を持つ要求を受け付ける。実行用要求に `commandIds`・`pins`・`shortcuts` の上書きは受け付けない。
- 設定session・page・発行済みaction ID・現在のページ利用可否の検査を保つ。通常のinvoke経路からも同じ検証関数を呼び、専用transportだけに検査を置かない。
- [設定runtime](../src/renderer/settings/runtime.ts)の入力確定・保存キューを通す。パレットの選択・実行待ちの間はキューを占有しない。開く要求が失敗した場合は共通の設定エラー表示とスクリーンリーダー通知へ接続する。
- `requestId` を操作ごとに新規発行する。同じリンクの開く要求が待機中の間は二重送信を防ぎ、別要求のパレットは既存の新要求による取消に従う。
- 元の説明が破棄されたら、その部品が所有する `requestId` だけをcancelする。後から開いた別要求を閉じない。完了・取消後に現在のページ・接続・DOMを確認してフォーカスを戻す。

本体renderer専用の `SettingsPageApi` 境界を維持し、Applet runtimeやMCPの `commands.execute` の権限を広げない。説明中の参照は別Applet・ホストのIDも指定できるが、それだけで実行権限を与えない。自身のコマンドを直接実行する既存 `settingActions` の所有者制限は変更しない。

### Shellから切り離す範囲

| 対象 | 方針 |
| --- | --- |
| `shellRegions` / 設定の「Shellの変更」 | `overlay.command-palette` を公開・選択対象から外す。残る対象はタイトルバー・リボン・ステータスバー・通知バナー・デスクトップ通知の5領域 |
| manifestの旧 `shell.views["overlay.command-palette"]` | 既存の廃止領域と同じく受理して不活性にする。形式・相対パスの安全性の検証は保ち、UIを読み込まず、Viewを起動しない。これだけを宣言したAppletでも、無関係なコマンド・設定を停止させない |
| 保存済み `host.shellProviders["overlay.command-palette"]` | 既存の廃止領域と同様に値を保持して不活性にする。自動削除・別キーへの移動・Default Shellへの書換えを行わない |
| Shell状態・MCPのShell選択schema | 現在の `shellRegions` から導出する5領域だけを表示・編集対象にする。廃止キーを新しく編集する入口は作らない |
| Default Shellのmanifest・配布物 | パレットのviews宣言と専用描画を除く。一時リボングループのoverlay描画は必要範囲で保持する |
| `ShellOverlayApi` / `overlay-preload.ts` | Shell由来の一時リボングループに必要な契約だけを残す。パレットの描画モデルと操作は本体用APIへ分離する |
| Shellの実行条件・ready監視 | 旧領域を満たすためにAppletを起動・待機しない。旧領域の `shellRequirement` を持つコマンドは廃止領域の理由で利用不可とし、条件を外して実行可能にしない。manifest読込で無関係なコマンドまで拒否しないよう、宣言検証も合わせて変更する |

現行の `LegacyShellRegion` / `isRetiredShellRegion` / `shellView` の仕組みを拡張し、旧キーの扱いを新しい独自移行処理として作らない。保存JSONの他のShell指定・未知キーの保持も既存契約に従う。公開仕様の廃止に当たるため、実装時には破壊的変更として本体のマイナー版を更新する。

## 6. 検索・メタデータ・保存

元の `description` は文字列のまま保持する。タグや解決したコマンド名を `settings.json`、端末状態、設定の保存値、リセット対象へ書き込まない。元の説明文を返すmanifest/APIも、タグを含む原文を保持する。

[設定検索カタログ](../src/shared/settings-catalog.ts)では、表示用の説明・検索語へ `commandTextPlain` を適用する。元の `SettingDefinition.description` は保持し、描画時のタグ情報を失わない。タグ構文を検索結果へ露出させず、現在のコマンド名で対象設定へ移動できるようにする。IDも検索語へ含める。

Applet概要・セクション説明・一覧フィールドの説明も同じルールにそろえる。管理一覧の概要など対話しない場所もプレーンテキスト投影を使う。検索結果にリンク操作を追加せず、現在の設定項目への移動・アンカー・折りたたみ展開を維持する。

解析したトークンと参照ID集合は説明文の変更に伴って更新する。名前の解決と検索索引はコマンドカタログの変更・言語変更にも追従させる。変更していない監視周期で全説明文・全コマンドを再走査しない。既存の表示カタログ/状態キーとページ単位の索引を共用する。

既存の説明文はタグがなければ同じテキストを表示する。専用構文を文字として説明するときはエスケープを使う。旧ホストではタグが文字列として表示される。新規にタグ対応を必須とするAppletは `minimumHostVersion:0.105.0` 以降を宣言する。先行したWindowsToolsは旧ホストでも説明の原文を保つ。

## 7. WindowsToolsへの適用例

現行の `displayOffSeconds`、`autoLockEnabled`、`autoLockMinutes` のキー・保存値・既定値・監視動作を保ち、分類と説明だけを整える。

| 分類 | 項目 | 説明例 |
| --- | --- | --- |
| コマンドの動作 | ディスプレイ消灯コマンドの待機時間（秒） | `[command:at365.windows-tools.display-off] を実行してから、ディスプレイを消灯するまでの時間です。` |
| セキュリティ | 無操作時の自動ロック | 指定した時間、マウス・キーボードの操作がなかった場合に、Windowsをロックします。 |
| セキュリティ | 自動ロックまでの無操作時間（分） | 既存の範囲と監視開始・リセットの説明を保持する。 |

「コマンドの動作」「セキュリティ」のセクション自体にはdescriptionを置かない。自動ロックの動作・起動中に限ることと `[command:at365.windows-tools.toggle-auto-lock]` の案内は「無操作時の自動ロック」のdescriptionへまとめる。自動ロックと独立した即時ロックのコマンドを、その設定の対象と誤認させない。

Appletとホストの起動中に動くこと、設定変更の反映時期、予約取消など、現在の[WindowsTools利用仕様](../../Applet.WindowsTools.at365/docs/usage.md)を保つ。OFF時の入力欄の無効化など新しい設定間依存の実装は、この共通リンク設計へ混ぜない。WindowsTools 0.2.10の発行済みmetadataを、本体の隔離GUI検証に使用する。
