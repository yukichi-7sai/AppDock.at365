# テストの作成と整理

AppDock本体とAppletのテストを追加・修正・整理するときの判断基準です。実行段階、必要回帰の選択、成功結果の再利用、証跡は[開発手順](development-workflow.md)を正本とします。画面の仕様は[設定UI指針](settings-ui-guidelines.md)などの機能別文書を参照します。

## 何を守るか

テスト名から「どの操作・入力で、どんな利用者の不具合を防ぐか」が分かるようにします。失敗時に製品を直すか、意図した仕様変更に合わせて期待値を直すかは、現行の要件と実際の挙動から判断します。テスト側を更新すること自体は、削除の理由になりません。

| 対象                                                                     | 方針                                                                                   |
| ------------------------------------------------------------------------ | -------------------------------------------------------------------------------------- |
| 保存・取消・再起動後の保持、他の値の保護、競合・失敗時の処理             | 維持する。画面操作から保存結果までを確認する                                           |
| 操作許可、認証、秘密値、入力の所有権、条件・順序・first/all、更新・復旧  | 関係する正常系と拒否・境界・失敗系を維持する                                           |
| 操作できない、フォーカスを失う、スクロールしても届かない、文字が読めない | 利用者が困る状態を検出する最小限のUI検査を残す                                         |
| 余白・角丸・文字の中央位置・装飾色・細かな寸法の完全一致                 | 継続して固定する要件と固有の不具合がなければ除去する。必要な見た目の確認は変更時に行う |
| CSSのgrid/flex、内部要素の段数、列の実装用class、SVGのパス文字列         | 同じ動作を保つ実装修正で失敗する条件は除去する。操作・意味・保存結果で確認する         |
| 同じ共通部品を使う全ページでの同一検査                                   | 共通部品の代表例へ集約し、機能固有の挙動だけを各ページで検査する                       |

ソース文字列の検査を一括で削除しません。公開APIの境界、禁止された内部import、preloadへの危険な公開など、明示した構造上の制約を守る検査は別に評価します。ファイル読み取りの有無だけでは価値を判定できません。

## 適切な層を選ぶ

- 値の検証、計画、条件、保存データの保護は、可能なら`tests/*.test.cjs`の小さな入力と出力で確認する。純粋関数の全組み合わせをGUIでも繰り返さない。
- GUIは、利用者の入力、ダイアログの確定・取消、フォーカス、画面と保存値の接続を確認する。通常は`getByRole`・`getByLabel`、安定した操作対象には`data-testid`を使う。内部classは既存部品の識別に必要な範囲へとどめる。
- 明暗テーマや狭幅は共通部品の代表的な条件を選ぶ。テーマ×画面幅×全ページの総当たりを標準にしない。特定の組み合わせだけで起きた不具合には、その条件を明示した検査を残す。
- 読みやすさは共通パレットのコントラストと代表的な実画面で確認する。背景色の完全一致や全ページの枠線検査で代用しない。
- スクロールは実際に操作へ到達できること、必要なキーボード操作、ダイアログ終了後の復帰を確認する。`sticky`や`transform`の指定方法、ツールバーからの厳密な距離を動作の合否にしない。
- スクリーンショットは失敗の診断、または変更時に必要な代表画面へ絞る。画像を保存しただけで表示や操作を検証済みとしない。

UIの待機には描画・保存・接続の条件を使います。固定時間のsleepを追加して成功させたり、失敗するまで全体を繰り返したりしません。テスト用の設定・profile・模擬サーバーを使い、実利用のデータ、認証、Windows設定を変更しません。PauseとF13～F24の実入力・OS登録の禁止など、[作業規則](../AGENTS.md)も適用します。

## 整理するときの確認

1. assertionごとに、守る要件と検出する不具合を確認する。実装のコピーだけになった条件、役目を終えた画面の期待値、重複を候補にする。
2. ファイル全体を削除する前に、保存・取消・拒否・アクセシビリティなどの検査が混ざっていないか読む。重複している場合は、代わりに守る既存の試験を明示する。
3. 必要な検査を維持・移動・集約し、呼び出し元と現行の文書を更新する。過去の検証記録やログ内の旧パスは履歴として残す。
4. 構文・書式・参照を確認し、変更したテストを実行する。テストが通ることだけで検査能力を確認したことにせず、重要な結果を逆にする一時的な不具合でも失敗するか必要に応じて調べ、必ず元へ戻す。
5. 削除した検査、維持した契約と担当試験、実行結果、未実行範囲をVERIFICATIONへ記録する。ファイル数・行数と実際のテスト件数、測っていない実行時間を混同しない。

## 設定・トリガーの主な担当

`scripts/overlay-shadows-ui-test.cjs [固定EXE]`は、ダイアログ/パレット・バナー・デスクトップ通知の影を個別に切り替え、表示中の反映、通知ID/期限/sessionの保持、折りたたみのキーボード操作と検索による展開、再起動後の設定保持を確認する。設定の配置と明暗・狭幅は代表画像で確認する。`tests/appearance.test.cjs`は既定値・保存・ページ別リセットと共通appearance配信を担当する。

`scripts/command-palette-ui-test.cjs [固定EXE]`は、検索0件、3方式の有効割り当てと全体OFFの即時反映、稲妻からの対象ID指定・解除・再移動、停止中・未割り当ての非実行、明暗・広幅/狭幅を確認する。寸法と折り返し位置は測定値・代表画像を記録して変更時に確認する。タッチパッドのnative呼出し境界は隔離プロセス内でstub化し、F13〜F24の登録・送信やWindowsのタッチパッド設定変更を行わない。条件・表示順・保存値の不変とナビゲーション拒否は`command-triggers.test.cjs`・`command-palette.test.cjs`が担当する。

`scripts/modal-trigger-input-ui-test.cjs [固定EXE]`は共通ダイアログ・パレットの単独Tab/Escape/Enter/上下左右の操作、修飾キー付きとその他のキー・マウスの継続、別アプリでの7キーの実行、Windows標準ダイアログ、実キー記録中の抑止と復帰、保存済み割り当ての保持を確認する。タッチパッドのキー記録中の継続は`tests/gestures.test.cjs`、全修飾キーと押下・解放の判定は`InputTests --input-blocking`のOS入力を送らないfixtureで補完する。

`scripts/command-links-ui-test.cjs [固定EXE]`はタグ・未知参照・エスケープ、初期対象の可視性、明示実行、フォーカス、設定入力・エラー値の保持と一覧ダイアログ、WindowsToolsの停止中リンクを確認する。`scripts/shell-overlay-ui-test.cjs [固定EXE]`は本体パレットのIME・Tab・ピン・選択モード、下のAppletの入力とフォーカス、Shellからの独立、1回のクラッシュ復旧と再失敗の打切りを担当する。

| 試験                                                                                                                         | 主な契約                                                                                                                                 |
| ---------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `scripts/settings-controls-ui-test.cjs [固定EXE]`                                                                            | 即時保存と操作コマンドの反映、代表的な明暗・狭幅でのキーボード開閉とフォーカス、通知バナー6位置と下側の伸長・再表示、通知先の選択・保存・取消、検索による移動、AIダイアログの保存・取消 |
| `scripts/settings-usability-ui-test.cjs <固定EXE>`                                                                           | 模擬APIのモデル・ボイス取得、直接入力、通知の宛先と継承、隔離したCodex設定の登録・解除                                                   |
| `scripts/command-triggers-ui-test.cjs [固定EXE]`                                                                             | 4タブ、検索・種類・提供元・入力の絞り込み、3方式の追加・編集・削除・並べ替え、スクロールとフォーカスの復帰、再起動後の保存               |
| `scripts/settings-input-ui-test.cjs [固定EXE]`、`scripts/settings-hints-ui-test.cjs [固定EXE]`                               | 共通入力・確定・取消、ヒント・エラーの操作と表示設定                                                                                     |
| `tests/appearance.test.cjs`、`scripts/appearance-ui-test.cjs [固定EXE]`、`scripts/notification-colors-ui-test.cjs [固定EXE]` | 共通パレット、実画面の配色と読みやすさ                                                                                                   |
| `tests/settings-editing.test.cjs`、`tests/command-triggers.test.cjs`、`tests/command-stacks.test.cjs`                        | 保存範囲、競合、安定ID、条件と実行順を保つデータ操作                                                                                     |

各スクリプトの引数・前提は現物と機能別文書で確認します。標準の`.\dev.bat test`はビルドと`tests/*.test.cjs`を実行し、上記の専用GUIスクリプトを一律には実行しません。

`scripts/applet-information-ui-test.cjs [固定EXE]`は、概要のプレーンテキスト表示、停止・開始待ち・失敗・再起動中の計測、読み取り専用データ、概要からの検索移動、設定の確定保存、選択Appletに限定した更新確認と他対象/全体更新の拒否を隔離fixtureで確認する。配布元リンクは外部ブラウザー呼出しを捕捉し、クリック/Enter/中クリック、更新先の上書きとの独立、起動失敗時の閲覧、起動エラーの表示と再試行、保存値と設定ページの保持を確認する。情報パネルが唯一の見出しとしてツールバーの上にあること、両ページの「起動時間の計測」が最下部にあること、Aboutのフォーム/JSON切替と自動確認の抑制は、専用Applet試験と`scripts/about-ui-test.cjs [固定EXE]`で確認する。既存の本体計測の共通表示は`scripts/host-startup-timing-ui-test.cjs [固定EXE]`を使う。

`command-triggers-ui-test.cjs --trigger-tabs-only`は、3方式の種類別タブと機能ページで、登録コマンドの順序、無効・利用不可の表示、編集取消と設定保持、操作列のアクセシブルな見出しを確認する。折り返しや列幅の見た目は変更時の代表画面で確認し、細かな寸法の一致を永続試験にしない。

代表的な実行例:

```powershell
.\dev.bat run build
.\dev.bat exec node scripts/settings-controls-ui-test.cjs
.\dev.bat exec node scripts/command-triggers-ui-test.cjs
.\dev.bat exec node --test tests/settings-editing.test.cjs tests/command-triggers.test.cjs tests/command-stacks.test.cjs tests/appearance.test.cjs
```

製品コード・設定・依存・ビルド/配布内容を変えないテストと開発文書だけの整備では、製品の版更新・publishは行いません。製品側の不具合を修正する場合は、[開発手順](development-workflow.md)に戻って影響先の検証と発行を行います。
